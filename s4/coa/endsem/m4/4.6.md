### 4.6 Common Framework for Memory Hierarchies

This section provides a unified way to look at different levels of memory (Cache vs. Main Memory and Main Memory vs. Virtual Memory). Despite their different physical implementations, they all share the same fundamental principles.

#### 1. The Four Questions of the Framework
To understand any level in the hierarchy, we ask four questions:
1.  **Block Placement:** Where can a block be placed? (Direct, Associative, or Set-Associative).
2.  **Block Identification:** How is a block found? (Tags in Cache, Page Tables in Virtual Memory).
3.  **Block Replacement:** Which block should be replaced on a miss? (LRU, FIFO, Random).
4.  **Write Strategy:** What happens on a write? (Write-through or Write-back).

#### 2. Comparison: Cache vs. Virtual Memory
The framework allows us to compare these two levels side-by-side:

| Feature | Cache (Level 1/2) | Virtual Memory |
| :--- | :--- | :--- |
| **Typical Size** | KB to MB | GB to TB |
| **Managed by** | Hardware (CPU) | Hardware + OS |
| **Block Size** | Lines (e.g., 64 bytes) | Pages (e.g., 4 KB) |
| **Placement** | Set-Associative / Direct | Fully Associative |
| **Miss Penalty** | Small (cycles) | Huge (milliseconds - Disk seek) |
| **Miss Handler** | Hardware | Software (Operating System) |

#### 3. Why Virtual Memory is Always "Fully Associative"
Because the "Miss Penalty" for Virtual Memory involves a Disk access (which is millions of times slower than RAM), the system must minimize page faults at all costs. 
*   **Fully Associative** placement (allowing a page to go anywhere in RAM) provides the lowest miss rate.
*   The complexity of searching a large page table is handled by the **Page Table** in memory and the **TLB** in hardware.

#### 4. The Unified Write Strategy
*   **Cache:** Uses both Write-Through and Write-Back.
*   **Virtual Memory:** **Always uses Write-Back**. Writing to a disk for every single store instruction would be prohibitively slow. Changes are kept in RAM and written to disk only when the page is evicted (using a "dirty bit").

#### 5. Common Frames of Reference
The term "Frame" usually refers to the physical slots in Main Memory, while "Block" is the generic term for the unit of data transfer between any two levels. The goal of the framework is to optimize the **Average Memory Access Time (AMAT)**:
$$AMAT = Hit\_Time + (Miss\_Rate \times Miss\_Penalty)$$
