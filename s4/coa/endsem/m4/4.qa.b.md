#### **Q11. Illustrate the concept of virtual memory. Explain in detail how address translation is carried out.**
*Ref: Dec 2018, Dec 2019, 2025 Internal (10 Marks)*

**Concept:** Virtual Memory is a technique that allows a program to be executed even if it is only partially present in the Main Memory (RAM). It gives the illusion of a very large memory by using the Secondary Storage (Hard Disk) as an extension of RAM.

**Address Translation Mechanism (Paging):**
1.  **Address Division:** The CPU generates a **Virtual Address**, which is divided into two parts:
    *   **Page Number (p):** Identifies the page within virtual memory.
    *   **Offset (d):** Identifies the specific word within that page.
2.  **Page Table Lookup:** The **Page Number** acts as an index into a **Page Table** (stored in RAM). Each entry in the Page Table contains:
    *   **Page Frame Number:** The corresponding block address in physical RAM.
    *   **Presence/Valid Bit:** If '1', the page is in RAM. If '0', a **Page Fault** occurs.
3.  **Physical Address Construction:** The hardware (MMU) takes the **Page Frame Number** from the table and appends the original **Offset**. This forms the **Physical Address** used to access the actual RAM hardware.
4.  **TLB Acceleration:** To avoid accessing the Page Table in RAM every time, a specialized cache called the **Translation Lookaside Buffer (TLB)** stores the most recent translations for instant access.

#### **Q13. How are parallel operations implemented effectively? Discuss instruction pipelining and its various stages.**
*Ref: Sept 2020, 2025 Internal (10 Marks)*

Parallelism is achieved by overlapping the execution of multiple instructions using an **Instruction Pipeline**. This is effective because different hardware units (Fetch unit, ALU, Write-back unit) can work on different instructions simultaneously.

**The Six Stages of an Instruction Pipeline:**
1.  **FI (Fetch Instruction):** The CPU reads the instruction from the memory address pointed to by the PC.
2.  **DI (Decode Instruction):** The instruction is interpreted to determine the opcode and the addressing mode.
3.  **CO (Calculate Operands):** The Effective Address (EA) of the source operands is calculated (e.g., adding an offset to a register).
4.  **FO (Fetch Operand):** The actual data (operands) are fetched from memory or registers.
5.  **EI (Execute Instruction):** The ALU performs the specified operation (Add, Sub, etc.).
6.  **WO (Write Operand):** The result is written back to the destination register or memory location.

**Effectiveness measure:** The total time to execute $n$ instructions in a $k$-stage pipeline is $T = (k + n - 1) \times t$ (where $t$ is the clock cycle).

#### **Q14. Explain structural, data, and control hazards with suitable assembly-level examples for each.**
*Ref: Dec 2018, May 2019, Sept 2020 (10 Marks)*

**1. Structural Hazard (Resource Conflict):**
*   **Cause:** Hardware cannot support all overlapping instructions (e.g., single memory port).
*   **Example:** If the pipeline needs to fetch Instruction 4 (Stage FI) at the same time Instruction 1 needs to fetch data from memory (Stage FO).
*   **Solution:** Separate I-Cache and D-Cache.

**2. Data Hazard (Data Dependency):**
*   **Cause:** An instruction needs a result that hasn't been written back yet.
*   **Example (RAW - Read After Write):**
    *   $I_1$: `ADD R1, R2, R3`  ($R1 \leftarrow R2+R3$)
    *   $I_2$: `SUB R4, R1, R5`  ($R4 \leftarrow R1-R5$)
    *   *Conflict:* $I_2$ tries to read $R1$ before $I_1$ has finished writing the sum into it.
*   **Solution:** **Data Forwarding** (sending the result directly from ALU output to ALU input).

**3. Control Hazard (Branch Hazard):**
*   **Cause:** The pipeline fetches the sequential instruction before knowing if a branch will jump elsewhere.
*   **Example:**
    *   $I_1$: `BRN Target` (Branch to Target if negative)
    *   $I_2$: `ADD R1, R2, R3` (Fetched by mistake)
    *   *Conflict:* If the branch is "Taken," $I_2$ must be flushed (thrown away), wasting cycles.
*   **Solution:** Branch Prediction or Delayed Branching.

#### **Q17. Technical Classification of Memory Types (ROM/DRAM)**
*Ref: KeralaNotes / Syllabus (Short Answer Focus)*

*   **Modern DRAM Types:**
    *   **SDRAM (Synchronous DRAM):** Synchronizes with the system clock for faster access.
    *   **DDR (Double Data Rate):** Transfers data on both the rising and falling edges of the clock.
*   **ROM Classifications:**
    *   **PROM:** Programmable once by the user.
    *   **EPROM:** Erasable using Ultraviolet (UV) light and re-programmable.
    *   **EEPROM:** Electrically Erasable and Programmable.
    *   **Flash Memory:** A variant of EEPROM that allows data to be erased/written in large blocks (used in SSDs and USB drives).
