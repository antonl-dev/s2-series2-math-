### 4.5 Virtual Memory

**Virtual Memory** is a memory management technique that creates an illusion for the programmer that the computer has a much larger main memory than it physically does. It allows the execution of programs that are larger than the available physical RAM.

#### 1. Basic Concept
The program resides on the **Secondary Memory** (Hard Disk/SSD), while only the currently active portions are kept in **Main Memory** (RAM).
*   **Virtual Address:** The address used by the programmer/CPU (part of a large "Virtual Address Space").
*   **Physical Address:** The actual address in the physical RAM.
*   **Address Mapping:** The hardware (Memory Management Unit - MMU) automatically translates Virtual Addresses into Physical Addresses during execution.

[Click here to see Virtual to Physical Address Mapping Concept](https://www.google.com/search?q=virtual+memory+address+mapping+MMU+diagram&udm=2)

#### 2. Paging
The most common implementation of virtual memory is **Paging**.
*   **Pages:** The virtual address space is divided into fixed-size blocks called Pages.
*   **Page Frames:** Physical RAM is divided into blocks of the same size called Frames.
*   **Page Table:** A table stored in memory that keeps track of which virtual page is stored in which physical frame. It contains a **Presence Bit** (or Valid bit) to indicate if the page is currently in RAM.

#### 3. Address Translation Process
A virtual address is typically divided into two parts: **Page Number** and **Offset**.
1.  The CPU provides a virtual address.
2.  The **Page Number** is used as an index into the **Page Table**.
3.  If the Presence Bit is 1, the **Frame Number** is retrieved from the table.
4.  The Frame Number is combined with the **Offset** to form the final **Physical Address**.

[Click here to see the Page Table address translation diagram](https://www.google.com/search?q=virtual+address+page+table+translation+diagram+offset&udm=2)

#### 4. Page Faults
If the CPU tries to access a page that is not currently in RAM (Presence Bit = 0), a **Page Fault** occurs.
1.  The execution is suspended.
2.  The Operating System (OS) locates the required page on the disk.
3.  The page is copied into an empty frame in RAM.
4.  The Page Table is updated, and the instruction is restarted.

#### 5. Page Replacement Algorithms
If RAM is full during a page fault, an existing page must be swapped out to make room.
*   **FIFO (First-In-First-Out):** The oldest page is replaced.
*   **LRU (Least Recently Used):** The page that hasn't been accessed for the longest time is replaced.
*   **Optimal (OPT):** Replaces the page that will not be used for the longest period in the future (Theoretical reference).

#### 6. Translation Lookaside Buffer (TLB)
Because the Page Table is in memory, every memory access would technically require *two* accesses (one for the table, one for the data). To speed this up, a small, high-speed cache called the **TLB** stores the most recent translations.
