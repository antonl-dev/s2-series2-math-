#### **Q1. What does memory hierarchy mean? Explain its significance in terms of size, speed, and cost per bit.**
*Ref: May 2019, Sept 2020, 2025 Internal (5-10 Marks)*

**Memory Hierarchy** is a structured organization of different types of memory in a computer system designed to minimize the speed gap between the processor and the storage.

**Significance & Trends:**
As we move from the top (Registers) to the bottom (Magnetic Disk):
1.  **Access Time (Speed):** Increases. Registers take $<1$ ns, Cache takes $1-10$ ns, Main Memory takes $60$ ns, and Disk takes milliseconds.
2.  **Storage Capacity (Size):** Increases significantly. Registers (Bytes), Cache (MB), Main Memory (GB), Secondary Storage (TB).
3.  **Cost per Bit:** Decreases. Registers are the most expensive; secondary storage is the cheapest.

**Why it works:** The hierarchy relies on the **Principle of Locality**. By keeping small amounts of active data in fast memory (Cache/Registers), the CPU achieves high performance at a lower total system cost.

#### **Q2. Distinguish between Static RAM (SRAM) and Dynamic RAM (DRAM).**
*Ref: 2025 Internal (5 Marks)*

| Feature | Static RAM (SRAM) | Dynamic RAM (DRAM) |
| :--- | :--- | :--- |
| **Cell Structure** | Uses Flip-flops (6 Transistors). | Uses 1 Transistor + 1 Capacitor. |
| **Refreshing** | Not required. | Required periodically (due to charge leak). |
| **Speed** | Very Fast (1–10 ns). | Slower (60 ns). |
| **Density/Size** | Less dense (takes more chip space). | Very dense (compact cell). |
| **Cost** | High. | Low. |
| **Usage** | Used for **Cache Memory**. | Used for **Main Memory (RAM)**. |

#### **Q4. Elaborate on the term "Locality of Reference" and its types.**
*Ref: 2025 Internal (5 Marks)*

**Locality of Reference** refers to the observation that a processor, over a short period, tends to access a specific, small portion of the memory repeatedly.

1.  **Temporal Locality:** If an item is referenced, it will tend to be referenced again soon (e.g., instructions inside a loop, sum variables).
2.  **Spatial Locality:** If an item is referenced, items with nearby addresses will tend to be referenced soon (e.g., sequential instruction execution, traversing an array).

#### **Q12. Discuss the various mapping techniques used in cache memories (Direct, Associative, and Set-Associative) with diagrams.**
*Ref: May 2019, Sept 2020 (10 Marks)*

Since the cache is smaller than main memory, we need mapping functions to decide where blocks are stored.

**1. Direct Mapping:**
*   **Logic:** Each memory block maps to exactly one specific line in the cache.
*   **Formula:** $i = j \pmod N$ (where $i$ is cache line, $j$ is memory block, $N$ is total cache lines).
*   **Address Breakdown:** Divided into **Tag**, **Line/Index**, and **Word/Offset**.
*   **Drawback:** If two blocks that map to the same line are needed, **Thrashing** occurs (constant swapping).

**2. Associative Mapping:**
*   **Logic:** A memory block can be placed in **any** available cache line.
*   **Mechanism:** Uses **Content Addressable Memory (CAM)** to compare the **Tag** bits of the address with all cache tags simultaneously.
*   **Advantage:** Most flexible; no thrashing.
*   **Drawback:** Complex and expensive hardware for parallel search logic.

**3. Set-Associative Mapping:**
*   **Logic:** A compromise. The cache is divided into $V$ sets, each containing $k$ lines ($k$-way). A block $j$ maps to set $i$ where $i = j \pmod V$. Once in the set, it can occupy any of the $k$ lines.
*   **Example:** In a 2-way set-associative cache, the hardware only needs to search 2 tags in parallel within a specific set.

#### **Q16. Describe the LRU (Least Recently Used) algorithm for cache replacement with an access sequence example.**
*Ref: Handwritten Notes (5 Marks)*

The **LRU Algorithm** discards the item that has not been accessed for the longest period. It uses "Age Bits" to track usage.

**Example Sequence:** `A, B, C, D, E, D, F` (Assume cache size = 4 blocks)
1.  `A, B, C, D` fill the four blocks.
2.  **Access E:** A "Cache Miss" occurs. The algorithm looks at which was used least recently. `A` was accessed first and hasn't been used since. **E replaces A**.
3.  **Access D:** A "Cache Hit" occurs. The age bit for `D` is reset to "most recent."
4.  **Access F:** A "Cache Miss" occurs. Among `E, B, C, D`, `B` is now the least recently used. **F replaces B**.

#### **Q8. Describe various methods for dealing with the branch hazard.**
*Ref: 2025 Internal (5 Marks)*

Branch hazards (Control Hazards) occur when the pipeline doesn't know the next instruction address because of a branch.

1.  **Stall (Freeze):** Simplest method. Stop fetching new instructions until the branch target is determined. This creates a "bubble" (lost cycles).
2.  **Branch Prediction:**
    *   **Static:** Always assume "Branch Not Taken" (fetch $PC+4$). If wrong, flush the pipeline.
    *   **Dynamic:** Uses a **Branch Target Buffer (BTB)** to track previous history and predict "Taken" or "Not Taken" based on behavior.
3.  **Delayed Branch:** The hardware is designed to **always** execute the single instruction immediately following the branch. The compiler must find a useful, independent instruction to put in this "delay slot."
