### 4.7 Introduction to Pipelining - Basic Principles

**Pipelining** is an implementation technique where multiple instructions are overlapped in execution. It is analogous to an assembly line in a factory; instead of waiting for one product to be finished before starting the next, different stages of the process work on different products simultaneously.

#### 1. The Basic Principle
In a non-pipelined processor, the CPU must complete all phases of an instruction (Fetch, Decode, Execute, Write Back) before starting the next one. In a pipelined processor, as soon as the first instruction moves from the 'Fetch' stage to the 'Decode' stage, the hardware for the 'Fetch' stage becomes free and immediately starts fetching the second instruction.

*   **Objective:** To increase the **throughput** (number of instructions completed per unit time).
*   **Note:** Pipelining does *not* decrease the time it takes to execute a single instruction (latency); it simply allows more instructions to be "in-flight" at once.

#### 2. Pipeline Segments and Registers
A pipeline is divided into several **segments** (or stages). Each segment is separated by **pipeline registers** (also called buffers/latches).
*   **Function of Registers:** They hold the intermediate results of one stage and pass them to the next stage on the next clock pulse.
*   **Synchronization:** All stages are controlled by a common master clock. The duration of a clock cycle is determined by the time taken by the **slowest stage** in the pipeline.

#### 3. Throughput and Speedup
The performance gain from pipelining is measured by **Speedup (S)**.
*   If a process has $k$ segments and we need to execute $n$ tasks:
    *   **Non-pipelined time ($T_n$):** $n \times k$ clock cycles.
    *   **Pipelined time ($T_p$):** $(k + n - 1)$ clock cycles.
*   **Speedup (S):** $\frac{n \times k}{k + n - 1}$
*   **Ideal Case:** For a very large number of instructions ($n \to \infty$), the speedup approaches $k$ (the number of stages).

#### 4. Space-Time Diagram
A space-time diagram (or pipeline execution chart) is used to show how instructions move through the segments over time.
*   **Vertical Axis:** Segments/Stages ($S_1, S_2, S_3...$).
*   **Horizontal Axis:** Clock cycles ($1, 2, 3...$).

#### 5. Example: 3-Segment Pipeline
Consider a process $A_i * B_i + C_i$:
1.  **Segment 1:** Fetch $A_i$ and $B_i$.
2.  **Segment 2:** Multiply ($A_i * B_i$).
3.  **Segment 3:** Add $C_i$ to the product.
By cycle 3, the adder is working on the first task, the multiplier on the second, and the fetch unit on the third.
