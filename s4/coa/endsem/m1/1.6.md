### 1.6 Instruction Formats and Instruction Sets

The design of an instruction format is a compromise between providing enough information for the CPU and keeping the instruction word short enough to fit in memory efficiently.

#### 1. General Instruction Format
An instruction is represented as a bit string, usually 16 or 32 bits long. It is divided into fields:
*   **Mode Field:** Specifies how the address field should be interpreted (e.g., direct vs. indirect).
*   **Opcode Field:** Identifies the operation (e.g., 001 for ADD, 010 for SUB). The number of bits determines the number of unique operations possible (3 bits = 8 operations).
*   **Address/Operand Field:** Contains the address of the operand or the operand itself.

#### 2. Instruction Set Architectures (ISA): RISC vs. CISC
A common theme in the exam papers is the comparison between the two major philosophies of instruction set design.

**A. CISC (Complex Instruction Set Computer)**
*   **Philosophy:** "Make one instruction do a lot."
*   **Characteristics:**
    *   Many instructions (hundreds).
    *   Variable-length instructions (e.g., 1 byte to 15 bytes).
    *   Instructions can perform complex tasks (e.g., adding a memory location directly to another memory location).
    *   Emphasis is on hardware.
    *   **Goal:** Minimize the number of instructions per program.

**B. RISC (Reduced Instruction Set Computer)**
*   **Philosophy:** "Make simple instructions that run very fast."
*   **Characteristics:**
    *   Fewer, simpler instructions.
    *   Fixed-length instructions (usually exactly 32 bits).
    *   **Load/Store Architecture:** Only specific instructions (`Load` and `Store`) can access memory. All arithmetic must happen between registers.
    *   Single-cycle execution for most instructions.
    *   Emphasis is on software/compilers.
    *   **Goal:** Minimize the time required for each instruction.

| Feature | RISC | CISC |
| :--- | :--- | :--- |
| **Instruction Size** | Fixed | Variable |
| **Addressing Modes** | Simple and Few | Many and Complex |
| **Memory Access** | Only Load/Store | Most instructions can access |
| **Execution Speed** | Fast (usually 1 cycle) | Varies (multi-cycle) |

---

#### 3. Categories of Instructions in a Set
A complete instruction set must include four types of operations:
1.  **Data Transfer Instructions:** Moving data between registers, or between memory and registers (e.g., `MOVE`, `LOAD`, `STORE`).
2.  **Arithmetic & Logic Instructions:** Operations performed by the ALU (e.g., `ADD`, `SUB`, `AND`, `OR`, `SHIFT`).
3.  **Program Control (Sequencing) Instructions:** Changing the flow of execution (e.g., `BRANCH`, `JUMP`, `CALL`, `RETURN`).
4.  **I/O Instructions:** Transferring data between the CPU and external peripherals (e.g., `IN`, `OUT`).

---

#### 4. Byte Addressability and Ordering
How instructions and data are organized in memory depends on the architecture:
*   **Byte-Addressable Memory:** Every single byte (8 bits) has a unique address.
*   **Big-Endian:** The **most significant byte** is stored at the lowest address (left-to-right).
*   **Little-Endian:** The **least significant byte** is stored at the lowest address (right-to-left).

**Example:** Hex value `0x12345678` at address 1000.
*   **Big-Endian:** Address 1000 holds `12`, 1001 holds `34`, 1002 holds `56`, 1003 holds `78`.
*   **Little-Endian:** Address 1000 holds `78`, 1001 holds `56`, 1002 holds `34`, 1003 holds `12`.
