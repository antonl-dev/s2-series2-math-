#### 1. MIPS-Specific Addressing Mode Details
*(Sourced from Q&A PDF)*

**A. PC-Relative Addressing (MIPS):**
*   **Math:** The effective address is the sum of the PC and a 16-bit two's complement offset.
*   **Constraint:** Because the offset is 16 bits, branch instructions can only move $32768$ bytes above or below the current PC.
*   **Example:** `beqz $t0, strEnd`
    *   If current branch instruction address is `0x4000000C`, and the offset is `100`.
    *   The formula is $PC + 4 + (Offset \times 4)$.
    *   New EA = `0x4000000C` $+ 4 + (100 \times 4)$.

**B. Pseudo-Direct Addressing (MIPS):**
*   **Usage:** Specifically used for J-type (Jump) instructions like `j` and `jal`.
*   **Format:** 6 bits of opcode + 26 bits of immediate target value.
*   **Math:** The Effective Address is calculated by taking the **upper 4 bits of the PC**, concatenating them with the **26-bit immediate value**, and appending **00** to the lower two bits (to ensure word alignment).
*   **Constraint:** This constrains the jump target to anywhere within the current 256 MB block of code ($1/16$ of the 4 GB address space).

#### 2. Nested Subroutines and The Processor Stack
*(Sourced from Q&A PDF)*

When a program calls a subroutine, the Return Address (the current PC) must be saved.
*   **Nesting:** If Subroutine 1 calls Subroutine 2, the return address for Subroutine 1 will be overwritten and lost unless saved properly.
*   **Solution:** The CPU uses a **Processor Stack** in memory, managed by a **Stack Pointer (SP)** register.
*   **Execution:**
    1.  The `CALL` instruction pushes the contents of the PC onto the processor stack.
    2.  The `RETURN` instruction pops the return address from the top of the stack back into the PC.
    *   Because a stack is Last-In-First-Out (LIFO), nested subroutines will automatically return in the exact reverse order they were called.

#### 3. Synchronous vs. Asynchronous Buses
*(Sourced from Q&A PDF)*

| Feature | Synchronous Bus | Asynchronous Bus |
| :--- | :--- | :--- |
| **Clock** | Transmitter and receiver are synchronized by a common clock. | No common clock synchronization. |
| **Data Transfer** | Takes place in blocks at a constant rate. | Character-oriented; data can arrive at any rate. |
| **Handshaking** | Not strictly required (relies on strict timing). | Requires Start and Stop bits for each character. |
| **Speed** | Used for high-speed transmission. | Used for low-speed transmission. |

#### 4. Condition Codes and The Status Register
*(Sourced from Typed KTU Notes & Q&A PDF)*

The CPU keeps track of the results of ALU operations using individual bits called **Condition Code Flags**, grouped in a **Status Register**.
*   **N (Negative):** Set to 1 if the result is negative; otherwise 0.
*   **Z (Zero):** Set to 1 if the result is exactly 0; otherwise 0.
*   **V (Overflow):** Set to 1 if arithmetic overflow occurs; otherwise 0.
*   **C (Carry):** Set to 1 if a carry-out results from the MSB of the operation; otherwise 0.

*(Specific to the PIC16F8X example in the Q&A PDF):*
The 8-bit STATUS register is mapped as: `IRP | RP1 | RP0 | TO | PD | Z | DC | C`
*   Bits 5 & 6 (`RP0, RP1`) are used for Direct Addressing Bank Selection.
*   Bit 1 (`DC`) is a Digit Carry (carry-out from the 4th low-order bit).

#### 5. 4-bit ALU and 4-bit Shifter Design
*(Sourced from Q&A PDF)*

**4-Bit ALU Logic Table:**
Controlled by Mode ($M$), and Selectors ($S1, S0$):
*   **If M = 0 (Logic Operations):**
    *   $S1=0, S0=0 \rightarrow A \text{ AND } B$
    *   $S1=0, S0=1 \rightarrow A \text{ OR } B$
    *   $S1=1, S0=0 \rightarrow A \text{ XOR } B$
*   **If M = 1 (Arithmetic Operations):**
    *   $S1=0, S0=0 \rightarrow \text{Transfer } A$
    *   $S1=0, S0=1 \rightarrow A + 1$
    *   $S1=1, S0=0 \rightarrow A + B'$ (A plus 1's complement of B)
    *   $S1=1, S0=1 \rightarrow A - B$

**4-Bit Serial-in to Parallel-out Shift Register:**
*   Built using 4 D-Flip-Flops (FFA, FFB, FFC, FFD) sharing a common clock.
*   The output ($Q$) of FFA feeds into the Data input ($D$) of FFB, and so on.
*   With each clock pulse, the data is shifted one place to the right, converting a serial bitstream into a 4-bit parallel word output ($Q_A, Q_B, Q_C, Q_D$).

#### 6. Detailed Instruction Cycle Flowchart Logic
*(Sourced from Handwritten Notes)*

Once an instruction is fetched and placed in the IR ($IR \leftarrow M[AR]$), the hardware must decode it. The handwritten notes detail a specific hardware check:
*   The instruction is decoded. The Opcode is in $IR(12-14)$, the Indirect bit $I$ is $IR(15)$, and the address is $IR(0-11)$.
*   **The $D_7$ Check:** A decoder looks at the opcode. If the opcode is `111` (which is decimal 7), the decoder activates the $D_7$ line.
*   **Branching Logic:**
    *   **If $D_7 = 0$:** It is a **Memory Reference Instruction**. The CPU checks the $I$ bit to see if it must fetch an indirect address before executing.
    *   **If $D_7 = 1$:** It is NOT a memory reference instruction. The CPU then checks the $I$ bit ($IR(15)$):
        *   If $I = 0$: It is a **Register Reference Instruction**.
        *   If $I = 1$: It is an **I/O Reference Instruction**.
