### 1.2 Basic Operational Concepts

To perform any given task, a computer executes an appropriate program consisting of a list of instructions stored in the memory. The interaction between the processor and the memory is the core of these operations.

#### 1. The Core Registers involved in Operations
To facilitate the movement of data and instructions, the processor contains several specialized high-speed storage locations called **Registers**:

*   **Program Counter (PC):** Contains the memory address of the **next** instruction to be fetched and executed. It "keeps track" of the program's progress.
*   **Instruction Register (IR):** Holds the instruction that is **currently** being executed.
*   **Memory Address Register (MAR):** Holds the address of the memory location that the CPU wants to read from or write to.
*   **Memory Data Register (MDR):** Holds the actual data that is being transferred to or from the memory.
*   **General Purpose Registers ($R_0$ through $R_{n-1}$):** Used for holding operands loaded from memory, intermediate results of ALU operations, or addresses.

#### 2. Instruction Processing Steps (General Logic)
The operation of the computer follows a repeated cycle of fetching and executing. A typical instruction like `Add LOC, R2` involves these high-level steps:
1.  **Fetch:** The instruction is fetched from memory location `LOC` and placed into the IR.
2.  **Decode:** The Control Unit examines the IR to understand that an "Add" operation is required.
3.  **Execute:** The operand at `LOC` is fetched and added to the contents of `R2` by the ALU, and the sum is stored back in `R2`.

#### 3. Detailed Hardware Operating Steps
Based on the provided technical materials, the exact step-by-step sequence for hardware interaction is as follows:

*   **Step 1:** The program resides in memory. The **PC** is set to point to the first instruction.
*   **Step 2:** The contents of the **PC** are transferred to the **MAR**. A **Read** signal is sent to the memory.
*   **Step 3:** The instruction is read out from memory and loaded into the **MDR**.
*   **Step 4:** The contents of the **MDR** are transferred to the **IR**.
*   **Step 5:** The Control Unit decodes the instruction. If the instruction requires data (operands), their addresses are sent to the **MAR**, a **Read** is performed, and the data arrives in the **MDR**.
*   **Step 6:** Data from the **MDR** is sent to the **ALU** or a General Purpose Register.
*   **Step 7:** The **ALU** performs the operation (e.g., Add, Sub).
*   **Step 8:** The result is either stored in a General Purpose Register or sent to memory (Address to **MAR**, Result to **MDR**, then a **Write** signal).
*   **Step 9:** During execution, the **PC** is incremented to point to the next instruction.

#### 4. Handling Interrupts
A critical operational concept is the **Interrupt**.
*   In order to respond immediately to an external event (like a keyboard press or a printer error), the execution of the current program must be suspended.
*   The device raises an **Interrupt Signal**.
*   The processor saves its current state and executes a special program called an **Interrupt-Service Routine (ISR)**.
*   Once the ISR is finished, the processor resumes the original program from where it left off.

#### 5. Types of Instructions (Basic Examples)
*   **Load LOC, R2:** Transfers data from memory location `LOC` to register `R2`.
*   **Store R2, LOC:** Transfers data from register `R2` to memory location `LOC`.
*   **Add R1, R2, R3:** Adds contents of $R1$ and $R2$, then places the sum into $R3$.
