### 1.8 Instruction Cycle

The **Instruction Cycle** is the complete process by which a computer retrieves a program instruction from its memory, determines what actions the instruction requires, and carries out those actions. This cycle is repeated continuously by the CPU from boot-up until the computer is shut down.

---

#### 1. The Two Primary Phases
An instruction cycle is fundamentally divided into two major phases:
1.  **Fetch Phase:** The instruction is brought from memory into the processor. This phase is common to all instructions.
2.  **Execute Phase:** The processor interprets the instruction and performs the specific operation (arithmetic, data transfer, etc.).

#### 2. Detailed Step-by-Step Execution (Single Bus)
To understand the timing and control, we break the cycle into specific "Time Steps" ($T_0, T_1, T_2, ...$).

**Phase 1: Fetching (Common to all instructions)**
*   **Step 1 ($T_0$):** The address of the next instruction is moved from the **Program Counter (PC)** to the **Memory Address Register (MAR)**. A **Read** signal is sent to memory.
    *   *Control Signal:* $PC_{out}, MAR_{in}, Read, Select4, Add, Z_{in}$ (Note: The CPU often starts incrementing the PC simultaneously).
*   **Step 2 ($T_1$):** The processor waits for the memory to respond (**Wait for MFC**). The updated PC value (PC+4) is moved from $Z$ back to the $PC$.
    *   *Control Signal:* $Z_{out}, PC_{in}, Y_{in}, WMFC$.
*   **Step 3 ($T_2$):** The instruction word arrives in the **MDR** and is then moved to the **Instruction Register (IR)**.
    *   *Control Signal:* $MDR_{out}, IR_{in}$.

**Phase 2: Decoding and Execution (Varies by instruction)**
*   **Step 4 ($T_3$):** The Instruction Decoder interprets the opcode in the IR. If the instruction is `Add (R3), R1` (Indirect mode):
    *   The contents of $R3$ are moved to the **MAR** to fetch the actual operand from memory.
    *   *Control Signal:* $R3_{out}, MAR_{in}, Read$.
*   **Step 5 ($T_4$):** Transfer $R1$ to temporary register $Y$ to prepare for addition.
    *   *Control Signal:* $R1_{out}, Y_{in}, WMFC$.
*   **Step 6 ($T_5$):** The operand from memory (now in **MDR**) is added to the value in $Y$.
    *   *Control Signal:* $MDR_{out}, SelectY, Add, Z_{in}$.
*   **Step 7 ($T_6$):** The final sum in $Z$ is moved to register $R1$.
    *   *Control Signal:* $Z_{out}, R1_{in}, End$.

#### 3. Branching Logic within the Cycle
When a **Branch Instruction** (like `JUMP` or `Branch>0`) is executed, the instruction cycle is modified:
1.  **Target Calculation:** Instead of just $PC+4$, the CPU calculates a "Branch Target Address" (usually $PC + Offset$).
2.  **Update:** This target address is loaded into the **PC**.
3.  **Result:** The next fetch phase will pull the instruction from the new address instead of the sequential one.

#### 4. The Instruction Decoder's Role
Located between the fetch and execute phases, the **Instruction Decoder** is a combinational circuit that:
*   Examines the bits in the **IR**.
*   Identifies the **Addressing Mode**.
*   Triggers the correct sequence of control signals for the execution phase.

---

### Summary of Register Involvement
*   **PC:** Provides the address for the fetch.
*   **MAR:** Holds address for both instruction fetch and data operand fetch.
*   **MDR:** Gateway for instruction code and data operands arriving from memory.
*   **IR:** Holds the opcode so the decoder can manage the execution phase.
