### 1.7 Processor Unit: Fundamental Concepts

This section explains the internal structure of the processor and how its components (registers, ALU, and control unit) interact to process data.

#### 1. Internal Architecture of the CPU
The processor consists of several key hardware blocks interconnected by an internal bus. The primary goal is to fetch instructions from memory, decode them, and execute the required operations.

**Key Internal Components:**
*   **Arithmetic and Logic Unit (ALU):** The combinational circuit that performs the math and logic. It has two inputs ($A$ and $B$) and one output ($R$).
*   **Control Unit:** The hardware that issues control signals to manage the timing and routing of data.
*   **Register File:** A set of general-purpose registers ($R_0$ to $R_{n-1}$) used for temporary data storage.
*   **Specialized Registers:**
    *   **PC (Program Counter):** Points to the next instruction.
    *   **IR (Instruction Register):** Holds the current instruction opcode.
    *   **MAR (Memory Address Register):** Interfaces with the address lines of the external memory bus.
    *   **MDR (Memory Data Register):** Interfaces with the data lines of the external memory bus.

#### 2. Register Transfers
The most basic operation inside a processor is moving data from one register to another using the internal bus.
*   **Control Signals:** Each register has an **input enable** signal ($R_{in}$) and an **output enable** signal ($R_{out}$).
*   **Mechanism:** When $R1_{out}$ is set to 1, the contents of register R1 are placed on the bus. When $R4_{in}$ is set to 1, the data currently on the bus is loaded into register R4.
*   **Constraint:** Only one register can output data to the bus at a time to avoid electrical conflict.

#### 3. Execution of an Instruction (Fundamental Logic)
To execute an instruction, the processor must perform a sequence of micro-operations.

**A. Fetching a Word from Memory:**
1.  **Address to MAR:** The processor moves the address from a register (like PC) to the MAR ($MAR \leftarrow [PC]$).
2.  **Read Signal:** The control unit sends a **Read** signal on the memory bus.
3.  **Wait for MFC:** The processor waits for the **Memory Function Completed (MFC)** signal from the RAM.
4.  **Data to MDR:** The data from the memory bus arrives in the MDR.
5.  **MDR to Destination:** The processor moves the data from the MDR to a register (like IR or a GP register).

**B. Storing a Word in Memory:**
1.  **Address to MAR:** $MAR \leftarrow [Address]$.
2.  **Data to MDR:** $MDR \leftarrow [Data]$.
3.  **Write Signal:** The control unit sends a **Write** signal.
4.  **Completion:** The processor waits for the MFC signal to ensure the write is finished.

---

#### 4. Performing Arithmetic Operations (ALU Logic)
Since the ALU is a combinational circuit with no memory, both operands must be present at its inputs simultaneously.
*   **Operand A:** Usually comes from a temporary register **Y**.
*   **Operand B:** Usually comes directly from the internal bus.
*   **Result:** The output is stored in a temporary register **Z** before being moved to the final destination.

**Example: Sequence for `Add R1, R2` (Single Bus):**
1.  $R1_{out}, Y_{in}$ (Move first operand to Y).
2.  $R2_{out}, Select Y, Add, Z_{in}$ (Place second operand on bus, select ALU function, store in Z).
3.  $Z_{out}, R2_{in}$ (Move result to destination).

---

#### 5. Multiple Bus Efficiency
As discussed in section 1.3, multiple buses allow these fundamental concepts to happen in parallel.
*   In a **Three-Bus Organization**, the processor can fetch two operands from the register file (via Bus A and Bus B) and send the result back (via Bus C) all in a **single clock cycle**. This significantly reduces the instruction execution time.
