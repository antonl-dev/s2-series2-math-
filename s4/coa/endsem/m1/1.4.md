### 1.4 Representation of Instructions: Machine Instructions and Operands

A machine instruction must contain all the information required by the CPU to perform a specific operation. This information is represented in binary but discussed using Assembly Language for clarity.

#### 1. Components of an Instruction
Every instruction is divided into fields:
*   **Opcode (Operation Code):** Specifies the type of operation to be performed (e.g., ADD, SUB, MOVE, LOAD).
*   **Operands:** The data on which the operation is performed. Operands can be:
    *   Stored in **Memory** (identified by an address).
    *   Stored in **Processor Registers** (identified by a register number like R0, R1).
    *   Provided **Immediately** within the instruction itself (a constant value).

#### 2. Instruction Word Length
The length of an instruction word is usually a multiple of the byte size (8 bits). 
*   In a 32-bit word length machine, an instruction is typically 4 bytes long.
*   The number of address fields in an instruction significantly impacts the word length and the internal organization of the CPU.

#### 3. Instruction Types by Number of Operands/Addresses
Instructions are classified based on how many operand addresses they contain. This is a very common exam topic.

**A. Three-Address Instructions**
*   **Format:** `Operation Source1, Source2, Destination`
*   **Example:** `Add A, B, C`
*   **Logic:** $C \leftarrow [A] + [B]$
*   **Advantage:** Very powerful; can perform complex arithmetic in one line.
*   **Disadvantage:** Requires a very long instruction word to fit three memory addresses.

**B. Two-Address Instructions**
*   **Format:** `Operation Source, Destination`
*   **Example:** `Add A, B`
*   **Logic:** $B \leftarrow [A] + [B]$
*   **Note:** The original value of $B$ is destroyed and replaced by the result. One operand acts as both a source and a destination.
*   **To preserve data:** To calculate $C = A + B$ without destroying $A$ or $B$, we must use a MOVE:
    1. `Move B, C`
    2. `Add A, C`

**C. One-Address Instructions (Accumulator Organization)**
*   **Format:** `Operation Source`
*   **Example:** `Add A`
*   **Logic:** $Accumulator \leftarrow Accumulator + [A]$
*   **Mechanism:** Uses a specialized implicit register called the **Accumulator (ACC)**.
*   **Typical Set:** 
    *   `Load A` (Copies memory A to ACC)
    *   `Store A` (Copies ACC to memory A)

**D. Zero-Address Instructions (Stack Organization)**
*   **Logic:** Operands are taken from the top of a **Stack** data structure.
*   **Example:** `Add`
*   **Mechanism:** It pops the top two elements from the stack ($TOS$ and $TOS_{-1}$), adds them, and pushes the result back onto the stack.
*   **Commands:** `Push` and `Pop` are used to move data between memory and the stack.

#### 4. Register Transfer Notation (RTN)
To describe how data moves between locations, we use square brackets `[]` and an arrow `←`.
*   **Value of a location:** `[LOC]` means the contents of memory location `LOC`.
*   **Transfer:** `R1 ← [LOC]` means move the value at memory `LOC` into register `R1`.
*   **Addition:** `R3 ← [R1] + [R2]` means add values of `R1` and `R2` and place the sum in `R3`.

#### 5. Assembly Language Notation
While RTN is for description, Assembly is for actual programming.
*   **Syntax:** `Opcode Source, Destination` (Note: In some architectures, the order is Destination, Source. KTU notes usually follow `Source, Destination` or `Operand1, Operand2, Destination`).
*   **Example:** `Move LOC, R1` (Copies data, `LOC` is unchanged).
