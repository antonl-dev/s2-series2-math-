# 4.6 Common Framework for Memory Hierarchies

### Overview
The "Common Framework" is a set of four questions used to understand and compare any two levels in a memory hierarchy (such as Cache vs. Main Memory or Main Memory vs. Virtual Memory). Although the specific terminology changes (Blocks vs. Pages), the underlying logic remains the same.

### 1. The Four Questions of the Framework
Every level of the hierarchy must address these four problems:

#### **Q1: Block Placement (Where can a block be placed?)**
*   **Cache:** Uses mapping (Direct, Associative, or Set-Associative).
*   **Virtual Memory:** Usually "Fully Associative" (a page can be placed in any available block/frame in RAM) to minimize expensive Page Faults.

#### **Q2: Block Identification (How is a block found?)**
*   **Cache:** Uses a **Tag** to identify if the data in the cache line matches the requested memory address.
*   **Virtual Memory:** Uses a **Page Table** (Mapping Table) to translate a Virtual Address into a Physical Address (PDF 2, Page 3).

#### **Q3: Block Replacement (Which block is replaced on a miss?)**
When the memory is full, the system must choose which data to discard to make room for new data. As seen in **PDF 1, Page 10**, common strategies include:
*   **FIFO:** Oldest one out.
*   **LRU (Least Recently Used):** The one not accessed for the longest time.
*   **Optimal:** The one that won't be used for the longest time in the future (theoretical).

#### **Q4: Write Strategy (What happens on a write?)**
*   **Write-Through:** Data is updated in both the current level and the level below simultaneously.
*   **Write-Back:** Data is updated only in the current level. The level below is updated only when that block is replaced.

### 2. Comparison Summary
| Feature | Cache (Level 1/2) | Virtual Memory (Level 3/4) |
| :--- | :--- | :--- |
| **Managed by** | Hardware (Cache Controller) | Hardware + OS (MMU) |
| **Block Size** | Small (e.g., 64 bytes) | Large (e.g., 4KB - 8KB) |
| **Miss Penalty** | Small (cycles) | Very Large (millions of cycles) |
| **Mapping** | Direct/Set-Associative | Fully Associative |
