# 4.10 Pipeline Hazard Detection and Resolution

### Overview
A **Pipeline Hazard** is a problem that occurs in a pipeline that prevents the next instruction in the instruction stream from executing in its designated clock cycle. Hazards reduce the performance from the ideal speedup.

### 1. Types of Hazards (PDF 1, Page 15; PDF 2, Page 13)
There are three main categories of pipeline hazards:

#### **A. Structural Hazards (Hardware/Resource Conflicts)**
*   **Cause:** Occurs when the hardware cannot support all possible combinations of instructions in the same clock cycle. Multiple instructions try to use the same physical resource (e.g., memory, ALU, or registers) simultaneously.
*   **Example (PDF 1, Page 16):** Instruction 1 is in the **Result Write Back** stage (using memory), while Instruction 4 is in the **Fetch** stage (also using memory) at the same clock cycle.
*   **Resolution:** 
    *   **Stalling:** Wait (insert a "bubble") until the resource is free.
    *   **Hardware Duplication:** Use separate instruction and data memories (Harvard Architecture).

#### **B. Data Hazards**
*   **Cause:** Occurs when an instruction depends on the result of a previous instruction that is still moving through the pipeline.
*   **Types (PDF 1, Page 16):**
    1.  **RAW (Read After Write):** Instruction 2 tries to read a register before Instruction 1 has finished writing to it. This is a "True Data Dependency."
    2.  **WAR (Write After Read):** Instruction 2 tries to write to a register before Instruction 1 has read it.
    3.  **WAW (Write After Write):** Instruction 2 tries to write to a destination before Instruction 1 has written to it.
*   **Resolution:** 
    *   **Forwarding (Bypassing):** Passing the result directly from the output of the ALU to the input of the next stage without waiting for it to be written to a register.
    *   **Stalling (Bubble):** Adding a delay until the data is ready.

#### **C. Control Hazards (Branch Hazards)**
*   **Cause:** Occurs due to branch, jump, or interrupt instructions. The pipeline does not know which instruction to fetch next until the branch condition is calculated.
*   **Example (PDF 2, Page 12):** If a "Branch if Equal" condition is met, the program jumps to a new address. The instructions already "pre-fetched" in the pipeline behind the branch become invalid and must be discarded.
*   **Resolution:** 
    *   **Branch Prediction:** Guessing whether the branch will be taken or not.
    *   **Delayed Branching:** Reordering instructions so the CPU does useful work while the branch is being decided.
    *   **Flush Pipeline:** Clearing the pipeline when a branch is taken (costs cycles).

### 2. Hazard Detection
Modern CPUs use **Hazard Detection Units**. These are logic circuits that compare the source registers of an instruction in the "Decode" stage with the destination registers of instructions already in the "Execute" or "Memory" stages. If a match is found, the unit triggers a **Stall** or **Forwarding** signal.
