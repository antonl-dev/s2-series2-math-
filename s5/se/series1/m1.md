### **PART 1: Introduction to SE & Software Engineering Ethics**

**1. Software Engineering (SE)**
An engineering discipline focused on all aspects of software production. The goal is to build software that is reliable, delivered on time, and within budget.
*   **Professional Software Development:** Building software for business/clients, which requires strict scheduling, team collaboration, testing, and long-term maintenance (unlike coding a personal hobby project).

**2. Software Engineering Ethics (ACM/IEEE Code of Ethics)**
Software engineers must act honestly and ethically. The 8 core principles are:
1.  **Public:** Act consistently with the public interest.
2.  **Client & Employer:** Act in their best interests, consistent with the public interest.
3.  **Product:** Ensure products meet the highest professional standards.
4.  **Judgment:** Maintain integrity in professional judgment.
5.  **Management:** Promote ethical management of software development.
6.  **Profession:** Advance the reputation of the profession.
7.  **Colleagues:** Be fair to and supportive of colleagues.
8.  **Self:** Participate in lifelong learning.

### **PART 2: The Waterfall Model**

The classic linear, sequential approach. You must finish one phase 100% before moving to the next. There is no going backwards.

*   **Requirements:** Gathering and documenting client needs (SRS).
*   **Design:** Creating system architecture and data structures.
*   **Implementation:** Writing the actual code (Unit testing).
*   **Testing:** Integrating modules and testing the whole system. *(Takes maximum effort during development).*
*   **Maintenance:** Fixing bugs post-release. *(Takes maximum effort in the software's entire lifetime).*

**Advantages:** Simple to manage; strict documentation.
**Disadvantages:** Rigid; working software is produced very late; cannot easily handle changing requirements.

**ASCII Visualization: The Waterfall Cascading Steps**
```text
 [Requirements]
       │
       └──> [System Design]
                  │
                  └──> [Implementation (Coding)]
                             │
                             └──> [Integration & Testing]
                                        │
                                        └──> [Maintenance]
```

### **PART 3: V-Model & Incremental Model**

#### **1. The V-Model (Verification and Validation)**
Instead of moving straight down like Waterfall, the phases bend upwards after coding, forming a "V". For every development phase on the left, a corresponding testing phase is planned on the right.
*   **Advantages:** Defects are found early; highly disciplined.
*   **Disadvantages:** Inflexible to changes.

**ASCII Visualization: The V-Model**
```text
 Requirements Analysis                      Acceptance Testing
           \                                      /
            \                                    /
      System Design                       System Testing
              \                                /
               \                              /
        Architecture Design         Integration Testing
                 \                          /
                  \                        /
             Module Design           Unit Testing
                       \                  /
                        \                /
                         \              /
                          [   Coding   ]
```

#### **2. The Incremental Model**
The project is divided into multiple small modules (increments). The core, most important features are delivered in **Increment 1**. Then, subsequent increments add more features.
*   **Advantages:** Working software is delivered early; easier to test small chunks.
*   **Disadvantages:** Requires excellent initial architecture to ensure all increments fit together later.

**ASCII Visualization: Incremental Model**
```text
 [Core Features] ---> Build 1 ---> Delivered to Client!
       +
 [Extra Features] ---> Build 2 ---> Delivered!
       +
 [Final Polish] -----> Build 3 ---> Final Product Completed!
```

### **PART 4: The Spiral Model**

Proposed by Barry Boehm, this is a **Risk-Driven** iterative model. It handles large, expensive, and complex projects by constantly evaluating risks. The project spirals outwards through 4 main quadrants.

*   **Quadrant 1 (Determine Objectives):** Identify goals, alternatives, and constraints.
*   **Quadrant 2 (Risk Analysis):** Evaluate risks and build prototypes to solve them.
*   **Quadrant 3 (Development & Testing):** Build the actual software using models like Waterfall.
*   **Quadrant 4 (Review & Planning):** Client reviews the progress, and the team plans the next loop of the spiral.
*   **Advantages:** Excellent risk management; good for huge projects.
*   **Disadvantages:** Complex to manage; requires expensive risk experts.

### **PART 5: The Agile Model**

Agile focuses on extreme flexibility, minimal documentation, and heavy customer collaboration. Software is built in short 2-to-4 week cycles called **Sprints**.

*   **The 4 Core Values (Agile Manifesto):**
    1.  **Individuals & interactions** over processes & tools.
    2.  **Working software** over comprehensive documentation.
    3.  **Customer collaboration** over contract negotiation.
    4.  **Responding to change** over following a strict plan.
*   **Advantages:** Adapts to changes easily; client sees progress every sprint.
*   **Disadvantages:** Hard to predict final budget/time; lacks documentation.
*   **Examples of Agile Models:** Scrum, Kanban, Extreme Programming (XP), Feature-Driven Development (FDD).
