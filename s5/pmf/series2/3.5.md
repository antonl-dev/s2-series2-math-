# 3.5 Project Scheduling

## 1. Calendars in MS Project
Project scheduling is fundamentally based on working time. MS Project relies on three distinct layers of calendars to determine when work can actually be performed:
*   **Project Calendar:** The base calendar for the entire project. It establishes standard working days (e.g., Mon-Fri), shift hours (e.g., 8:00 AM - 5:00 PM), and organization-wide holidays.
*   **Resource Calendar:** Defines the individual availability of a specific resource (a person or equipment). It accounts for personal vacations, sick leaves, or specific shifts for that resource.
*   **Task Calendar:** A specialized calendar applied to a specific task that requires unique working hours outside the normal project rules (e.g., a machine that runs 24/7).

## 2. Task Relationships (Dependencies / Links)
In project scheduling, tasks rarely occur in isolation; they are logically connected. MS Project uses **task links** to establish the sequence of project activities.
There are four types of relationships:
1.  **Finish-to-Start (FS):** The successor task cannot start until the predecessor task finishes. (Most common).
2.  **Start-to-Start (SS):** The successor task cannot start until the predecessor task starts. (Tasks run concurrently).
3.  **Finish-to-Finish (FF):** The successor task cannot finish until the predecessor task finishes.
4.  **Start-to-Finish (SF):** The successor task cannot finish until the predecessor task starts. (Rarely used).

## 3. Lag Time and Lead Time
Sometimes, a standard task link is not enough, and you need to introduce a specific delay or overlap.
*   **Lag Time (Delay):** A mandatory waiting period introduced between dependent tasks. Written with a **plus sign (+)**.
    *   *Example syntax:* `3FS + 2d` (Task starts 2 days *after* Task 3 finishes).
*   **Lead Time (Overlap):** An overlap introduced where a successor can start *before* the predecessor completely finishes (used to fast-track schedules). Written with a **minus sign (-)**.
    *   *Example syntax:* `3FS - 2d` (Task starts 2 days *before* Task 3 finishes).

## 4. Task Constraints
Constraints govern how the MS Project scheduling engine places tasks on the timeline relative to strict target dates.
*   **Flexible Constraints:** Allow tasks to move freely dynamically based on network logic (e.g., *As Soon As Possible (ASAP)*).
*   **Hard Constraints:** Force a task to start or finish on a specific rigid date regardless of network logic (e.g., *Must Finish On*).

## 5. The Task Information Dialog Box
A comprehensive window in MS Project used to inspect or modify all properties of a single task in one place (resources, constraints, advanced notes, and calendars).

## Exam Questions & Answers for Section 3.5

### Short Questions (2 Marks)

**Q1. State the role of task dependencies in project scheduling.**
**Answer:** Task dependencies (links) establish the logical relationships and correct sequence between project activities. They ensure that the scheduling engine understands which tasks must finish or start before subsequent tasks can begin, preventing impossible workflow scenarios.

**Q2. List any two types of task relationships used in project scheduling.**
**Answer:** 
1. Finish-to-Start (FS)
2. Start-to-Start (SS)

**Q3. Name two ways to assign a calendar to a task in MS Project.**
**Answer:**
1. **Via Task Information Dialog Box:** Double-click the task -> go to the *Advanced* tab -> choose the desired calendar from the Calendar drop-down menu.
2. **Via Task Sheet Table View:** Insert the *Task Calendar* column into the active Task Sheet table and select the specific calendar from the drop-down menu.

**Q4. How do you type Lag Time and Lead Time in MS Project?**
**Answer:** They are typed directly into the *Predecessors* column in the Task Sheet. Lag time uses a plus sign (e.g., `FS+3d` for a 3-day delay), and Lead time uses a minus sign (e.g., `FS-2d` for a 2-day overlap).

**Q5. Discuss how MS Project shows task connections visually.**
**Answer:** MS Project shows task connections using **dependency lines (link arrows)** on the right-hand Gantt Chart timeline. The arrow originates from the predecessor task bar and points directly to the successor task bar, visually indicating the logical sequence (e.g., an arrow pointing from the end of one bar to the start of another indicates a Finish-to-Start link).

**Q6. Explain the use of the Task Information dialog box in MS Project.**
**Answer:** It is a comprehensive window used to inspect and modify all properties of a specific task. By double-clicking a task, managers can use this dialog box to assign resources, set task calendars, define constraints, and add advanced notes without cluttering the main screen.

### Essay Questions (8 Marks)

**Q7. Explain how Project Calendars, Task Calendars, and Resource Calendars work together in MS Project.** *(Covers Essay Q2)*
**Answer:**
**Introduction:**
In MS Project, accurate scheduling depends entirely on defining working vs. non-working time. The software evaluates three interacting layers of calendars simultaneously to schedule work. If any of these calendars specify non-working time, scheduling is adjusted accordingly.

**1. Project Calendar (The Foundation):**
*   *Function:* This is the default organizational calendar applied to the entire project.
*   *Details:* It defines the base working days, standard shift hours (e.g., Monday to Friday, 8:00 AM - 5:00 PM), and company-wide holidays.

**2. Resource Calendar (The Human/Equipment Element):**
*   *Function:* Defines the individual working availability for a specific assigned resource.
*   *Details:* It inherits the base rules from the Project Calendar but allows for personal overrides. For example, if "Engineer A" takes a 3-day personal vacation, it is entered here.
*   *Interaction:* When Engineer A is assigned to a task, MS Project will *not* schedule work on those 3 vacation days, thereby extending the task's timeline automatically.

**3. Task Calendar (The Exception Rule):**
*   *Function:* Applied to specific tasks that must run on unique schedules outside the normal project rules.
*   *Details:* Used for special operations. For example, a project calendar may be 5 days a week, but the task "Concrete Curing" requires 24/7 continuous time, including weekends.
*   *Interaction (Task Override):* If a task has a Task Calendar applied, the user can check a box labeled *"Scheduling ignores resource calendars"*. This forces the task to follow the Task Calendar strictly, regardless of individual resource availability or the base project holidays.

**Q8. Explain the four types of task links (FS, SS, FF, SF) in MS Project with simple examples / Explain the different types of task relationships used in project scheduling and illustrate the role of each.** *(Covers Essay Q6, Q26)*
**Answer:**
**Role of Task Relationships:**
In project scheduling, task relationships (dependencies) dictate the logical sequence of project activities. They tell the scheduling engine how a change in one task's date should impact the dates of subsequent tasks. 

**The Four Types of Task Links:**

**1. Finish-to-Start (FS):**
*   *Definition:* The successor task cannot start until the predecessor task completely finishes. This is the most natural and commonly used logical relationship.
*   *Example:* "Wall Painting" (Successor) cannot start until "Drywall Installation" (Predecessor) finishes.

**2. Start-to-Start (SS):**
*   *Definition:* The successor task cannot start until the predecessor task starts. They do not have to finish at the same time, but they run concurrently.
*   *Example:* "Concrete Pouring" (Predecessor) and "Concrete Leveling" (Successor) must start around the same time to ensure the concrete doesn't set unevenly.

**3. Finish-to-Finish (FF):**
*   *Definition:* The successor task cannot finish until the predecessor task finishes.
*   *Example:* "Software Testing" (Successor) cannot completely finish until "Code Writing" (Predecessor) is completely finished. Testing can happen concurrently, but the final sign-off waits for the final code.

**4. Start-to-Finish (SF):**
*   *Definition:* The successor task cannot finish until the predecessor task starts. This is extremely rare in project management.
*   *Example:* A "Legacy Security System" (Successor) cannot be shut down/finished until the "New Security System" (Predecessor) officially starts operating to ensure there is no gap in security.

**Q9. Explain the difference between flexible constraints (ASAP) and hard constraints (Must Finish On) in MS Project.** *(Covers Essay Q7)*
**Answer:**
**Introduction to Constraints:**
Task Constraints govern how MS Project's scheduling engine places tasks on the timeline relative to strict target dates. They fall into two major categories: Flexible and Hard constraints. Understanding the difference is crucial because misuse of constraints can break the automated logic of a project schedule.

**1. Flexible Constraints (Soft Constraints):**
*   *Mechanism:* Flexible constraints do *not* lock a task to a specific, rigid date. They allow the MS Project scheduling engine to move tasks dynamically forward or backward based on predecessor links, lag times, and resource availability.
*   *Role in CPM:* Because they move freely, they allow the Critical Path Method (CPM) algorithm to function perfectly, calculating float naturally.
*   *Examples:* 
    *   **As Soon As Possible (ASAP):** The default mode. The software schedules the task to start at the earliest possible date given its dependencies.
    *   **As Late As Possible (ALAP):** Pushes the task to the latest possible date without delaying the project.

**2. Hard Constraints (Rigid/Must Constraints):**
*   *Mechanism:* Hard constraints strictly lock a task's start or finish date to a specific calendar day, *regardless* of surrounding network logic. 
*   *Impact on the Schedule:* If a predecessor task is delayed, a hard constraint will refuse to move the successor task. This often leads to scheduling conflicts, network errors, and negative slack/float (meaning the schedule is mathematically impossible to achieve).
*   *Examples:*
    *   **Must Start On (MSO):** Forces the task to start on the exact date specified.
    *   **Must Finish On (MFO):** Forces the task to finish on the exact date specified, usually mandated by a strict external contract deadline.
