# 3.6 Project Control and Monitoring

## 1. What is Project Control and Monitoring?
Once the planning phase is complete and execution begins, the project manager must ensure the project stays on track. **Project Control and Monitoring** involves tracking actual progress, comparing it against the original planned baseline, identifying deviations (variances) in schedule or cost, and implementing corrective actions.

## 2. Setting the Project Baseline
Before you can track deviations, you need a point of reference. 
*   **Definition:** A **Baseline** is an approved snapshot of the original project schedule (start/finish dates, duration, cost, and work estimates). 
*   **Purpose:** It serves as the static benchmark against which actual project performance is evaluated.
*   **In MS Project:** You set this via the *Project Tab -> Set Baseline*.

## 3. Key Tracking Parameters Monitored
During execution, a project manager updates MS Project regularly with actual field data:
*   **% Complete:** Updates actual task progress (e.g., a task is 50% done).
*   **Actual Start / Actual Finish Dates:** Recorded when work *actually* begins or finishes, which may differ from the planned dates.
*   **Remaining Duration:** How much time is left to finish the task.
*   **Actual Costs:** Real money spent versus the planned budget.

## 4. Tools for Variance Analysis in MS Project
When actual data is entered, MS Project automatically calculates deviations using:
*   **Schedule Variance:** `Variance = Actual Date - Baseline Date`. A positive number indicates the project is behind schedule.
*   **Tracking Gantt View:** A special visual view that displays the baseline bars (colored gray) directly beneath the actual/planned progress bars (colored red/blue). This allows for instant visual comparison.
*   **Earned Value Analysis (EVA):** Advanced financial metrics calculating Schedule Variance (SV) and Cost Variance (CV) to see if the project is over/under budget.

## 5. Custom Fields and Data Exchange (Excel)
*   **Custom Fields:** MS Project allows users to add user-defined parameters (costs, risk ratings, text codes) beyond standard fields (like Duration). They use lookups, formulas, or graphical indicators (like Red/Yellow/Green stoplights) to filter and organize tasks.
*   **Excel Integration:** Project data can be seamlessly imported from or exported to Microsoft Excel using the **Import/Export Wizard** and built-in field mapping. This is crucial for sharing data with stakeholders who do not have MS Project installed.

### Short Questions (2 Marks)

**Q1. State the importance of project monitoring in MS Project.**
**Answer:** Project monitoring is crucial to ensure that the project is progressing according to the initial plan. It allows project managers to identify schedule and cost deviations early, evaluate the impact of delays, and take necessary corrective actions to prevent project failure.

**Q2. List any two parameters that can be monitored using MS Project.**
**Answer:** 
1. Actual Start and Actual Finish dates.
2. Percentage (%) Complete of tasks.

**Q3. State the role of updating project progress in MS Project.**
**Answer:** Updating project progress (by entering actual dates and % complete) enables the MS Project scheduling engine to recalculate remaining work, shift dependent future tasks automatically, and flag schedule and cost deviations against the baseline.

### Essay Questions (8 Marks)

**Q4. Explain the complete process of project monitoring and control using MS Project, from preparation of the initial plan to implementation of corrective measures. / Discuss how schedule deviations can be identified and controlled.** *(Covers Essay Q33, Q34, Q35, Q36, Q37)*
**Answer:**
**Introduction:**
Project monitoring and control is a continuous cycle executed during the project lifecycle. MS Project provides automated tools to compare planned performance with actual progress, identify delays, and help managers implement corrective actions. The systematic process involves four major steps:

**Step 1: Establishing the Baseline (The Reference Point)**
Before execution begins, the project manager finalizes the project schedule and budget. In MS Project, they navigate to the *Project Tab* and click **Set Baseline**. This creates a permanent, approved snapshot of the initial schedule, costs, and work estimates. Without a baseline, variance calculation is impossible.

**Step 2: Updating Actual Project Progress**
As work occurs on the ground, the manager must feed real-time data into MS Project. Key parameters updated include:
*   **Actual Start & Finish Dates:** Did the task start on time?
*   **% Complete:** Is the task physically halfway done (50%)?
*   Updating this data forces the software's engine to recalculate the remaining duration of tasks.

**Step 3: Identifying Schedule Deviations and Analyzing the Critical Path**
Once actuals are updated, MS Project automatically calculates deviations (variances). Managers identify these deviations through:
*   **Tracking Gantt View:** This visual tool displays the original baseline as a gray bar underneath the current actual colored task bar. If the colored bar extends past the gray bar, a delay is visually evident.
*   **Variance Tables:** MS Project calculates `Schedule Variance = Actual Date - Baseline Date`. 
*   **Critical Path Analysis:** The manager pays special attention to critical tasks (red bars). If a deviation occurs on a critical task, MS Project will automatically push the final project completion date forward, alerting the manager to a serious overall delay.

**Step 4: Taking Corrective Actions (Controlling)**
Once a critical delay is identified, the manager must control it. In MS Project, they can simulate corrective actions such as:
*   **Fast-Tracking:** Changing task links (e.g., from Finish-to-Start to Start-to-Start) to allow overlapping of delayed tasks.
*   **Crashing:** Adding more resources (e.g., assigning a second team) to a delayed critical task to reduce its remaining duration, bringing the schedule back in line with the baseline.

**Q5. Explain how to use Custom Fields in MS Project to organize project tasks.** *(Covers Essay Q3)*
**Answer:**
While MS Project comes with standard fields (like Task Name, Duration, and Start Date), **Custom Fields** allow project managers to record, calculate, and categorize user-defined data specific to their organization's needs. 

**Types of Custom Fields and Their Uses:**
1.  **Text / Flag Fields:** Used for custom labeling or simple Yes/No indicators (e.g., Creating a flag field for "Requires Client Approval").
2.  **Number / Cost Fields:** Used for tracking secondary budgets, vendor quotes, or custom risk scores.
3.  **Formula Fields:** Managers can program fields to auto-calculate values based on built-in metrics (e.g., calculating a specific tax percentage based on the Baseline Cost).

**Key Mechanisms for Organization:**
*   **Lookup Tables:** To prevent data entry errors, custom fields can be restricted to predefined drop-down options (e.g., assigning tasks to specific departments like "Electrical", "Civil", "Mechanical").
*   **Graphical Indicators:** Managers can replace boring numbers with visual alert symbols. For example, a custom field can display a Red/Yellow/Green stoplight icon based on schedule variance thresholds, instantly alerting stakeholders to high-risk tasks.
*   **Grouping & Filtering:** Once custom fields are populated, the manager can group or filter the Task Sheet (e.g., "Show me only tasks labeled 'High Risk' in the Civil department").

**Q6. Explain how project data can be imported from or exported to Microsoft Excel in MS Project.** *(Covers Essay Q4, Q5)*
**Answer:**
Interoperability between MS Project and standard spreadsheet software like Excel is crucial for bulk data editing and sharing reports with stakeholders who do not have MS Project installed. This is managed using the **Import/Export Wizard**.

**Exporting Data to Excel:**
1.  Go to the *File* menu, select *Save As*, and choose the *Excel Workbook (.xlsx)* file format.
2.  The **Export Wizard** opens. The user chooses whether to export using an existing template map or create a custom data map.
3.  Select the specific data type to export: Tasks, Resources, or Assignments.
4.  **Field Mapping:** The user maps MS Project fields (e.g., Task Name, Start Date, Cost) to standard Excel column headers. Once finished, MS Project generates a clean Excel spreadsheet containing the project data.

**Importing Data from Excel:**
1.  Go to the *File* menu, select *Open*, and browse for the target Excel file.
2.  The **Import Wizard** initiates.
3.  The user specifies how the incoming data should be handled: *Append* to the active project, *Merge* into the active project (overwriting existing data), or *Create* a completely new project file.
4.  Just like exporting, the user must map the Excel spreadsheet columns to the corresponding MS Project fields so the software understands where to place task names and durations on the Gantt chart.
