# 3.6 Project Control and Monitoring in MS Project

**Course:** 23HUT535 / 24HUT535 – Project Management and Finance  
**Module III:** Project Management Using MS Project  
**File:** `3.6.md`

---

## 1. Concept of Project Control and Monitoring

* **Project Monitoring:** The continuous process of collecting, measuring, and reporting actual project performance data (schedule dates, hours worked, costs incurred, quality) during execution.
* **Project Control:** Comparing monitored actual performance against the **approved Baseline plan**, analyzing variances, and taking **corrective or preventive actions** (crashing, fast-tracking, resource reallocation) to keep scope, time, and cost on target.

In **MS Project**, monitoring and controlling follow a structured cycle:
$$\text{Save Baseline} \rightarrow \text{Set Status Date} \rightarrow \text{Update Actuals} \rightarrow \text{Analyze Variances / EVM} \rightarrow \text{Take Corrective Action}$$

[Click here to see the diagram for Project Monitoring and Control Cycle in MS Project](https://www.google.com/search?q=MS+Project+tracking+gantt+baseline+variance+monitoring+diagram&udm=2)

---

## 2. Step-by-Step Workflow in MS Project

### Step 1: Save a Baseline (`Project > Set Baseline`)
Before work starts, the finalized schedule and budget must be frozen as a **Baseline**.
* **How:** Go to **`Project > Set Baseline > Set Baseline`** → select **Entire Project** (or Selected Tasks).
* **What Gets Saved:** Original **Start, Finish, Duration, Work, and Cost** for every task and resource.
* **Capacity:** MS Project supports saving up to **11 Baselines** (`Baseline`, plus `Baseline 1` through `Baseline 10`) to preserve historical snapshots when approved scope changes occur.
* **Interim Plan:** A lighter snapshot (`Set Interim Plan`) that saves *only* Start and Finish dates (up to 10 interim plans) to track date shifts without overwriting full cost/work baselines.

### Step 2: Set the Status Date (`Project > Status Date`)
* **Purpose:** Tells MS Project the exact "as-of" cutoff date for progress updates and Earned Value calculations.
* **Visual Tip:** Go to **`Gantt Chart Format > Gridlines`** and set a red vertical line for **Status Date** so delayed tasks to the left of the line are immediately obvious.

### Step 3: Enter Actual Progress (`Task` / `Project` Tab)
Switch to the **Tracking Table** (`View > Tables > Tracking`) or use the **Task** tab tools:
1. **Mark on Track (`Task > Mark on Track`):** Automatically marks selected tasks as up-to-date through the Status Date.
2. **Percentage Complete Metrics:**
   * **`% Complete`:** Percentage of **Duration** elapsed ($\frac{\text{Actual Duration}}{\text{Total Duration}} \times 100\%$).
   * **`% Work Complete`:** Percentage of **Labor Hours (Work)** completed.
   * **`Physical % Complete`:** User-entered true technical completion independent of hours/days elapsed (recommended for accurate **Earned Value**).
3. **Update Tasks Dialog (`Task > Mark on Track dropdown > Update Tasks`):** Enter exact **Actual Start**, **Actual Finish**, **Actual Duration**, and **Remaining Duration**.
4. **Reschedule Uncompleted Work (`Project > Update Project`):** Automatically pushes unfinished portions of overdue tasks to resume *after* the Status Date so the schedule stays realistic.

### Step 4: Monitor Variances (Tracking Gantt & Tables)
MS Project compares **Current/Actual** values against **Baseline** values (`Variance = Current – Baseline`):
1. **Tracking Gantt View (`View > Other Views > Tracking Gantt`):**
   * Displays **gray Baseline bars** directly beneath **blue/red Scheduled/Actual bars** along with `% Complete`. Any misalignment reveals slippage visually.
2. **Variance Table (`View > Tables > Variance`):**
   * Displays `Start Variance` and `Finish Variance` (positive value = days behind schedule).
3. **Cost Table (`View > Tables > Cost`):**
   * Displays `Total Cost`, `Baseline Cost`, `Variance` (Cost Variance = `Total Cost – Baseline Cost`), `Actual`, and `Remaining`.
4. **Built-in Monitoring Filters (`View > Filter`):**
   * **`Slipping Tasks`:** Shows tasks finishing later than their baseline finish date.
   * **`Incomplete Tasks`** / **`Tasks with Deadlines`** / **`Critical`**: Quickly isolates problem areas.

## 3. Earned Value Management (EVM) in MS Project

**Earned Value Management (EVM)** integrates **Scope, Schedule, and Cost** into objective performance indicators. Access it in MS Project via **`View > Tables > More Tables > Earned Value`** (or *Earned Value Schedule Indicators* / *Earned Value Cost Indicators*).

### Key EVM Terms & Formulas in MS Project

| Standard Term | MS Project Column Name | Meaning & Formula |
| :--- | :--- | :--- |
| **PV** (Planned Value) | **BCWS** *(Budgeted Cost of Work Scheduled)* | Authorized baseline cost of work planned up to the Status Date. |
| **EV** (Earned Value) | **BCWP** *(Budgeted Cost of Work Performed)* | Baseline budget value of work *actually* accomplished up to Status Date ($\text{BAC} \times \%\text{ Complete}$). |
| **AC** (Actual Cost) | **ACWP** *(Actual Cost of Work Performed)* | Actual money spent for the work performed up to the Status Date. |
| **BAC** (Budget at Completion) | **BAC** *(Baseline Cost)* | Total approved baseline budget for the entire project. |
| **SV** (Schedule Variance) | **SV** | $\text{SV} = \text{BCWP} - \text{BCWS} = \text{EV} - \text{PV}$ |
| **CV** (Cost Variance) | **CV** | $\text{CV} = \text{BCWP} - \text{ACWP} = \text{EV} - \text{AC}$ |
| **SPI** (Schedule Performance Index) | **SPI** | $\text{SPI} = \dfrac{\text{BCWP}}{\text{BCWS}} = \dfrac{\text{EV}}{\text{PV}}$ |
| **CPI** (Cost Performance Index) | **CPI** | $\text{CPI} = \dfrac{\text{BCWP}}{\text{ACWP}} = \dfrac{\text{EV}}{\text{AC}}$ |
| **EAC** (Estimate at Completion) | **EAC** | Projected final total cost: $\text{EAC} = \text{AC} + \dfrac{\text{BAC} - \text{EV}}{\text{CPI}} = \dfrac{\text{BAC}}{\text{CPI}}$ |
| **VAC** (Variance at Completion) | **VAC** | Expected budget surplus/deficit at finish: $\text{VAC} = \text{BAC} - \text{EAC}$ |

### Interpreting EVM Metrics (Exam Quick Rules)
* **Variances (`SV`, `CV`, `VAC`):**
  * **$SV > 0$:** Ahead of schedule | **$SV < 0$:** Behind schedule.
  * **$CV > 0$:** Under budget | **$CV < 0$:** Over budget.
* **Indices (`SPI`, `CPI`):**
  * **$SPI > 1.0$:** Ahead of schedule | **$SPI < 1.0$:** Behind schedule (e.g., $SPI = 0.80$ means only 80% of planned progress achieved).
  * **$CPI > 1.0$:** Under budget | **$CPI < 1.0$:** Over budget (e.g., $CPI = 0.85$ means getting only ₹0.85 of work per ₹1 spent).

[Click here to see the diagram for Earned Value Management EVM S-Curve PV EV AC](https://www.google.com/search?q=earned+value+management+EVM+S+curve+PV+EV+AC+SV+CV+diagram&udm=2)

## 4. Reporting & Corrective Control Actions

### Built-in Reports (`Report` Tab)
* **Dashboards:** *Project Overview*, *Cost Overview*, *Work Overview*, *Upcoming Tasks*.
* **In Progress Reports:** *Critical Tasks*, *Late Tasks*, *Milestone Report*, *Slipping Tasks*.
* **Visual Reports (`Report > Visual Reports`):** Exports S-curves and Earned Value charts directly into **Microsoft Excel** or Visio.

### Corrective Actions Taken After Variance Detection
1. **Schedule Recovery:** Crash critical tasks (add overtime/extra resources) or fast-track tasks (change `FS` links to `SS` or add Lead time `-`).
2. **Resource Rebalancing:** Move idle workers from high-slack non-critical tasks to delayed critical tasks, or run **Resource Leveling**.
3. **Cost Control:** Negotiate vendor rates, reduce non-essential scope (with formal Change Control approval), or re-estimate remaining work.
4. **Re-baselining (Only on Formal Approval):** Save updated plan into `Baseline 1` while keeping original `Baseline` intact for audit history.

**Question:** Describe the complete project monitoring and control process in MS Project. Explain how Earned Value Management (EVM) metrics are used in MS Project to evaluate schedule and cost health, illustrating with a numerical example.

**Answer:**

**1. Project Monitoring & Control Workflow in MS Project (3.5 Marks):**  
1. **Set Baseline (`Project > Set Baseline`):** Freeze original planned schedule, work, and budget before execution starts.
2. **Set Status Date (`Project > Status Date`):** Anchor the reporting cutoff date for tracking and EVM calculations.
3. **Record Actual Performance (`View > Tables > Tracking`):** Enter `% Complete`, `Physical % Complete`, Actual Start/Finish, and Actual Costs; use `Project > Update Project` to push uncompleted overdue work beyond the Status Date.
4. **Identify Variances:** Use **Tracking Gantt** (baseline vs. actual bars), **Variance Table** (`Finish Variance`), **Cost Table**, and filters (`Slipping Tasks`, `Critical`) to detect schedule slippage or budget overruns.
5. **Apply Corrective Actions & Report:** Compress delayed critical tasks via crashing/fast-tracking, reallocate resources from high-slack tasks, and export dashboards (`Report > Project Overview / Cost Overview / Burndown`).

**2. Earned Value Management (EVM) in MS Project (2.5 Marks):**  
Via **`View > Tables > More Tables > Earned Value`**, MS Project evaluates three core inputs up to the Status Date:
* **BCWS (PV – Planned Value):** Authorized baseline cost scheduled to be completed.
* **BCWP (EV – Earned Value):** Baseline cost of work actually accomplished.
* **ACWP (AC – Actual Cost):** Actual cost spent on work performed.

From these, MS Project computes:
* **Schedule Variance:** $SV = EV - PV$ ($<0 \Rightarrow$ behind schedule) and **$SPI = EV / PV$** ($<1 \Rightarrow$ behind schedule).
* **Cost Variance:** $CV = EV - AC$ ($<0 \Rightarrow$ over budget) and **$CPI = EV / AC$** ($<1 \Rightarrow$ over budget).
* **Estimate at Completion:** $EAC = BAC / CPI$ and **Variance at Completion:** $VAC = BAC - EAC$.

**3. Illustrative Numerical Example (2 Marks):**  
Suppose a project has total budget $BAC = \text{Rs.\; } 10,00,000$. At the Status Date:
* Planned Value ($PV / BCWS$) = Rs. 5,00,000
* Earned Value ($EV / BCWP$) = Rs. 4,00,000
* Actual Cost ($AC / ACWP$) = Rs. 4,50,000

Calculations:
* $SV = 4,00,000 - 5,00,000 = \mathbf{-\text{Rs.\; } 1,00,000}$ and $SPI = \frac{4,00,000}{5,00,000} = \mathbf{0.80}$ $\rightarrow$ **Behind schedule** (only 80% of planned progress achieved).
* $CV = 4,00,000 - 4,50,000 = \mathbf{-\text{Rs.\; } 50,000}$ and $CPI = \frac{4,00,000}{4,50,000} = \mathbf{0.89}$ $\rightarrow$ **Over budget** (spending ₹1 for ₹0.89 of value).
* $EAC = \frac{10,00,000}{0.89} \approx \mathbf{\text{Rs.\; } 11,23,596}$ $\rightarrow$ Projected cost overrun of Rs. 1,23,596 unless corrective action is taken.
