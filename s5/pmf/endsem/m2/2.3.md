## 1. Introduction to Resource Scheduling

### What is Resource Scheduling?
**Resource Scheduling** is the process of planning, assigning, and timing project activities while considering the **availability and capacity limits of resources** (manpower, machinery, materials, tools, and budget).

### Why Basic CPM / PERT is Insufficient
Classical **CPM and PERT** assume **unlimited resource availability**—meaning any number of parallel activities can run simultaneously as long as precedence logic allows.  
In real-world projects, however, multiple parallel activities often compete for the same **limited skilled labor, heavy crane, testing rig, or daily cash flow**, creating **resource overallocation (conflict)**. Resolving these conflicts is known as **Project Scheduling with Constrained Resources** (or the **Resource-Constrained Project Scheduling Problem – RCPSP**).

## 2. Classification of Resource Constraints

### A. Based on Project Flexibility (Time vs. Resource)
1. **Time-Constrained Project:**
   * The **project completion deadline is fixed** and cannot be extended.
   * Extra resources (overtime, subcontracting, temporary hires) are brought in if needed, and non-critical tasks are shifted within their float to smooth usage (**Resource Leveling**).
2. **Resource-Constrained Project:**
   * **Resource availability is strictly capped** (e.g., max 10 welders, 1 tower crane, or fixed monthly budget) and cannot be exceeded.
   * Activities are delayed whenever resource limits are hit, even if doing so **extends the overall project completion date** (**Resource Allocation / Smoothing under hard caps**).

### B. Based on Nature of Resources
1. **Renewable Resources:** Available period-by-period up to a fixed capacity; usage in one day does not permanently consume them for future days (e.g., engineers, electricians, cranes, machines).
2. **Non-Renewable (Consumable) Resources:** Have a fixed total stock for the entire project; once used, they are gone (e.g., total project capital budget, steel tonnage, cement bags).
3. **Doubly Constrained Resources:** Constrained both per period and across the total project (e.g., limited monthly cash outflow *and* total project budget).

## 3. Techniques for Constrained-Resource Scheduling

Because exact mathematical optimization becomes computationally impractical for large networks, two broad approaches are used:

### 1. Exact Mathematical Methods (For Small Projects)
* **Integer Linear Programming (ILP) / Dynamic Programming / Branch-and-Bound:** Formulates start times and resource caps as mathematical equations to find the guaranteed shortest duration. Used mostly in small projects or academic optimization.

### 2. Heuristic Priority-Rule Methods (Practical Industry Standard)
Uses step-by-step **dispatching rules** (heuristics) to decide which eligible activity gets scarce resources first when a conflict arises.

**Common Heuristic Priority Rules (Ordered by Effectiveness):**
1. **Minimum Slack / Total Float First (MINSLK):** Prioritize the task with the **least Total Float** (critical tasks first). *Most widely used and effective rule.*
2. **Minimum Late Finish / Late Start (LFT / LST):** Prioritize the task with the earliest Late Finish or Late Start date.
3. **Shortest Processing Time (SPT):** Prioritize the shortest-duration activity to free resources quickly and reduce waiting queues.
4. **Longest Processing Time (LPT):** Prioritize the longest activity first to avoid leaving big tasks until the end.
5. **Most Immediate Successors (MIS):** Prioritize the task that unlocks the highest number of downstream tasks.
6. **Maximum Resource Demand / First-Come-First-Served (FCFS):** Tie-breaking rules when priorities are equal.

### Serial vs. Parallel Scheduling Approach
* **Parallel Method (Clock-driven):** Moves time step-by-step ($t = 0, 1, 2, \dots$). At each time unit, lists all eligible activities whose predecessors are finished and allocates available resources in priority order until resources run out; remaining eligible tasks wait for the next time step.
* **Serial Method (Activity-driven):** Orders all activities once by priority, then schedules each activity as early as precedence and remaining resource profiles allow.

## 4. Worked Numerical Example (Constrained Resource Scheduling)

**Problem:** A project has 4 activities with a strict **maximum manpower limit of 6 workers/day**. Schedule the project using the **Parallel Method** with the **Minimum Total Float (MINSLK)** priority rule and find the new project duration.

| Activity | Predecessor | Duration (Days) | Daily Workers Required |
| :---: | :---: | :---: | :---: |
| A | – | 2 | 4 |
| B | – | 3 | 3 |
| C | A | 2 | 4 |
| D | B | 2 | 2 |

**Step 1: Unconstrained CPM Analysis (Assuming Unlimited Workers)**
* Path $A \rightarrow C = 2 + 2 = 4$ days ($TF_A = 1,\; TF_C = 1$)
* Path $B \rightarrow D = 3 + 2 = \mathbf{5\text{ days}}$ (Critical Path, $TF_B = 0,\; TF_D = 0$)
* *Note:* At Day 0, starting A and B together needs $4 + 3 = 7\text{ workers} > 6\text{ limit}$ (Resource Conflict!).

**Step 2: Apply Parallel Heuristic Scheduling (Cap = 6 Workers/Day)**

* **At Time $t = 0$:**
  * Eligible activities: **A** ($TF = 1$, 4 workers) and **B** ($TF = 0$, 3 workers).
  * By **MINSLK**, **B** has higher priority ($TF = 0 < 1$).
  * Schedule **B** from **$t = 0$ to $3$** (uses 3 workers; remaining = $6 - 3 = 3$ workers).
  * Can **A** (needs 4 workers) start? **No** ($4 > 3$ remaining). Delay **A**.

* **At Time $t = 3$:**
  * **B** finishes. Eligible activities: **A** (needs 4 workers, dur 2) and **D** (unlocked by B, needs 2 workers, dur 2).
  * Combined demand $= 4 + 2 = 6 \le 6$ workers!
  * Schedule both **A** and **D** from **$t = 3$ to $5$** (uses 6 workers; remaining = 0).

* **At Time $t = 5$:**
  * **A** and **D** finish. Eligible activity: **C** (unlocked by A, needs 4 workers, dur 2).
  * Schedule **C** from **$t = 5$ to $7$** (uses 4 workers $\le 6$).

**Result:**
* Unconstrained Duration = **5 days**
* **Resource-Constrained Project Duration = 7 days** (extended by 2 days because A had to wait for B to free manpower, while maximum daily workforce never exceeded **6 workers**).

## 5. Critical Chain Project Management (CCPM) — Modern Extension

Introduced by **Eliyahu M. Goldratt** (Theory of Constraints), **Critical Chain Project Management (CCPM)** extends CPM by defining the **Critical Chain** as the longest path considering **both task dependencies AND resource dependencies**.
* Eliminates hidden individual task padding (student syndrome/Parkinson's law).
* Protects the project using **Project Buffers** (at the end), **Feeding Buffers** (where non-critical chains join the critical chain), and **Resource Buffers** (early warnings for scarce shared resources).

#### Model Question 2 (5 Marks – Part B Style)
**Source:** *Self-Created (Syllabus Topic 2.3 – Heuristic Priority Rules)*  
**Question:** Why do classical CPM/PERT schedules fail under resource constraints? Explain any four heuristic priority rules used in resource-constrained project scheduling.

**Answer:**  
Classical CPM and PERT calculate schedules purely from precedence logic assuming **unlimited resources**. In reality, multiple concurrent activities often require the same limited crew, machinery, or budget, causing **resource overallocation** that makes the unconstrained CPM schedule impossible to execute.

To resolve conflicts systematically, project managers use **Heuristic Priority Rules** to decide which eligible task receives scarce resources first:
1. **Minimum Slack / Total Float First (MINSLK):** Gives highest priority to activities with the smallest Total Float so critical and near-critical paths are not delayed.
2. **Minimum Late Finish / Late Start (LFT / LST):** Schedules tasks with the earliest allowable completion dates first.
3. **Shortest Processing Time (SPT):** Prioritizes shorter tasks to complete them rapidly and free up shared equipment/crew for waiting activities.
4. **Most Immediate Successors (MIS):** Prioritizes tasks that unlock the largest number of downstream activities, reducing overall network bottlenecks.

#### Model Question 3 (8 Marks – Part B University Exam Style)
**Source:** *Self-Created (Syllabus Topic 2.3 – Comprehensive Theory + Solved Problem)*  
**Question:** Explain the problem of project scheduling with constrained resources. Describe the Parallel Heuristic Method and solve the following scheduling problem assuming a maximum resource limit of **5 technicians per day**.

| Activity | Predecessor | Duration (Days) | Technicians/Day |
| :---: | :---: | :---: | :---: |
| A | – | 3 | 3 |
| B | – | 2 | 4 |
| C | A | 2 | 2 |
| D | B | 3 | 3 |

**Answer:**

**1. Resource-Constrained Scheduling Concept (2 Marks):**  
When multiple concurrent activities require more renewable resources (technicians, cranes, testing rigs) than are available, a **resource conflict** occurs. Since CPM ignores resource caps, **Resource-Constrained Project Scheduling (RCPSP)** sequences activities according to **both precedence logic and strict resource limits**, using priority heuristics (such as Minimum Total Float) to minimize project delay.

**2. Parallel Heuristic Method Steps (2 Marks):**
1. Perform an unconstrained CPM pass to compute Total Float ($TF$) for all tasks.
2. Start at clock time $t = 0$ and list all eligible activities (predecessors finished).
3. Rank eligible activities using a priority rule (e.g., Minimum Total Float; tie-breaker: Shortest Duration).
4. Allocate resources sequentially until the resource cap is reached; delay remaining tasks.
5. Advance $t$ to the next activity completion time and repeat until all tasks are scheduled.

**3. Solution to the Numerical Problem (4 Marks):**
* **Unconstrained CPM Check:**
  * Path $A \rightarrow C = 3 + 2 = 5$ days ($TF = 0$)
  * Path $B \rightarrow D = 2 + 3 = 5$ days ($TF = 0$)
  * Unconstrained Duration = **5 days** (both paths critical). At $t=0$, $A+B$ need $3+4=7 > 5$ technicians (Conflict!).

* **Parallel Scheduling (Priority: Minimum $TF$, Tie-breaker: Shortest Duration; Cap = 5 techs/day):**
  * **At $t = 0$:** Eligible = A ($TF=0, D=3$, needs 3) and B ($TF=0, D=2$, needs 4).  
    By tie-breaker (Shortest Duration), schedule **B** ($t = 0 \to 2$, uses 4 techs; 1 tech left). A (needs 3) must wait.
  * **At $t = 2$:** B finishes. Eligible = A ($TF=0$, needs 3) and D (unlocked by B, $TF=0$, needs 3).  
    $3 + 3 = 6 > 5$ (Conflict!). Both have $TF=0$; check remaining duration / tie-breaker: A ($D=3$) vs D ($D=3$); choose **A** first (alphabetical/earlier original start) from **$t = 2 \to 5$** (uses 3 techs; 2 left, insufficient for D).
  * **At $t = 5$:** A finishes. Eligible = C (unlocked by A, needs 2, $D=2$) and D (needs 3, $D=3$).  
    Combined demand $= 2 + 3 = 5 \le 5$! Schedule both **C** ($t = 5 \to 7$) and **D** ($t = 5 \to 8$) simultaneously!

* **Final Constrained Schedule:**
  * **B:** $0 \to 2$ (4 techs)
  * **A:** $2 \to 5$ (3 techs)
  * **C:** $5 \to 7$ (2 techs) and **D:** $5 \to 8$ (3 techs) $\rightarrow$ total $5$ techs during $5\text{–}7$, $3$ techs during $7\text{–}8$.
  * **Constrained Project Completion Time = 8 days** (increased from 5 days due to the 5-technician limit).
