## 1. Gantt Chart (Bar Chart)

### Definition
A **Gantt Chart**, developed by **Henry L. Gantt** in the 1910s, is a visual horizontal **bar chart** used to represent a project schedule. It plots **project activities/tasks** on the vertical axis against a **time scale** (days, weeks, or months) on the horizontal axis, where the length of each horizontal bar represents the planned duration of that activity.

[Click here to see the diagram for Gantt Chart Example](https://www.google.com/search?q=gantt+chart+example+project+management+diagram&udm=2)

### Key Features of a Gantt Chart
1. **Task List (Vertical Axis):** Displays all project activities or WBS work packages sequentially.
2. **Timeline Scale (Horizontal Axis):** Shows project duration broken into hours, days, weeks, or months.
3. **Activity Bars:** Horizontal bars whose start position, length, and end position indicate start date, duration, and finish date.
4. **Milestones:** Zero-duration key checkpoints/events typically represented by diamond symbols ($\diamond$).
5. **Dependencies (Modern Gantt Charts):** Arrows linking bars to show precedence relationships (e.g., Finish-to-Start).
6. **Progress Tracking Shading:** A darker fill or percentage bar inside each activity bar compares **actual progress** against **planned progress**, often with a vertical "today" status line.
7. **Resource Assignment:** Can display the person, team, or equipment assigned to each bar.

### Advantages and Limitations of Gantt Charts

| Advantages | Limitations |
| :--- | :--- |
| Simple, intuitive, and easy for non-technical stakeholders to read. | Becomes cluttered and hard to manage for very large projects (hundreds of tasks). |
| Clearly shows task start dates, end dates, and overlaps at a glance. | Traditional Gantt charts do not clearly show complex interdependencies or critical paths. |
| Useful for tracking planned vs. actual progress in status meetings. | Does not quantify uncertainty in activity durations (unlike PERT). |
| Helps in basic workload visualization and resource planning. | Bar lengths represent duration, not cost or work complexity. |

## 2. Network Fundamentals (AOA vs. AON)

Before applying **CPM** or **PERT**, a project is modeled as a **Network Diagram** showing logical dependencies between activities.

1. **Activity-on-Arrow (AOA) Network:**
   * **Arrows** represent activities; **Nodes (Circles)** represent events (milestones/start or finish of activities).
   * Uses **Dummy Activities** (dashed arrows with zero duration and zero resource) purely to maintain logical dependency or avoid duplicate numbering between two nodes.
   * Nodes are numbered using **Fulkerson's Rule** (left to right, tail event number $i <$ head event number $j$).

2. **Activity-on-Node (AON) / Precedence Diagram:**
   * **Nodes (Boxes)** represent activities; **Arrows** represent precedence relationships.
   * No dummy activities are needed. Modern software (MS Project, Primavera) uses AON.

## 3. Critical Path Method (CPM)

### Concept and Definition
The **Critical Path Method (CPM)**, developed in 1957 by **Morgan R. Walker (DuPont)** and **James E. Kelley Jr. (Remington Rand)**, is a **deterministic** network-based scheduling technique used for projects with **well-known, predictable activity durations** (such as construction, manufacturing, and plant maintenance).

* **Critical Path:** The **longest path** through the project network from start to finish. It determines the **minimum possible time** in which the entire project can be completed.
* **Critical Activities:** Activities lying on the critical path. They have **zero slack/float**; any delay in a critical activity directly delays the entire project completion date.
* **Non-Critical Activities:** Activities not on the critical path; they possess positive float and can be delayed up to their float limit without delaying the project.

[Click here to see the diagram for Critical Path Method Forward Backward Pass](https://www.google.com/search?q=critical+path+method+CPM+forward+backward+pass+diagram&udm=2)

### Why is CPM Useful? (Importance of CPM)
1. Identifies the **minimum project duration** and **critical bottleneck activities** requiring tight monitoring.
2. Quantifies **float (slack)** for non-critical tasks, enabling flexible resource allocation and leveling.
3. Highlights activity interdependencies clearly, preventing sequence errors.
4. Provides a mathematical basis for **time-cost trade-off (project crashing)** to accelerate projects at minimum extra cost.

### Steps Involved in the CPM Technique
1. **List Activities & Predecessors:** Break the project into discrete activities (via WBS) and identify immediate predecessors for each.
2. **Estimate Deterministic Durations:** Assign a single, known time estimate ($D$) for each activity based on historical data.
3. **Draw the Network Diagram:** Construct the AOA or AON network showing logical sequence.
4. **Perform Forward Pass (Calculate $ES$ and $EF$):** Move from project start to finish to find Earliest Start, Earliest Finish, and total **Project Duration**.
5. **Perform Backward Pass (Calculate $LF$ and $LS$):** Move from project finish back to start to find Latest Finish and Latest Start.
6. **Calculate Floats (Total Float & Free Float):** Determine scheduling flexibility for every activity.
7. **Identify the Critical Path:** Trace the path(s) of activities having **Total Float = 0** (the longest path in the network).
8. **Monitor, Update & Optimize:** Track execution, crash critical activities if needed, and update the network.

## 4. CPM Formulas (Forward Pass, Backward Pass & Floats)

### A. Forward Pass (Left to Right — Finding Earliest Times)
* Start of project: $ES_{\text{start}} = 0$
* For any activity $i$:
  $$EF_i = ES_i + D_i$$
* For an activity with multiple predecessors:
  $$ES_i = \max(\text{EF of all immediate predecessors})$$
* **Project Duration ($T$):** Maximum $EF$ at the final node.

*(In AOA notation, Event Earliest Occurrence Time: $E_j = \max_i (E_i + D_{ij})$, with $E_1 = 0$.)*

### B. Backward Pass (Right to Left — Finding Latest Times)
* End of project: $LF_{\text{end}} = \text{Project Duration } (T)$
* For any activity $i$:
  $$LS_i = LF_i - D_i$$
* For an activity with multiple successors:
  $$LF_i = \min(\text{LS of all immediate successors})$$

*(In AOA notation, Event Latest Occurrence Time: $L_i = \min_j (L_j - D_{ij})$, with $L_n = E_n$.)*

### C. Types of Float (Slack)
1. **Total Float ($TF$):** Maximum time an activity can be delayed from its earliest start without delaying the **overall project completion date**.
   $$TF = LS - ES = LF - EF$$
   *(In AOA for activity $i\text{–}j$: $TF_{ij} = L_j - E_i - D_{ij}$)*
   * **Rule:** If $TF = 0$, the activity is **Critical**.

2. **Free Float ($FF$):** Maximum time an activity can be delayed without delaying the **Earliest Start ($ES$) of any immediate succeeding activity**.
   $$FF = \min(ES_{\text{immediate successors}}) - EF$$
   *(In AOA for activity $i\text{–}j$: $FF_{ij} = E_j - E_i - D_{ij}$)*
   * Note: $0 \le FF \le TF$.

3. **Independent Float ($IF$):** Spare time available if all preceding activities finish as late as possible ($L_i$) and all succeeding activities start as early as possible ($E_j$).
   $$IF_{ij} = \max\left(0,\; E_j - L_i - D_{ij}\right)$$

#### Question 5 (5 Marks)
**Source:** *Internal Assessment (Series Test-I), August 2025 (23HUT535 – Class: B. Tech), Part B – Q10(b) [BL: L2, CO2]*  
**Question:** When a project is analyzed, one path in the network determines the minimum time in which the project can be completed. Identify the concept and explain briefly.

**Answer:**  
The concept is the **Critical Path** (used in **CPM/PERT network analysis**).

**Brief Explanation:**
* **Definition:** The **Critical Path** is the **longest path** (in terms of cumulative duration) through a project network from the start node to the finish node.
* **Why Longest Path = Minimum Project Time:** Because all paths in a project must be completed before the project ends, the project cannot finish earlier than its longest sequential chain of dependent tasks.
* **Critical Activities & Zero Float:** Every activity on the critical path has **Total Float = 0** (meaning $ES = LS$ and $EF = LF$). Any delay in a critical activity delays the entire project by the same amount.
* **Management Significance:** Identifying the critical path enables project managers to focus monitoring efforts on critical tasks, allocate backup resources to them, and select them first when **crashing** (accelerating) the project.

**Question:** Explain the steps involved in CPM technique.

**Answer:**  
The **Critical Path Method (CPM)** follows these systematic steps:

1. **Identify Activities & Precedence:** Break the project into distinct tasks and determine immediate predecessors for each.
2. **Estimate Durations:** Assign a deterministic (single-value) duration to every activity.
3. **Construct the Network Diagram:** Draw the project network (AOA or AON) reflecting logical dependencies.

#### Question 7 (5 Marks — Solved CPM Numerical, AOA Network)
**Source:** *Internal Assessment (Series Test-I), August 2026 (24HUT535 – Class: EL2K24), Part B – Q9(a) [BL: L2, CO2]*  
**Question:** Given the activity table below:

| Activity | Duration |
| :---: | :---: |
| 1–2 | 13 |
| 1–3 | 12 |
| 2–4 | 2 |
| 3–4 | 8 |
| 2–5 | 15 |
| 4–5 | 2 |

Determine the following:
1. Draw the project network
2. Calculate the Earliest Start ($ES$), Earliest Finish ($EF$), Latest Start ($LS$), and Latest Finish ($LF$) for each activity.
3. Determine the Total Float for each activity.
4. Identify the Critical Path.

**Answer:**

**1. Project Network (AOA Diagram):**
```text
           (13)             (15)
       +---------> [2] --------------+
       |            |                |
      [1]          (2)               v
       |            |               [5]
       |            v                ^
       +---------> [3] ---> [4] -----+
           (12)        (8)      (2)
```
*(Arrows: 1→2 (13), 1→3 (12), 2→4 (2), 3→4 (8), 2→5 (15), 4→5 (2).)*

**2. Forward Pass (Event Earliest Times $E_j$) & Backward Pass (Event Latest Times $L_i$):**

* **Forward Pass:**
  * $E_1 = 0$
  * $E_2 = E_1 + 13 = 13$
  * $E_3 = E_1 + 12 = 12$
  * $E_4 = \max(E_2 + 2,\; E_3 + 8) = \max(13 + 2,\; 12 + 8) = \max(15,\; 20) = 20$
  * $E_5 = \max(E_2 + 15,\; E_4 + 2) = \max(13 + 15,\; 20 + 2) = \max(28,\; 22) = 28$
  * **Total Project Duration = 28 units.**

* **Backward Pass:**
  * $L_5 = E_5 = 28$
  * $L_4 = L_5 - 2 = 28 - 2 = 26$
  * $L_3 = L_4 - 8 = 26 - 8 = 18$
  * $L_2 = \min(L_5 - 15,\; L_4 - 2) = \min(28 - 15,\; 26 - 2) = \min(13,\; 24) = 13$
  * $L_1 = \min(L_2 - 13,\; L_3 - 12) = \min(13 - 13,\; 18 - 12) = \min(0,\; 6) = 0$

**3. Schedule & Total Float Table ($ES = E_i$, $EF = ES + D$, $LF = L_j$, $LS = LF - D$, $TF = LS - ES$):**

| Activity | Duration ($D$) | $ES$ | $EF$ | $LS$ | $LF$ | Total Float ($TF = LS - ES$) | Critical? |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **1–2** | 13 | 0 | 13 | 0 | 13 | $0 - 0 = \mathbf{0}$ | **Yes** |
| **1–3** | 12 | 0 | 12 | 6 | 18 | $6 - 0 = 6$ | No |
| **2–4** | 2 | 13 | 15 | 24 | 26 | $24 - 13 = 11$ | No |
| **3–4** | 8 | 12 | 20 | 18 | 26 | $18 - 12 = 6$ | No |
| **2–5** | 15 | 13 | 28 | 13 | 28 | $13 - 13 = \mathbf{0}$ | **Yes** |
| **4–5** | 2 | 20 | 22 | 26 | 28 | $26 - 20 = 6$ | No |

**4. Critical Path Identification:**
* Path durations:
  * $1 \rightarrow 2 \rightarrow 5 = 13 + 15 = \mathbf{28}$ *(Longest path, all activities have $TF = 0$)*
  * $1 \rightarrow 2 \rightarrow 4 \rightarrow 5 = 13 + 2 + 2 = 17$
  * $1 \rightarrow 3 \rightarrow 4 \rightarrow 5 = 12 + 8 + 2 = 22$
* **Critical Path:** **$1 \rightarrow 2 \rightarrow 5$** (Activities **1–2** and **2–5**)
* **Project Duration:** **28 time units**

i) Identify the critical path and project duration.

```text
          +---> [B: 6] ---> [D: 3] ---+
          |                           |
[A: 4] ---+                           +---> [F: 4]
          |                           |
          +---> [C: 5] ---> [E: 7] ---+
```

**ii) Forward Pass ($ES$, $EF = ES + D$):**

* **F:** $LF = 20,\quad LS = 20 - 4 = 16$
* **D:** $LF = LS_F = 16,\quad LS = 16 - 3 = 13$

* **B:** $LF = LS_D = 13,\quad LS = 13 - 6 = 7$
* **C:** $LF = LS_E = 9,\quad LS = 9 - 5 = 4$
* **A:** $LF = \min(LS_B, LS_C) = \min(7, 4) = 4,\quad LS = 4 - 4 = 0$

| **B** | 6 | 4 | 10 | 7 | 13 | $7 - 4 = 3$ | $ES_D - 10 = 10 - 10 = 0$ | No |
| **C** | 5 | 4 | 9 | 4 | 9 | $4 - 4 = \mathbf{0}$ | $ES_E - 9 = 9 - 9 = 0$ | **Yes** |
| **D** | 3 | 10 | 13 | 13 | 16 | $13 - 10 = 3$ | $ES_F - 13 = 16 - 13 = 3$ | No |

**i) Critical Path and Project Duration:**

  * $A \rightarrow B \rightarrow D \rightarrow F = 4 + 6 + 3 + 4 = 17$ days

#### Question 9 (8 Marks — End-Semester Full Question)
**Source:** *Fifth Semester B. Tech. Degree Examination, Regular, November 2025 (23HUT535, QP Code: 5010BHU25T535), Part B – Module 2, Q13*  
**Question:** Explain the steps involved in the CPM technique with an example.

**Answer:**

**1. Introduction to CPM (1 Mark):**  
The **Critical Path Method (CPM)** is a deterministic network scheduling technique used when activity durations are known with certainty. It calculates the minimum project completion time, identifies critical bottleneck activities (zero float), and determines float for non-critical activities.

**2. Steps Involved in the CPM Technique (3.5 Marks):**

1. **Step 1 – Project Breakdown & Precedence Identification:** Break the project into discrete activities using a WBS and identify the immediate predecessor(s) for each task.
2. **Step 2 – Estimate Activity Durations:** Assign a single, deterministic duration ($D$) to each activity.
3. **Step 3 – Draw the Network Diagram:** Represent activities and logical dependencies as an AOA or AON network diagram.
4. **Step 4 – Perform Forward Pass:** Start at time 0 and move forward to compute Earliest Start ($ES = \max(EF_{\text{predecessors}})$) and Earliest Finish ($EF = ES + D$). The maximum $EF$ at the final task gives the **Project Duration**.
5. **Step 5 – Perform Backward Pass:** Set $LF = \text{Project Duration}$ at the end and move backward to compute Latest Finish ($LF = \min(LS_{\text{successors}})$) and Latest Start ($LS = LF - D$).
6. **Step 6 – Compute Floats:** Calculate Total Float ($TF = LS - ES$) and Free Float ($FF = \min(ES_{\text{successors}}) - EF$) for every activity.
7. **Step 7 – Identify the Critical Path:** Trace the continuous path of activities with **$TF = 0$** (the longest path from start to finish).

**3. Illustrative Example (3.5 Marks):**  
Consider installing a small office solar system with activities:

| Activity | Description | Predecessor | Duration (Days) |
| :---: | :--- | :---: | :---: |
| A | Site survey & design | – | 2 |
| B | Procure panels & inverter | A | 5 |
| C | Roof mounting structure | A | 3 |
| D | Electrical installation & testing | B, C | 4 |

* **Forward Pass:**
  * A: $ES=0,\; EF=2$
  * B: $ES=2,\; EF=7$
  * C: $ES=2,\; EF=5$
  * D: $ES=\max(7,5)=7,\; EF=11 \Rightarrow$ **Project Duration = 11 days.**
* **Backward Pass:**
  * D: $LF=11,\; LS=7$
  * B: $LF=7,\; LS=2$
  * C: $LF=7,\; LS=4$
  * A: $LF=\min(2,4)=2,\; LS=0$
* **Float Summary:**
  * A: $TF = 0 - 0 = 0$ (Critical)
  * B: $TF = 2 - 2 = 0$ (Critical)
  * C: $TF = 4 - 2 = 2$ days (Non-critical; can slip up to 2 days without delaying project)
  * D: $TF = 7 - 7 = 0$ (Critical)
* **Result:** The **Critical Path** is **$A \rightarrow B \rightarrow D$**, giving a minimum project duration of **11 days**.
