### **Q1. Explain the features, advantages, and limitations of the Gantt chart.** *(5 Marks)*

A **Gantt chart** is a widely used horizontal bar-chart visual tool for project scheduling and tracking progress over time.

#### **1. Key Features:**
* **Two-Axis Representation:** The horizontal axis represents the project timeline (calendar days, weeks, months), while the vertical axis lists project tasks or Work Breakdown Structure (WBS) elements.
* **Task Duration Bars:** Each activity is displayed as a horizontal bar; the start point represents task start, the length represents duration, and the endpoint represents task finish.
* **Milestone Indicators:** Special symbols (often diamonds) represent critical milestones or zero-duration events.
* **Dependency Links:** Modern Gantt charts use arrows connecting task bars to display predecessor-successor relationships.

#### **2. Advantages:**
1. **Simplicity and Clarity:** Provides an intuitive visual snapshot of project activities and timelines easily understood by non-technical stakeholders.
2. **Real-time Progress Tracking:** Comparing filled bar lengths against planned timelines quickly displays whether tasks are on schedule, ahead, or delayed.
3. **Resource Scheduling:** Helps avoid double-booking team members across overlapping tasks.

#### **3. Limitations:**
1. **Complexity in Large Projects:** Becomes unwieldy and hard to view for projects with hundreds of activities.
2. **Weak Dependency Representation:** Does not clearly highlight critical path activities or calculate floats/slack mathematically like CPM/PERT networks.
3. **Does Not Reflect Work Volume:** A long bar represents time duration, not necessarily the amount of labor or work effort required.

### **Q2. Explain the steps involved in the PERT technique and how the probability of project completion is determined.** *(5/8 Marks)*

**PERT (Program Evaluation and Review Technique)** is a probabilistic network planning tool designed for projects with uncertain activity durations.

```
 [ Identify Activities ] ──> [ Establish Logic/Precedence ] ──> [ Draw Network Diagram ]
                                                                        │
 [ Find Project Completion Probabilities ] <── [ Identify Critical Path ] <── [ Calculate expected times (te) & Variance ]
```

#### **Phase I: Steps Involved in PERT Technique**

1. **Activity Breakdown & Identification:** Define all individual project activities and milestones required for completion.
2. **Establish Precedence Relationships:** Determine task sequencing by defining predecessors and successors for each task.
3. **Estimate Activity Durations (3-Time Estimate System):** Gather three time estimates for every activity:
   * **Optimistic Time ($t_o$):** Best-case duration.
   * **Most Likely Time ($t_m$):** Normal case duration.
   * **Pessimistic Time ($t_p$):** Worst-case duration.
4. **Calculate Expected Time ($t_e$) and Variance ($\sigma^2$):**
   $$\text{Expected Time } (t_e) = \frac{t_o + 4t_m + t_p}{6}$$
   $$\text{Variance } (\sigma^2) = \left( \frac{t_p - t_o}{6} \right)^2$$
5. **Construct Project Network Diagram:** Draw the activity network (AOA or AON) showing nodes, arrows, and path dependencies.
6. **Identify Critical Path:** Calculate Early Start/Finish ($ES, EF$) and Late Start/Finish ($LS, LF$) times. The critical path is the longest path through the network with zero float.

---

#### **Phase II: Determining the Probability of Project Completion**

To find the probability of completing the project within a target due date ($T_d$):

1. **Calculate Total Expected Project Duration ($T_E$):**
   Sum the expected times of all activities along the critical path ($CP$):
   $$T_E = \sum t_e \text{ (for critical activities)}$$

2. **Calculate Project Variance ($\sigma^2_{\text{proj}}$) and Standard Deviation ($\sigma_{\text{proj}}$):**
   Sum the variances of activities on the critical path:
   $$\sigma^2_{\text{proj}} = \sum \sigma^2_{\text{critical activities}}$$
   $$\sigma_{\text{proj}} = \sqrt{\sigma^2_{\text{proj}}}$$

3. **Compute the Standard Normal Variable ($Z$):**
   $$Z = \frac{T_d - T_E}{\sigma_{\text{proj}}}$$
   *Where:* $T_d = \text{Target completion date}$, $T_E = \text{Expected critical path duration}$.

4. **Lookup Probability from Z-Table:**  
   Find the area under the standard normal distribution curve corresponding to the calculated $Z$-score (e.g., $Z = 0 \implies 50\%$ probability; $Z = 1.65 \implies 95\%$ probability).

### **Q3. Differentiate between PERT and CPM.** *(4/5 Marks)*

| Feature | PERT (Program Evaluation & Review Technique) | CPM (Critical Path Method) |
| :--- | :--- | :--- |
| **1. Nature / Approach** | **Probabilistic** (deals with uncertainties in time). | **Deterministic** (deals with known, predictable times). |
| **2. Time Estimates** | Uses **3 time estimates** ($t_o, t_m, t_p$) per activity. | Uses **1 single time estimate** per activity. |
| **3. Focus** | Focuses on managing **Time** and meeting target deadlines. | Focuses on optimizing **Cost vs. Time** trade-offs. |
| **4. Ideal Application** | Research & Development (R&D), new product launches, unique projects. | Construction, civil works, routine maintenance, manufacturing. |
| **5. Orientation** | **Event-oriented** network structure. | **Activity-oriented** network structure. |
| **6. Concept of Floats** | Uses Slack (associated with events). | Uses Floats (Total, Free, and Independent floats for activities). |
| **7. Crashing** | Crashing is generally not applicable due to uncertain activity nature. | **Project Crashing** is a core concept used to shorten duration at minimum cost. |

### **Q4. Explain the Critical Path Method (CPM) with a suitable illustration.** *(5/8 Marks)*

#### **1. Concept:**
The **Critical Path Method (CPM)** is a step-by-step project management technique used to identify activities on the critical path—the longest path of dependent activities through a network. The duration of the critical path determines the shortest possible total execution time for the project.

#### **2. Steps in CPM:**
1. **Define Scope and List Activities:** Break down the project into discrete activities.
2. **Determine Precedence:** Define which activities must precede others.
3. **Draw Network Diagram:** Connect activities using arrows and nodes.
4. **Forward Pass (Calculate Early Times):**
   * Early Start ($ES$) = Maximum Early Finish ($EF$) of immediate predecessors.
   * Early Finish ($EF$) = $ES + \text{Duration}$.
5. **Backward Pass (Calculate Late Times):**
   * Late Finish ($LF$) = Minimum Late Start ($LS$) of immediate successors.
   * Late Start ($LS$) = $LF - \text{Duration}$.
6. **Calculate Total Float ($TF$):**
   $$\text{Total Float } (TF) = LS - ES = LF - EF$$
7. **Identify Critical Path:** Activities where $TF = 0$ constitute the critical path.

---

#### **3. Illustration:**

Consider a project with 4 activities:
* Activity **A** (Start activity): Duration = 3 days
* Activity **B** (Predecessor: A): Duration = 4 days
* Activity **C** (Predecessor: A): Duration = 2 days
* Activity **D** (Predecessors: B and C): Duration = 3 days

```
                 [B] Duration=4
                /   \
       [A] ────      ────> [D] Duration=3
    Duration=3  \   /
                 [C] Duration=2
```

**Paths through the network:**
* **Path 1:** $A \rightarrow B \rightarrow D = 3 + 4 + 3 = 10 \text{ days}$
* **Path 2:** $A \rightarrow C \rightarrow D = 3 + 2 + 3 = 8 \text{ days}$

**Conclusion:**  
* **Critical Path:** Path 1 ($A \rightarrow B \rightarrow D$) with a minimum project completion duration of **10 days**.  
* **Activity C Float:** $10 - 8 = 2\text{ days}$ of total float (slack). Activity C can be delayed by up to 2 days without affecting project completion.

### **Q5. Explain the concept, procedure, and advantages of project crashing.** *(5/8 Marks)*

#### **1. Concept of Project Crashing:**
**Project Crashing** is a method used to shorten the total project completion time by allocating additional resources (e.g., overtime hours, extra labor, specialized tools) to critical path activities. It aims to achieve maximum schedule compression at the **minimum additional direct cost**.

#### **2. Cost Terminology:**
* **Normal Time ($NT$):** Standard duration required to execute an activity under normal conditions.
* **Normal Cost ($NC$):** Direct cost incurred when executing an activity in Normal Time.
* **Crash Time ($CT$):** Absolute minimum duration to which an activity can be reduced.
* **Crash Cost ($CC$):** Direct cost incurred when executing an activity in Crash Time.
* **Cost Slope:** The additional direct cost incurred per unit time saved:
  $$\text{Cost Slope} = \frac{\text{Crash Cost } (CC) - \text{Normal Cost } (NC)}{\text{Normal Time } (NT) - \text{Crash Time } (CT)}$$

```
      Direct Cost
          ^
   Crash  |         *  (Crash Point: CT, CC)
   Cost   |        /
   (CC)   |       /   <--- Cost Slope
   Normal |      /
   Cost   |     *  (Normal Point: NT, NC)
   (NC)   +-------------------------------------> Duration
               Crash Time     Normal Time
                  (CT)            (NT)
```

---

#### **3. Step-by-Step Procedure for Project Crashing:**
1. Determine total project duration and identify the critical path using normal times and costs.
2. Calculate the **Cost Slope** for every activity in the network.
3. Identify critical path activities that can still be crashed ($NT > CT$).
4. Select the critical activity with the **lowest cost slope** and crash it by 1 time unit (or to its maximum allowable limit / until a new path becomes critical).
5. Recalculate critical path(s) and project total cost:
   $$\text{Total Cost} = \text{Direct Costs} + \text{Indirect Costs}$$
   *(Note: As duration decreases, Direct Costs increase, but Indirect Overhead Costs decrease).*
6. Repeat the process until the target completion date is met, or until further crashing increases the total project cost.

#### **4. Advantages:**
* Allows recovery from unexpected delays and brings projects back on schedule.
* Helps meet critical deadline penalties or early completion incentives.
* Reduces total **indirect costs** (overhead, equipment rentals, supervision fees) due to shorter project duration.

### **Q6. Explain resource allocation and resource leveling with suitable examples.** *(5/8 Marks)*

Efficient resource scheduling resolves conflicts when labor, equipment, or materials are limited.

#### **1. Resource Allocation (Resource Loading / Smoothing):**
Resource allocation assigns available project resources to specific network tasks over defined time periods based on activity early start times ($ES$). 

* **Problem:** Unconstrained allocation can lead to fluctuating resource requirements day-to-day (e.g., 2 workers needed on Day 1, 12 workers on Day 2, 3 workers on Day 3).

---

#### **2. Resource Leveling (Constrained Resource Scheduling):**
Resource Leveling shifts non-critical activities within their available floats ($TF$) to create a smooth, consistent rate of resource utilization that does not exceed a maximum availability limit ($R_{\max}$).

* **Example:**
  Suppose a project has two parallel tasks on Day 1:
  * Task A (Critical, needs 4 engineers)
  * Task B (Non-critical, $TF = 2\text{ days}$, needs 3 engineers)
  * **Constraint:** Total firm limit = 5 engineers.

  * **Unleveled State:** Day 1 total requirement = $4 + 3 = 7\text{ engineers}$ (Exceeds capacity limit of 5!).
  * **Leveled Solution:** Shift Task B to start on Day 2 (using its float). Day 1 now uses 4 engineers, and Day 2 uses 3 engineers. Resource capacity is maintained without delaying total project duration.

```
       Unleveled Resource Profile            Leveled Resource Profile
      Resource                               Resource
       Demand                                 Demand
         ^                                      ^
       8 |    [ Over-allocation ]            8 |
       6 |    | Task B |                     6 |
       4 |    | Task A |                     4 |    | Task A |  | Task B |
       2 |    | Task A |                     2 |    | Task A |  | Task B |
         +------------------------> Time        +------------------------> Time
                Day 1   Day 2                          Day 1      Day 2
```

### **Q7. Discuss the estimation of time, cost, and resources required for project scheduling.** *(5 Marks)*

Accurate project scheduling relies on structured estimation techniques for three core components:

#### **1. Time Estimation:**
* **Analogous Estimation:** Uses historical durations from past similar projects.
* **Parametric Estimation:** Multiplies unit work volume by standard production rates (e.g., 1 welder completes 5 meters of weld per hour; total 50 meters = 10 hours).
* **Three-Point PERT Estimate:** Uses weighted averages ($t_e = \frac{t_o + 4t_m + t_p}{6}$) to account for risks.

#### **2. Resource Estimation (Man, Material, Tool/Equipment):**
* **Work Breakdown Structure (WBS):** Deconstructs project deliverables down to individual work packages.
* **Resource Breakdown Structure (RBS):** Identifies categories of required human labor (skill level), materials (quantities), and specialized machinery/tools (crane hours, software licenses).

#### **3. Cost Estimation:**
* **Direct Costs:** Directly traceable to specific project activities (e.g., worker wages, raw material purchases, sub-contractor fees).
* **Indirect Costs:** General administrative overheads, project supervision salaries, security, equipment rental fees, and utility bills that accrue over time.
* **Contingency Reserves:** Funds added to baselines to cover identified project risks.
