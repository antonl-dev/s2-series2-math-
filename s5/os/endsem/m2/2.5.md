# 2.5 Process Scheduling: Basic Concepts, Scheduling Queues, and Schedulers

---

## 1. Basic Concepts of Process Scheduling

The primary objective of **multiprogramming** is to have some process running at all times, to maximize CPU utilization. 
The objective of **time-sharing** is to switch the CPU among processes so frequently that users can interact with each program while it is running. 
To meet these objectives, the **Process Scheduler** selects an available process for program execution on the CPU.

### The CPU–I/O Burst Cycle
Process execution consists of an alternating cycle of **CPU execution** and **I/O wait**. Processes alternate between these two states.
- **CPU Burst:** A period of time when a process is actively executing instructions on the CPU (doing math, logic, etc.).
- **I/O Burst:** A period of time when a process is waiting for an I/O operation to complete (reading a disk, waiting for network data, waiting for user keyboard input).

Execution begins with a CPU burst. That is followed by an I/O burst, which is followed by another CPU burst, and so on. The final CPU burst ends with a system call to terminate execution (`exit`).

### I/O-Bound vs. CPU-Bound Processes
Based on these bursts, processes are categorized into two types:
1. **I/O-Bound Process:** Spends more time doing I/O than doing computations. It has many **short CPU bursts**. (Example: A web browser or word processor).
2. **CPU-Bound Process:** Spends more time doing computations. It has a few very **long CPU bursts**. (Example: Video rendering software, complex mathematical simulations).

## 2. Scheduling Queues

As processes enter the system and change states, they are placed into various **scheduling queues** managed by the OS. These queues are typically implemented as linked lists of **Process Control Blocks (PCBs)**.

### Types of Queues
1. **Job Queue (Historical/Batch):** As processes enter the system (from the disk), they are put into a job queue. This queue consists of all processes in the system.
2. **Ready Queue:** The processes that are currently residing in main memory (RAM) and are ready and waiting to execute on the CPU are kept in this queue.
3. **Wait Queues (Device Queues):** When a process requests an I/O operation (like reading a disk), it must wait for that slow device to finish. The process is moved from the CPU to a wait queue dedicated to that specific device (e.g., Disk Drive Queue, Network Queue).

### The Queuing Diagram Representation
Process scheduling is commonly represented by a **queuing diagram**. 
- Circles represent the resources that serve the queues (the CPU, I/O devices).
- Rectangles represent the queues themselves (Ready Queue, I/O Queues).
- Arrows represent the flow of processes (PCBs) through the system.

**Workflow:** 
A new process enters the Ready Queue. It is dispatched to the CPU. From the CPU, it could:
1. Issue an I/O request $\rightarrow$ Placed in an I/O Wait Queue.
2. Experience a Timer Interrupt (time slice expires) $\rightarrow$ Forced back into the Ready Queue.
3. Call `fork()` to create a child $\rightarrow$ Waits in a queue for the child to terminate.
4. Finish execution $\rightarrow$ Exits the system.

## 3. Types of Schedulers

An operating system uses different schedulers to manage the flow of processes through the various queues. They are categorized based on the **frequency** at which they make decisions.

### 1. Short-Term Scheduler (CPU Scheduler)
- **Role:** Selects from among the processes in the **Ready Queue** and allocates the CPU to one of them.
- **Frequency:** Executes **very frequently** (at least once every few milliseconds, whenever a timer interrupt occurs).
- **Key Requirement:** Because it runs so often, it must be **extremely fast**. If it takes 1 millisecond to decide which process to run next, and the time slice is 10 milliseconds, 9% of the CPU time is wasted just on scheduling overhead!
- **Control:** It strictly controls CPU allocation.

### 2. Long-Term Scheduler (Job Scheduler)
- **Role:** Selects processes from a mass-storage pool (the disk/job queue) and loads them into **Main Memory (Ready Queue)** for execution.
- **Frequency:** Executes **infrequently** (seconds or minutes). It only runs when a process leaves the system or when a new batch of jobs arrives.
- **Key Requirement:** It controls the **Degree of Multiprogramming** (the total number of processes currently existing in memory). 
- **The "Mix" Strategy:** To keep system performance high, the long-term scheduler must select a good **mix of I/O-bound and CPU-bound processes**. 
  - If it loads *only* I/O-bound processes, the Ready Queue will always be empty, and the CPU will sit idle.
  - If it loads *only* CPU-bound processes, the I/O wait queues will be empty, and hardware devices will sit idle.

*(Note: On modern time-sharing OSes like Windows and Linux, the long-term scheduler is essentially absent. Every program a user executes is simply loaded into memory immediately. The system relies instead on the Medium-Term Scheduler to manage memory limits).*

### 3. Medium-Term Scheduler (Swapper)
- **Role:** Sometimes, the system runs out of main memory. The medium-term scheduler removes a process from RAM, stores it temporarily on the hard disk, and brings it back later to resume execution.
- **Process:** This technique is called **Swapping**. 
  - **Swap Out:** Moving a partially executed process from Memory to Disk to free up RAM.
  - **Swap In:** Moving the process from Disk back to Memory to continue running.
- **Key Requirement:** It helps reduce the degree of multiprogramming dynamically when the system is overloaded (preventing thrashing).

## 4. Summary Table of Schedulers

| Feature | Short-Term Scheduler | Long-Term Scheduler | Medium-Term Scheduler |
| :--- | :--- | :--- | :--- |
| **Also Known As** | CPU Scheduler | Job Scheduler | Swapper |
| **Selection** | Selects from Ready Queue to give to CPU. | Selects from Disk (Job pool) to load into RAM. | Selects from RAM to swap to Disk (and vice versa). |
| **Frequency** | Very frequent (milliseconds). | Infrequent (seconds/minutes). | Moderate (when memory is full). |
| **Speed Requirement** | Must be extremely fast. | Speed is not critical. | Moderate speed. |
| **Primary Goal** | Minimize response time / maximize CPU utilization. | Maintain a good mix of I/O & CPU-bound jobs. | Manage available RAM and reduce multiprogramming. |

## 5. Exam Questions & Answers

> **Note on Provided Question Papers:** The provided end-semester and internal exams focus on the actual *algorithms* of CPU scheduling (FCFS, SJF, RR) in topics 2.6 and 2.7. However, foundational theory questions on queues and schedulers are standard in OS exams. Below are expected questions to fully cover Topic 2.5.

### Expected Question 1 (Medium Answer – 6 Marks)
**Question:**
*Explain the differences between the short-term, medium-term, and long-term schedulers. What is the degree of multiprogramming, and which scheduler controls it?*

**Answer:**
**1. Scheduler Differences (4.5 Marks):**
- **Short-Term Scheduler (CPU Scheduler):** Runs very frequently (every few milliseconds). Its job is to select a process from the Ready Queue and allocate the CPU to it. Because it runs so often, it must be highly optimized and fast to minimize overhead.
- **Long-Term Scheduler (Job Scheduler):** Runs infrequently. It selects programs from the disk (job pool) and loads them into main memory (the ready queue). It aims to create a balanced mix of CPU-bound and I/O-bound processes.
- **Medium-Term Scheduler:** Runs moderately frequently when system memory is constrained. It performs "swapping"—removing a process from memory and storing it on disk (swap out) to free up RAM, and later restoring it to memory (swap in) to resume execution.

**2. Degree of Multiprogramming (1.5 Marks):**
The **degree of multiprogramming** refers to the total number of processes currently residing in main memory. The **Long-Term Scheduler** controls this by deciding how many, and which, processes to admit into the system. (If memory gets too full, the Medium-Term scheduler can temporarily reduce this degree via swapping).

---

### Expected Question 2 (Short Answer – 4 Marks)
**Question:**
*Differentiate between an I/O-bound process and a CPU-bound process. Why is it important for the long-term scheduler to select a good mix of both?*

**Answer:**
**1. Differentiation (2 Marks):**
- **I/O-Bound Process:** Spends the vast majority of its time waiting for I/O operations (like disk reads or user input). It is characterized by many very short CPU bursts.
- **CPU-Bound Process:** Spends the majority of its time performing heavy computational work. It is characterized by a few very long CPU bursts.

**2. Importance of the Mix (2 Marks):**
The long-term scheduler must select a balanced mix of both types of processes to keep the entire system busy. 
- If all processes are I/O-bound, the Ready Queue will frequently be empty, and the CPU will sit idle, wasting computational power. 
- If all processes are CPU-bound, the I/O wait queues will be empty, and the system's disk and peripheral hardware will sit idle. 
A good mix maximizes the utilization of both the CPU and the I/O devices simultaneously.

---

### Expected Question 3 (Short Answer – 4 Marks)
**Question:**
*Describe the various scheduling queues maintained by the operating system to track processes.*

**Answer:**
As processes move through the system, the OS manages them using linked lists of Process Control Blocks (PCBs) called scheduling queues:
1. **Job Queue:** Contains all processes currently in the system, both residing in memory and waiting on the disk.
2. **Ready Queue:** Contains processes that are loaded in main memory and are actively ready to execute on the CPU. The short-term scheduler selects the next process from this queue.
3. **Wait / Device Queues:** Contains processes that are blocked waiting for a specific event or an I/O device (e.g., waiting for data from the hard drive). Each I/O device typically has its own dedicated wait queue. When the I/O completes, the process is moved back to the Ready Queue.

### Quick Self-Check Key Points for Revision
- **CPU Burst vs I/O Burst:** CPU burst = crunching numbers; I/O burst = waiting for disk/network/keyboard.
- **Queues:** Ready Queue (waiting for CPU), Device Queue (waiting for I/O).
- **Short-term Scheduler:** Fast, runs every few ms, picks from Ready Queue.
- **Long-term Scheduler:** Slow, picks from Disk to RAM, controls **degree of multiprogramming**, needs an I/O & CPU mix.
- **Medium-term Scheduler:** Swaps processes in/out of RAM to Disk when memory is full.
