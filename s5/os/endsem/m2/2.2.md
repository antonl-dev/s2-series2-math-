# 2.2 Process States, Process Control Block (PCB), and Context Switch

---

## 1. Process States

As a process executes, it changes **state**. The state of a process is defined by its current activity. In a standard operating system, a process can be in one of five fundamental states at any given time.

### The 5-State Process Model

1. **New:** 
   - The process is currently being created by the OS. The OS is allocating its memory and setting up its initial structures, but it is not yet ready to run.
2. **Ready:** 
   - The process has been loaded into main memory, has all the resources it needs, and is just waiting to be assigned to a processor (CPU) by the scheduler. It resides in the **Ready Queue**.
3. **Running:** 
   - Instructions are currently being executed on the CPU. (On a single-core CPU, only **one** process can be in the Running state at any exact moment).
4. **Waiting (also called Blocked or Asleep):** 
   - The process cannot execute right now because it is waiting for some event to occur (e.g., waiting for user input from a keyboard, waiting for a disk file to be read, or waiting for a lock/semaphore). It resides in a **Wait Queue** or **Device Queue**.
5. **Terminated:** 
   - The process has finished execution (either normally via `exit()` or abnormally due to an error/crash). The OS is in the process of reclaiming its memory and resources.

### Process State Transitions (Events)

Processes move smoothly between these states based on specific events:
- **Admitted (New $\rightarrow$ Ready):** The OS has finished setting up the new process and admits it to the ready queue.
- **Scheduler Dispatch (Ready $\rightarrow$ Running):** The CPU scheduler selects this process from the ready queue and allocates the CPU to it.
- **Interrupt (Running $\rightarrow$ Ready):** The process's time slice expires (timer interrupt), forcing it to yield the CPU back to the OS so another process can run.
- **I/O or Event Wait (Running $\rightarrow$ Waiting):** The process requests an I/O operation (like a disk read) or makes a blocking system call. The OS moves it out of the CPU and into a wait queue so it doesn't waste CPU cycles.
- **I/O or Event Completion (Waiting $\rightarrow$ Ready):** The requested I/O operation finishes (e.g., the disk data is now in memory). A hardware interrupt wakes the OS, which moves the process back to the ready queue.
- **Exit (Running $\rightarrow$ Terminated):** The process executes its final instruction and asks the OS to terminate it.

## 2. Process Control Block (PCB)

To manage the thousands of processes running on a modern system, the OS needs a way to keep track of all the information associated with each specific process. 
It does this using a data structure called the **Process Control Block (PCB)**, sometimes called a **Task Control Block**.

### What is the PCB?
The PCB is a repository for any information that may vary from process to process. Whenever a process is created, the OS allocates a new PCB for it in **Kernel Memory**. 

### Key Components Stored in the PCB
1. **Process State:** The current state (New, Ready, Running, Waiting, Terminated).
2. **Program Counter (PC):** The memory address of the very next instruction this process needs to execute.
3. **CPU Registers:** The saved contents of the process's general-purpose registers, stack pointer, and condition code flags. (Crucial for resuming the process after it has been paused).
4. **Process Number (PID):** A unique integer identifier assigned by the OS (Process ID).
5. **CPU-Scheduling Information:** The process's priority, pointers to scheduling queues, and other scheduling parameters.
6. **Memory-Management Information:** The values of the base and limit registers, or pointers to the page tables/segment tables that define the process's virtual address space.
7. **Accounting Information:** The amount of CPU time used, time limits, execution time, etc.
8. **I/O Status Information:** A list of I/O devices currently allocated to the process (e.g., open files, network connections).

## 3. Context Switch

A **Context Switch** is the core mechanism that allows an operating system to provide CPU virtualization (time-sharing). 

### The Concept
When an interrupt occurs (e.g., a timer interrupt or an I/O request), the OS must pause the currently running process and switch the CPU to execute a different process. 
- The system must save the exact **context (state)** of the currently running process so it can be resumed correctly later.
- It must then restore the saved **context (state)** of the new process it is about to run.
- This context is represented in the process's **PCB**.

### Steps in a Context Switch (Process $P_0$ to Process $P_1$)
1. Process $P_0$ is running in the CPU.
2. A timer interrupt or system call occurs.
3. The OS takes control (switches to Kernel Mode).
4. The OS **saves the state** (registers, PC, SP) of $P_0$ into $P_0$'s PCB.
5. The OS changes $P_0$'s state to *Ready* (or *Waiting*) and moves it to the appropriate queue.
6. The CPU Scheduler selects $P_1$ from the Ready Queue.
7. The OS **loads the state** of $P_1$ from $P_1$'s PCB into the physical CPU registers.
8. The OS changes $P_1$'s state to *Running*.
9. The OS executes a return-from-trap, switching back to User Mode, and $P_1$ resumes execution exactly where it left off.

[Click here to see the diagram for Context Switch timeline between two processes](https://www.google.com/search?q=context+switch+timeline+between+two+processes+OS+diagram&udm=2)

### Context-Switch Time is Pure Overhead
Context switching is purely overhead for the system—**the system does no useful computational work while switching.**
- Its speed heavily depends on memory speed, the number of registers that must be copied, and hardware support (some CPUs have multiple sets of registers so a context switch simply requires changing a single pointer).
- A typical context switch takes a few microseconds. If an OS context switches too frequently, the system wastes too much CPU time just switching instead of executing user programs.

**Question:**
*A process is admitted into the ready queue, selected by the CPU scheduler for execution, requests an I/O operation, and resumes execution after the I/O completes. Finally, the process completes its execution. Using the basic process-state model, trace the states through which the process moves and indicate the event responsible for each state transition. Draw the corresponding process-state diagram.*

**Answer:**
**State Trace and Events (3 Marks):**
Based on the given scenario, the process moves through the following states triggered by specific events:
1. **New $\rightarrow$ Ready:** The process is created and **"admitted"** by the OS into the Ready queue.
2. **Ready $\rightarrow$ Running:** The **"CPU Scheduler selects"** (dispatches) the process, and it begins execution on the CPU.
3. **Running $\rightarrow$ Waiting:** The process **"requests an I/O operation"** (e.g., waiting for a disk read). It cannot proceed, so it yields the CPU and blocks.
4. **Waiting $\rightarrow$ Ready:** The **"I/O completes"** (hardware interrupt). The data is now available, so the OS wakes the process and moves it back to the ready queue.
5. **Ready $\rightarrow$ Running:** The scheduler eventually **selects the process again** so it can resume execution.
6. **Running $\rightarrow$ Terminated:** The process **"completes its execution"** (calls `exit()`) and releases its resources.

### Expected Question 2 (Short Answer – 4 Marks)
**Question:**
*What is a Process Control Block (PCB)? List any four important fields contained within it and explain the purpose of a context switch.*

**Answer:**
**Process Control Block (PCB) (2 Marks):**
A PCB is a crucial data structure maintained by the Operating System kernel for every active process. It serves as a repository for all the information necessary to manage and track that process.
Four important fields include:
1. **Process State:** Current status (Ready, Running, Waiting, etc.).
2. **Program Counter (PC):** The memory address of the next instruction to be executed.
3. **CPU Registers:** Saved context (general registers, stack pointer) required to resume the process.
4. **Process ID (PID):** A unique integer identifying the process.

**Context Switch (2 Marks):**
A context switch is the process of stopping one running process and starting (or resuming) another. Its purpose is to enable CPU virtualization and time-sharing. The OS saves the exact CPU state (registers, PC) of the currently running process into its PCB, and then loads the saved state from the PCB of the next process to be run. Context switching introduces pure overhead, as no user-level work is accomplished during the switch.

### Quick Self-Check Key Points for Revision
- **5 States:** New, Ready, Running, Waiting (Blocked), Terminated.
- **Waiting vs Ready:** Ready = waiting for the *CPU*. Waiting = waiting for *I/O or an event* (cannot run even if given the CPU).
- **PCB:** The "ID Card" and "Save Game State" of a process. Contains PC, Registers, PID, State. Stored in Kernel Memory.
- **Context Switch:** Save current process state to its PCB $\rightarrow$ Load new process state from its PCB. Pure overhead, heavily relies on hardware speed.
