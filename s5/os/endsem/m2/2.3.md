# 2.3 Process Control System Calls: fork, wait, exec, getpid, getppid

---

## 1. Process Hierarchy in UNIX/Linux

In UNIX and Linux operating systems, a process is created by another existing process. This creates a **parent-child hierarchy** (a tree of processes). 
- The very first process created by the OS at boot time is usually `init` (or `systemd`), which is assigned **Process ID (PID) 1**. 
- Every other process in the system is ultimately a descendant of `init`.

When a program wants to create a new process, it uses a set of powerful system calls provided by the OS kernel. The most fundamental of these are the **fork-exec-wait** system calls.

---

## 2. Process Identification: `getpid()` and `getppid()`

Every active process is identified by a unique positive integer called the **Process ID (PID)**.
- **`getpid()`**: Returns the PID of the currently calling process.
- **`getppid()`**: Returns the PID of the **parent** of the currently calling process.

*Example:* If Process A (PID 1000) creates Process B (PID 1005), inside Process B's code, `getpid()` returns 1005, and `getppid()` returns 1000.

---

## 3. Creating a Process: The `fork()` System Call

The `fork()` system call is the only way to create a new process in UNIX/Linux. 

### How `fork()` Works
When a process (the Parent) calls `fork()`, the OS creates a brand new process (the Child).
- **Exact Duplicate:** The OS creates an **exact duplicate** of the parent's virtual address space. The child gets a full copy of the parent's Code, Data, Heap, and Stack segments. 
- **Separate Memory Spaces:** Although the child is a clone, its memory space is physically separate. If the child modifies a variable `x`, the parent's variable `x` remains unchanged (no shared memory).
- **Execution Resumption:** Both the parent and the child continue execution at the exact same instruction immediately following the `fork()` call.

### The Magic of the Return Value
Because both parent and child execute the exact same code after the fork, how can they do different things? The secret is in the **return value of `fork()`**. 

`fork()` is called *once* in the parent, but it **returns twice**:
1. **In the Parent Process:** `fork()` returns the **Process ID (PID) of the newly created child** (a positive integer).
2. **In the Child Process:** `fork()` returns **`0`**.
3. *(If `fork()` fails, it returns `-1` to the parent and no child is created).*

#### Typical `fork()` Logic Pattern in C:
```c
#include <stdio.h>
#include <unistd.h>

int main() {
    pid_t rc = fork();
    
    if (rc < 0) {
        // fork failed
        printf("Fork failed!\n");
    } else if (rc == 0) {
        // Child process executes this block
        printf("I am the child (PID: %d)\n", getpid());
    } else {
        // Parent process executes this block
        printf("I am the parent (PID: %d), my child is %d\n", getpid(), rc);
    }
    return 0;
}
```

## 4. The `exec()` Family of System Calls

While `fork()` creates a clone, we usually want the child to run a completely different program (e.g., the terminal `forks` a child, and the child `execs` the `ls` command).

- **What `exec()` does:** The `exec()` system call entirely replaces the current process's memory space (Code, Data, Heap, Stack) with a **brand new program** loaded from disk. 
- **It does NOT create a new process:** The PID remains exactly the same. It just changes *what* the process is running.
- **Return Behavior:** If `exec()` is successful, it **never returns**, because the old code (which called `exec`) is completely overwritten by the new program!

*(Variants of `exec` include `execl`, `execp`, `execv`, `execvp`, which just differ in how command-line arguments are passed).*

---

## 5. Synchronization and Reaping: The `wait()` System Call

Because the parent and child run concurrently, the CPU scheduler decides who runs first. Often, the parent needs to pause and wait for the child to finish its task.

- **`wait()` / `waitpid()`:** When a parent calls `wait()`, its execution is blocked (put to sleep) until one of its child processes terminates.
- **Reaping:** When a child calls `exit()`, it frees its memory, but its **Process Control Block (PCB)** remains in the OS kernel so the parent can read its exit status. The `wait()` call allows the parent to read this status, at which point the OS fully deletes the child's PCB. This is called **reaping**.

---

## 6. Zombie and Orphan Processes

What happens when `wait()` is NOT used properly, or processes die in the wrong order?

### A. Zombie Process
- **Definition:** A process that has completed execution (terminated) but whose parent has **not yet called `wait()`**. 
- **Mechanism:** The child is dead and its memory is released, but its PCB (containing its exit status) is still lingering in the OS Process Table taking up space. It is a "living dead" process.
- **Example:** A server creates many child processes to handle requests, but forgets to call `wait()` when they finish. The system fills up with Zombie processes and eventually cannot create any new processes.

### B. Orphan Process
- **Definition:** A process that is still actively running, but its **parent has terminated** (died or crashed).
- **Mechanism:** The child is now "orphaned". The OS cannot allow a process to exist without a parent. 
- **Resolution:** The OS automatically reparents the orphan to the root process (`init` or `systemd`, PID 1). The `init` process periodically calls `wait()` to gracefully reap adopted orphans when they eventually finish.

### Question 1
**Source:** *End Semester Examination – November 2025 (Module 2, Q4a – 4 Marks, CO2)*

**Question:**
*How many times 'Good Luck' and 'Do well' will be printed after executing the following code. Justify your answer and illustrate the process creation hierarchy.*
```c
void main()
{
    fork();
    printf("Good Luck\n");
    fork();
    fork();
    printf("Do well\n");
}
```

**Answer:**
**Calculation and Justification (3 Marks):**
Let the initial process be $P_0$.
1. **First `fork()`:** $P_0$ creates $P_1$. We now have **2 processes** ($P_0$, $P_1$).
2. **`printf("Good Luck\n")`:** Executed by both $P_0$ and $P_1$. 
   $\rightarrow$ **'Good Luck' is printed 2 times.**
3. **Second `fork()`:** Both $P_0$ and $P_1$ execute `fork()`. $P_0$ creates $P_2$, and $P_1$ creates $P_3$. We now have **4 processes**.
4. **Third `fork()`:** All 4 processes execute `fork()`. Each creates one child, resulting in a total of $4 \times 2 = $ **8 processes** ($P_0$ to $P_7$).
5. **`printf("Do well\n")`:** Executed by all 8 currently active processes.
   $\rightarrow$ **'Do well' is printed 8 times.**

**Process Creation Hierarchy (1 Mark):**
*(Draw a tree diagram like this)*:
```text
           P0
         /    \
   (f1) P0     P1      (Total = 2) -> Print Good Luck
       / \     / \
 (f2) P0 P2   P1 P3    (Total = 4)
     /\  /\   /\  /\
(f3)P0 P4 ...          (Total = 8) -> Print Do well
```

**Source:** *End Semester Examination – November 2025 (Module 2, Q4b – 4 Marks, CO2)*

**Question:**
*Distinguish Zombie process and Orphan process with example.*

**Answer:**
| Feature | Zombie Process | Orphan Process |
| :--- | :--- | :--- |
| **Definition** | A child process that has terminated, but its parent has not yet called `wait()` to collect its exit status. | A child process that is still running, but its parent process has unexpectedly terminated. |
| **Execution State** | **Dead** (execution is finished, memory is freed, but PCB remains in the process table). | **Alive** (still actively executing instructions). |
| **Problem / Fix** | Wastes process table slots. Fixed when the parent finally calls `wait()`. | Handled automatically by the OS. The `init` (PID 1) process adopts it and eventually calls `wait()`. |
| **Example** | Parent code: `if(fork() > 0) { sleep(50); }` <br>Child code: `exit(0);`. <br>Child dies immediately, but parent sleeps for 50s without waiting. Child is a Zombie for 50s. | Parent code: `if(fork() > 0) { exit(0); }` <br>Child code: `sleep(50);`. <br>Parent dies immediately. Child is now an Orphan adopted by `init`. |

### Question 3
**Source:** *Internal Test – I, August 2026 (Q3a – 5 Marks, BL-3, CO2)*

**Question:**
*Consider the following C program: Without executing the program, answer the following:*
```c
#include <stdio.h>
#include <unistd.h>
int main() {
    printf("A\n");
    fork();
    printf("B\n");
    fork();
    printf("C\n");
    return 0;
}
```
*i. How many processes exist after the first fork()?*
*ii. How many processes exist after the second fork()?*
*iii. Draw the process tree showing the processes created by the program.*
*iv. Is the exact order in which all the Bs and Cs appear guaranteed? Justify your answer.*

**Answer:**
- **i. (1 Mark):** **2 processes.** (The original parent $P_0$ and one child $P_1$).
- **ii. (1 Mark):** **4 processes.** (Both $P_0$ and $P_1$ execute the second `fork()`, resulting in $P_0, P_1, P_2, P_3$).
- **iii. Process Tree (1.5 Marks):**
```text
           P0        (Prints A)
         /    \
      P0        P1   (Both print B)
     /  \      /  \
    P0   P2   P1   P3 (All 4 print C)
```
- **iv. (1.5 Marks):** **No, the exact order is NOT guaranteed.** Once a `fork()` occurs, the parent and child execute concurrently. The OS CPU scheduler decides which process runs next based on its internal algorithms (which can be influenced by system load and timer interrupts). Therefore, a "B" from the parent might print before or after the "B" from the child, resulting in a non-deterministic execution order (concurrency).

### Question 4
**Source:** *Internal Test – I, August 2026 (Q5b – 5 Marks, BL-3, CO1)*

**Question:**
*Identify the type of process created in each situation and explain how the operating system handles each case.*
*i. The child terminates, but the parent continues execution without calling wait().*
*ii. The parent terminates while the child is still executing.*
*b) A process with PID 4200 executes: `pid_t x = fork();`. Assume the newly created child receives PID 4201. (i) Determine the value of x in the parent process and in the child process. (ii) Write a C program that makes the parent and child execute different sections of code. Explain the logic used.*

**Answer:**
**(a) Process Types (2 Marks):**
- **i. Zombie Process:** The OS leaves the child's Process Control Block (PCB) in the process table so its exit status remains available. It takes up a process slot until the parent eventually calls `wait()`.
- **ii. Orphan Process:** The OS automatically reparents the orphan child to the root process (`init` or `systemd`, PID 1). `init` will periodically execute `wait()` to properly reap the orphan when it eventually finishes.

**(b.i) Values of x (1 Mark):**
- In the **Parent process** (PID 4200), `x = 4201` (the PID of the child).
- In the **Child process** (PID 4201), `x = 0`.

**(b.ii) C Program and Logic (2 Marks):**
```c
#include <stdio.h>
#include <unistd.h>
int main() {
    pid_t x = fork(); // Create child

    if (x < 0) {
        printf("Fork failed\n");
    } else if (x == 0) {
        // Logic: fork() returns 0 to the newly created child process
        printf("I am the child process executing child section.\n");
    } else {
        // Logic: fork() returns the child's PID (a positive integer > 0) to the parent
        printf("I am the parent process executing parent section.\n");
    }
    return 0;
}
```

### Quick Self-Check Key Points for Revision
- **`fork()` Return Values:** `<0` = Error, `==0` = I am the Child, `>0` = I am the Parent (and this number is my child's PID).
- **Process Counting:** If a program has $n$ consecutive `fork()` calls, it creates **$2^n$ processes** in total.
- **Zombie vs. Orphan:**
  - *Zombie:* Child dies, Parent ignores it (forgets `wait()`).
  - *Orphan:* Parent dies, Child is left alone (adopted by `init`).
- **`exec()`:** Overwrites memory with a new program. Does *not* create a new process (PID stays the same).
