# 4.1 Address Spaces, Memory View of a Process, and Review of malloc/free

---

## 1. Introduction: The Concept of an Address Space

In early computers (like MS-DOS or early mainframes), physical memory (RAM) was not virtualized. Programs were loaded directly into physical memory addresses, meaning a program could accidentally overwrite the Operating System or another program's data, causing catastrophic crashes.

To solve this, modern Operating Systems provide a crucial abstraction: the **Address Space**.
- **Definition:** An address space is the **running program's (process's) view of memory in the system**. 
- It creates the illusion that the process has its own massive, private, and contiguous block of memory, starting at address `0` and going up to a maximum address (e.g., $2^{32}-1$ on a 32-bit system).
- The OS (with hardware help) secretly translates these "fake" virtual addresses into real physical RAM addresses behind the scenes.

**Goals of the Address Space Abstraction:**
1. **Transparency:** The program doesn't need to know where it actually resides in physical RAM.
2. **Protection / Isolation:** A bug in Process A cannot corrupt Process B's memory because Process A cannot even generate a virtual address that maps to Process B's physical RAM.
3. **Efficiency:** The OS can move processes around in physical memory or even swap parts of them to the disk without the process knowing.

---

## 2. Memory View of a Process

When a program is executed, the OS allocates an address space for it. This virtual address space is logically divided into distinct contiguous sections, often called **segments**. 

A standard process memory layout consists of four main areas:

### 1. Code (Text) Segment
- **Purpose:** Stores the compiled machine-language instructions of the program.
- **Characteristics:** 
  - It is typically **Read-Only** to prevent the program from accidentally modifying its own instructions (which prevents a common class of security exploits).
  - It is **Sharable**. If you open 5 tabs of Google Chrome, the OS only loads one copy of the Chrome code segment into physical RAM and maps it into the address space of all 5 processes to save memory.

### 2. Data Segment
- **Purpose:** Stores global variables and static variables.
- **Sub-divisions:**
  - **Initialized Data:** Variables initialized by the programmer (e.g., `int count = 50;`).
  - **Uninitialized Data (BSS):** Variables declared but not initialized (e.g., `int count;`). The OS automatically initializes this area to zero when the program starts.

### 3. The Heap
- **Purpose:** Used for **dynamic memory allocation** at run-time. 
- **Characteristics:** 
  - When a programmer does not know how much memory they will need until the program is actually running (e.g., loading a variable-sized image file), they request memory from the heap.
  - The heap typically starts right above the Data segment and **grows upward** (towards higher memory addresses) as more memory is allocated.
  - Managed manually by the programmer in languages like C/C++ (using `malloc`/`free`) or automatically by a Garbage Collector in Java/Python.

### 4. The Stack
- **Purpose:** Used for managing function calls and temporary data.
- **Characteristics:**
  - Stores **local variables**, function parameters, and the return address (where the CPU should jump back to after the function finishes).
  - Every time a function is called, a new block of memory called a **Stack Frame** is pushed onto the stack. When the function returns, the frame is popped off.
  - The stack is located at the very top of the address space and **grows downward** (towards lower memory addresses) to meet the heap.

**The Gap:** Between the Heap (growing up) and the Stack (growing down), there is a massive unallocated gap of virtual memory. If they ever collide, the program runs out of memory and crashes (Stack Overflow / Out of Memory).

## 3. Review of `malloc` and `free` System Calls

*Technical Note: `malloc()` and `free()` are actually C Standard Library functions (APIs), not raw OS system calls. Behind the scenes, they invoke actual system calls like `brk()`, `sbrk()`, or `mmap()` to request pages of memory from the OS kernel. However, they are treated as system-level memory management tools in this context.*

### Memory Allocation: `malloc()`
The `malloc` (memory allocation) function is used to dynamically allocate a single large block of contiguous memory on the **Heap**.
- **Syntax:** `void* malloc(size_t size);`
- **How it works:** 
  - You pass the number of bytes you need (e.g., `malloc(100 * sizeof(int))`).
  - It searches the heap for a free block large enough to satisfy the request.
  - **Success:** It returns a pointer (memory address) to the beginning of the newly allocated block.
  - **Failure:** If the heap is full and the OS refuses to give the process more memory, it returns a `NULL` pointer.

### Memory Deallocation: `free()`
Unlike the Stack (which cleans up local variables automatically when a function ends), Heap memory is persistent. It stays allocated until the programmer explicitly releases it.
- **Syntax:** `void free(void* ptr);`
- **How it works:** 
  - You pass the pointer that was previously returned by `malloc`.
  - The memory manager marks that block of heap memory as "free" so it can be reused by future `malloc` calls.

### Common Memory Management Errors
Because programmers must manually manage the heap with `malloc` and `free`, several severe bugs frequently occur:
1. **Memory Leak:** Forgetting to call `free()`. The heap fills up with unused "garbage" data until the program eventually runs out of memory and crashes.
2. **Dangling Pointer:** Calling `free(ptr)` but then trying to use `ptr` again later. The memory might have been reallocated to something else, causing unpredictable behavior.
3. **Double Free:** Calling `free()` twice on the exact same pointer. This corrupts the heap management data structures and usually causes an immediate crash.
4. **Buffer Overflow / Segmentation Fault:** Allocating an array of 10 items via `malloc`, but trying to write to the 11th item. The CPU's Memory Management Unit (MMU) catches the illegal access and terminates the process (Segfault).

### Expected Question 1 (Medium Answer – 6 Marks)
**Question:**
*Describe the concept of a virtual address space. Draw and explain the logical memory layout of a process, detailing the purpose of the Code, Data, Heap, and Stack segments.*

**Answer:**
**Virtual Address Space (2 Marks):**
An address space is the Operating System's abstraction of physical memory. It provides every running process with the illusion that it has its own private, contiguous, and large block of memory, isolated from all other processes. The OS maps these logical virtual addresses to physical RAM addresses behind the scenes.

**Memory Layout and Segments (4 Marks):**
*(Draw a vertical rectangle divided into 4 main blocks: Stack at the top growing down, a gap in the middle, Heap growing up, Data, and Code at the bottom).*
1. **Code (Text) Segment:** Located at the lowest memory addresses. It contains the compiled machine-language instructions of the program. It is typically read-only to prevent accidental modification and sharable across multiple instances of the program.
2. **Data Segment:** Located above the code segment. It stores global and static variables. It is subdivided into initialized data (values set by the programmer) and uninitialized data (BSS, zeroed out by the OS).
3. **Heap:** Located above the data segment and grows **upward**. It is used for dynamic memory allocation managed by the programmer at runtime (using `malloc()` in C or `new` in Java/C++).
4. **Stack:** Located at the highest memory addresses and grows **downward** toward the heap. It is used automatically by the compiler to store temporary data, such as local variables, function parameters, and return addresses for function calls.

### Expected Question 2 (Short Answer – 4 Marks)
**Question:**
*Explain the purpose of the `malloc()` and `free()` functions in C. What is a memory leak, and how does it relate to these functions?*

**Answer:**
**`malloc()` and `free()` (2 Marks):**
- **`malloc(size_t size)`:** Used to dynamically allocate a specified number of bytes in the **Heap** segment of a process's address space at runtime. It returns a pointer to the start of the allocated memory, or `NULL` if allocation fails.
- **`free(void *ptr)`:** Used to deallocate (release) a block of memory on the heap that was previously allocated by `malloc()`. This makes the memory block available for future allocations.

**Memory Leak (2 Marks):**
A memory leak is a critical bug that occurs when a programmer dynamically allocates memory using `malloc()` but forgets to release it using `free()` after it is no longer needed. Because the OS thinks the memory is still in use, that memory cannot be reclaimed. Over time, repeated leaks will consume the entire Heap, eventually causing the program (or the entire system) to crash due to out-of-memory errors.

### Quick Self-Check Key Points for Revision
- **Address Space:** The OS creates a fake, private, safe memory illusion for every process.
- **Code (Text):** Read-only, instructions.
- **Data:** Globals / Statics.
- **Heap:** Dynamic memory (`malloc`), grows UP. 
- **Stack:** Local variables, function calls, grows DOWN.
- **`malloc()`:** Asks OS for Heap space.
- **`free()`:** Gives Heap space back. Forgetting this = **Memory Leak**.
