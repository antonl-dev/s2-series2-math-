# 4.3 Segmentation and Free Space Management

---

## 1. Segmentation

### The Problem with Base and Bounds (Dynamic Relocation)
As we saw in Topic 4.2, using a single Base and Limit register means the entire virtual address space must be placed into a single contiguous block of physical RAM. This causes a massive waste of memory because the large unused "gap" between the Heap and the Stack is also mapped into physical RAM.

### The Solution: Segmentation
To solve this memory waste, OS designers introduced **Segmentation**.
- **The Idea:** Instead of having just *one* Base and Limit register for the entire address space, why not have **a Base and Limit pair for every logical segment** of the address space?
- A typical process has three main logical segments: **Code (Text)**, **Heap**, and **Stack**. (The Data segment is often grouped with Code or Heap).
- By treating each segment independently, the OS can place the Code, Heap, and Stack in **different, non-contiguous physical locations** in RAM.
- **The Result:** The massive unused gap of virtual memory is simply *not mapped* to physical RAM. It takes up zero physical space!

### How Segmentation Works (Address Translation)
The MMU is upgraded to contain a **Segment Table** (an array of Base and Limit registers).

When the CPU generates a virtual address, it must contain two pieces of information:
1. **Segment Number (s):** Which segment is the CPU trying to access? (e.g., Code = 0, Heap = 1, Stack = 2).
2. **Offset (d):** Where exactly *inside* that segment is the data located?

**Translation Steps:**
1. The hardware uses the Segment Number ($s$) to index into the Segment Table and retrieve the Base and Limit for that specific segment.
2. The hardware checks if the Offset ($d$) is less than the Limit. If $d \geq$ Limit, it throws a segmentation fault (protection violation).
3. If valid, the physical address is calculated as: **`Physical Address = Base + Offset (d)`**.

[Click here to see the diagram of Segmentation hardware address translation via Segment Table](https://www.google.com/search?q=segmentation+hardware+address+translation+segment+table+diagram+OS&udm=2)

*(Note on the Stack: Because the stack grows backwards/downwards, the hardware must perform a slightly different mathematical calculation for stack offsets, usually subtracting the offset from the maximum segment size).*

### Advantages and Disadvantages of Segmentation
- **Advantages:** 
  1. Solves the internal gap waste problem of Base/Bounds. 
  2. Makes it very easy to **share** memory. If two processes run the same program, they can have their own private Heap and Stack segments, but their Code segment pointers can point to the exact same physical Base address!
- **Disadvantages (External Fragmentation):**
  - Because segments are of **variable sizes** (the Code segment might be 2MB, Heap 1MB, Stack 64KB), placing them in physical memory creates a major problem called **External Fragmentation**. Over time, physical memory becomes full of tiny "holes" between segments that are too small to hold new segments, even if the *total* free memory is large enough.

## 2. Free Space Management

Because segmentation allocates chunks of memory of variable sizes, the Operating System must keep track of which parts of physical RAM are used and which parts are free. This is the **Free-Space Management** problem (also faced by `malloc()` when managing the variable-sized Heap).

The OS maintains a **Free List**: a data structure (usually a linked list) containing all the free, contiguous blocks (holes) in physical memory.

### Variable-Size Allocation Strategies
When a process requests a segment of size $N$, the OS searches the free list to find a hole large enough. The algorithm used to select the hole dramatically impacts system performance and fragmentation.

The three classic allocation algorithms are:

#### 1. First Fit
- **How it works:** The OS scans the free list from the beginning and allocates the **first** hole that is big enough ($\ge N$). 
- **Pros:** Fast and simple.
- **Cons:** Tends to fragment the beginning of the memory space with many tiny leftover holes.

#### 2. Best Fit
- **How it works:** The OS scans the *entire* free list and allocates the **smallest** hole that is big enough ($\ge N$).
- **Pros:** Minimizes the size of the leftover unallocated space for that specific allocation.
- **Cons:** Slow (must search the whole list). Counter-intuitively, it actually creates the *worst* fragmentation over time because the leftover holes are so incredibly tiny that they are practically useless for future requests.

#### 3. Worst Fit
- **How it works:** The OS scans the *entire* free list and allocates the **largest** available hole.
- **Pros:** The leftover hole will still be quite large, making it more likely to be useful for a future request.
- **Cons:** Slow (must search the whole list). Also tends to consume all the large blocks quickly, making it impossible to satisfy a genuinely large request later.

### Solving External Fragmentation: Compaction
When memory becomes highly fragmented (many small holes), the OS can perform **Compaction**.
- **How it works:** The OS pauses running processes, physically copies their segments in RAM to push them all together at one end of memory, and combines all the tiny free holes into one massive contiguous free block.
- **The Catch:** It is extremely expensive in terms of CPU time (copying megabytes/gigabytes of RAM takes millions of CPU cycles). 

*(Because External Fragmentation is such a difficult mathematical problem to solve efficiently, modern OSes abandoned pure Segmentation in favor of **Paging**—Topic 4.4).*

## 3. Exam Questions & Answers (From Provided Question Papers)

### Question 1 (Memory Allocation Algorithms)
**Source:** *Internal Test – II, October 2026 (Q5b – 5 Marks, BL-3, CO5)*

**Question:**
*A system uses fixed partitioning with partitions of 450K, 300K, 500K, 200K, 350K (in that order). Four processes are waiting to run: P1 = 190K, P2 = 440K, P3 = 130K, P4 = 370K (in order). Show the allocation under (i) First Fit (ii) Best Fit (iii) Worst Fit (1 mark each), and find the internal and external fragmentation (if any) in each case (2 marks).*

**Answer / Solution:**
*(Note: The question states "fixed partitioning", which means holes cannot be split. If a process of 190K is put in a 450K partition, the remaining 260K is wasted as **Internal Fragmentation** inside that partition. If a process cannot fit anywhere, but total free space is enough, that is **External Fragmentation**).*

**Available Partitions (in order):** `[450K, 300K, 500K, 200K, 350K]`
**Processes (in order):** P1=190K, P2=440K, P3=130K, P4=370K

**1. First Fit (Allocates to the first partition that is large enough):**
- **P1 (190K):** Scans left-to-right. 450K is big enough. $\rightarrow$ **P1 in 450K partition**. (Internal Frag: $450 - 190 = 260$K).
- **P2 (440K):** 450K is taken. 300K too small. 500K is big enough. $\rightarrow$ **P2 in 500K partition**. (Internal Frag: $500 - 440 = 60$K).
- **P3 (130K):** 450K taken, 300K is big enough. $\rightarrow$ **P3 in 300K partition**. (Internal Frag: $300 - 130 = 170$K).
- **P4 (370K):** 450K taken, 300K taken, 500K taken. 200K too small. 350K too small. $\rightarrow$ **P4 must wait (Cannot be allocated).**
- *Fragmentation for First Fit:*
  - **Internal:** $260\text{K (from P1)} + 60\text{K (from P2)} + 170\text{K (from P3)} = \textbf{490K}$.
  - **External:** There is a free 200K and a free 350K partition (Total 550K free). P4 needs 370K. Since $550\text{K} \ge 370\text{K}$ but it is not contiguous, the **External Fragmentation is 370K** (the size of the blocked process).

**2. Best Fit (Allocates to the smallest partition that is large enough):**
- **P1 (190K):** Smallest partition $\ge$ 190K is 200K. $\rightarrow$ **P1 in 200K partition**. (Internal Frag: $200 - 190 = 10$K).
- **P2 (440K):** Smallest partition $\ge$ 440K is 450K. $\rightarrow$ **P2 in 450K partition**. (Internal Frag: $450 - 440 = 10$K).
- **P3 (130K):** Remaining available: 300K, 500K, 350K. Smallest $\ge$ 130K is 300K. $\rightarrow$ **P3 in 300K partition**. (Internal Frag: $300 - 130 = 170$K).
- **P4 (370K):** Remaining available: 500K, 350K. Smallest $\ge$ 370K is 500K. $\rightarrow$ **P4 in 500K partition**. (Internal Frag: $500 - 370 = 130$K).
- *Fragmentation for Best Fit:*
  - **Internal:** $10 + 10 + 170 + 130 = \textbf{320K}$.
  - **External:** All processes were allocated, so **External Fragmentation is 0**.

**3. Worst Fit (Allocates to the largest available partition):**
- **P1 (190K):** Largest partition is 500K. $\rightarrow$ **P1 in 500K partition**. (Internal Frag: $500 - 190 = 310$K).
- **P2 (440K):** Remaining largest is 450K. $\rightarrow$ **P2 in 450K partition**. (Internal Frag: $450 - 440 = 10$K).
- **P3 (130K):** Remaining largest is 350K. $\rightarrow$ **P3 in 350K partition**. (Internal Frag: $350 - 130 = 220$K).
- **P4 (370K):** Remaining available: 300K, 200K. Neither is large enough. $\rightarrow$ **P4 must wait (Cannot be allocated).**
- *Fragmentation for Worst Fit:*
  - **Internal:** $310 + 10 + 220 = \textbf{540K}$.
  - **External:** Total free space is 500K (300K + 200K). P4 needs 370K. **External Fragmentation is 370K**.

### Expected Question 2 (Theory)
**Source:** *End Semester Examination – November 2025 (Module 4, Q8a – 5 Marks, CO5)*

**Question:**
*Explain the concept of segmentation with suitable diagrams.*

**Answer:**
**Concept (2.5 Marks):**
Segmentation is a memory management scheme that supports the programmer's view of memory. Instead of forcing the entire virtual address space into a single contiguous physical block (which wastes space), segmentation divides the logical address space into multiple variable-sized **segments** (e.g., Code segment, Data segment, Heap segment, Stack segment). 

The Operating System can load each of these segments into different, non-contiguous physical memory locations. This eliminates the internal fragmentation caused by the empty gap between the heap and the stack. Address translation is handled by a **Segment Table**, where each entry contains a **Base** (starting physical address) and a **Limit** (length of the segment) for that specific segment.

### Expected Question 3 (Theory)
**Source:** *End Semester Examination – November 2025 (Module 4, Q8b – 3 Marks, CO5)*

**Question:**
*Differentiate between internal and external fragmentation.*

**Answer:**
| Feature | Internal Fragmentation | External Fragmentation |
| :--- | :--- | :--- |
| **Definition** | Occurs when the memory allocated to a process is slightly larger than the requested memory. The unused space is **inside** the allocated block. | Occurs when there is enough total free memory space to satisfy a request, but the available spaces are not contiguous (it is fragmented into many small holes **between** allocated blocks). |
| **Occurrence** | Common in systems using fixed-size allocation (like Paging or Fixed Partitioning). | Common in systems using variable-size allocation (like Segmentation or dynamic heap allocation). |
| **Solution** | Cannot be easily recovered. Best solved by allocating memory in variable sizes or smaller fixed sizes (pages). | Solved by **Compaction** (shuffling memory contents to place all free memory together in one large block) or by using Paging. |

### Quick Self-Check Key Points for Revision
- **Segmentation:** Split address space by logical meaning (Code, Heap, Stack). Each gets a Base/Limit.
- **Benefit:** No memory wasted on the gap between Heap/Stack. Allows easy sharing of Code.
- **Drawback:** Variable sizes cause **External Fragmentation**.
- **Algorithms:** First Fit (first big enough), Best Fit (smallest big enough - causes tiny useless holes), Worst Fit (largest available).
- **Internal vs External Frag:** Internal = wasted space *inside* the box you were given. External = enough total free space, but chopped up into pieces too small to use.
