# 4.4 Paging

---

## 1. Introduction: The Problem Paging Solves

In the previous topic (4.3), we saw that **Segmentation** allows the OS to place different parts of a program (Code, Heap, Stack) in different areas of physical memory. However, because these segments are of *variable sizes*, they eventually chop physical memory into many tiny, unusable holes. This is called **External Fragmentation**.

To completely eliminate external fragmentation, OS designers invented **Paging**. 

- **The Core Idea:** Instead of dividing a process into variable-sized logical segments, we divide the process's logical memory into **fixed-size blocks called Pages**. 
- We also divide the physical memory (RAM) into fixed-size blocks of the exact same size, called **Frames**.
- Because all Pages and Frames are the exact same size, *any* Page can be placed into *any* available Frame. There are no awkward variable-sized holes left over!

### Advantages of Paging
1. **No External Fragmentation:** Any free frame can hold any page. Physical memory is 100% utilized without needing compaction.
2. **Easy Free-Space Management:** The OS just maintains a simple list of free frames. If a process needs 4 pages, the OS grabs any 4 frames from the list.
3. **Internal Fragmentation:** While external fragmentation is eliminated, paging does suffer from **internal fragmentation**. If a page size is 4KB, and a process needs 5KB of memory, the OS must allocate 2 pages (8KB). The remaining 3KB in the second page is wasted internally. (This is generally accepted as a small price to pay).

---

## 2. Address Translation in Paging

Because physical memory is no longer contiguous (Page 1 of a process might be in Frame 10, while Page 2 might be in Frame 500), the OS needs a way to map Logical Pages to Physical Frames. It does this using a **Page Table**.

### The Logical Address Breakdown
When the CPU generates a logical (virtual) address, the MMU splits it into two parts:
1. **Page Number ($p$):** Used as an index into the Page Table. It tells the hardware which logical page the CPU is trying to access.
2. **Page Offset ($d$):** The exact byte location *inside* that page. 

*Crucially, because Pages and Frames are the same size, the offset ($d$) does not change during translation!*

### Translation Steps
1. The CPU generates a Logical Address (e.g., 32 bits long).
2. The hardware splits the address into Page Number ($p$) and Offset ($d$).
3. The hardware uses $p$ as an index into the **Page Table**.
4. The Page Table entry contains the **Frame Number ($f$)** where that page is physically located in RAM.
5. The hardware takes the Frame Number ($f$) and attaches the original Offset ($d$) to the end of it to form the final **Physical Address**.

## 3. Paging Mathematics (Bit Calculations)

Paging problems are entirely based on powers of 2. You must be comfortable converting between bytes, kilobytes, and bits.

**Memory Size Conversions:**
- $1 \text{ KB} = 2^{10} \text{ bytes}$
- $1 \text{ MB} = 2^{20} \text{ bytes}$
- $1 \text{ GB} = 2^{30} \text{ bytes}$

**Formulas for Paging Bits:**
If the size of the Logical Address Space is $2^m$ bytes, and the Page Size is $2^n$ bytes:
- **Total Logical Address Bits = $m$ bits.**
- **Page Offset Bits ($d$) = $n$ bits.** (Because it must address every byte inside a page of size $2^n$).
- **Page Number Bits ($p$) = $m - n$ bits.**
- **Total Number of Pages = $2^{m-n}$** (or Total Logical Memory / Page Size).

Similarly, if Physical Memory is $2^k$ bytes:
- **Total Physical Address Bits = $k$ bits.**
- **Frame Offset Bits ($d$) = $n$ bits.** (Must be exactly the same as the Page offset!).
- **Frame Number Bits ($f$) = $k - n$ bits.**
- **Total Number of Frames = $2^{k-n}$** (or Total Physical Memory / Frame Size).

## 4. Exam Questions & Answers (From Provided Question Papers)

### Question 1 (Paging Bit Calculations)
**Source:** *Internal Test – II, October 2026 (Q3a – 5 Marks, BL-3, CO5)*

**Question:**
*A logical address space has 128 pages of 2048 words each, mapped onto a physical memory of 32 frames. i) How many bits are needed for the logical address? ii) How many bits are needed for the physical address? (2.5 marks each)*

**Answer / Solution:**
**Given Data:**
- Number of Pages = $128 = 2^7$
- Page Size (which equals Frame Size) = $2048 \text{ words} = 2^{11} \text{ words}$
- Number of Frames in Physical Memory = $32 = 2^5$

**i) Bits needed for the Logical Address (2.5 Marks):**
The logical address consists of two parts: the Page Number ($p$) and the Page Offset ($d$).
- **Bits for Page Number ($p$):** Since there are 128 pages ($2^7$), we need **7 bits** to uniquely identify a page.
- **Bits for Page Offset ($d$):** Since the page size is 2048 words ($2^{11}$), we need **11 bits** to address every word inside a single page.
- **Total Logical Address Bits:** $p + d = 7 + 11 =$ **18 bits**.

**ii) Bits needed for the Physical Address (2.5 Marks):**
The physical address consists of two parts: the Frame Number ($f$) and the Frame Offset ($d$).
- **Bits for Frame Number ($f$):** Since there are 32 frames ($2^5$) in physical memory, we need **5 bits** to uniquely identify a physical frame.
- **Bits for Frame Offset ($d$):** The frame size is identical to the page size. Therefore, the offset remains exactly the same: **11 bits**.
- **Total Physical Address Bits:** $f + d = 5 + 11 =$ **16 bits**.

### Expected Question 2 (Paging vs Segmentation)
**Question:**
*Compare Paging and Segmentation memory management schemes in terms of fragmentation and the programmer's view of memory.*

**Answer:**
| Feature | Paging | Segmentation |
| :--- | :--- | :--- |
| **Basic Unit** | Memory is divided into **fixed-size** blocks (Pages and Frames). | Memory is divided into **variable-size** blocks based on logical units (Code, Stack). |
| **Programmer's View** | **Transparent.** The programmer is completely unaware of paging. The OS and hardware handle it. | **Visible.** The programmer (or compiler) actively organizes memory into distinct logical segments. |
| **External Fragmentation** | **None.** Because all frames are the exact same size, any frame can hold any page. | **Severe.** Variable-sized segments leave tiny unusable holes in memory over time. |
| **Internal Fragmentation** | **Yes.** If a process's memory requirement is not an exact multiple of the page size, the last page will have unused wasted space inside it. | **None.** The OS creates segments exactly the size the program requests, so no space inside the segment is wasted. |

### Quick Self-Check Key Points for Revision
- **Page:** Fixed-size block of Logical Memory.
- **Frame:** Fixed-size block of Physical RAM. 
- **Rule:** Page Size **MUST EXACTLY EQUAL** Frame Size.
- **Address Translation:** Split logical address into Page Number ($p$) and Offset ($d$). Look up $p$ in Page Table to find Frame Number ($f$). Replace $p$ with $f$. Keep $d$ the exact same.
- **Fragmentation:** Paging eliminates External Fragmentation but causes Internal Fragmentation (on the very last page of a process).
- **Math trick:** Log base 2 is your friend. 4KB = $2^2 \times 2^{10} = 2^{12}$, so offset is 12 bits.
