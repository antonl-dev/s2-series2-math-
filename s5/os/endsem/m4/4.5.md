# 4.5 Virtual Memory: Demand Paging and the Translation Look-aside Buffer (TLB)

---

## 1. The Performance Problem with Paging

Paging (Topic 4.4) brilliantly solves the problem of external fragmentation by dividing memory into fixed-size frames. However, implementing paging in hardware introduces a massive performance bottleneck.

### The Two-Memory-Access Problem
To find where a page is stored, the hardware uses a **Page Table**. 
- Because modern page tables are very large (often megabytes in size), they cannot be stored in tiny, fast CPU registers. 
- The Page Table is stored in **Main Memory (RAM)**, and a single CPU register (the Page-Table Base Register, PTBR) points to it.

Therefore, executing a simple instruction like `Load Register from Address X` now takes **two physical memory accesses**:
1. **First Access:** The CPU must go to RAM, read the Page Table to find the Frame Number for Address X.
2. **Second Access:** Now that the CPU has the physical address, it must go to RAM *again* to actually read the data.

**Result:** Paging slows the computer down by exactly 50%! Every memory access takes twice as long.

---

## 2. The Solution: Translation Look-Aside Buffer (TLB)

To fix this severe performance penalty, hardware designers added a special, super-fast hardware cache to the Memory Management Unit (MMU) called the **Translation Look-aside Buffer (TLB)**.

### What is a TLB?
The TLB is a very small, extremely fast associative cache memory built directly into the CPU. 
- It stores a small number of **recent Page Table entries** (specifically, pairs of `Page Number` $\rightarrow$ `Frame Number`).
- Because it is built using associative memory (parallel search hardware), it can compare a Page Number against all entries in the TLB simultaneously, in a fraction of a nanosecond.

### How the TLB Works (Address Translation Flow)
When the CPU generates a logical address containing a Page Number ($p$) and an Offset ($d$):
1. **TLB Search:** The MMU first sends the Page Number ($p$) to the TLB.
2. **TLB Hit:** If the Page Number is found in the TLB (a TLB hit), the TLB instantly returns the Frame Number ($f$). The physical address is generated, and the CPU goes to RAM exactly **once** to get the data. (Fast!).
3. **TLB Miss:** If the Page Number is *not* in the TLB (a TLB miss):
   - The hardware must do it the slow way. It goes to RAM, reads the full Page Table, and finds the Frame Number.
   - Before completing the instruction, the hardware **copies that Page Table entry into the TLB** so that future accesses to that page will be extremely fast TLB hits. (If the TLB is full, it replaces an old entry, often using an LRU policy).

## 3. Introduction to Virtual Memory (Demand Paging)

Up to this point, we assumed that if a process is 100 MB in size, all 100 MB of its pages must be loaded into physical RAM for the process to run.
- **Problem:** What if we only have 64 MB of RAM? Or what if we want to run ten 100 MB programs simultaneously?

### The Core Idea of Virtual Memory
**Virtual Memory** is the separation of user logical memory from physical memory. It creates the illusion of an extremely large main memory, allowing the execution of processes that are much larger than the available physical RAM.

### How it is Implemented: Demand Paging
Virtual memory is typically implemented using **Demand Paging**.
- Instead of loading the entire program into RAM at boot time, the OS leaves the program on the Hard Disk.
- The OS only loads a page into physical RAM **on demand**—specifically, when the CPU tries to execute an instruction on that page.
- **Lazy Swapper (Pager):** A pager never swaps a page into memory unless that specific page is needed.

### The Demand Paging Process (Handling a Page Fault)
What happens when a process tries to access a page that is still on the disk?
1. **Invalid Bit Check:** Every entry in the Page Table has a valid/invalid bit. If the page is in RAM, it's marked *valid*. If it's on the disk, it's marked *invalid*.
2. **Page Fault Trap:** The MMU translates the address, sees the *invalid* bit, and instantly triggers a hardware trap called a **Page Fault**. The OS takes control.
3. **OS Resolution:**
   - The OS checks its internal tables to verify the address was a legal memory request (if illegal, it kills the process).
   - The OS finds a free physical frame in RAM.
   - The OS issues a disk I/O request to read the missing page from the hard drive into the free frame.
   - While waiting for the slow disk, the OS context-switches to another process.
4. **Resumption:** Once the disk read completes, the OS updates the Page Table (sets it to *valid* and assigns the frame number). It then restarts the exact instruction that caused the page fault. This time, the page is in RAM, so it succeeds!

## 4. Exam Questions & Answers (From Provided Question Papers)

### Question 1 (TLB Diagram and Explanation)
**Source:** *Internal Test – II, October 2026 (Q3b – 5 Marks, BL-2, CO5)*

**Question:**
*Using a diagram, explain how a Translation Look-aside Buffer (TLB) improves the performance of a paging system.*

**Answer:**
**Explanation (3 Marks):**
In a standard paging system, every logical memory reference requires **two** physical memory accesses: one to access the Page Table (which is stored in RAM) to translate the address, and a second to access the actual data. This effectively halves the speed of the CPU.

A **Translation Look-aside Buffer (TLB)** improves performance by acting as a high-speed, associative hardware cache inside the CPU's Memory Management Unit. It stores a small subset of recently used Page Table entries (Page Number $\rightarrow$ Frame Number). 
When the CPU generates a logical address, the MMU first checks the TLB in parallel. 
- If the Page Number is found (**TLB Hit**), the frame number is returned instantly, and the CPU only accesses RAM once to get the data. 
- Due to the principle of locality, TLB hit rates are typically over 99%, meaning the massive overhead of checking the Page Table in RAM is almost entirely eliminated, bringing execution speed back up to normal hardware levels.

**Diagram (2 Marks):**
*(Draw a flowchart diagram showing:)*
1. CPU generates Logical Address (Page $p$, Offset $d$).
2. $p$ goes into the **TLB block**.
3. **Decision Diamond:** Is $p$ in TLB?
   - **YES (Hit):** TLB outputs Frame $f$.
   - **NO (Miss):** $p$ goes to the **Page Table** in Physical Memory to get Frame $f$ (and updates the TLB).
4. Combine Frame $f$ with Offset $d$ to form the Physical Address.
5. Physical Address goes to Physical Memory to retrieve Data.

### Expected Question 2 (Demand Paging and Page Faults)
**Question:**
*Explain the concept of Demand Paging. Outline the sequence of steps the operating system takes when a Page Fault occurs.*

**Answer:**
**Demand Paging Concept (2 Marks):**
Demand paging is the core mechanism used to implement Virtual Memory. Instead of loading an entire process into physical RAM when it starts, the OS only loads pages "on demand"—meaning a page is brought from the secondary storage (disk) into physical memory exactly at the moment the CPU tries to access it. This allows systems to run programs much larger than physical RAM and increases the degree of multiprogramming.

**Page Fault Sequence (3 Marks):**
When the CPU tries to access a page that is not currently in physical RAM, the MMU triggers a hardware trap called a **Page Fault**. The OS handles it through the following steps:
1. The OS checks internal tables to verify the memory request is legal. If illegal, it aborts the process.
2. The OS searches for a free physical frame in RAM.
3. The OS schedules a disk I/O operation to read the desired page from the hard disk into the newly allocated free frame.
4. Once the disk read is complete, the OS updates the Page Table for that process, marking the page as "valid" and recording the new frame number.
5. The OS restarts the exact CPU instruction that was interrupted by the page fault. The CPU will now find the page in RAM and execute successfully.

### Quick Self-Check Key Points for Revision
- **Paging Problem:** Requires 2 RAM accesses per instruction (Slow!).
- **TLB Solution:** Hardware cache for Page Table entries. TLB Hit = 1 RAM access (Fast!). TLB Miss = 2 RAM accesses.
- **Virtual Memory:** Illusion of massive RAM. Processes can be bigger than physical memory.
- **Demand Paging:** Only load a page from disk to RAM when the CPU actually asks for it.
- **Page Fault:** Hardware trap when the CPU asks for a page that is currently sitting on the disk. OS fetches it, updates the table, and restarts the instruction.
