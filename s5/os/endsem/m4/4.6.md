# 4.6 Page Replacement Algorithms (Part 1: FIFO and LRU)

---

## 1. Introduction: Why do we need Page Replacement?

In Demand Paging (Virtual Memory), the OS loads pages into physical RAM frames only when they are needed. 
Eventually, **Physical Memory becomes completely full**. 
- If a process triggers a Page Fault, the OS needs to bring a page from the disk into a free frame.
- But if there are *no free frames* left, the OS must **evict (swap out)** an existing page from RAM to the disk to make room for the new page.

**Page Replacement** is the process of selecting a "victim" frame to be evicted. 
- The goal of a Page Replacement Algorithm is to select a victim in a way that minimizes the total number of page faults. (If you evict a page that the CPU is going to need again in 5 milliseconds, you will just cause another page fault immediately!).

### The Page Replacement Flow
1. Find the location of the desired page on the disk.
2. Find a free frame:
   - If there is a free frame, use it.
   - If there is no free frame, use a **Page Replacement Algorithm** to select a **victim frame**.
   - Write the victim frame back to the disk (if it was modified) and update its Page Table entry to *invalid*.
3. Read the desired new page from the disk into the newly freed frame.
4. Update the Page Table (set to *valid*).
5. Restart the user instruction.

*(Note: Page replacement technically requires two disk transfers: one to write the victim out, and one to read the new page in. This is very slow).*

---

## 2. First-In, First-Out (FIFO) Algorithm

The simplest page-replacement algorithm is **FIFO**.

- **How it works:** The OS associates with each page the time when that page was brought into memory. When a page must be replaced, the OS chooses the **oldest** page (the one that has been in RAM the longest).
- **Implementation:** It is easily implemented using a simple FIFO queue (like a line at a grocery store). Pages enter at the tail, and victims are chosen from the head.
- **Pros:** Very simple to understand and extremely easy to code. Low overhead.
- **Cons:** **Poor performance**. The oldest page might be a critical initialization library or a frequently used global variable. If the OS evicts it, it will just cause a page fault again immediately.

### Belady's Anomaly
Normally, you would expect that giving a computer *more physical RAM* (more frames) would result in *fewer page faults*. 
- **Belady's Anomaly** is a famous mathematical phenomenon specific to the FIFO algorithm where **increasing the number of page frames actually INCREASES the number of page faults** for certain reference strings. (This will be tested in the exam questions below).

---

## 3. Least Recently Used (LRU) Algorithm

To improve upon FIFO, we use the principle of **Locality of Reference** (if a page was used recently, it will likely be used again soon).

- **How it works:** Instead of looking at when a page was *brought into* memory (FIFO), LRU looks at when a page was *last used*. When a frame must be evicted, LRU chooses the page that has **not been used for the longest period of time**.
- **Pros:** Excellent performance. It avoids Belady's Anomaly entirely (it is a "stack" algorithm). It is the standard algorithm used by most modern operating systems.
- **Cons:** **Requires massive hardware support.** The OS needs to constantly update a timestamp or move items in a linked list on *every single memory access* (millions of times a second). Pure LRU is often too slow to implement directly in software, so OSes use approximations (like the Clock algorithm).

### Question 1 (FIFO and Belady's Anomaly)

**Question:**
*Consider the following page reference string: 7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2, 0. Indicate page faults and calculate total number of page faults for FIFO algorithm, assuming that number of frames as three and four. Remember initially all the frames are empty. Check whether Belady's anomaly happens.*

**Answer / Solution:**

**Part A: FIFO with 3 Frames**
Reference String: 7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2, 0

| **0** | 2 | 0 | 1 | Hit | [0, 1, 2] |

| **4** | **4** | 3 | 0 | **F (7)** | [3, 0, 4] (Replaced 2) |

**Total Page Faults (3 Frames) = 12**

**Part B: FIFO with 4 Frames**

| Ref | F1 | F2 | F3 | F4 | Fault? | Queue (Oldest $\rightarrow$ Newest) |
| :---: | :---: | :---: | :---: | :---: | :---: | :--- |

| **4** | 3 | **4** | 1 | 2 | **F (6)** | [1, 2, 3, 4] (Replaced 0) |
| **2** | 3 | 4 | 1 | 2 | Hit | [1, 2, 3, 4] |
| **3** | 3 | 4 | 1 | 2 | Hit | [1, 2, 3, 4] |
| **0** | 3 | 4 | **0** | 2 | **F (7)** | [2, 3, 4, 0] (Replaced 1) |

| **2** | 3 | 4 | 0 | 2 | Hit | [2, 3, 4, 0] |

### Quick Self-Check Key Points for Revision
- **Page Replacement:** Evicting a page from full RAM to disk to load a new one. Goal: minimize page faults.
- **FIFO:** Replaces the page that was brought in first. Easy, but dumb.
- **Belady's Anomaly:** Specific to FIFO. Sometimes giving the OS *more* RAM frames causes *more* page faults!
- **LRU (Least Recently Used):** Looks back in time. Replaces the page that hasn't been used for the longest time. No Belady's Anomaly. Excellent performance, but hard to implement in hardware.
