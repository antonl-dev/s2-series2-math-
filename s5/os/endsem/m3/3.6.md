# 3.6 Deadlock Prevention and Deadlock Avoidance

---

## 1. Deadlock Prevention

As discussed in Topic 3.5, a deadlock requires four necessary conditions to hold simultaneously: Mutual Exclusion, Hold and Wait, No Preemption, and Circular Wait. 
**Deadlock Prevention** provides a set of strict methods to ensure that **at least one of these four conditions cannot possibly hold**, thereby preventing deadlocks from ever occurring.

### Breaking Condition 1: Mutual Exclusion
- **Strategy:** Make all resources sharable. 
- **Reality:** We cannot deny the mutual exclusion condition for inherently non-sharable resources. For example, a Mutex lock or a printer cannot be simultaneously shared by two processes. Therefore, this condition is usually impossible to break in practice.

### Breaking Condition 2: Hold and Wait
- **Strategy:** Guarantee that whenever a process requests a resource, it does not hold any other resources.
- **Protocol:** A process must request and be allocated **all of its required resources at once**, right before it begins execution. 
- **Reality:** This approach has massive disadvantages. Resource utilization is extremely low (a process might hold a printer for 5 hours just because it needs it for 1 minute at the end). Also, **starvation** is possible if a process needs a popular resource.

### Breaking Condition 3: No Preemption
- **Strategy:** Allow resource preemption (taking resources away forcefully).
- **Protocol:** If a process $P_1$ holds some resources and requests another resource that is currently held by $P_2$, the OS checks if $P_2$ is waiting for anything. If $P_2$ is waiting, the OS **preempts** (takes away) the resource from $P_2$ and gives it to $P_1$.
- **Reality:** This is only practical for resources whose state can be easily saved and restored (like CPU registers or memory space via swapping). It cannot be applied to physical hardware like printers.

### Breaking Condition 4: Circular Wait
- **Strategy:** Impose a **total ordering** of all resource types.
- **Protocol:** Every resource type in the system is assigned a unique integer (e.g., Disk = 1, Printer = 2, Tape = 3). A process is only allowed to request resources in an **increasing order of enumeration**. If a process holds Resource 2, it can only request Resource 3; it cannot request Resource 1. 
- **Reality:** This is the most practical prevention method, but it forces programmers to write code in a highly restricted manner.

---

## 2. Deadlock Avoidance

Because Deadlock Prevention is too restrictive and wastes system resources, modern systems prefer **Deadlock Avoidance**.
In deadlock avoidance, the OS requires **additional *a priori* (advance) information** about how resources will be requested. 
- Every process must declare the **Maximum number** of resources of each type that it will ever need.
- When a process makes a request, the OS runs an algorithm to dynamically check if granting that request will leave the system in a **Safe State**.

### Safe State vs. Unsafe State
- **Safe State:** The system can allocate resources to each process (up to its maximum) in some order without causing a deadlock. This order is called a **Safe Sequence**.
- **Unsafe State:** A state where a deadlock *could* potentially occur. (Not all unsafe states are deadlocks, but all deadlocks are unsafe states).
- **The Rule:** If a resource request puts the system into an unsafe state, the OS will **deny the request** and force the process to wait.

### The Banker's Algorithm
For systems with **multiple instances** of each resource type, the OS uses the **Banker's Algorithm**. (The name comes from a banking system ensuring the bank never runs out of cash to satisfy all customer limits).

The Banker's Algorithm uses four data structures (matrices/arrays):
1. **Available:** How many instances of each resource are currently free.
2. **Max:** The maximum demand of each process.
3. **Allocation:** How many resources are currently allocated to each process.
4. **Need:** How many *more* resources each process might still request. 
   - **Formula:** `Need = Max - Allocation`

## 3. Exam Questions & Answers (Banker's Algorithm Calculations)

> **IMPORTANT EXAM NOTE:** The Banker's algorithm is mathematically rigorous. You must calculate the `Need` matrix first, then find a `Safe Sequence` by checking `Need <= Available`. If a sequence exists, the system is safe.

### Question 1
**Source:** *Internal Test – II, October 2026 (Q2 – 10 Marks, BL-3, CO4)*

**Question:**
*A system has Five processes P0–P4 and four resource types A, B, C, D. The state at time t0 is given below. Apply the Banker's algorithm to answer the following:*
*(i) Total instances of each type (2 marks)*
*(ii) Need matrix (2 marks)*
*(iii) Is the system safe? Find a safe sequence if any (3 marks)*
*(iv) Can a request (1, 0, 1, 0) from P1 be granted immediately? (3 marks)*

| Process | Allocation (A B C D) | Max (A B C D) | Available (A B C D) |
| :--- | :--- | :--- | :--- |
| **P0** | 2 0 0 1 | 4 2 1 2 | 3 3 2 1 |
| **P1** | 3 1 2 1 | 5 2 5 2 | |
| **P2** | 2 1 0 3 | 2 3 1 6 | |
| **P3** | 1 3 1 2 | 1 4 2 4 | |
| **P4** | 1 4 3 2 | 3 6 6 5 | |

**Answer / Solution:**

**Step (i): Total instances of each type (2 Marks)**
- Total = Sum of `Allocation` column + `Available`
- Sum of Allocation for A: $2 + 3 + 2 + 1 + 1 = 9$
- Sum of Allocation for B: $0 + 1 + 1 + 3 + 4 = 9$
- Sum of Allocation for C: $0 + 2 + 0 + 1 + 3 = 6$
- Sum of Allocation for D: $1 + 1 + 3 + 2 + 2 = 9$
- Available: $A=3, B=3, C=2, D=1$
- **Total Instances (A, B, C, D):** (9+3, 9+3, 6+2, 9+1) = **(12, 12, 8, 10)**

**Step (ii): Need matrix (2 Marks)**
- Formula: `Need = Max - Allocation`

| Process | Need (A B C D) |
| :--- | :--- |
| **P0** | (4-2, 2-0, 1-0, 2-1) = **2 2 1 1** |
| **P1** | (5-3, 2-1, 5-2, 2-1) = **2 1 3 1** |
| **P2** | (2-2, 3-1, 1-0, 6-3) = **0 2 1 3** |
| **P3** | (1-1, 4-3, 2-1, 4-2) = **0 1 1 2** |
| **P4** | (3-1, 6-4, 6-3, 5-2) = **2 2 3 3** |

**Step (iii): Is the system safe? Find a safe sequence (3 Marks)**
Initial Available = **(3, 3, 2, 1)**
1. Check **P0:** Need (2,2,1,1) $\leq$ Avail (3,3,2,1)? **True.**
   - Execute P0. New Avail = Avail + Alloc_P0 = (3,3,2,1) + (2,0,0,1) = **(5, 3, 2, 2)**
2. Check **P1:** Need (2,1,3,1) $\leq$ Avail (5,3,2,2)? False (Needs 3 C, only 2 available). Skip.
3. Check **P2:** Need (0,2,1,3) $\leq$ Avail (5,3,2,2)? False (Needs 3 D, only 2 available). Skip.
4. Check **P3:** Need (0,1,1,2) $\leq$ Avail (5,3,2,2)? **True.**
   - Execute P3. New Avail = (5,3,2,2) + (1,3,1,2) = **(6, 6, 3, 4)**
5. Check **P4:** Need (2,2,3,3) $\leq$ Avail (6,6,3,4)? **True.**
   - Execute P4. New Avail = (6,6,3,4) + (1,4,3,2) = **(7, 10, 6, 6)**
6. Re-check **P1:** Need (2,1,3,1) $\leq$ Avail (7,10,6,6)? **True.**
   - Execute P1. New Avail = (7,10,6,6) + (3,1,2,1) = **(10, 11, 8, 7)**
7. Re-check **P2:** Need (0,2,1,3) $\leq$ Avail (10,11,8,7)? **True.**
   - Execute P2. New Avail = (10,11,8,7) + (2,1,0,3) = **(12, 12, 8, 10)** *(Matches Total instances!)*

**Conclusion:** Yes, the system is in a safe state. A safe sequence is **<P0, P3, P4, P1, P2>**.

**Step (iv): Can a request (1, 0, 1, 0) from P1 be granted? (3 Marks)**
*Request Rule Checks:*
1. Request $\leq$ Need? (1,0,1,0) $\leq$ (2,1,3,1) $\rightarrow$ **True**.
2. Request $\leq$ Available? (1,0,1,0) $\leq$ (3,3,2,1) $\rightarrow$ **True**.

*Pretend to allocate:*
- New Avail = (3,3,2,1) - (1,0,1,0) = **(2, 3, 1, 1)**
- New Alloc_P1 = (3,1,2,1) + (1,0,1,0) = **(4, 1, 3, 1)**
- New Need_P1 = (2,1,3,1) - (1,0,1,0) = **(1, 1, 2, 1)**

*Run Safety Algorithm with New Available (2, 3, 1, 1):*
1. **P0:** Need (2,2,1,1) $\leq$ (2,3,1,1) $\rightarrow$ **True**.
   - Exec P0. Avail = (2,3,1,1) + (2,0,0,1) = **(4, 3, 1, 2)**
2. **P1:** Need (1,1,2,1) $\leq$ (4,3,1,2) $\rightarrow$ False.
3. **P2:** Need (0,2,1,3) $\leq$ (4,3,1,2) $\rightarrow$ False.
4. **P3:** Need (0,1,1,2) $\leq$ (4,3,1,2) $\rightarrow$ **True**.
   - Exec P3. Avail = (4,3,1,2) + (1,3,1,2) = **(5, 6, 2, 4)**
5. **P1 (Re-check):** Need (1,1,2,1) $\leq$ (5,6,2,4) $\rightarrow$ **True**.
   - Exec P1. Avail = (5,6,2,4) + (4,1,3,1) = **(9, 7, 5, 5)**
6. **P2 (Re-check):** Need (0,2,1,3) $\leq$ (9,7,5,5) $\rightarrow$ **True**.
   - Exec P2. Avail = (9,7,5,5) + (2,1,0,3) = **(11, 8, 5, 8)**
7. **P4:** Need (2,2,3,3) $\leq$ (11,8,5,8) $\rightarrow$ **True**.
   - Exec P4. Avail = (11,8,5,8) + (1,4,3,2) = **(12, 12, 8, 10)**

**Conclusion:** The pretend state is Safe (Sequence: P0, P3, P1, P2, P4). **Yes, the request can be immediately granted.**

### Question 2
**Source:** *End Semester Examination – November 2025 (Module 3, Q5 – 8 Marks, CO4)*

*(Note regarding Question Paper Typo: The ESE question paper erroneously printed the table columns as `Max` followed by `Allocation`. However, the mathematical values dictate that the first data block is actually `Allocation` and the second is `Max`, because Allocation cannot logically be greater than Max [e.g., P2 cannot have a Max of 1000 and an Allocation of 1750]. The solution below proceeds with the standard, mathematically valid assignment).*

**Question:**
*Consider the snapshot of a system with five processes P1-P5 and four resources A,B,C,D. Using Bankers Algorithm find the following: (i) Calculate the Need Matrix. (ii) Is system in safe state? Find safe sequence. (iii) If request from P2 (0, 3, 2, 0) arrives, can it be immediately granted?*

| Process | Allocation (A B C D) | Max (A B C D) | Available (A B C D) |
| :--- | :--- | :--- | :--- |
| **P1** | 0 0 1 2 | 0 0 1 2 | 1 5 2 0 |
| **P2** | 1 0 0 0 | 1 7 5 0 | |
| **P3** | 1 3 5 4 | 2 3 5 6 | |
| **P4** | 0 6 3 2 | 0 6 5 2 | |
| **P5** | 0 0 1 4 | 0 6 5 6 | |

**Answer / Solution:**

**Step (i): Need Matrix (2 Marks)**
`Need = Max - Allocation`
- **P1:** (0-0, 0-0, 1-1, 2-2) = **0 0 0 0**
- **P2:** (1-1, 7-0, 5-0, 0-0) = **0 7 5 0**
- **P3:** (2-1, 3-3, 5-5, 6-4) = **1 0 0 2**
- **P4:** (0-0, 6-6, 5-3, 2-2) = **0 0 2 0**
- **P5:** (0-0, 6-0, 5-1, 6-4) = **0 6 4 2**

**Step (ii): Safe State & Sequence (3 Marks)**
Initial Available = **(1, 5, 2, 0)**
1. **P1:** Need (0,0,0,0) $\leq$ (1,5,2,0)? **True**.
   - Avail = (1,5,2,0) + (0,0,1,2) = **(1, 5, 3, 2)**
2. **P2:** Need (0,7,5,0) $\leq$ (1,5,3,2)? False. Skip.
3. **P3:** Need (1,0,0,2) $\leq$ (1,5,3,2)? **True**.
   - Avail = (1,5,3,2) + (1,3,5,4) = **(2, 8, 8, 6)**
4. **P4:** Need (0,0,2,0) $\leq$ (2,8,8,6)? **True**.
   - Avail = (2,8,8,6) + (0,6,3,2) = **(2, 14, 11, 8)**
5. **P5:** Need (0,6,4,2) $\leq$ (2,14,11,8)? **True**.
   - Avail = (2,14,11,8) + (0,0,1,4) = **(2, 14, 12, 12)**
6. **P2 (Re-check):** Need (0,7,5,0) $\leq$ (2,14,12,12)? **True**.
   - Avail = (2,14,12,12) + (1,0,0,0) = **(3, 14, 12, 12)**

**Conclusion:** Yes, the system is in a safe state. Safe sequence: **<P1, P3, P4, P5, P2>**.

**Step (iii): Request from P2 for (0, 3, 2, 0) (3 Marks)**
1. Request $\leq$ Need? (0,3,2,0) $\leq$ (0,7,5,0) $\rightarrow$ True.
2. Request $\leq$ Available? (0,3,2,0) $\leq$ (1,5,2,0) $\rightarrow$ True.

*Pretend State:*
- New Avail = (1,5,2,0) - (0,3,2,0) = **(1, 2, 0, 0)**
- New Alloc_P2 = (1,0,0,0) + (0,3,2,0) = **(1, 3, 2, 0)**
- New Need_P2 = (0,7,5,0) - (0,3,2,0) = **(0, 4, 3, 0)**

*Run Safety Algorithm with Avail = (1, 2, 0, 0):*
1. **P1:** Need (0,0,0,0) $\leq$ (1,2,0,0) $\rightarrow$ **True**.
   - Avail = (1,2,0,0) + (0,0,1,2) = **(1, 2, 1, 2)**
2. **P2:** Need (0,4,3,0) $\leq$ (1,2,1,2) $\rightarrow$ False.
3. **P3:** Need (1,0,0,2) $\leq$ (1,2,1,2) $\rightarrow$ **True**.
   - Avail = (1,2,1,2) + (1,3,5,4) = **(2, 5, 6, 6)**
4. **P4:** Need (0,0,2,0) $\leq$ (2,5,6,6) $\rightarrow$ **True**.
   - Avail = (2,5,6,6) + (0,6,3,2) = **(2, 11, 9, 8)**
5. **P5:** Need (0,6,4,2) $\leq$ (2,11,9,8) $\rightarrow$ **True**.
   - Avail = (2,11,9,8) + (0,0,1,4) = **(2, 11, 10, 12)**
6. **P2 (Re-check):** Need (0,4,3,0) $\leq$ (2,11,10,12) $\rightarrow$ **True**.
   - Avail = (2,11,10,12) + (1,3,2,0) = **(3, 14, 12, 12)**

**Conclusion:** The pretend state is Safe. **Yes, the request can be granted immediately.**

### Quick Self-Check Key Points for Revision
- **Prevention:** Break one of the 4 conditions. Often results in terrible performance or impossible constraints.
- **Avoidance:** OS dynamically checks every request. Uses **Banker's Algorithm**.
- **Safe State:** There is at least one sequence to finish all processes without deadlocking. 
- **Banker's Need Matrix:** `Need = Max - Allocation`.
- **Banker's Safety Check:** Find a process where `Need <= Available`. "Execute" it by doing `Available = Available + Allocation`. Repeat until all processes are finished.
