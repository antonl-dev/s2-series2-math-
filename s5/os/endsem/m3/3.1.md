# 3.1 Concurrency: Threads, Single-threaded vs. Multithreaded Programming, and Thread API

---

## 1. What is a Thread?

In Module 2, we treated a **process** as a program in execution with a single point of control (one Program Counter). However, modern software requires a process to do multiple things at once. 

A **thread** is the basic unit of CPU utilization and execution. It is often called a **lightweight process**. 
Instead of having a single sequence of instructions, a multithreaded program has multiple points of execution happening concurrently inside the *same* process.

### Anatomy of a Thread
Every thread has its own **private state** so it can execute independently:
1. **Thread ID (TID):** A unique identifier for the thread.
2. **Program Counter (PC):** Keeps track of where *this specific thread* is in the instruction sequence.
3. **Register Set:** Private CPU registers for intermediate calculations.
4. **Stack:** A private stack to keep track of its own local variables and function calls.

However, all threads created within a process **share** the process's overall resources:
- **Code (Text) Section:** They all execute the same program code.
- **Data Section:** They all share global and static variables.
- **Heap:** They all share dynamically allocated memory.
- **OS Resources:** They share open file descriptors, network sockets, and signals.

---

## 2. Single-Threaded vs. Multithreaded Programming

### Single-Threaded Process
A traditional process has a single thread of control. 
- It has one Program Counter, one stack, and executes one instruction at a time.
- If a single-threaded web browser has to download a large image, the entire browser freezes and cannot respond to user clicks until the download finishes (because the single thread is blocked waiting for network I/O).

### Multithreaded Process
A multithreaded process contains several threads of control.
- It has **multiple Program Counters** and **multiple Stacks** (one for each thread).
- **Motivation / Benefits:**
  1. **Responsiveness:** A multithreaded web browser can use one thread to download an image in the background while another thread keeps the UI responsive to user clicks.
  2. **Resource Sharing:** Because threads share the same Code, Data, and Heap, it is much easier and more memory-efficient for them to communicate than using Inter-Process Communication (IPC) like shared memory or message passing.
  3. **Economy:** Creating a process is heavy and slow (requires allocating huge memory spaces). Creating a thread is extremely fast and "cheap" because the memory space already exists. Context switching between threads of the same process is also much faster than switching between different processes.
  4. **Scalability (Multiprocessor Architecture):** On a multi-core CPU, different threads of the *same* process can run in true parallel on different cores.

## 3. User-Level Threads vs. Kernel-Level Threads

Threads can be implemented at two different levels in the system: User space and Kernel space.

### 1. User-Level Threads (ULT)
- **Managed by:** A thread library operating entirely in **User Space** (e.g., POSIX Pthreads in older systems, Java threads).
- **OS Awareness:** The Operating System kernel is completely unaware that these threads exist. To the OS, it just looks like one normal single-threaded process.
- **Advantages:** 
  - **Extremely Fast:** Thread creation and context switching are done via local function calls in the user library. No system calls or Kernel Mode traps are required!
  - OS independent (can run on any OS that supports the library).
- **Disadvantages:**
  - **Blocking Problem:** If one user-level thread makes a blocking system call (like reading a file), the OS blocks the *entire process*, meaning all other threads in that process freeze as well.
  - Cannot utilize true parallelism on a multi-core CPU (since the OS only sees one process, it assigns it to a single core).

### 2. Kernel-Level Threads (KLT)
- **Managed by:** The Operating System itself. (Windows, Linux, and macOS all use KLTs today).
- **OS Awareness:** The kernel maintains a Thread Control Block (TCB) for every single thread in the system.
- **Advantages:**
  - **No Blocking Problem:** If one thread blocks on I/O, the kernel can simply schedule another thread from the exact same process to run.
  - **True Parallelism:** The kernel can schedule different threads from the same process on different physical CPU cores simultaneously.
- **Disadvantages:**
  - **Slower (Overhead):** Creating and managing threads requires system calls (trapping into Kernel Mode), making it slower than User-Level threads.

## 4. The Thread API (POSIX Pthreads)

To write a multithreaded program, programmers use a **Thread API**. The most common standard in UNIX/Linux systems is the **POSIX Threads (pthreads)** library.

### Key API Functions
1. **`pthread_create()`**: 
   - Equivalent to `fork()` for processes, but creates a thread.
   - It takes a function pointer as an argument. The new thread immediately begins executing that specific function.
2. **`pthread_join()`**: 
   - Equivalent to `wait()` for processes. 
   - It makes the calling thread (usually the main thread) pause and wait for the specified thread to finish executing before the program exits.
3. **`pthread_mutex_lock()` / `pthread_mutex_unlock()`**: 
   - Used for synchronization (preventing race conditions over shared data), which will be deeply covered in upcoming topics.

### Question 1
**Source:** *Internal Test – II, October 2026 (Q1a – 5 Marks, BL-2, CO3)*

**Question:**
*What is a thread? (1 mark) In what ways is a thread different from a process? (2 marks) Compare user-level threads with kernel-level threads. (2 marks)*

**Answer:**

**1. What is a thread? (1 Mark):**
A thread is the basic unit of CPU utilization and execution. It is a lightweight process that exists within a standard process, having its own Thread ID, Program Counter (PC), CPU register set, and Stack, while sharing the code, data, and OS resources with other threads of the same process.

**2. Differences between a Thread and a Process (2 Marks):**
| Feature | Process | Thread |
| :--- | :--- | :--- |
| **Definition** | A program in execution. It is a heavy-weight, independent entity. | A segment of a process. It is a light-weight, dependent entity. |
| **Memory Space** | Each process has its own isolated, private virtual address space. | Threads within the same process share the same memory space (Code, Data, Heap). |
| **Context Switching** | Very high overhead (must save/load heavy PCBs, flush CPU cache/TLB). | Low overhead (only need to save/load registers and stack pointers). |
| **Communication** | Requires slow Inter-Process Communication (IPC) like message passing. | Highly efficient; threads communicate directly by reading/writing shared memory variables. |

**3. Comparison of User-Level Threads (ULT) and Kernel-Level Threads (KLT) (2 Marks):**
| Feature | User-Level Threads (ULT) | Kernel-Level Threads (KLT) |
| :--- | :--- | :--- |
| **Management** | Managed entirely by a user-level library. OS kernel is unaware of them. | Managed directly by the Operating System kernel. |
| **Performance (Speed)** | Creation and context switching are **very fast** (no system calls required). | Slower (requires system calls and trapping into Kernel Mode). |
| **Blocking Behavior** | If one thread makes a blocking system call (e.g., I/O), the OS blocks the entire process (all threads halt). | If one thread blocks, the kernel can schedule another thread from the same process to run. |
| **Multiprocessing** | Cannot utilize multiple CPU cores simultaneously (OS sees only 1 process). | Can be scheduled across multiple CPU cores for true parallelism. |

### Quick Self-Check Key Points for Revision
- **Thread = Lightweight Process.** 
- **What is Shared?** Code (Text), Data (Globals), Heap, Files.
- **What is Private?** Registers, Program Counter (PC), Stack (Local vars).
- **Process vs Thread:** Process = Heavy, Private Memory, Slow Context Switch. Thread = Light, Shared Memory, Fast Context Switch.
- **ULT vs KLT:** ULT = OS doesn't know, super fast, but 1 block = all block. KLT = OS manages, true multi-core parallel, but slower to create (requires system calls).
