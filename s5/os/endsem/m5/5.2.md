# 5.2 File Access Methods and File Protection

---

## 1. File Access Methods

When a file is used, its information must be accessed and read into computer memory. Different applications need to access data in different ways. Over time, operating systems and file systems have developed several **Access Methods**.

### A. Sequential Access
This is the simplest and most common access method. Information in the file is processed **in order, one record (or byte) after the other**.
- **Mechanism:** The OS maintains a `current-file-position` pointer.
  - When a `read()` is called, the OS reads the next block of data and automatically advances the pointer.
  - When a `write()` is called, data is appended to the end of the file, and the pointer advances.
- **Use Cases:** Text editors, compilers, multimedia playback (watching a video from start to finish).
- **Analogy:** Listening to a cassette tape. You must listen to track 1 before you get to track 2, and you can rewind or fast-forward, but you are moving sequentially.

### B. Direct Access (Random Access)
In this method, a file is viewed as a numbered sequence of blocks or records. The program can read or write blocks rapidly in **no particular order**.
- **Mechanism:** The `read(n)` and `write(n)` operations explicitly state the block number $n$ to be accessed. The OS can instantly jump the disk head to block $n$.
- **Use Cases:** Databases. (If you want to read the banking record for Customer #5000, you do not want to sequentially read through the first 4999 customers. You calculate the byte offset and jump directly to block 5000).
- **Analogy:** Listening to a CD or MP3 player. You can instantly jump to track 7 without listening to tracks 1-6.

### C. Other Access Methods (Indexed Access)
Built on top of Direct Access, indexed methods use an **Index** (like the index at the back of a textbook) to find data.
- **Mechanism:** The index contains pointers to the various blocks. To find a record, the application first searches the Index, and then uses the pointer to directly access the file.
- **Use Case:** Massive databases where even direct calculation of block numbers is too complex, so a fast search tree (like a B-tree) is used as an index.

## 2. File Protection

When information is stored in a computer system, we want to keep it safe from physical damage (Reliability) and improper access (Protection).
- **Reliability:** Handled by making duplicate copies of files (Backups / RAID).
- **Protection:** Handled by controlling who can do what to a file. In a multi-user system, file protection is critical to prevent one user from reading or deleting another user's private data.

### Types of Access Operations to Protect
Protection mechanisms must be able to independently allow or deny specific operations on a file:
1. **Read:** Read from the file.
2. **Write:** Write or append to the file.
3. **Execute:** Load the file into memory and run it as a program.
4. **Append:** Write new information only at the end of the file.
5. **Delete:** Delete the file and free its space.
6. **List:** List the name and attributes of the file (usually applies to directories).

### File Protection Strategies

Operating systems use different strategies to implement file protection. The two most common strategies are **Access Control Lists (ACLs)** and **Passwords**.

#### Strategy 1: Passwords
- **How it works:** A password can be attached to a specific file or a directory. When a user attempts to access the file, they are prompted for the password. If it matches, access is granted.
- **Disadvantages:** 
  - Extremely cumbersome for users (remembering 100 different passwords for 100 different files is impossible).
  - If a password is leaked, anyone has full access.
  - It does not allow fine-grained control (e.g., User A can only read, User B can read and write).

#### Strategy 2: Access Control Lists (ACLs) - The Standard Approach
- **How it works:** The OS attaches a list to each file and directory. The list specifies exactly which users (or groups of users) are allowed access to the file, and specifically *what types* of access they have.
- **Implementation in UNIX/Linux (The 9-bit method):**
  Because maintaining a massive list of every user on the system takes up too much space, UNIX condenses the ACL into three classifications of users:
  1. **Owner:** The user who created the file.
  2. **Group:** A set of users who share the file and need similar access.
  3. **Universe (Others):** All other users in the system.
  
  For each classification, the OS maintains 3 bits: **Read (r), Write (w), and Execute (x)**.
  - Example output of `ls -l` in Linux: `-rwxr-xr--`
    - `rwx` (Owner): Can Read, Write, and Execute.
    - `r-x` (Group): Can Read and Execute, cannot Write.
    - `r--` (Others): Can only Read.
- **Advantages of ACLs:** Very flexible, fine-grained control, and highly space-efficient (the UNIX method only takes 9 bits of storage per file!).

## 3. Exam Questions & Answers (From Provided Question Papers)

### Question 1 (File Access Methods and Protection)
**Source:** *End Semester Examination – November 2025 (Module 5, Q9 – 8 Marks total, CO6)*

**Question:**
*a. Explain different access methods of a file. (4 marks)*
*b. Explain two common file protection strategies. (4 marks)*

**Answer:**

**Part a. Explain different access methods of a file (4 Marks):**
An access method dictates how the data inside a file is read or written. The two primary access methods are:

1. **Sequential Access (2 Marks):**
   This is the simplest and most widely used method. Information is processed strictly in order, one byte/record after the other. The OS maintains a logical pointer indicating the current position. Reads advance the pointer automatically, and writes append data to the end of the file. It is highly efficient for text files, compilers, and magnetic tapes, similar to fast-forwarding or rewinding an audio cassette.
2. **Direct (Random) Access (2 Marks):**
   In this method, the file is treated as a numbered sequence of fixed-size blocks. Programs can read or write to any block directly and rapidly, in no specific order. Operations like `read(n)` allow the disk head to jump directly to block $n$ without sequentially reading blocks $1$ to $n-1$. This method is absolutely essential for large databases, similar to skipping to a specific track on a CD.

**Part b. Explain two common file protection strategies (4 Marks):**
In a multi-user operating system, files must be protected from unauthorized access. The two common strategies are:

1. **Passwords (2 Marks):**
   A specific password can be attached to an individual file or directory. When a user requests access, the OS prompts for the password. While conceptually simple, it is highly impractical for large systems. Users cannot memorize hundreds of passwords for different files, and if one password is leaked, the file is completely compromised. It also lacks fine-grained control (it cannot easily grant User A 'read-only' access while giving User B 'write' access).
2. **Access Control Lists (ACLs) (2 Marks):**
   This is the most common and robust strategy. The OS associates a list with each file, specifying exactly which users have access and what type of access (Read, Write, Execute). 
   To save space, systems like UNIX condense this into three categories: **Owner, Group, and Others (Universe)**. For each category, the OS stores 3 bits (`rwx`), dictating read, write, and execute permissions. This strategy provides excellent, fine-grained, automated security without requiring users to memorize extra passwords.

### Quick Self-Check Key Points for Revision
- **Sequential Access:** Read in order (byte 1, byte 2...). Good for text files/media. Uses a current-file pointer.
- **Direct Access:** Jump directly to block $N$. Good for databases.
- **File Protection:** Controlling Read (r), Write (w), Execute (x) permissions.
- **Passwords:** Bad strategy. Hard to remember, no fine-grained control.
- **Access Control Lists (ACLs):** Good strategy. UNIX divides the world into 3 groups: **Owner, Group, Others**. Each gets an `rwx` permission setting.
