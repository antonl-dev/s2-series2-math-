# 5.4 Allocation Methods

---

## 1. Introduction: The Disk Allocation Problem

A major responsibility of the File System is managing space on the secondary storage device (the hard disk). Disks are divided into fixed-size physical blocks (e.g., 4 KB blocks).

When a user creates a new file, the OS must decide **which specific disk blocks to allocate to that file**. 
The method used to allocate these blocks drastically affects two things:
1. **Disk Space Utilization:** Does the method waste space (Internal or External Fragmentation)?
2. **Access Speed:** How fast can the OS read the file sequentially? How fast can it jump directly to a specific block (Random Access)?

There are three primary allocation methods used in operating systems:
1. **Contiguous Allocation**
2. **Linked Allocation**
3. **Indexed Allocation**

---

## 2. Contiguous Allocation

### How it Works
In contiguous allocation, a file is allocated a single contiguous set of blocks on the disk. 
- If a file needs 5 blocks, and it starts at block $b$, it will occupy blocks $b, b+1, b+2, b+3, b+4$.
- The directory entry for the file simply needs to store two numbers: the **starting block address** and the **length** of the file (number of blocks).

### Advantages
1. **Maximum Performance:** Reading the file is incredibly fast. The hard drive's magnetic head moves to the starting block and reads sequentially without ever having to move (seek) again.
2. **Great for Direct Access:** If a file starts at block 10, and you want to randomly access the 4th block of the file, the OS instantly calculates the physical block: $10 + 4 = 14$. 

### Disadvantages
1. **External Fragmentation:** Over time, as files are created and deleted, the disk becomes full of variable-sized "holes". Eventually, a user might try to save a 10-block file, but the OS cannot find 10 contiguous blocks together (even if there are 100 free blocks scattered around the disk).
2. **File Growth:** When a file is created, the OS must guess its final size. If a file is allocated 5 blocks, but later the user wants to add more text (making it 6 blocks), the file cannot grow if block $b+5$ is already taken by another file! The OS must find a larger hole, copy the entire file to the new location, and free the old blocks (very slow).

## 3. Linked Allocation

### How it Works
To solve the problems of contiguous allocation, linked allocation treats the file as a **Linked List** of disk blocks.
- The blocks can be scattered anywhere on the disk in any order.
- The directory entry only stores a pointer to the **First block** and the **Last block**.
- Each physical disk block contains a hidden pointer (a few bytes) that points to the physical address of the next block in the file.

### Advantages
1. **No External Fragmentation:** Any free block on the disk can be used. There is never a need to find contiguous blocks.
2. **Easy File Growth:** If a file needs to grow, the OS simply finds any free block anywhere on the disk, adds data to it, and updates the pointer in the old last block to point to the new block.

### Disadvantages
1. **Terrible for Direct (Random) Access:** If you want to read the 500th block of a file, you cannot calculate its location mathematically. You must start at block 1, read it to find the pointer to block 2, read block 2 to find the pointer to block 3... all the way to 500. This causes massive disk thrashing and is unacceptably slow.
2. **Space Overhead:** Every single disk block wastes a few bytes to store the pointer.
3. **Reliability:** If the pointer in block 3 gets corrupted by a hardware error, the OS loses block 4 and every subsequent block in the file forever.

*(Note: The FAT (File Allocation Table) system used in MS-DOS and older USB drives is a highly optimized variation of Linked Allocation).*

## 4. Indexed Allocation

### How it Works
Indexed allocation solves the problems of both contiguous (fragmentation) and linked (terrible direct access) methods.
- **The Concept:** It brings all the scattered pointers together into one specific block called the **Index Block**.
- Each file has its own Index Block. The index block is essentially an array of disk block addresses.
- The directory entry contains a pointer to the **Index Block**.
- When the OS wants the $i^{th}$ block of a file, it reads the Index Block, looks at the $i^{th}$ entry, and finds the exact physical block address.

### Advantages
1. **No External Fragmentation:** Blocks can be scattered anywhere on the disk.
2. **Excellent Direct (Random) Access:** To access the 500th block, the OS just looks at the 500th entry in the Index Block and jumps directly to that physical disk block. No traversing linked lists required.

### Disadvantages
1. **Space Overhead (Wasted Space):** For tiny files (e.g., a 10-byte text file), Contiguous allocation only uses 1 block. Linked uses 1 block. Indexed allocation requires **2 blocks**: one for the data, and one entire block just for the Index (which will be 99% empty).
2. **The Large File Problem:** What if a file is extremely large? If a disk block is 4KB, an index block can hold about 1024 pointers. If a file needs more than 1024 data blocks, a single Index Block is not big enough! 
   - *Solution (UNIX inodes):* Modern systems use a multi-level indexing scheme. The main inode contains 12 direct block pointers, 1 single-indirect pointer (points to an index block of pointers), 1 double-indirect pointer (points to an index block of index blocks), etc. This allows UNIX to support files that are terabytes in size.

## 5. Comparison Table of Allocation Methods

| Feature | Contiguous | Linked | Indexed |
| :--- | :--- | :--- | :--- |
| **Directory Entry** | Start Block & Length | First Block & Last Block | Pointer to Index Block |
| **External Fragmentation** | Yes (Severe) | No | No |
| **File Growth** | Difficult (May require copying) | Very Easy | Easy (Requires managing index blocks) |
| **Sequential Access Speed** | **Fastest** | Fast | Moderate |
| **Direct/Random Access** | Excellent (Mathematical calculation) | **Terrible** (Must read sequentially) | Excellent (Direct lookup in index) |
| **Best Used For** | CD-ROMs, simple media files | Small files accessed sequentially | General purpose modern file systems (UNIX/Linux) |

## 6. Exam Questions & Answers

> **Note on Provided Question Papers:** The exams for Module 5 focused on File Properties (5.1/5.2) and Hardware (5.5). However, Allocation Methods are heavily tested in theoretical OS exams. Below are expected standard questions for this topic.

### Expected Question 1 (Medium Answer – 6 Marks)
**Question:**
*Compare Contiguous Allocation and Linked Allocation methods for storing files on a disk. What are the advantages and disadvantages of each?*

**Answer:**
**Contiguous Allocation (3 Marks):**
In this method, a file occupies a set of contiguous physical blocks on the disk. The directory simply stores the starting block and length.
- **Advantages:** It provides the fastest sequential access (the disk head doesn't need to seek) and excellent direct/random access (block location is mathematically calculated).
- **Disadvantages:** It suffers from severe **external fragmentation** as disk holes form. Additionally, allowing a file to grow is very difficult; if the adjacent block is occupied, the entire file must be copied to a new, larger hole elsewhere on the disk.

**Linked Allocation (3 Marks):**
In this method, a file is a linked list of scattered disk blocks. The directory points to the first and last blocks, and each data block contains a pointer to the next block.
- **Advantages:** Completely eliminates external fragmentation (any free block anywhere can be used). File growth is trivially easy (just grab any free block and update the last pointer).
- **Disadvantages:** It is completely useless for **direct/random access**. To read the 100th block, the OS must physically read the first 99 blocks to follow the pointers, causing massive disk thrashing and slow performance.

---

### Expected Question 2 (Short Answer – 4 Marks)
**Question:**
*Explain how Indexed Allocation solves the direct-access problem of linked allocation. What is its main disadvantage?*

**Answer:**
**How Indexed Allocation Solves the Problem (3 Marks):**
Linked allocation fails at direct access because the pointers to the next blocks are scattered across the physical disk inside the data blocks themselves. Indexed allocation solves this by taking all those pointers and centralizing them into a single, dedicated disk block called the **Index Block**. 
When a program requests the 100th block of a file, the OS simply reads the file's Index Block, looks at the 100th array entry, and instantly retrieves the physical block address. It can then seek directly to that block, providing excellent direct-access performance without sequential traversal.

**Main Disadvantage (1 Mark):**
The primary disadvantage is **space overhead**. Even a very small file (e.g., 10 bytes) that only needs one data block will require an additional entire disk block just to serve as the Index Block, wasting physical storage. Additionally, managing extremely large files requires complex multi-level index schemes.

### Quick Self-Check Key Points for Revision
- **Contiguous:** All in a row. **Pro:** Super fast, great random access. **Con:** External Fragmentation, can't grow files easily.
- **Linked:** Scattered, connected by pointers inside the blocks. **Pro:** No fragmentation, easy to grow. **Con:** Terrible for random access (must traverse list).
- **Indexed:** Scattered, but pointers are stored in an **Index Block**. **Pro:** Great random access, no external fragmentation. **Con:** Wastes an entire block just for index pointers (bad for tiny files).
