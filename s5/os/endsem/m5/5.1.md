# 5.1 File Concept: Attributes, Operations, Types, and Structure

---

## 1. The File Concept

Computers store information on various storage media (Hard Disk Drives, Solid-State Drives, Magnetic Tapes). To make the computer system convenient to use, the Operating System abstracts away the physical properties of these storage devices and defines a uniform logical unit of information storage: the **File**.

- **Definition:** A file is a named collection of related information that is recorded on secondary storage. 
- From the user's perspective, a file is the smallest allotment of logical secondary storage; data cannot be written to secondary storage unless it is within a file.
- Files represent both programs (source code, executables) and data (text, images, databases).

---

## 2. File Attributes

To manage files, the OS maintains a set of **attributes** (metadata) for each file. This information is not the data inside the file itself, but data *about* the file. It is typically stored in the directory structure or an inode on the disk.

Common file attributes include:
1. **Name:** The symbolic file name (e.g., `report.pdf`) kept in human-readable form. (This is usually the only attribute in human-readable form).
2. **Identifier:** A unique tag (usually a number) that identifies the file within the file system (e.g., an inode number in UNIX). It is the non-human-readable name for the file.
3. **Type:** Needed for systems that support different types of files (e.g., `.txt`, `.exe`, `.jpg`).
4. **Location:** A pointer to a device and to the physical location (disk blocks/sectors) of the file on that device.
5. **Size:** The current size of the file (in bytes, words, or blocks) and possibly the maximum allowed size.
6. **Protection:** Access-control information determining who can do reading, writing, and executing (`rwx` permissions).
7. **Time, Date, and User Identification:** Data for creation time, last modification time, and last access time. Useful for protection, security, and usage monitoring (backups).

---

## 3. File Operations

The Operating System provides a set of system calls (APIs) to allow programs to perform basic operations on files. The six most fundamental operations are:

1. **Creating a file:** The OS allocates space in the file system and creates a new entry in the directory.
2. **Writing a file:** A system call is made specifying the file and the data. The OS must keep a **write pointer** to the location in the file where the next write is to take place. 
3. **Reading a file:** A system call specifies the file and where (in memory) the next block of data should be put. The OS maintains a **read pointer**. *(Most OSes combine the read and write pointers into a single **current-file-position pointer**).*
4. **Repositioning within a file (Seek):** The directory is searched for the appropriate entry, and the current-file-position pointer is repositioned to a given value (without reading or writing any data).
5. **Deleting a file:** The OS searches the directory for the named file, releases all disk space (blocks) allocated to it, and erases the directory entry.
6. **Truncating a file:** The user wants to erase the *contents* of a file but keep its attributes. The file size is reset to zero and the disk blocks are freed, but the file name and permissions remain.

### The `Open()` and `Close()` Operations
Because performing directory searches for every single read or write would be extremely slow, OSes require a file to be **opened** before it is used.
- **`open()`:** Searches the directory on disk once, extracts the file's attributes and physical location, and copies them into an **open-file table** in main memory (RAM). It returns a pointer/index (File Descriptor) to this table.
- **`close()`:** When the process finishes, the OS removes the entry from the in-memory open-file table to free up space.

## 4. File Types

Operating systems often recognize and support different file types. This is usually implemented by adding an **extension** to the file name. 

| File Type | Usual Extension | Function / Characteristics |
| :--- | :--- | :--- |
| **Executable** | `exe`, `com`, `bin` | Ready-to-run machine language programs. |
| **Object** | `obj`, `o` | Compiled machine language, not yet linked. |
| **Source Code** | `c`, `java`, `cpp` | Source code in various languages. |
| **Batch / Shell** | `bat`, `sh` | Commands given to the command interpreter. |
| **Text** | `txt`, `doc` | ASCII or Unicode textual data. |
| **Multimedia** | `mp4`, `jpg`, `mp3` | Binary data containing video, audio, or images. |
| **Archive** | `zip`, `tar` | Related files grouped together, often compressed. |

*How the OS uses types:* 
- In Windows, the OS relies heavily on the extension (e.g., if you double-click a `.docx`, the OS looks up the extension in the registry and launches Microsoft Word). 
- In UNIX/Linux, the OS mostly ignores extensions; it uses "Magic Numbers" (a specific byte pattern at the very beginning of the file) to determine the type.

## 5. File Structure

Files can be structured internally in several ways. The structure determines how the OS or the application reads the file.

1. **Unstructured (Byte Sequence):**
   - The file is just a massive, unformatted sequence of 8-bit bytes. 
   - The OS does not know or care what is inside the file. It is entirely up to the application program to interpret the bytes. 
   - *This is the structure used by UNIX, Linux, and Windows.* It provides maximum flexibility.

2. **Simple Record Structure:**
   - The file is a sequence of fixed-length records or variable-length records.
   - Example: A file might be a sequence of 80-byte lines (historically based on punched cards).

3. **Complex Structures:**
   - The file is organized as a formatted document, an indexed file, or a highly structured tree.
   - Example: An executable file has a very rigid, complex structure (headers, text segment, data segment, symbol table) that the OS loader must understand to run it.

### Expected Question 1 (Medium Answer – 6 Marks)
**Question:**
*Define a file in the context of an Operating System. List and briefly explain any five major attributes maintained by the OS for a file.*

**Answer:**
**Definition (1 Mark):**
A file is a named collection of related information that is recorded on non-volatile secondary storage. It provides a logical, uniform abstraction for data storage, hiding the physical complexities of disks and tapes from the user.

**Five Major Attributes (5 Marks):**
1. **Name:** The symbolic, human-readable name of the file (e.g., `document.txt`).
2. **Identifier (Inode):** A unique tag (usually an integer) generated by the file system to identify the file internally. It is not human-readable.
3. **Location:** A pointer to the specific device and the exact physical disk blocks/sectors where the file's data is stored.
4. **Size:** The current size of the file in bytes, words, or blocks.
5. **Protection:** Access-control data that determines which users can read, write, or execute the file.
*(Additional: Time/Date/User details for creation or last modification).*

---

### Expected Question 2 (Short Answer – 4 Marks)
**Question:**
*Why do operating systems require a process to `open()` a file before performing read or write operations on it? Explain the role of the open-file table.*

**Answer:**
Operating systems require the `open()` system call to improve performance and efficiency. Before a file can be read or written, the OS must locate its attributes and physical disk blocks by searching through the directory structure on the slow hard disk. Doing this search for every single `read()` or `write()` operation would cause massive performance degradation.

When `open()` is called, the OS searches the disk directory exactly once. It extracts the file's attributes and physical location information and copies it into a data structure in fast main memory (RAM) called the **open-file table**. The OS then gives the process an index/pointer (file descriptor) to this table. Subsequent read/write operations simply use this index to instantly access the file's details in RAM, completely bypassing slow disk directory searches.
