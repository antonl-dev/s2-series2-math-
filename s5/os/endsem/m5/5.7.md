# 5.7 Disk Formatting

---

## 1. Introduction: From Blank Platter to Usable Drive

When a brand-new magnetic hard disk drive comes off the factory assembly line, its platters are just blank sheets of magnetic recording material. The Operating System cannot immediately save files like `notes.txt` onto it.

Before a disk can store data, it must be prepared through a multi-step process called **Disk Formatting**. 

Disk formatting consists of three distinct stages:
1. **Low-Level Formatting (Physical Formatting)**
2. **Partitioning**
3. **High-Level Formatting (Logical Formatting)**

---

## 2. Stage 1: Low-Level Formatting (Physical Formatting)

- **When it happens:** Almost always performed at the **factory** before the disk is sold.
- **What it does:** It divides the blank disk platters into physical **sectors** that the disk controller can read and write. 
- **Structure of a Sector:** Low-level formatting fills the entire disk with a special data structure for every single sector. A sector typically consists of three parts:
  1. **Header:** Contains the sector number (so the hardware knows where it is).
  2. **Data Area:** The actual storage space (traditionally 512 bytes, now often 4096 bytes / 4 KB).
  3. **Trailer (ECC - Error-Correcting Code):** Mathematical checksum bits calculated from the data. 
     - *Purpose of ECC:* When the disk controller writes data to a sector, it computes the ECC and stores it in the trailer. When it reads the sector back, it recomputes the ECC. If they don't match, it means a bit got corrupted by magnetic decay or dust! The controller uses the ECC to detect and often *automatically repair* the corrupted bits.

---

## 3. Stage 2: Partitioning

After physical formatting, the disk is just a massive raw array of sectors. Before the OS can install a file system, it must record its own data structures on the disk. The first step in doing this is **Partitioning**.

- **What it does:** It logically divides the single physical disk into one or more groups of cylinders called **partitions** (or volumes).
- The Operating System treats each partition as if it were a completely separate, independent physical disk drive (e.g., `C:` drive and `D:` drive in Windows).
- **Why partition a drive?**
  1. **Dual-Booting:** You can install Windows on Partition 1 (using NTFS) and Linux on Partition 2 (using ext4) on the exact same physical hard drive.
  2. **System Organization & Safety:** Keeping the Operating System on one partition and user data on another makes it easy to wipe and reinstall the OS without deleting your personal files.
  3. **Swap Space:** An OS can dedicate a small, raw partition strictly for Virtual Memory swapping (avoiding the overhead of a file system).

- **Partition Table:** The boundaries (start and end sectors) of every partition are recorded in a special table stored at the very beginning of the disk—traditionally the **MBR (Master Boot Record)**, or the modern **GPT (GUID Partition Table)**.

---

## 4. Stage 3: High-Level Formatting (Logical Formatting)

Once the partitions are created, you still cannot save files to them until you perform **Logical Formatting** (this is what happens when you right-click a USB drive and select "Format").

- **What it does:** It creates a specific **File System** (such as NTFS, FAT32, APFS, or ext4) inside a specific partition.
- **Data Structures Created:** The OS writes the initial, empty file-system data structures onto the partition:
  - A **Boot Block** (if the partition will boot an OS).
  - A **Superblock / Volume Control Block** (stores metadata about the partition size and block size).
  - **Free-Space Management Tables** (bitmaps or free lists tracking which blocks are empty).
  - An initial empty **Root Directory** (`/` or `C:\`).

### Quick Format vs. Full Format
When a user formats a drive in an OS:
- **Quick Format:** Simply erases the old Root Directory and resets the Free-Space bitmap to "all free". It takes 2 seconds. *(Note: The actual data files are still sitting on the platters until overwritten, which is why data recovery software can restore quick-formatted drives).*
- **Full Format:** Does a quick format AND scans every single physical sector on the partition to check for **Bad Blocks** (physically damaged sectors) and marks them so the OS will never try to save data to them.

---

## 5. Bad-Block Management

Because disks have moving parts and microscopic tolerances, sectors occasionally become physically damaged and can no longer reliably store magnetic data. These are called **Bad Blocks**.

How does the OS/Controller handle them?
- **Sector Sparing (Forwarding):** During factory low-level formatting, the manufacturer sets aside a secret pool of "spare" physical sectors on the disk. When the disk controller notices a sector is consistently failing its ECC checks (going bad), the controller silently and automatically maps that logical sector address to one of the hidden **spare sectors**. The OS never even realizes a physical sector died!
- **Sector Slipping:** Re-mapping all sectors after the bad one down by one slot to maintain sequential reading speed (usually only done during factory formatting).

## 6. Exam Questions & Answers

> **Note on Provided Question Papers:** Disk Formatting is a minor capstone syllabus topic. No standalone questions appeared in the provided past papers, so below are the high-probability expected questions covering the essential theory.

### Expected Question 1 (Medium Answer – 5 Marks)
**Question:**
*Explain the three main steps required to prepare a brand-new physical hard disk to store files (Low-level formatting, Partitioning, and Logical formatting).*

**Answer:**
Before an Operating System can store user files on a blank hard disk, three distinct steps must be performed:

1. **Low-Level (Physical) Formatting (2 Marks):**
   Usually done at the factory, this step fills the blank disk platters with special hardware data structures to create physical **sectors**. Each sector consists of a header (sector ID), a data area (e.g., 512 bytes or 4KB), and a trailer containing an Error-Correcting Code (ECC) to detect and repair corrupted bits.
2. **Partitioning (1.5 Marks):**
   The OS divides the massive array of physical cylinders into one or more independent logical groups called **partitions** (e.g., C: and D: drives). The OS treats each partition as a separate disk. The layout of these partitions is stored in the MBR or GPT partition table.
3. **High-Level (Logical) Formatting (1.5 Marks):**
   This step creates a specific **file system** (like NTFS or ext4) inside a partition. The OS writes the initial empty file-system data structures onto the partition, including the superblock, free-space management bitmaps, and an initial empty root directory. Only after this step can users save files.

---

### Expected Question 2 (Short Answer – 3 Marks)
**Question:**
*What is an Error-Correcting Code (ECC) in the context of disk sectors, and how does Sector Sparing handle bad blocks?*

**Answer:**
- **ECC (1.5 Marks):** During low-level formatting, a trailer containing an Error-Correcting Code is added to every disk sector. When data is written, the controller calculates a mathematical checksum and stores it in the ECC. When data is read back, the ECC is recalculated. If they differ, the hardware detects data corruption and uses the ECC math to automatically fix minor bit errors.
- **Sector Sparing (1.5 Marks):** Hard disks eventually develop physically damaged sectors called "bad blocks." Disk controllers keep a hidden pool of spare sectors set aside from the factory. When a sector repeatedly fails ECC checks, the controller automatically remaps its logical address to a healthy spare sector, transparently hiding the hardware failure from the OS.

---

### Quick Self-Check Key Points for Revision
- **Low-Level Formatting:** Done at the factory. Creates Sectors (Header + Data + ECC Trailer).
- **ECC:** Detects and fixes corrupted data bits on the platter.
- **Partitioning:** Chops 1 physical disk into multiple logical drives (C:, D:). Stored in MBR/GPT.
- **High-Level (Logical) Formatting:** Installs the File System (NTFS, ext4). Creates the empty Root Directory and Free-Space maps.
- **Bad Blocks:** Physically damaged sectors. Fixed automatically by the controller via **Sector Sparing** (swapping it with a hidden spare sector).
