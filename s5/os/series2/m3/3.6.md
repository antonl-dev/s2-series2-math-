# 3.6 Deadlock Prevention and Deadlock Avoidance

## 1. Deadlock Prevention
Deadlock prevention provides a set of methods to ensure that at least one of the four necessary conditions (Mutual Exclusion, Hold and Wait, No Preemption, Circular Wait) **cannot** hold. By preventing just one, deadlocks are impossible.

### Strategies to break the 4 Conditions:
1.  **Breaking Mutual Exclusion:**
    *   Not always possible since some resources (like a mutex lock or a physical printer) are inherently non-sharable. However, for devices like printers, we can use *Spooling* (where processes write to a sharable queue rather than the printer directly).
2.  **Breaking Hold and Wait:**
    *   **Protocol 1:** Require each process to request and be allocated *all* its resources before it begins execution.
    *   **Protocol 2:** Allow a process to request resources only when it has none. Before it can request additional resources, it must release all the resources it currently holds.
    *   *Disadvantages:* Low resource utilization and high chance of starvation.
3.  **Breaking No Preemption:**
    *   If a process holding some resources requests another resource that cannot be immediately allocated to it, then all resources currently held by this process are *preempted* (released). The process will be restarted only when it can regain its old resources plus the new ones.
4.  **Breaking Circular Wait:**
    *   This is the most practical prevention method. We assign a unique integer number to each resource type (e.g., $R_1 = 1$, $R_2 = 2$). 
    *   **Rule:** A process must request resources in an strictly increasing order of enumeration. If it holds $R_1$, it can request $R_2$, but it cannot request $R_1$ if it already holds $R_2$. This physically makes a circular cycle impossible.

## 2. Deadlock Avoidance
Instead of restricting how requests are made, **Deadlock Avoidance** requires that the OS be given additional information in advance about which resources a process will request and use during its lifetime. 

With this a priori knowledge, the OS can decide for each request whether or not the process should wait. The OS only grants requests that keep the system in a **Safe State**.

### Safe State
A state is safe if the system can allocate resources to each process (up to its maximum need) in some order and still avoid a deadlock. This order is called a **Safe Sequence** $<P_1, P_2, ..., P_n>$.
*   If a system is in a safe state $\rightarrow$ NO deadlocks.
*   If a system is in an unsafe state $\rightarrow$ Possibility of deadlock.
*   *Avoidance ensures that a system will never enter an unsafe state.*

---

## 3. Avoidance Algorithms

### A. Resource-Allocation Graph (RAG) Algorithm
*   Used only when there is a **single instance** of each resource type.
*   In addition to request and assignment edges, we introduce a **claim edge** ($P_i \dashrightarrow R_j$), which indicates that process $P_i$ *may* request resource $R_j$ in the future.
*   When a process requests a resource, the claim edge converts to a request edge. When granted, it converts to an assignment edge.
*   **The Algorithm:** A request can be granted only if converting the request edge to an assignment edge does not result in the formation of a cycle in the RAG. If no cycle exists, the state is safe.

### B. Banker's Algorithm
*   Used when there are **multiple instances** of each resource type.
*   When a new process enters, it must declare the maximum number of instances of each resource it may need.
*   When a process requests resources, the system checks if granting them leaves the system in a safe state. If yes, the resources are allocated; if no, the process must wait.

**Data Structures for Banker's Algorithm:** Let $n$ = number of processes, $m$ = number of resource types.
*   **Available:** Vector of length $m$. Indicates how many instances of each resource are currently available.
*   **Max:** $n \times m$ matrix. Defines maximum demand of each process.
*   **Allocation:** $n \times m$ matrix. Defines number of resources currently allocated to each process.
*   **Need:** $n \times m$ matrix. Indicates the remaining resources needed. 
    `Need[i][j] = Max[i][j] - Allocation[i][j]`

### Q1. A system has four processes P1-P4 and four resources R1-R4, each with a single instance. At time t1, R1 is held by P2, waiting for R2. R2 is held by P3, waiting for R3. R3 is held by P4. P1, P2 and P4 may request R4 in the future. At time t2, P4 requests R4. Using the Resource-Allocation Graph algorithm, decide whether this request can be granted immediately. Justify your answer. (Question 12)
**Answer:**
1.  **Analyze the initial state (t1):**
    *   Assignment edges: $R_1 \rightarrow P_2$, $R_2 \rightarrow P_3$, $R_3 \rightarrow P_4$.
    *   Request edges: $P_2 \rightarrow R_2$, $P_3 \rightarrow R_3$.
    *   Claim edges: $P_1 \dashrightarrow R_4$, $P_2 \dashrightarrow R_4$, $P_4 \dashrightarrow R_4$.
2.  **Analyze the request (t2):**
    *   $P_4$ requests $R_4$. The claim edge $P_4 \dashrightarrow R_4$ converts to a request edge $P_4 \rightarrow R_4$.
3.  **Simulate Granting the Request:**
    *   If we grant the request, the edge becomes an assignment edge: $R_4 \rightarrow P_4$.
4.  **Check for Cycles:**
    *   Looking at the graph with $R_4 \rightarrow P_4$ added, we trace the paths.
    *   $P_2$ is waiting for $P_3$ (via $R_2$), $P_3$ is waiting for $P_4$ (via $R_3$). $P_4$ holds $R_3$ and $R_4$. $P_4$ is NOT waiting for any resource. 
    *   Since $P_4$ is not waiting, the chain terminates at $P_4$. No circular wait (cycle) is formed even when considering the remaining claim edges ($P_1 \dashrightarrow R_4$, $P_2 \dashrightarrow R_4$). 
5.  **Conclusion:**
    *   **Yes**, the request can be granted immediately because granting it does not result in a cycle in the Resource-Allocation Graph, meaning the system remains in a safe state.

### Q2. A system has five processes P0–P4 and four resource types A, B, C, D. Its current state is shown. Using Banker's algorithm: (i) Total instances? (ii) Compute Need matrix. (iii) Is system safe? Give safe sequence. (Question 13)

**Data given:**
*   **Max:** P0(6,0,1,3), P1(2,7,5,0), P2(2,3,5,6), P3(1,6,5,3), P4(1,6,5,6)
*   **Alloc:** P0(4,0,0,1), P1(1,1,0,0), P2(1,2,5,4), P3(0,6,3,3), P4(0,2,1,2)
*   **Available:** A=3, B=2, C=2, D=1

**Answer:**
**i) Total number of instances of each resource:**
Total = Sum of Allocated + Available
*   A = (4+1+1+0+0) + 3 = 6 + 3 = **9**
*   B = (0+1+2+6+2) + 2 = 11 + 2 = **13**
*   C = (0+0+5+3+1) + 2 = 9 + 2 = **11**
*   D = (1+0+4+3+2) + 1 = 10 + 1 = **11**

**ii) Compute the Need Matrix (Need = Max - Allocation):**
*   P0 = (6,0,1,3) - (4,0,0,1) = **(2, 0, 1, 2)**
*   P1 = (2,7,5,0) - (1,1,0,0) = **(1, 6, 5, 0)**
*   P2 = (2,3,5,6) - (1,2,5,4) = **(1, 1, 0, 2)**
*   P3 = (1,6,5,3) - (0,6,3,3) = **(1, 0, 2, 0)**
*   P4 = (1,6,5,6) - (0,2,1,2) = **(1, 4, 4, 4)**

**iii) Is the system in a safe state?**
We use the Safety Algorithm. Initial Work = Available = (3, 2, 2, 1). Finish = [false, false, false, false, false].
1.  Check P0: Need(2,0,1,2) $\le$ Work(3,2,2,1)? No (D is 2 > 1).
2.  Check P1: Need(1,6,5,0) $\le$ Work(3,2,2,1)? No.
3.  Check P2: Need(1,1,0,2) $\le$ Work(3,2,2,1)? No.
4.  Check P3: Need(1,0,2,0) $\le$ Work(3,2,2,1)? **Yes**.
    *   Execute P3. New Work = Work + Alloc_P3 = (3,2,2,1) + (0,6,3,3) = **(3, 8, 5, 4)**. Finish[3] = true.
5.  Check P4: Need(1,4,4,4) $\le$ Work(3,8,5,4)? **Yes**.
    *   Execute P4. New Work = (3,8,5,4) + (0,2,1,2) = **(3, 10, 6, 6)**. Finish[4] = true.
6.  Re-check P0: Need(2,0,1,2) $\le$ Work(3,10,6,6)? **Yes**.
    *   Execute P0. New Work = (3,10,6,6) + (4,0,0,1) = **(7, 10, 6, 7)**. Finish[0] = true.
7.  Re-check P1: Need(1,6,5,0) $\le$ Work(7,10,6,7)? **Yes**.
    *   Execute P1. New Work = (7,10,6,7) + (1,1,0,0) = **(8, 11, 6, 7)**. Finish[1] = true.
8.  Re-check P2: Need(1,1,0,2) $\le$ Work(8,11,6,7)? **Yes**.
    *   Execute P2. New Work = (8,11,6,7) + (1,2,5,4) = **(9, 13, 11, 11)**. Finish[2] = true.

Since all processes finished, **Yes, the system is in a safe state.**
A safe sequence is: **<P3, P4, P0, P1, P2>**

### Q3. A system has five processes P1–P5 and four resource types A, B, C, D. Its current state is shown. (Question 14)

**Data given:**
*   **Max:** P1(0,0,1,2), P2(1,6,5,0), P3(2,3,5,6), P4(0,6,5,2), P5(0,6,5,6)
*   **Alloc:** P1(0,0,1,2), P2(1,0,0,0), P3(1,3,5,4), P4(0,6,3,2), P5(0,0,1,4)
*   **Avail:** A=1, B=5, C=3, D=0

**i) Compute the Need matrix (Max - Alloc).**
**Answer:**
*   P1: (0,0,1,2) - (0,0,1,2) = **(0, 0, 0, 0)**
*   P2: (1,6,5,0) - (1,0,0,0) = **(0, 6, 5, 0)**
*   P3: (2,3,5,6) - (1,3,5,4) = **(1, 0, 0, 2)**
*   P4: (0,6,5,2) - (0,6,3,2) = **(0, 0, 2, 0)**
*   P5: (0,6,5,6) - (0,0,1,4) = **(0, 6, 4, 2)**

**ii) Is the system in a safe state? If so, give a safe sequence.**
**Answer:**
Work = Avail = (1, 5, 3, 0).
1.  P1 Need(0,0,0,0) $\le$ (1,5,3,0)? **Yes**. Work = (1,5,3,0) + (0,0,1,2) = **(1, 5, 4, 2)**.
2.  P2 Need(0,6,5,0) $\le$ (1,5,4,2)? No (B is 6 > 5).
3.  P3 Need(1,0,0,2) $\le$ (1,5,4,2)? **Yes**. Work = (1,5,4,2) + (1,3,5,4) = **(2, 8, 9, 6)**.
4.  P4 Need(0,0,2,0) $\le$ (2,8,9,6)? **Yes**. Work = (2,8,9,6) + (0,6,3,2) = **(2, 14, 12, 8)**.
5.  P5 Need(0,6,4,2) $\le$ (2,14,12,8)? **Yes**. Work = (2,14,12,8) + (0,0,1,4) = **(2, 14, 13, 12)**.
6.  P2 Need(0,6,5,0) $\le$ (2,14,13,12)? **Yes**. Work = (2,14,13,12) + (1,0,0,0) = **(3, 14, 13, 12)**.
All finished. **Yes, it is safe.** Sequence: **<P1, P3, P4, P5, P2>**.

**iii) P2 now requests (0, 3, 2, 0). Can this request be granted immediately? Justify.**
**Answer:**
**Step 1: Check conditions:**
*   Request $\le$ Need? $(0,3,2,0) \le (0,6,5,0)$. True.
*   Request $\le$ Available? $(0,3,2,0) \le (1,5,3,0)$. True.

**Step 2: Pretend to allocate and update states:**
*   New Available = (1,5,3,0) - (0,3,2,0) = **(1, 2, 1, 0)**
*   New Alloc P2 = (1,0,0,0) + (0,3,2,0) = **(1, 3, 2, 0)**
*   New Need P2 = (0,6,5,0) - (0,3,2,0) = **(0, 3, 3, 0)**

**Step 3: Run Safety Algorithm with new states:**
Initial Work = (1, 2, 1, 0).
1.  P1 Need(0,0,0,0) $\le$ (1,2,1,0)? **Yes**. Work = (1,2,1,0) + (0,0,1,2) = **(1, 2, 2, 2)**.
2.  P2 Need(0,3,3,0) $\le$ (1,2,2,2)? No.
3.  P3 Need(1,0,0,2) $\le$ (1,2,2,2)? **Yes**. Work = (1,2,2,2) + (1,3,5,4) = **(2, 5, 7, 6)**.
4.  P2 Need(0,3,3,0) $\le$ (2,5,7,6)? **Yes**. Work = (2,5,7,6) + (1,3,2,0) = **(3, 8, 9, 6)**.
5.  P4 Need(0,0,2,0) $\le$ (3,8,9,6)? **Yes**. Work = (3,8,9,6) + (0,6,3,2) = **(3, 14, 12, 8)**.
6.  P5 Need(0,6,4,2) $\le$ (3,14,12,8)? **Yes**. Work = (3,14,12,8) + (0,0,1,4) = **(3, 14, 13, 12)**.
Since the system remains in a safe state, **Yes, the request can be granted immediately.**
