# 4.4 Paging and the Translation Look-aside Buffer (TLB)

## 1. Introduction to Paging
As we saw in the previous section, **Segmentation** divides memory into variable-sized pieces, which inevitably leads to **External Fragmentation**. To solve this, Operating Systems use a different approach called **Paging**. 

Instead of dividing the process address space into variable-sized logical segments, Paging divides both the logical address space and the physical memory into **fixed-sized blocks**.
*   **Pages:** The logical address space of a process is divided into fixed-size blocks called *Pages*.
*   **Frames:** The physical memory (RAM) is divided into fixed-size blocks called *Frames*.
*   *Crucial Rule:* **Page Size = Frame Size**. (Usually between 4 KB and 8 KB).

Because pages and frames are the exact same size, any logical page can be placed into any available physical frame. This completely eliminates external fragmentation.

---

## 2. Paging Address Translation
When the CPU generates a logical address, it is divided by the hardware into two parts:
1.  **Page Number ($p$):** Used as an index into a **Page Table**. The page table contains the base address (Frame Number) of each page in physical memory.
2.  **Page Offset ($d$):** The specific byte location within that page/frame. Because the page size equals the frame size, the offset remains exactly the same in both the logical and physical address.

### The Translation Process:
1.  The CPU generates a logical address and extracts $p$ and $d$.
2.  The hardware uses $p$ to look up the corresponding Frame Number ($f$) in the Page Table.
3.  The physical address is constructed by combining $f$ and $d$ (Physical Address = $f \times \text{Frame Size} + d$).

**Fragmentation in Paging:**
*   Paging has **NO External Fragmentation** because any empty frame can be used.
*   Paging **DOES suffer from Internal Fragmentation**. If a process requires 72 KB of memory and the page size is 4 KB, it needs 18 pages. But if it requires 73 KB, it needs 19 pages. The 19th page is allocated, but only 1 KB is used, leaving 3 KB wasted *inside* the allocated frame.

## 3. The Translation Look-aside Buffer (TLB)
While paging is excellent for managing memory, it introduces a severe performance problem. 
The Page Table itself is usually very large and is stored in physical memory (RAM). Therefore, to access a single byte of data, the CPU must perform **two memory accesses**:
1.  One access to read the Page Table (to get the frame number).
2.  One access to read the actual data using the constructed physical address.
*Since memory access is slow compared to CPU speeds, this effectively halves the computer's speed.*

To solve this, the Memory Management Unit (MMU) uses a specialized, high-speed hardware cache called the **Translation Look-aside Buffer (TLB)**.
*   The TLB stores a small number of the most recently used Page-to-Frame translations (typically 64 to 1024 entries).
*   **TLB Hit:** When the CPU generates a logical address, the MMU first checks the TLB. If the page number is found, the frame number is retrieved almost instantly, and the memory access proceeds quickly.
*   **TLB Miss:** If the page number is not in the TLB, the MMU must read the Page Table in RAM, do the translation, and then load this new translation into the TLB for future use.

### Q1. a. Explain paging with a neat diagram. (Question 20a)
**Answer:**
**Paging** is a memory management scheme that eliminates the need for contiguous allocation of physical memory, thereby solving the problem of external fragmentation. 
In paging, the physical memory is divided into fixed-size blocks called **frames**, and the logical memory (address space of a process) is divided into blocks of the exact same size called **pages**. When a process is to be executed, its pages are loaded into any available memory frames from their source (e.g., a file system or backing store).

The hardware translates logical addresses to physical addresses using a **Page Table**. 
*   A logical address consists of two parts: a Page Number ($p$) and a Page Offset ($d$).
*   The Page Number ($p$) is used as an index into the Page Table to find the corresponding Frame Number ($f$).
*   The physical address is formed by appending the identical Offset ($d$) to the base address of the Frame ($f$).

### Q2. b. Using a diagram, explain how a Translation Look-aside Buffer (TLB) improves the performance of a paging system. (Question 20b)
**Answer:**
**The Problem:** In standard paging, every memory access requires two trips to physical RAM: one to access the page table to get the translation, and a second to access the actual data. This drastically slows down the CPU.

**The Solution:** The TLB (Translation Look-aside Buffer) is a small, ultra-fast associative cache memory built directly into the CPU's MMU. It stores recently used Page-to-Frame mappings.
When a logical address is generated:
1.  The MMU first checks the TLB for the page number ($p$).
2.  **TLB Hit:** If the page is in the TLB, the frame number is retrieved immediately at hardware speed. The CPU accesses physical memory once.
3.  **TLB Miss:** If the page is not in the TLB, the MMU accesses the page table in RAM, retrieves the frame number, updates the TLB with this new mapping, and then accesses the data. 

Because programs exhibit *locality of reference* (they tend to access the same memory areas repeatedly), the TLB hit rate is typically very high (e.g., 99%). This means the vast majority of memory accesses avoid the double-memory-penalty, vastly improving overall system performance.

*(Self-Draw Diagram Description for Exam)*: 
Draw the CPU outputting `[ p | d ]`. Draw an arrow from `p` into a box labeled "TLB". 
*   Path 1 (Hit): An arrow goes directly from the TLB combining with `d` to form the Physical Address.
*   Path 2 (Miss): An arrow goes from the TLB down to the "Page Table" in RAM, retrieves `f`, updates the TLB, and then forms the Physical Address.

### Q3. c. A logical address space has 128 pages of 2048 words each, mapped onto a physical memory of 32 frames. How many bits are needed for (i) the logical address and (ii) the physical address? (Question 20c)
**Answer:**
**Given Data:**
*   Page size = Frame size = $2048$ words. 
*   $2048 = 2^{11}$. Therefore, the **Offset ($d$) requires 11 bits**.
*   Number of Pages in logical address space = $128$.
*   $128 = 2^7$. Therefore, the **Page Number ($p$) requires 7 bits**.
*   Number of Frames in physical memory = $32$.
*   $32 = 2^5$. Therefore, the **Frame Number ($f$) requires 5 bits**.

**(i) Bits needed for Logical Address:**
*   Logical Address = Page Number bits ($p$) + Offset bits ($d$)
*   Logical Address = $7 + 11 = $ **18 bits**.

**(ii) Bits needed for Physical Address:**
*   Physical Address = Frame Number bits ($f$) + Offset bits ($d$)
*   Physical Address = $5 + 11 = $ **16 bits**.
