## **Question 1**
**1. a) Define critical section? State and explain the conditions to be satisfied by a solution to the critical section problem. [4 Marks]**
**Answer:**
*   **Definition:** A critical section is a segment of code within a process where the process accesses and modifies shared resources (like common variables, tables, or files). When one process is executing in its critical section, no other process is allowed to execute in its critical section simultaneously to prevent data inconsistency (race conditions).
*   **Conditions:** Any solution must satisfy these three requirements:
    1.  **Mutual Exclusion:** If process $P_i$ is executing in its critical section, then no other processes can be executing in their critical sections.
    2.  **Progress:** If no process is executing in its critical section and some wish to enter, only those processes *not* in their remainder sections can participate in deciding who goes next. This decision cannot be postponed indefinitely.
    3.  **Bounded Waiting:** There must be a strict limit on the number of times other processes are allowed to enter their critical sections after a process has made a request to enter, ensuring no process starves waiting.

**1. b) Explain the concept of a semaphore and describe how semaphores can be used as a process synchronization mechanism. [6 Marks]**
**Answer:**
*   **Concept:** A semaphore is a robust synchronization tool provided by the OS. It is an integer variable (`S`) that, apart from initialization, is accessed only through two standard, indivisible (atomic) operations: `wait()` and `signal()`.
    *   `wait(S)`: Decrements the value. If $S \le 0$, the process blocks/waits until $S > 0$.
    *   `signal(S)`: Increments the value, potentially waking up a waiting process.
*   **How it is used for synchronization:**
    1.  **Mutual Exclusion (Binary Semaphore):** Initialized to 1. Before entering the critical section, a process calls `wait(mutex)` (making it 0, locking out others). When it finishes, it calls `signal(mutex)` (making it 1, letting the next process in).
    2.  **Order of Execution:** If process $P_2$ must wait for $P_1$ to finish task A before $P_2$ can start task B, initialize a semaphore `sync` to 0. $P_1$ executes task A, then calls `signal(sync)`. $P_2$ calls `wait(sync)` before starting task B. $P_2$ is forced to wait until $P_1$ signals.

## **Question 2**
**2. a) Consider a scenario where two threads are pushing and popping items from a shared stack at the same time. How can Peterson's algorithm help avoid conflicts? [5 Marks]**
**Answer:**
If Thread $T_0$ (Push) and Thread $T_1$ (Pop) access the shared stack top concurrently, a race condition occurs, potentially corrupting the stack structure or losing data. 
Peterson's algorithm is a software-based solution that can protect the stack operations (the critical section) for these two threads. It uses two shared variables:
*   `boolean flag[2] = {false, false};` (Indicates if a thread wants to access the stack)
*   `int turn;` (Indicates whose turn it is to access the stack)

**Implementation for Thread 0 (Push):**
```c
flag[0] = true;         // T0 declares intent to use the stack
turn = 1;               // T0 graciously offers the turn to T1
while (flag[1] && turn == 1); // T0 waits if T1 wants to use it and it's T1's turn

// CRITICAL SECTION: Perform Stack Push operations safely here

flag[0] = false;        // T0 leaves, stack is free
```
**How it avoids conflicts:**
*   **Mutual Exclusion:** Both threads cannot be in the critical section simultaneously. Even if both set their flags to `true` at the exact same time, the `turn` variable can only hold one value (either 0 or 1). The thread that overwrites `turn` last will be forced to wait in the `while` loop, allowing the other thread to access the stack exclusively.

**2. b) Compare process and thread. [3 Marks]**
**Answer:**
| Process | Thread |
| :--- | :--- |
| Heavyweight unit of execution. | Lightweight unit of execution. |
| Requires separate memory space and resources. | Shares memory space and resources with sibling threads. |
| Context switching is slow and expensive. | Context switching is faster (less state to save/load). |

**2. c) Describe resource allocation graph. [2 Marks]**
**Answer:**
A Resource Allocation Graph (RAG) is a directed graph used to model system deadlocks. It consists of two types of vertices: Processes (circles) and Resources (squares with dots for instances). It has two types of edges:
*   **Request Edge ($P_i \rightarrow R_j$):** Process $P_i$ is requesting resource $R_j$.
*   **Assignment Edge ($R_j \rightarrow P_i$):** An instance of resource $R_j$ is allocated to process $P_i$.
A cycle in this graph indicates a potential (or certain) deadlock.

## **Question 3**
**3. a) Differentiate logical and physical address space. [2 Marks]**
**Answer:**
*   **Logical Address Space:** The set of all virtual addresses generated by the CPU for a running program. It is the program's *view* of memory, starting from address 0.
*   **Physical Address Space:** The set of all actual, physical memory addresses corresponding to the logical addresses in the hardware (RAM). The OS maps logical addresses to physical addresses dynamically.

## **Question 4**
**4. a) Describe the working of dynamic relocation with the help of base and bounds registers. [4 Marks]**
**Answer:**
Dynamic relocation is a hardware mechanism in the MMU that translates logical addresses to physical ones on the fly, allowing programs to be loaded anywhere in memory. 
It uses two registers per process:
1.  **Base Register:** Holds the starting physical address where the process is loaded.
2.  **Bounds (Limit) Register:** Holds the size of the logical address space for protection.
*Working:* When the CPU generates a logical address, the hardware first checks if `Logical Address < Bounds Register`. If it is greater, an illegal memory trap is generated. If it is valid, the hardware calculates `Physical Address = Logical Address + Base Register`.

## **Question 5**
**5. a) Consider a logical address space of 256 pages with a 4-KB page size, mapped onto a physical memory of 64 frames. Find the (i) number of bits in the logical address (ii) number of bits in the physical address. [2 Marks]**
**Answer:**
**Given:**
*   Page size = Frame size = $4\text{ KB} = 4 \times 1024\text{ bytes} = 4096\text{ bytes}$.
*   Since $4096 = 2^{12}$, the **Offset requires 12 bits**.
*   Number of Pages = 256. Since $256 = 2^8$, the **Page Number requires 8 bits**.
*   Number of Frames = 64. Since $64 = 2^6$, the **Frame Number requires 6 bits**.

**(i) Bits in Logical Address:**
Logical Address = Page bits + Offset bits = $8 + 12 = $ **20 bits**.

**(ii) Bits in Physical Address:**
Physical Address = Frame bits + Offset bits = $6 + 12 = $ **18 bits**.

**5. b) Explain the conditions that lead to deadlock. [4 Marks]**
**Answer:**
A deadlock occurs if and only if all four Coffman conditions hold simultaneously:
1.  **Mutual Exclusion:** At least one resource is non-sharable; only one process can use it at a time.
2.  **Hold and Wait:** A process is holding at least one resource and is waiting to acquire additional resources held by others.
3.  **No Preemption:** Resources cannot be forcibly taken away; they must be released voluntarily by the process holding them.
4.  **Circular Wait:** There exists a circular chain of processes, where each process is waiting for a resource held by the next process in the chain.

**5. c) Discuss the commonly used methods of free space management in operating systems. [4 Marks]**
**Answer:**
1.  **Bitmaps (Bit Vectors):** Memory is divided into fixed-size blocks. A string of bits is maintained where each bit represents a block (e.g., `0` for free, `1` for allocated). It is simple and has a predictable size, but finding a contiguous run of free blocks can be slow.
2.  **Linked Lists:** The OS maintains a linked list of nodes, where each node represents a free hole or an allocated segment. It tracks the start address and size. It makes it easier to allocate memory using First/Best Fit and allows merging of adjacent free blocks, but involves list maintenance overhead.
