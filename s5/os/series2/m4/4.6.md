# 4.6 Page Replacement and Memory Allocation Algorithms

## 1. Page Replacement Algorithms
When a page fault occurs and the physical memory (RAM) is completely full, the Operating System must choose a page currently in memory, swap it out to the disk, and swap the new page in. The algorithm used to select this "victim" page is the **Page Replacement Algorithm**. 

The main goal of these algorithms is to **minimize the number of page faults**.

### A. FIFO (First-In, First-Out)
*   **Logic:** Replaces the oldest page in memory. The OS maintains a queue; when a page comes in, it goes to the back of the queue. The page at the front (the oldest) is chosen as the victim.
*   **Pros:** Very simple to implement.
*   **Cons:** Performance is not always good. It might replace a page that is heavily used just because it was brought in a long time ago.
*   **Belady’s Anomaly:** Usually, giving a system more physical frames reduces page faults. However, with the FIFO algorithm, there are specific reference strings where **increasing the number of frames actually *increases* the number of page faults**. This counter-intuitive behavior is called Belady's Anomaly.

### B. Optimal Page Replacement (OPT / MIN)
*   **Logic:** Replaces the page that will not be used for the **longest period of time in the future**. 
*   **Pros:** Guarantees the lowest possible page-fault rate for a fixed number of frames. Never suffers from Belady's Anomaly.
*   **Cons:** It is impossible to implement in a real operating system because it requires the OS to predict the future (know the upcoming reference string). It is mainly used as a theoretical benchmark to compare other algorithms against.

### C. LRU (Least Recently Used)
*   **Logic:** An approximation of the Optimal algorithm. Instead of looking at the future, it looks at the past. It replaces the page that has not been used for the **longest period of time**.
*   **Pros:** Performs very well in practice because of *locality of reference* (pages used recently will likely be used again soon). Does not suffer from Belady's anomaly.
*   **Cons:** Requires hardware assistance (like counters or a stack) to track exactly when every page was last accessed, which adds overhead.

## 2. Memory Allocation Algorithms (Fixed Partitioning)
Before paging was invented, memory was divided into partitions. If these partitions are fixed in size by the OS at boot time, it is called **Fixed Partitioning**. 

When a process arrives, the OS must allocate it to an available partition that is large enough. The algorithms used to choose the partition are:

1.  **First Fit:**
    *   Allocates the **first** available partition that is large enough.
    *   *Pros:* Very fast since it doesn't need to search the whole list.
2.  **Best Fit:**
    *   Allocates the **smallest** available partition that is large enough.
    *   *Pros:* Minimizes wasted space inside the partition (Internal Fragmentation).
    *   *Cons:* Slower (must search entire list). Leaves tiny, useless leftover holes.
3.  **Worst Fit:**
    *   Allocates the **largest** available partition.
    *   *Pros:* The leftover space is large and might be usable for another process.
    *   *Cons:* Very wasteful for large partitions. Often performs the worst of the three.

### Fragmentation Definitions
*   **Internal Fragmentation:** The wasted memory *inside* an allocated partition. (e.g., Putting a 130K process in a 160K partition causes 30K of internal fragmentation).
*   **External Fragmentation:** The total memory space that is free and available, but cannot be used because it is not contiguous (split across multiple small holes).

### Q1. Consider the page reference string 6, 2, 3, 1, 3, 6, 4, 7, 7, 1, 0, 5, 6, 2, 3, 0, 1, 3, 0, 2. Assume demand paging with three frames. Find the number of page faults for (i) LRU (ii) FIFO (iii) Optimal. Which algorithm gives the fewest page faults? (Question 22)
**Answer:**
**Total Frames = 3. Reference String Length = 20.**

**(i) FIFO Page Replacement:** (Replaces oldest page)
*   `6, 2, 3` -> Fill frames `[6, 2, 3]`. (3 Faults)
*   `1` -> Replaces `6` -> `[1, 2, 3]` (Fault 4)
*   `3` -> Already in memory. (Hit)
*   `6` -> Replaces `2` -> `[1, 6, 3]` (Fault 5)
*   `4` -> Replaces `3` -> `[1, 6, 4]` (Fault 6)
*   `7` -> Replaces `1` -> `[7, 6, 4]` (Fault 7)
*   `7` -> Hit
*   `1` -> Replaces `6` -> `[7, 1, 4]` (Fault 8)
*   `0` -> Replaces `4` -> `[7, 1, 0]` (Fault 9)
*   `5` -> Replaces `7` -> `[5, 1, 0]` (Fault 10)
*   `6` -> Replaces `1` -> `[5, 6, 0]` (Fault 11)
*   `2` -> Replaces `0` -> `[5, 6, 2]` (Fault 12)
*   `3` -> Replaces `5` -> `[3, 6, 2]` (Fault 13)
*   `0` -> Replaces `6` -> `[3, 0, 2]` (Fault 14)
*   `1` -> Replaces `2` -> `[3, 0, 1]` (Fault 15)
*   `3, 0` -> Hit, Hit
*   `2` -> Replaces `3` -> `[2, 0, 1]` (Fault 16)
*   **Total FIFO Page Faults = 16**

**(ii) LRU Page Replacement:** (Replaces least recently used)
*   `6, 2, 3` -> `[6, 2, 3]` (3 Faults)
*   `1` -> LRU is `6` -> `[1, 2, 3]` (Fault 4)
*   `3` -> Hit (Recent order is now: 1, 2, 3)
*   `6` -> LRU is `2` -> `[1, 6, 3]` (Fault 5)
*   `4` -> LRU is `1` -> `[4, 6, 3]` (Fault 6)
*   `7` -> LRU is `3` -> `[4, 6, 7]` (Fault 7)
*   `7` -> Hit (Recent: 4, 6, 7)
*   `1` -> LRU is `6` -> `[4, 1, 7]` (Fault 8)
*   `0` -> LRU is `4` -> `[0, 1, 7]` (Fault 9)
*   `5` -> LRU is `7` -> `[0, 1, 5]` (Fault 10)
*   `6` -> LRU is `1` -> `[0, 6, 5]` (Fault 11)
*   `2` -> LRU is `0` -> `[2, 6, 5]` (Fault 12)
*   `3` -> LRU is `5` -> `[2, 6, 3]` (Fault 13)
*   `0` -> LRU is `6` -> `[2, 0, 3]` (Fault 14)
*   `1` -> LRU is `2` -> `[1, 0, 3]` (Fault 15)
*   `3, 0` -> Hit, Hit (Recent: 1, 3, 0)
*   `2` -> LRU is `1` -> `[2, 0, 3]` (Fault 16)
*   **Total LRU Page Faults = 16**

**(iii) Optimal Page Replacement:** (Replaces page not needed for longest time in future)
*   `6, 2, 3` -> `[6, 2, 3]` (3 Faults)
*   `1` -> Future needs: 3(next), 6(soon), 2(way later). Replace `2` -> `[6, 1, 3]` (Fault 4)
*   `3, 6` -> Hit, Hit
*   `4` -> Future needs: 7(next), 1(soon), 6(later), 3(later). Let's replace `3` -> `[6, 1, 4]` (Fault 5)
*   `7` -> Future needs: 1(next), 0(soon). Replace `4` -> `[6, 1, 7]` (Fault 6)
*   `7, 1` -> Hit, Hit
*   `0` -> Future needs: 5(next), 6(soon). Replace `7` -> `[6, 1, 0]` (Fault 7)
*   `5` -> Future needs: 6(next), 0(soon). Replace `1` -> `[6, 5, 0]` (Fault 8)
*   `6` -> Hit
*   `2` -> Future needs: 3(next), 0(soon). Replace `6` -> `[2, 5, 0]` (Fault 9)
*   `3` -> Future needs: 0(next), 1(soon). Replace `5` -> `[2, 3, 0]` (Fault 10)
*   `0` -> Hit
*   `1` -> Future needs: 3(next), 0(soon). Replace `2` -> `[1, 3, 0]` (Fault 11)
*   `3, 0` -> Hit, Hit
*   `2` -> Replace `1` -> `[2, 3, 0]` (Fault 12)
*   **Total Optimal Page Faults = 12**

**Conclusion:** **Optimal Algorithm** gives the fewest page faults (12).

### Q2. Consider the page reference string 6, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2, 0, 1. Using FIFO, find total page faults with 3 frames and 4 frames. Does Belady's anomaly occur? (Question 23)
**Answer:**
**With 3 Frames (FIFO):**
*   6, 0, 1 -> `[6, 0, 1]` (3 faults)
*   2 -> rep 6 -> `[2, 0, 1]` (Fault 4)
*   0 -> Hit
*   3 -> rep 0 -> `[2, 3, 1]` (Fault 5)
*   0 -> rep 1 -> `[2, 3, 0]` (Fault 6)
*   4 -> rep 2 -> `[4, 3, 0]` (Fault 7)
*   2 -> rep 3 -> `[4, 2, 0]` (Fault 8)
*   3 -> rep 0 -> `[4, 2, 3]` (Fault 9)
*   0 -> rep 4 -> `[0, 2, 3]` (Fault 10)
*   3, 2 -> Hit, Hit
*   1 -> rep 2 -> `[0, 1, 3]` (Fault 11)
*   2 -> rep 3 -> `[0, 1, 2]` (Fault 12)
*   0, 1 -> Hit, Hit
*   **Total Page Faults with 3 frames = 12**

**With 4 Frames (FIFO):**
*   6, 0, 1, 2 -> `[6, 0, 1, 2]` (4 faults)
*   0 -> Hit
*   3 -> rep 6 -> `[3, 0, 1, 2]` (Fault 5)
*   0 -> Hit
*   4 -> rep 0 -> `[3, 4, 1, 2]` (Fault 6)
*   2, 3 -> Hit, Hit
*   0 -> rep 1 -> `[3, 4, 0, 2]` (Fault 7)
*   3, 2 -> Hit, Hit
*   1 -> rep 2 -> `[3, 4, 0, 1]` (Fault 8)
*   2 -> rep 3 -> `[2, 4, 0, 1]` (Fault 9)
*   0, 1 -> Hit, Hit
*   **Total Page Faults with 4 frames = 9**

**Does Belady's anomaly occur?**
**No.** Belady's anomaly occurs when increasing the number of frames *increases* the page faults. Here, increasing frames from 3 to 4 decreased the faults from 12 to 9, which is normal expected behavior.

### Q3. Memory is divided into fixed partitions: 120 KB, 480 KB, 210 KB, 320 KB and 590 KB (in that order). Processes of 215 KB, 410 KB, 115 KB and 440 KB arrive in that order. Show allocation for First, Best, Worst Fit. Which uses memory most effectively? (Question 25)
**Answer:**

**i) First Fit (Allocates first hole large enough):**
*   **P1 (215 KB)** -> Scans: 120(no), 480(yes). Allocates to **480 KB** partition. (Internal frag = 265 KB).
*   **P2 (410 KB)** -> Scans remaining: 120(no), 210(no), 320(no), 590(yes). Allocates to **590 KB**. (Int frag = 180 KB).
*   **P3 (115 KB)** -> Scans remaining: 120(yes). Allocates to **120 KB**. (Int frag = 5 KB).
*   **P4 (440 KB)** -> Scans remaining: 210(no), 320(no). **Cannot be allocated (Must wait)**.

**ii) Best Fit (Allocates smallest hole large enough):**
*   *Sorted Holes: 120, 210, 320, 480, 590*
*   **P1 (215 KB)** -> Smallest fit is 320. Allocates to **320 KB**. (Int frag = 105 KB).
*   **P2 (410 KB)** -> Smallest fit is 480. Allocates to **480 KB**. (Int frag = 70 KB).
*   **P3 (115 KB)** -> Smallest fit is 120. Allocates to **120 KB**. (Int frag = 5 KB).
*   **P4 (440 KB)** -> Smallest fit is 590. Allocates to **590 KB**. (Int frag = 150 KB).
*   *All processes allocated successfully!*

**iii) Worst Fit (Allocates largest hole available):**
*   **P1 (215 KB)** -> Largest is 590. Allocates to **590 KB**. (Int frag = 375 KB).
*   **P2 (410 KB)** -> Largest remaining is 480. Allocates to **480 KB**. (Int frag = 70 KB).
*   **P3 (115 KB)** -> Largest remaining is 320. Allocates to **320 KB**. (Int frag = 205 KB).
*   **P4 (440 KB)** -> Largest remaining is 210. **Cannot be allocated (Must wait)**.

**Conclusion:**
**Best Fit** is the algorithm that uses memory most effectively here, as it is the only one capable of successfully allocating all four processes without suffering from prohibitive external fragmentation.
