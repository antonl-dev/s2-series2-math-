# 4.6 Page Replacement Algorithms - Lecture 1

## 1. The Need for Page Replacement
In a Demand Paging system, the OS brings pages into physical memory (RAM) only when they are needed. Eventually, physical memory will become completely full. 
If a process requests a new page (causing a Page Fault) and there are **no free frames** left in RAM, the OS must swap out an existing page to the disk to make room. 

The algorithm used to select which page to evict is called the **Page Replacement Algorithm**.
*   **Goal:** The primary objective of any page replacement algorithm is to **minimize the page-fault rate**. We want to avoid swapping out a page that will be needed again immediately.

---

## 2. First-In, First-Out (FIFO) Page Replacement
The simplest page-replacement algorithm is a FIFO algorithm.
*   **Logic:** The OS associates with each page the time when that page was brought into memory. When a page must be replaced, the **oldest page** is chosen.
*   **Implementation:** The OS simply maintains a FIFO queue of all pages in memory. We replace the page at the head of the queue. When a new page is brought in, it is inserted at the tail of the queue.
*   **Advantages:** Extremely easy to understand and program.
*   **Disadvantages:** Its performance is not always good. The oldest page might contain a heavily used variable that was initialized early and is used constantly. Replacing it will cause an immediate page fault.

### Belady’s Anomaly
Intuitively, one would expect that giving a system *more* physical memory (more frames) would result in *fewer* page faults. 
However, **Belady's Anomaly** is a phenomenon where, for certain page reference strings using the FIFO algorithm, **increasing the number of page frames actually increases the number of page faults**. 
*   *Note: This anomaly only affects FIFO. Algorithms like Optimal and LRU are immune to it.*

---

## 3. Optimal Page Replacement (OPT / MIN)
To avoid Belady's anomaly and guarantee the lowest possible page-fault rate, the Optimal Page Replacement algorithm was formulated.
*   **Logic:** Replace the page that **will not be used for the longest period of time in the future**.
*   **Advantages:** Guarantees the lowest possible page-fault rate for a fixed number of frames. Never suffers from Belady's Anomaly.
*   **Disadvantages:** It is **impossible to implement** in a real operating system. The OS cannot predict the future or know the exact sequence of upcoming memory references. 
*   **Use Case:** Because it can't be used in production, it is used primarily as a theoretical benchmark. We run simulations of other algorithms and compare them against Optimal to see how well they perform.

# 4.7 Page Replacement Algorithms - Lecture 2

## 1. Least Recently Used (LRU) Page Replacement
Since Optimal replacement is impossible to implement, OS designers look for an approximation. While Optimal looks forward in time, **LRU looks backward in time**.
*   **Logic:** It replaces the page that **has not been used for the longest period of time**. 
*   **Why it works:** It relies on the principle of *locality of reference*—pages that have been heavily used in the last few instructions will likely be used again heavily in the next few.
*   **Pros:** Generally performs much better than FIFO and comes closest to the performance of Optimal. It does not suffer from Belady's anomaly.
*   **Cons:** Requires substantial hardware assistance. The OS must keep track of *exactly* when every page was last accessed.

### Hardware Implementation of LRU
Software alone is too slow to update data on every single memory access. Hardware is needed:
1.  **Counters:** Every page table entry has a time-of-use field, and the CPU adds a logical clock/counter. On every memory reference, the clock is incremented, and the clock value is copied to the time-of-use field of the page. When a page needs replacement, the OS searches the table for the page with the smallest time value.
2.  **Stack:** Keep a stack of page numbers. Whenever a page is referenced, it is removed from its current position in the stack and pushed to the top. Therefore, the top is always the most recently used, and the bottom is the least recently used. No searching is needed for replacement, but updating the middle of a stack on every access requires specialized hardware.

🔗 **[Click here for a visual representation of LRU Page Replacement using a Stack](https://www.google.com/search?tbm=isch&q=lru+page+replacement+stack+implementation+operating+system)**

---

## 2. LRU Approximation (Second-Chance / Clock Algorithm)
Because pure LRU requires expensive hardware, many systems use an approximation based on a **Reference Bit**.
*   Each page table entry has a reference bit, initialized to 0. 
*   When a page is accessed, the hardware sets the bit to 1.
*   **Second-Chance Algorithm:** It uses a circular queue (like a clock). A pointer moves around the clock looking for a page to replace.
    *   If it points to a page with bit `0`, it replaces it.
    *   If it points to a page with bit `1`, it gives it a "second chance", sets the bit to `0`, and moves to the next page.

# 4.8 Frame Allocation and Thrashing 

## 1. Allocation of Frames
If we have multiple processes running concurrently, how do we allocate the fixed amount of free memory frames among them?

1.  **Equal Allocation:** If there are 100 frames and 5 processes, give each process exactly 20 frames. (Inefficient, because a tiny text editor gets the same memory as a massive database).
2.  **Proportional Allocation:** Allocate available memory to each process according to its size. A larger process gets more frames than a smaller one.
3.  **Global vs. Local Replacement:**
    *   *Global Replacement:* A process can take a replacement frame from the set of *all* frames, even if that frame belongs to another process. (High throughput, but process execution time varies wildly).
    *   *Local Replacement:* A process can only select a victim page from its *own* allocated set of frames. (More predictable execution time, but potentially wastes memory if some processes are under-utilizing their allocation).

---

## 2. Thrashing
**Thrashing** is a severe performance collapse in virtual memory systems. A system is thrashing if it is spending more time paging (swapping pages in and out of the disk) than executing actual instructions.

### The Cause of Thrashing:
1.  A process does not have enough frames to hold its "working set" (the minimum set of pages it needs to execute its current phase of code).
2.  It page-faults constantly. Since it needs the pages immediately, it replaces a page that it will need again shortly.
3.  Processes queue up waiting for the disk I/O to finish page swapping. The CPU sits idle.
4.  The OS scheduler sees CPU utilization dropping. To fix this, it increases the **Degree of Multiprogramming** by bringing *new* processes into memory.
5.  These new processes take frames away from the existing, starving processes, causing even more page faults. The system completely freezes.

### Prevention: The Working-Set Model
To prevent thrashing, the OS uses the Working-Set Model. It estimates how many frames a process actually needs right now (its working set). The OS will only allow a process to run if there are enough free frames to satisfy its entire working set.

## 3. Fixed Partition Allocation (Memory Allocation Methods)
*(Note: While paging handles virtual memory, partitioning algorithms are often used to allocate contiguous blocks in main memory or swap space. This is heavily tested in your numericals).*

When memory is divided into blocks (partitions), and a process of size $N$ arrives, how does the OS choose which hole to put it in?
*   **First Fit:** Allocates the *first* hole it finds that is $\ge N$. (Fastest).
*   **Best Fit:** Searches all holes and allocates the *smallest* hole that is $\ge N$. (Saves large holes, but creates tiny fragments).
*   **Worst Fit:** Searches all holes and allocates the *largest* hole available. (Leaves a moderately sized hole leftover, but is often inefficient).

### Q1. c. What is thrashing? Explain with a diagram. (Question 21c)
**Answer:**
**Thrashing** is a condition where a computer system's virtual memory subsystem is in a constant state of paging, rapidly exchanging data in memory for data on disk, to the exclusion of most application-level processing. The system spends more time swapping pages than executing instructions.

**Cause:** It happens when processes are not allocated enough physical frames to hold their active working set. They constantly trigger page faults. This forces the CPU to wait for disk I/O, dropping CPU utilization. The OS incorrectly responds by loading more processes to boost utilization, which steals more frames and creates a vicious cycle of page faults, freezing the system.

### Q2. A system uses fixed partitioning with partitions of 160K, 310K, 540K, 420K, 260K and 210K (in that order). Five processes are waiting: P1 (250K), P2 (130K), P3 (390K), P4 (310K) and P5 (360K). Show allocation under (i) First Fit (ii) Best Fit (iii) Worst Fit, and find internal fragmentation. (Question 24)

**Answer:**
**Partitions (in order):** 160K, 310K, 540K, 420K, 260K, 210K.
**Processes (in order):** P1(250), P2(130), P3(390), P4(310), P5(360).

**(i) First Fit Allocation:**
*   P1 (250K) -> Scans: 160(no), 310(yes). **Allocated to 310K**. (Internal Frag = 310 - 250 = 60K)
*   P2 (130K) -> Scans remaining: 160(yes). **Allocated to 160K**. (Internal Frag = 160 - 130 = 30K)
*   P3 (390K) -> Scans remaining: 540(yes). **Allocated to 540K**. (Internal Frag = 540 - 390 = 150K)
*   P4 (310K) -> Scans remaining: 420(yes). **Allocated to 420K**. (Internal Frag = 420 - 310 = 110K)
*   P5 (360K) -> Scans remaining: 260(no), 210(no). **Must Wait**.
*   *Total Internal Fragmentation = 60 + 30 + 150 + 110 = 350K.*

**(ii) Best Fit Allocation:**
*(Sorted Partitions: 160, 210, 260, 310, 420, 540)*
*   P1 (250K) -> Smallest fit is 260K. **Allocated to 260K**. (Int Frag = 10K)
*   P2 (130K) -> Smallest fit is 160K. **Allocated to 160K**. (Int Frag = 30K)
*   P3 (390K) -> Smallest fit is 420K. **Allocated to 420K**. (Int Frag = 30K)
*   P4 (310K) -> Smallest fit is 310K. **Allocated to 310K**. (Int Frag = 0K)
*   P5 (360K) -> Smallest fit is 540K. **Allocated to 540K**. (Int Frag = 180K)
*   *All processes allocated. Total Internal Fragmentation = 10 + 30 + 30 + 0 + 180 = 250K.*

**(iii) Worst Fit Allocation:**
*   P1 (250K) -> Largest partition is 540K. **Allocated to 540K**. (Int Frag = 540 - 250 = 290K)
*   P2 (130K) -> Largest remaining is 420K. **Allocated to 420K**. (Int Frag = 420 - 130 = 290K)
*   P3 (390K) -> Largest remaining is 310K. **Must wait** (390 > 310).
*   P4 (310K) -> Largest remaining is 310K. **Allocated to 310K**. (Int Frag = 0K)
*   P5 (360K) -> Largest remaining is 260K. **Must wait** (360 > 260).
*   *Processes P3 and P5 must wait. Total Internal Frag = 290 + 290 + 0 = 580K.*
