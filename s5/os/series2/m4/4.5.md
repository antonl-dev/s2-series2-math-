# 4.5 Virtual Memory, Demand Paging, and Thrashing

## 1. Introduction to Virtual Memory
Up to this point, our memory management strategies (Segmentation and Paging) required the *entire* process to be in physical memory (RAM) for it to execute. 

**Virtual Memory** involves the separation of logical memory as perceived by users from physical memory. This separation allows an extremely large virtual memory to be provided for programmers when only a smaller physical memory is available. 
*   It allows the execution of processes that are not completely in memory.
*   Programs can be larger than physical memory.
*   More programs can run concurrently, increasing CPU utilization.

---

## 2. Demand Paging and Swapping
Virtual memory is most commonly implemented using **Demand Paging**. 
Instead of loading the entire process into memory when it starts, a demand-paging system loads pages into memory *only when they are needed* (demanded) during execution. Pages that are never accessed are never loaded into physical memory.

### Swapping
To support demand paging, the system needs a secondary storage device (usually a hard disk or SSD), referred to as the **Backing Store** or **Swap Space**. 
*   **Swapping** is the mechanism of moving data between physical RAM and the disk. 
*   If physical memory becomes full, the OS must swap out (remove) a page from RAM to the disk to make room for a new page. When that swapped-out page is needed again, it is swapped back in. 
*   A program that does this page-level swapping is sometimes called a *pager*.

---

## 3. Page Faults
When a process tries to access a page that was not brought into physical memory (it resides on the disk), a **Page Fault** occurs.
The page table uses a **valid-invalid bit** to track this:
*   `Valid (v)`: The associated page is both legal and in memory.
*   `Invalid (i)`: The page is either not part of the address space, or it is valid but currently swapped out to the disk.

### Steps to Handle a Page Fault:
1.  **Check:** The hardware checks the internal page table. It sees the valid-invalid bit is set to `i`.
2.  **Trap:** The hardware generates a trap (exception) to the Operating System, signaling a page fault.
3.  **Validate:** The OS checks the process's internal control block to determine if the reference was a valid memory access or a bad pointer. If invalid, the process is terminated. If valid, the OS must bring it from the disk.
4.  **Find Free Frame:** The OS finds a free frame in physical memory. (If no frames are free, it must use a Page Replacement Algorithm to free one up).
5.  **Disk I/O:** The OS schedules a disk operation to read the desired page into the newly allocated frame.
6.  **Update Table:** Once the disk read is complete, the OS modifies the page table to indicate the page is now in memory (sets bit to `v`).
7.  **Restart:** The OS restarts the instruction that was interrupted by the page fault. The process can now access the page as if it had always been in memory.

## 4. Thrashing
If a system does not have enough physical memory frames to support the active pages of its running processes, it will constantly face page faults. 
The OS will swap out a page, but immediately need it again, causing another page fault. This high paging activity is called **Thrashing**.

**A system is thrashing if it is spending more time paging (swapping data to/from disk) than executing actual instructions.**

### The Cause of Thrashing:
1.  The OS monitors CPU utilization. If utilization is too low, the OS tries to increase the Degree of Multiprogramming by bringing new processes into memory.
2.  However, if the existing processes need more frames but none are available, they start causing page faults.
3.  These processes block and wait for the disk. CPU utilization drops further.
4.  The OS sees the drop in CPU utilization and erroneously brings in *even more* processes, making the memory shortage worse.
5.  The system grinds to a halt.

### Q1. a. What is demand paging? Explain swapping with a neat diagram. (Question 21a)
**Answer:**
**Demand Paging:** It is a virtual memory implementation technique where pages of a process are loaded into physical memory only when they are explicitly demanded (accessed) during execution. Pages that are never accessed are never brought into RAM, which saves memory and allows programs larger than physical memory to run.

**Swapping:** Swapping is the process of moving pages (or entire processes) back and forth between main memory (RAM) and a secondary storage device (the backing store). In a demand-paging system, if RAM is full and a new page must be brought in, the OS "swaps out" an older page to the disk and "swaps in" the newly requested page.

### Q2. b. Using a diagram, explain the steps taken to handle a page fault. (Question 21b)
**Answer:**
A page fault occurs when a program attempts to access a page that is mapped in the logical address space but is not currently loaded in physical memory (its valid-invalid bit is set to invalid).

**Steps to handle it:**
1.  **Reference:** The CPU tries to access a memory location. The hardware checks the page table and finds the valid-invalid bit is 'i' (invalid).
2.  **Trap:** The MMU generates a trap (interrupt) to the OS.
3.  **Check:** The OS examines the memory reference. If it was an illegal address, the process is aborted. If it was legal, the OS prepares to bring the page in.
4.  **Find Free Frame:** The OS locates an empty frame in physical memory.
5.  **Disk Read:** The OS instructs the disk controller to read the required page from the backing store into the free frame.
6.  **Update Page Table:** When the read completes, the OS updates the page table to point to the new frame and sets the valid bit to 'v'.
7.  **Restart Instruction:** The OS restarts the exact instruction that caused the trap. The CPU can now access the memory successfully.

### Q3. c. What is thrashing? Explain with a diagram. (Question 21c)
**Answer:**
**Thrashing** is a severe performance degradation that occurs when a system has insufficient physical memory. A system is said to be thrashing when it spends more time paging (swapping pages in and out of the disk) than executing actual process instructions. 

It happens because processes don't have enough frames to hold their active working set of pages. They constantly fault, displacing pages that will be needed again immediately. The CPU utilization drops as processes queue up waiting for the disk. The OS observes this low CPU utilization and mistakenly adds *more* processes to the system to increase multiprogramming, which only exacerbates the frame shortage and the paging traffic, causing the system to effectively freeze.
