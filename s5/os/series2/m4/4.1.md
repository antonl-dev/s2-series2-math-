# 4.1 Address Spaces, Memory View of a Process, and Dynamic Memory Allocation

## 1. The Abstraction: Address Space
In early computers, programs accessed physical memory directly. If a program had a bug and wrote to the wrong memory address, it could crash the entire operating system. To solve this, modern Operating Systems create an abstraction of physical memory called the **Address Space**.

The **Address Space** is the running program's *view* of memory in the system. It is a virtualization of memory. The OS provides each process with the illusion that it has its own large, private, contiguous array of memory, starting from address 0, even though the actual physical memory is shared among many processes and the OS itself.

---

## 2. Memory View of a Process
When a program is loaded into memory to become a process, its address space is divided into several logical segments. Understanding these segments is crucial for understanding how programs use memory.

1.  **Code Segment (Text Section):** 
    *   Contains the compiled machine code (executable instructions) of the program.
    *   It is usually marked as *read-only* to prevent the program from accidentally modifying its own instructions.
2.  **Data Segment:**
    *   Contains global variables and static variables.
    *   Often divided into two parts: 
        *   **Initialized Data:** Variables explicitly initialized by the programmer (e.g., `int count = 10;`).
        *   **BSS (Block Started by Symbol):** Uninitialized global/static variables (e.g., `int total;`). The OS initializes these to zero.
3.  **Heap Segment:**
    *   Used for **dynamic memory allocation** during the runtime of the program. 
    *   Memory here is allocated and freed explicitly by the programmer using system calls or library functions (like `malloc()` in C or `new` in Java/C++).
    *   The heap generally grows **upward** (towards higher memory addresses) as more memory is allocated.
4.  **Stack Segment:**
    *   Used for local variables, function parameters, return addresses, and control information.
    *   Whenever a function is called, a new "stack frame" is pushed onto the stack. When the function returns, the frame is popped off.
    *   The stack generally grows **downward** (towards lower memory addresses).

*Note: Because the Heap and Stack grow towards each other, the OS leaves a large gap of unallocated memory between them to allow both to expand during runtime.*

## 3. Review of `malloc()` and `free()`
In C programming, dynamic memory management (operating on the Heap) is handled by the standard library functions `malloc()` and `free()`.

*   **`malloc(size_t size)`:** Stands for "memory allocation". It requests a contiguous block of memory of the specified `size` (in bytes) from the Heap. 
    *   If successful, it returns a pointer to the beginning of the allocated memory block.
    *   If it fails (not enough memory), it returns a `NULL` pointer.
    *   The memory allocated by `malloc` is *not* initialized (it contains garbage values).
*   **`free(void *ptr)`:** Used to deallocate (release) the memory previously allocated by `malloc`. 
    *   It takes the pointer to the memory block as an argument.
    *   Failing to free memory results in a **Memory Leak**, where the heap fills up with unused data until the program crashes.

## Exam Questions & Answers for Module 4.1

### Q1. a. What is an address space? How is it different from physical memory? (Question 15a)
**Answer:**
*   **Address Space:** It is the logical abstraction of memory provided by the Operating System to a running process. It represents the running program's *view* of memory. It gives the process the illusion of having a large, private, and contiguous memory space starting from address zero, containing its code, data, heap, and stack.
*   **Physical Memory:** It is the actual, tangible hardware memory (RAM chips) installed in the computer. 
*   **Difference:** While an address space is a contiguous virtual construct ranging from 0 to some maximum size (e.g., 4GB on a 32-bit system), physical memory is a shared resource divided among the OS and all currently running processes. The OS maps the logical addresses in the address space to the actual physical addresses in physical memory behind the scenes.

### Q2. Write a sample program that uses malloc() and free(). Explain how these calls perform dynamic memory management. (Question 16)
**Answer:**
**Sample Program:**
```c
#include <stdio.h>
#include <stdlib.h> // Required for malloc and free

int main() {
    int *ptr;
    int n = 5;

    // 1. Dynamic Memory Allocation using malloc
    // Allocating memory for 5 integers on the heap
    ptr = (int*) malloc(n * sizeof(int));

    // Check if memory has been allocated successfully
    if (ptr == NULL) {
        printf("Memory allocation failed.\n");
        return 1;
    }

    // 2. Using the allocated memory
    for (int i = 0; i < n; i++) {
        ptr[i] = i + 1; // Assigning values
        printf("%d ", ptr[i]);
    }
    printf("\n");

    // 3. Dynamic Memory Deallocation using free
    // Releasing the memory back to the heap
    free(ptr);
    ptr = NULL; // Good practice to avoid dangling pointers

    return 0;
}
```

**Explanation of dynamic memory management:**
1.  **`malloc()`:** When `malloc(n * sizeof(int))` is called, the C standard library requests the Operating System to find a contiguous free block of memory in the **Heap segment** of the process's address space large enough to hold 5 integers (usually 20 bytes). The OS marks this block as "used" and `malloc` returns the starting address of this block to the pointer `ptr`.
2.  **`free()`:** When the program no longer needs this memory, `free(ptr)` is called. This function tells the OS that the block of memory pointed to by `ptr` is no longer in use. The OS then marks this block as "free" in its internal free-space tracking structures, making it available for future `malloc` calls by the same process. This prevents memory leaks and ensures efficient use of the Heap.
