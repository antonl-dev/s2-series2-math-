# 4.3 Segmentation and Free Space Management

## 1. Segmentation
The simple "Base and Bounds" dynamic relocation approach maps the entire logical address space (from 0 to max) into a single contiguous block of physical memory. This is highly inefficient because it allocates physical memory for the massive, unused "gap" between the growing heap and the growing stack. 

**Segmentation** solves this by generalizing the base and bounds concept. Instead of having just one base and bounds pair for the entire process, the OS creates a base and bounds pair for **each logical segment** of the address space (e.g., one pair for Code, one for Data, one for Heap, and one for Stack).

### How Segmentation Works
*   The OS places each segment in different, non-contiguous parts of physical memory.
*   Only the memory actually used by the segments is allocated in physical memory; the unused gap is not allocated.
*   The hardware Memory Management Unit (MMU) now uses a **Segment Table** (an array of base and limit registers) to perform translations.
*   A logical address is divided into two parts: `<Segment Number, Offset>`.
    *   **Segment Number:** Tells the hardware which segment's base and bounds to use.
    *   **Offset:** The specific byte address within that segment.

### Address Translation Process
1.  Extract the **Segment Number** and **Offset** from the logical address.
2.  Use the Segment Number as an index into the **Segment Table**.
3.  Check if `Offset < Limit`.
    *   If **No**, throw a Segmentation Fault (trap to OS).
    *   If **Yes**, `Physical Address = Base + Offset`.

## 2. Fragmentation
While segmentation saves memory by not allocating the gap between the heap and stack, it introduces a new problem: **Fragmentation**.

1.  **Internal Fragmentation:** Unused memory *inside* an allocated block. (Segmentation does *not* suffer from this because segments are exactly the size they need to be).
2.  **External Fragmentation:** Over time, as variable-sized segments are created and destroyed, physical memory becomes full of small, non-contiguous holes. The OS might have enough total free memory to satisfy a new segment request, but it cannot fulfill the request because the free memory is not in a single contiguous block. Segmentation **severely suffers** from external fragmentation.

---

## 3. Free-Space Management
Because segments (and dynamic heap allocations via `malloc`) are of variable sizes, the OS must track which parts of physical memory are in use and which are free. The OS maintains a **Free List** or similar data structure to manage this.

### Common Free-Space Management Techniques:
1.  **Bitmaps (Bit Vector):** Memory is divided into fixed-size blocks. A bitmap uses 1 bit for each block. `0` means free, `1` means allocated.
    *   *Advantage:* Simple to understand and takes up a predictable, relatively small amount of space.
    *   *Disadvantage:* Searching the bitmap for a large contiguous run of `0`s can be slow.
2.  **Linked Lists:** The OS maintains a linked list where each node represents either an allocated segment or a free hole. Each node contains a flag (Free/Allocated), starting address, length, and a pointer to the next node.
    *   *Advantage:* Easier to find contiguous blocks and merge adjacent free blocks.
    *   *Disadvantage:* List maintenance (inserting/deleting nodes) adds overhead.

### Allocation Algorithms (How to choose a free hole):
When a request of size *N* arrives, the OS searches the free list:
*   **First Fit:** Allocates the first hole that is big enough. (Fast, but leaves fragments at the beginning).
*   **Best Fit:** Searches the entire list and allocates the smallest hole that is big enough. (Saves large holes, but creates tiny, useless external fragments).
*   **Worst Fit:** Searches the entire list and allocates the largest available hole. (Leaves moderate-sized fragments, but requires searching the whole list).

## Exam Questions & Answers for Module 4.3

### Q1. a. Explain segmentation in memory management with a neat diagram. (Question 18a)
**Answer:**
**Segmentation** is a memory management scheme that supports the programmer's view of memory. Instead of treating the process's address space as one large, linear array, segmentation divides it into distinct logical segments (such as the main program, procedures, global variables, stack, and heap).

Each segment has a name (or number) and a length. The OS loads these segments into physical memory independently, meaning they do not need to be contiguous. 
To keep track of where each segment is located in physical memory, the OS maintains a **Segment Table** for each process. Each entry in this table has two components:
1.  **Segment Base:** The starting physical address of the segment.
2.  **Segment Limit:** The length of the segment.

### Q2. b. Does segmentation suffer from fragmentation? Justify your answer. (Question 18b)
**Answer:**
Yes, segmentation suffers from **External Fragmentation**. 
**Justification:** Because segments are of variable sizes, allocating and deallocating them over time creates variable-sized "holes" of free space scattered throughout physical memory. Eventually, the total free memory might be large enough to accommodate a new segment, but the OS cannot allocate it because the free memory is broken up into small, non-contiguous holes.
However, segmentation generally does **not** suffer from *Internal Fragmentation* because segments are dynamically sized to precisely fit the data they contain, leaving no wasted space inside the allocated block.

### Q3. Explain the common techniques used for free-space management in an operating system. Compare their advantages and disadvantages. (Question 17)
**Answer:**
The two most common techniques for free-space management are **Bitmaps** and **Linked Lists**.

**1. Bitmaps (Bit Vectors):**
Physical memory is divided into allocation units (blocks). The OS maintains a string of bits where each bit corresponds to one block. A `0` indicates the block is free, and a `1` indicates it is allocated.
*   **Advantages:** It is very simple. The size of the bitmap is fixed and predictable regardless of how fragmented the memory is.
*   **Disadvantages:** To allocate a segment of size *N* blocks, the OS must linearly scan the bitmap to find a contiguous run of *N* zeros, which can be computationally slow and cache-inefficient.

**2. Linked Lists:**
The OS maintains a linked list of free and allocated memory segments. Each node in the list contains a flag (Free/In-use), the base address, the size of the block, and a pointer to the next node.
*   **Advantages:** It is easy to find available blocks using algorithms like First Fit or Best Fit. When an allocated block is freed, it can be easily merged (coalesced) with adjacent free blocks to create a larger free block.
*   **Disadvantages:** Searching for a specific sized hole can be slow (O(n) time). Managing the linked list (creating and deleting nodes) requires extra memory and processing overhead.

### Q4. Using a diagram, explain how a logical address is converted into a physical address under segmentation. A process has the following segment table. Find the physical address for each logical address below. (Question 19)

**Segment Table:**
| Segment | Base | Limit |
| :--- | :--- | :--- |
| 0 | 230 | 620 |
| 1 | 2400 | 16 |
| 2 | 95 | 110 |
| 3 | 1350 | 590 |
| 4 | 1960 | 100 |

**Find physical address for:**
(i) 0, 450 (ii) 1, 12 (iii) 2, 520 (iv) 3, 410 (v) 4, 125

**Answer:**
**Explanation of Conversion:**
Under segmentation, a logical address is represented as a pair `<Segment Number, Offset>`. 
1. The hardware uses the Segment Number to index into the Segment Table to find the Base and Limit.
2. It checks if the Offset is less than the Limit. If Offset $\ge$ Limit, it generates an addressing error (trap).
3. If valid, the Physical Address is calculated as: **Base + Offset**.

**Calculations:**
*   **(i) 0, 450**: Segment 0. Offset = 450. Limit = 620. 
    *   Check: 450 < 620 (Valid). 
    *   Physical Address = Base + Offset = 230 + 450 = **680**.
*   **(ii) 1, 12**: Segment 1. Offset = 12. Limit = 16. 
    *   Check: 12 < 16 (Valid). 
    *   Physical Address = 2400 + 12 = **2412**.
*   **(iii) 2, 520**: Segment 2. Offset = 520. Limit = 110. 
    *   Check: 520 < 110 (**Invalid**). 
    *   Physical Address = **Trap / Addressing Error** (Segmentation Fault).
*   **(iv) 3, 410**: Segment 3. Offset = 410. Limit = 590. 
    *   Check: 410 < 590 (Valid). 
    *   Physical Address = 1350 + 410 = **1760**.
*   **(v) 4, 125**: Segment 4. Offset = 125. Limit = 100. 
    *   Check: 125 < 100 (**Invalid**). 
    *   Physical Address = **Trap / Addressing Error** (Segmentation Fault).
