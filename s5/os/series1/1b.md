### 1.3 Components of an Operating System

An operating system is a large and complex system that must be partitioned into smaller, well-defined modules or components. Each component handles a specific subsystem of the computer.

```
                  +--------------------------------+
                  |         User Interface         |
                  |     (Shell, GUI, System API)   |
                  +--------------------------------+
                                  |
    +-----------------------------+-----------------------------+
    |                             |                             |
+---+---+                     +---+---+                     +---+---+
|Process|                     | Memory|                     |Storage|
| Mgmt  |                     | Mgmt  |                     | Mgmt  |
+---+---+                     +---+---+                     +---+---+
    |                             |                             |
    +-----------------------------+-----------------------------+
                                  |
                  +--------------------------------+
                  |      Hardware Abstraction      |
                  |     (Drivers, I/O Control)     |
                  +--------------------------------+
```

#### 1. Process Management
A process is a program in execution. Unlike a static program (which is just a file on disk), a process is an active entity with a program counter, registers, and an allocated address space.
*   **Key Responsibilities:**
    *   Creating and terminating both user and system processes.
    *   Suspending and resuming processes.
    *   Providing mechanisms for process synchronization (e.g., mutexes, semaphores).
    *   Providing mechanisms for inter-process communication (IPC) (e.g., shared memory, message passing).
    *   Providing mechanisms for deadlock handling.

#### 2. Memory Management
Main memory (RAM) is a volatile, fast-access storage medium shared by the CPU and I/O devices. To execute, a program's instructions must be loaded into memory.
*   **Key Responsibilities:**
    *   Keeping track of which parts of memory are currently being used and by whom.
    *   Deciding which processes to load into memory when memory space becomes available.
    *   Allocating and deallocating memory blocks dynamically as requested by processes (e.g., tracking heaps via allocation tables).

#### 3. Storage Management (File and Disk Management)
To provide a clean logical view of information storage, the OS abstracts physical storage media (HDDs, SSDs, optical drives) into a uniform logical unit: the **File**.
*   **Key Responsibilities:**
    *   Creating and deleting files and directories.
    *   Supporting primitives for manipulating files and directories (read, write, seek).
    *   Mapping logical files onto physical storage blocks.
    *   Backing up files onto stable, non-volatile storage media.
    *   Disk scheduling (determining the order in which read/write requests are serviced on the hardware level).

#### 4. I/O System Management
The I/O subsystem hides the peculiarities of specific hardware devices from the operating system kernel.
*   **Key Responsibilities:**
    *   Managing buffer caching, scheduling, and spooling.
    *   Providing a general device-driver interface.
    *   Houses specific device drivers that understand how to interact with individual hardware controllers.

#### 5. Protection and Security
Protection refers to a mechanism for controlling access by programs, processes, or users to system and user resources. Security defends the system against external or internal attacks (e.g., unauthorized access, malware).
*   **Key Responsibilities:**
    *   Distinguishing between authorized and unauthorized usage.
    *   Enforcing access controls (read/write/execute permissions).
    *   Providing mechanisms for user authentication (passwords, certificates).

### 1.3.1 Types of Operating Systems

Operating systems have evolved through several distinct paradigms to optimize CPU efficiency, interactive responsiveness, and hardware capabilities.

#### 1. Batch Operating Systems
*   **Concept:** The user does not interact with the computer system directly. Instead, they prepare their job offline (using punch cards or magnetic tape) and submit it to a computer operator.
*   **Mechanism:** The operator sorts jobs with similar requirements into batches and runs them through the computer as a group.
*   **Drawback:** The CPU remains idle for long periods when slow I/O operations are occurring. There is no direct interaction between the user and the running job.

#### 2. Multiprogrammed Systems
*   **Concept:** Multiprogramming increases CPU utilization by organizing jobs so that the CPU always has something to execute.
*   **Mechanism:** Multiple jobs are kept in physical memory simultaneously. The OS selects one job and begins executing it. When that job needs to wait for an I/O operation to complete, the OS simply switches to and executes another job.
*   **Drawback:** While efficient for resource usage, it does not guarantee rapid interaction with a specific user.

```
Memory Layout in Multiprogramming:
+-------------------+
| Operating System  |
+-------------------+
| Job 1 (Active)    |
+-------------------+
| Job 2 (Waiting)   |
+-------------------+
| Job 3 (Ready)     |
+-------------------+
```

#### 3. Time-Sharing / Multitasking Systems
*   **Concept:** A logical extension of multiprogramming. The CPU executes multiple jobs by switching among them very frequently.
*   **Mechanism:** The switch occurs so rapidly that users can interact with each program while it is running. Each user is given a small slice of CPU time (time slice or quantum).
*   **Characteristics:** Uses CPU scheduling and virtual memory to allow multiple processes to run concurrently with low response times.

#### 4. Multiprocessor Systems (Parallel / Tightly Coupled Systems)
*   **Concept:** Systems containing two or more physical processors in close communication, sharing the computer bus, clock, memory, and peripheral devices.
*   **Advantages:**
    *   *Increased Throughput:* More work is done in less time. (Though $N$ processors do not equal an $N$-fold speedup due to scheduling and communication overhead).
    *   *Economy of Scale:* Multiprocessor systems cost less than equivalent multiple single-processor systems because they share peripherals, mass storage, and power supplies.
    *   *Increased Reliability (Graceful Degradation):* If functions can be distributed among several processors, the failure of one processor will not halt the system, only slow it down.

#### 5. Distributed Operating Systems
*   **Concept:** Systems that manage a collection of physically separate, heterogeneous computer nodes networked together, presenting them to users as a single, unified system (loosely coupled).
*   **Mechanism:** Processors do not share memory or a common clock; instead, they communicate over various communication lines (such as high-speed buses or networks).

#### 6. Real-Time Operating Systems (RTOS)
*   **Concept:** Used when rigid time requirements are placed on the operation of a processor or the flow of data. Often used in embedded control systems, robotics, and industrial automation.
*   **Classifications:**
    *   *Hard Real-Time:* Guarantees that critical tasks will be completed on time. A missed deadline constitutes a total system failure. Virtual memory and disk storage are often restricted or omitted to ensure deterministic timing.
    *   *Soft Real-Time:* Critical tasks receive priority over non-critical tasks and retain that priority until they complete. Deadlines may occasionally be missed without causing a catastrophic system failure.

### 1.4 Operating System Structures

Operating system design has evolved to balance performance, extensibility, modularity, and security.

#### 1. Simple Structure (Monolithic)
Many commercial operating systems started without a well-defined structure. They were small, simple, and limited systems that grew beyond their original scope.

*   **Example: MS-DOS**
    *   In MS-DOS, there is little separation between the application programs, device drivers, and the core operating system. 
    *   Application programs can directly write to hardware or the BIOS, making the entire system highly vulnerable to malicious or buggy programs. A crash in an application can halt the entire system.
*   **Example: Original UNIX**
    *   Consists of two parts: the system programs and the kernel. Everything below the system-call interface and above the physical hardware is the kernel.
    *   It contains file systems, CPU scheduling, memory management, and device drivers in one large program.

```
MS-DOS Structure:
+----------------------------------+
|       Application Program        |
+----------------------------------+
|      Resident System Program     |
+---------+------------------------+
|         | MS-DOS Device Drivers  |
|         +------------------------+
| ROM BIOS Device Drivers          |
+----------------------------------+
```

*   **Pros:** High performance (minimal interface boundaries; function calls occur directly with no boundary crossing overhead).
*   **Cons:** Hard to extend; extremely difficult to debug; a bug in any driver can crash the entire system.

---

#### 2. Layered Approach
The operating system is broken down into a number of layers (or levels), each built on top of lower layers. Layer 0 is the physical hardware; Layer $N$ is the user interface.

```
+---------------------------------------+
| Layer N: User Interface               |
+---------------------------------------+
| Layer 2: Memory & Storage Management  |
+---------------------------------------+
| Layer 1: CPU Scheduling               |
+---------------------------------------+
| Layer 0: Physical Hardware            |
+---------------------------------------+
```

*   **Mechanism:** A typical layer (Layer $M$) consists of data structures and a set of routines that can be invoked by higher-level layers. Layer $M$ can, in turn, invoke operations on lower layers but cannot call higher layers.
*   **Pros:** 
    *   *Simplicity of construction and debugging:* The first layer can be debugged without concern for the rest of the system. Once it is correct, its functions can be safely used to build the next layer.
*   **Cons:**
    *   *Difficult to define layers:* Carefully planning where functions belong is challenging (e.g., the backing-store driver must be below memory management, but memory management is needed to run the driver code).
    *   *Performance overhead:* Each layer traversed adds a boundary crossing. If an application performs an I/O operation, the request must pass through multiple layers, requiring register modifications and parameter copying, which slows performance.

---

#### 3. Microkernel Structure
This method structures the operating system by removing all non-essential components from the kernel and implementing them as system and user-level programs (servers).

```
+-------------------------------------------------+
|   User Space:  [Client Pgm]  [File Server]      |
|                      |             ^            |
|                      v             |            |
+------------------[ IPC / Message ]--------------+
|   Kernel Space:  [      Microkernel      ]      |
|                  [ IPC, Memory, Sched    ]      |
+-------------------------------------------------+
```

*   **Mechanism:** The core microkernel provides essential services: minimal memory management, thread scheduling, and an Inter-Process Communication (IPC) facility.
*   **Communication:** If a client program wishes to access a file, it does not call the kernel directly. Instead, it sends a message via IPC to the File Server (which runs in user space). The file server performs the action and replies via IPC.
*   **Pros:**
    *   *Extensibility:* New services can be added to user space without modifying the microkernel.
    *   *Portability:* The small microkernel is easy to port to new hardware architectures.
    *   *Reliability & Security:* If a user-space server crashes (e.g., the file system or device driver), the rest of the operating system remains unaffected.
*   **Cons:**
    *   *Performance overhead:* System functions require context switching and message passing between user-space servers and client programs. Traversing these boundaries degrades execution speed.

---

#### 4. Modules (Loadable Kernel Modules - LKM)
This represents the state-of-the-art methodology for modern operating system design (used extensively by modern Linux and macOS). 

```
             +-----------------------+
             |      Core Kernel      |
             +-----------------------+
             /           |           \
            /            |            \
  +------------+   +-----------+   +------------+
  | Filesystem |   | Driver B  |   | Executable |
  |   Module   |   |  Module   |   |   Format   |
  +------------+   +-----------+   +------------+
```

*   **Mechanism:** The kernel has a set of core components and dynamically links in additional services either at boot time or during runtime.
*   **Characteristics:**
    *   Unlike layered systems, any module can call any other module directly via clean interfaces.
    *   Unlike microkernels, modules run in privileged kernel space, avoiding the message-passing overhead of IPC.
*   **Pros:** Combining the high runtime performance of monolithic systems with the modular extensibility of layered and microkernel architectures.

---

### Linux Concept Connections

*   **Linux as a Monolithic-Modular Hybrid:**
    *   The Linux kernel is fundamentally monolithic (all subsystems run in the same privileged address space for peak execution speed).
    *   However, it is highly modular. You can load and unload code on-demand using tools like `insmod`, `modprobe`, and `rmmod`.
    *   For instance, if you plug in a new USB network card, the Linux kernel detects the device and dynamically loads the specific `.ko` (Kernel Object) driver file into memory, linking it directly with the running kernel without requiring a system reboot.
