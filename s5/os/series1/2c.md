### 2.6 Scheduling Metrics and Core Non-Preemptive Algorithms

The objective of a CPU scheduling algorithm is to maximize system performance and user responsiveness. Schedulers are evaluated using several standardized metrics:

$$\text{Turnaround Time (TAT)} = \text{Completion Time (C)}_i - \text{Arrival Time (A)}_i$$

$$\text{Waiting Time (WT)} = \text{Turnaround Time (TAT)} - \text{Burst Time (B)}_i$$

$$\text{Response Time (RT)} = \text{First Scheduled Time} - \text{Arrival Time (A)}_i$$

*   **Throughput:** The total number of processes completed per unit of time.
*   **CPU Utilization:** The percentage of time the CPU is actively executing a process (target is 100%).
*   **Fairness:** Ensuring every process gets a fair share of the CPU without experiencing starvation.

---

#### 2.6.1 First-Come, First-Served (FCFS)
*   **Concept:** The CPU executes processes in the exact order they arrive in the `Ready` queue. It is **non-preemptive**; once a process gets the CPU, it runs to completion.
*   **The Convoy Effect:** A major drawback of FCFS. If a CPU-bound process with a long burst time is scheduled first, all subsequent short processes (often I/O-bound) are blocked behind it in the queue, degrading average waiting and response times.

---

#### 2.6.2 Shortest Job First (SJF)
*   **Concept:** When the CPU becomes free, the scheduler selects the process with the shortest CPU burst time.
*   **Optimality:** SJF is provably optimal; it yields the minimum average waiting time for a given set of processes.
*   **Drawback:** It is difficult to predict the exact duration of future CPU bursts. The scheduler must estimate them using an exponential weighted moving average of past bursts.

---

### 2.7 Preemptive Scheduling Algorithms

```
               +---------------------------------------+
               |      Preemptive Schedulers            |
               +---------------------------------------+
                /                                     \
               /                                       \
  [ Shortest Remaining Time First ]             [ Round Robin (RR) ]
  * Preemptive version of SJF                   * Time-slice multiplexing
  * Switches if a shorter job arrives          * Excellent Response Time
```

#### 2.7.1 Shortest Remaining Time First (SRTF)
*   **Concept:** The preemptive variant of SJF. If a new process arrives with a remaining CPU burst time shorter than the currently running process, the running process is preempted, and the CPU is allocated to the new process.

---

#### 2.7.2 Priority Scheduling
*   **Concept:** Each process is assigned a priority integer. The CPU is allocated to the process with the highest priority (where the lowest integer often represents the highest priority).
*   **Starvation (Indefinite Blocking):** High-priority processes can monopolize the CPU, leaving low-priority processes waiting in the queue indefinitely.
*   **The Solution — Aging:** A technique that gradually increases the priority of processes that wait in the system for long periods. Over time, even a low-priority process will become the highest-priority task and execute.

---

#### 2.7.3 Round Robin (RR) Scheduling
*   **Concept:** Specifically designed for time-sharing systems. The CPU scheduler goes through the `Ready` queue, allocating CPU time to each process for a small time interval called a **time quantum** ($q$).
*   **Preemption:** If a process runs longer than $q$, it is preempted, placed back at the tail of the `Ready` queue, and the next ready process is scheduled.

#### Analyzing the Effect of Time Quantum ($q$) on Context Switches:
The performance of Round Robin depends heavily on the size of the time quantum relative to the average process burst time:

```
Case A: Time Quantum (q) = 10ms (Large)
P1 (Burst = 8ms)  |=== Runs to completion (8ms) ===|  --> No Context Switch mid-run

Case B: Time Quantum (q) = 2ms (Small)
P1 (Burst = 8ms)  |--2ms--| [CS] |--2ms--| [CS] |--2ms--| [CS] |--2ms--|
                  --> 3 Context Switches (High Overhead)
```

1.  **Very Large Time Quantum ($q \to \infty$):**
    *   If the quantum exceeds the longest process burst time, processes never exceed their time slice.
    *   **Behavior:** Round Robin degenerates into **FCFS** scheduling.
2.  **Very Small Time Quantum ($q \to 0$):**
    *   If $q$ is small (e.g., $1$ microsecond) relative to a context switch overhead of $10$ microseconds, the CPU spends more time switching contexts than executing application instructions.
    *   **Behavior:** This results in **Processor Sharing**, which degrades throughput due to excessive scheduling overhead.
3.  **Rule of Thumb:**
    *   To balance responsiveness and overhead, the time quantum should be chosen such that roughly **80% of the CPU bursts** are shorter than $q$.

2.  **Interval $2$ to $4$ ms:** P2 runs for $2$ ms. Remaining burst: P2 = $1$ ms.

3.  **Interval $4$ to $6$ ms:** P3 runs for $2$ ms. Remaining burst: P3 = $0$ ms (Terminates!).

Because FCFS is non-preemptive, processes are executed in their exact order of arrival:

#### FCFS Gantt Chart:

#### FCFS Metric Calculation Table:

| Process | Arrival | Burst | Completion | Turnaround ($TAT = C - A$) | Waiting ($WT = TAT - B$) |
| :---: | :---: | :---: | :---: | :---: | :---: |

    $$\frac{11 + 19 + 21 + 26 + 34}{5} = \frac{111}{5} = 22.2\text{ ms}$$

    $$\frac{0 + 6 + 15 + 17 + 22}{5} = \frac{60}{5} = 12.0\text{ ms}$$

### Part B: Round Robin (RR) Scheduling ($q = 4$ ms)

We trace the ready queue at each time step, managing preemptions and new arrivals carefully.

#### Tracing Execution Steps ($q = 4$):

*   **Time $t = 0$:** P0 arrives. Queue: `[P0]`.
    *   *Action:* P0 runs from $t=0 \to 4$. Remaining: P0 = $7$ ms.
*   **Time $t = 4$:** No new arrivals. Queue: `[P0]`.
    *   *Action:* P0 runs from $t=4 \to 5$. (At $t=5$, P1 arrives and is added to queue). P0 continues running until $t=8$. Remaining: P0 = $3$ ms.
*   **Time $t = 8$:** Queue at $t=8$ has `[P1]` (arrived at $5$), plus the preempted P0. Queue: `[P1, P0]`.
    *   *Action:* P1 runs from $t=8 \to 12$. (At $t=9$, P2 arrives and is added to queue). Remaining: P1 = $9$ ms.
*   **Time $t = 12$:** Queue has `[P0, P2]`, plus the preempted P1. Queue: `[P0, P2, P1]`.
    *   *Action:* P0 runs from $t=12 \to 15$ (terminates!). At $t=13$, P3 arrives.
*   **Time $t = 15$:** Queue: `[P2, P1, P3]`.
    *   *Action:* P2 runs from $t=15 \to 19$. Remaining: P2 = $2$ ms. At $t=17$, P4 arrives.
*   **Time $t = 19$:** Queue has `[P1, P3, P4]`, plus the preempted P2. Queue: `[P1, P3, P4, P2]`.
    *   *Action:* P1 runs from $t=19 \to 23$. Remaining: P1 = $5$ ms.
*   **Time $t = 23$:** Queue has `[P3, P4, P2]`, plus the preempted P1. Queue: `[P3, P4, P2, P1]`.
    *   *Action:* P3 runs from $t=23 \to 27$. Remaining: P3 = $5$ ms.
*   **Time $t = 27$:** Queue has `[P4, P2, P1]`, plus the preempted P3. Queue: `[P4, P2, P1, P3]`.
    *   *Action:* P4 runs from $t=27 \to 31$. Remaining: P4 = $8$ ms.
*   **Time $t = 31$:** Queue has `[P2, P1, P3]`, plus the preempted P4. Queue: `[P2, P1, P3, P4]`.
    *   *Action:* P2 runs from $t=31 \to 33$ (terminates!).
*   **Time $t = 33$:** Queue: `[P1, P3, P4]`.
    *   *Action:* P1 runs from $t=33 \to 37$. Remaining: P1 = $1$ ms.
*   **Time $t = 37$:** Queue has `[P3, P4]`, plus the preempted P1. Queue: `[P3, P4, P1]`.
    *   *Action:* P3 runs from $t=37 \to 41$. Remaining: P3 = $1$ ms.
