### Question 1(a): System Calls and Parameter Passing (4 Marks)

**Definition:**  
A **System Call** is an active gateway programmatic interface that allows user-space applications to safely request privileged services from the operating system kernel.

```
       [ METHOD 1: Registers ]             [ METHOD 2: Block / Table ]
        +------------------+                    +------------------+
        | Register: Param  |                    | Reg: Pointer-----+
        +------------------+                    +------------------|
                                                                   |
                                                                   v
                                                        +------------------+
                                                        | Block in RAM     |
                                                        | [Param 1]        |
                                                        | [Param 2]        |
                                                        +------------------+
```

#### Three Methods of Parameter Passing:
1.  **CPU Registers:** Parameters are written directly into designated CPU registers (fastest, but restricted by the hardware's register limit).
2.  **Memory Block/Table:** Parameters are stored in a contiguous block of RAM, and the memory address pointer to the block is passed to the kernel inside a single CPU register (can pass an unlimited number of parameters).
3.  **Process Stack:** Parameters are pushed onto the active system stack by the user program and popped off by the operating system kernel.

### Question 1(b): Properties of Operating System Types (6 Marks)

#### i) Batch Operating System:
*   The user has no direct interaction with the computer. Jobs are submitted on offline media (e.g., punch cards) to an operator, who groups similar jobs into batches to run them consecutively.
*   *Key Property:* Solves scheduling setup delays but leads to low CPU utilization because the CPU remains idle during slow I/O device operations.

#### ii) Time-Sharing Operating System:
*   A logical extension of multiprogramming. The CPU switches rapidly between multiple active user processes using a small time slice (time quantum).
*   *Key Property:* Provides highly responsive, interactive multitasking. Users feel as though they have exclusive use of the machine.

#### iii) Real-Time Operating System (RTOS):
*   Used in environments with strict time constraints on task execution.
*   *Key Property:* Execution must be deterministic. It is divided into:
    *   *Hard Real-Time:* Missing a timing deadline constitutes an immediate, catastrophic system failure.
    *   *Soft Real-Time:* Critical processes receive strict priority scheduling. Missing a deadline degrades quality but does not crash the system.

### Question 2(a): Five Functions of an Operating System (5 Marks)

1.  **Process Management:** Controls process creation, termination, synchronization, IPC, and context-switch scheduling.
2.  **Memory Management:** Tracks active RAM utilization, manages allocation/deallocation blocks, and handles virtual address space translation.
3.  **File Management:** Abstracts raw physical blocks into files and directory structures, handling creation, read/write primitives, and authorization.
4.  **Device Management:** Coordinates device communications via unified device drivers, managing cache buffers, spooling, and queues.
5.  **Protection and Security:** Insulates executing process memory spaces and validates system resource access limits via user permissions.

### Question 2(b): Microkernel vs. Layered OS Structure (5 Marks)

```
        LAYERED STRUCTURE                    MICROKERNEL STRUCTURE
+-------------------------------+       +-------------------------------+
| Layer N: User Applications    |       | User Space: Clients & Servers |
+-------------------------------+       |   (File system, Network, etc) |
| Layer 1: Memory & I/O Control |       +--------- [ IPC Traps ] -------+
+-------------------------------+       | Kernel Space: Microkernel     |
| Layer 0: Hardware             |       |   (IPC, Threads, Mem Map)     |
+-------------------------------+       +-------------------------------+
```

| Structural Characteristic | Layered Architecture | Microkernel Architecture |
| :--- | :--- | :--- |
| **Core Concept** | OS organized into progressive layers ($0 \dots N$). Layer $i$ can only invoke functions in lower layers. | Non-essential services are stripped from the kernel and run as user-space servers. |
| **Modularity & Safety** | Moderate. If an error occurs in a low-level driver layer, it can crash layers above it. | High. If a user-space server crashes, the microkernel and other servers continue running safely. |
| **Performance** | Slower when traversing deep layers due to multiple system call execution boundaries. | Slower due to IPC message-passing overhead between client applications and servers. |
| **Extensibility** | Difficult to modify without disrupting adjacent layers. | Highly extensible; new user-space services can be added without modifying the kernel. |

#### i) First-Come, First-Served (FCFS)

**FCFS Gantt Chart:**
```
+-------+---------------+-------------+---------+
|  P1   |      P2       |     P3      |   P4    |
+-------+---------------+-------------+---------+

```

**Metric Calculations (FCFS):**

| Process | Arrival ($A$) | Burst ($B$) | Completion ($C$) | Turnaround ($TAT = C - A$) | Waiting ($WT = TAT - B$) |
| :---: | :---: | :---: | :---: | :---: | :---: |
| **P1** | 0 | 5 | 5 | $5 - 0 = 5$ | $5 - 5 = 0$ |
| **P2** | 1 | 8 | 13 | $13 - 1 = 12$ | $12 - 8 = 4$ |
| **P3** | 2 | 6 | 19 | $19 - 2 = 17$ | $17 - 6 = 11$ |
| **P4** | 3 | 4 | 23 | $23 - 3 = 20$ | $20 - 4 = 16$ |

*   **Average Turnaround Time (FCFS):** $\frac{5 + 12 + 17 + 20}{4} = \frac{54}{4} = \mathbf{13.5\text{ ms}}$
*   **Average Waiting Time (FCFS):** $\frac{0 + 4 + 11 + 16}{4} = \frac{31}{4} = \mathbf{7.75\text{ ms}}$

### Question 4(b): Context Switch Process and Timeline (5 Marks)

A context switch stops one running process and starts another by saving the current state to its PCB and loading the new process's state from its PCB.

```
Process P1                    OS Kernel                   Process P2
    |                             |                           |
[Running]                         |                           |
    |-----(Timer Interrupt)------>|                           |
    |                             |--[Save registers to PCB1] |
    |                             |--[Select P2 to execute]   |
    |                             |--[Load registers from PCB2]
    |                             |-------------------------->|
    |                             |                       [Running]
```

1.  **Interrupt Trigger:** A timer interrupt or blocking system call occurs, transferring execution control from the running Process $P_1$ to the OS Kernel.
2.  **State Save:** The kernel writes the current CPU physical registers (PC, SP, general-purpose registers) into $P_1$'s Process Control Block ($PCB_1$).
3.  **Scheduling Selection:** The OS scheduler runs to select the next ready process ($P_2$).
4.  **State Restore:** The kernel loads the saved register values from $P_2$'s Process Control Block ($PCB_2$) back into the physical registers of the CPU.
5.  **Execution Resume:** The CPU executes a return-from-trap instruction, switching back to User Mode to execute $P_2$.

### Question 5(a): Simple vs. Modular OS Structures (5 Marks)

```
       SIMPLE STRUCTURE (MS-DOS)              MODULAR STRUCTURE (Modern)
+-----------------------------------+             +-----------------------+
|        Application Program        |             |      Core Kernel      |
+-----------------------------------+             +-----------------------+
|      Resident System Program      |             /           |           \
+-----------------------------------+            /            |            \
| ROM BIOS & Low-Level Drivers      |     [Fs Module]    [USB Module]  [Net Mod]
+-----------------------------------+     (Loadable Kernel Modules link dynamically)
```

*   **Simple Structure (e.g., MS-DOS):**
    *   No defined separation boundaries between user application space, resident system programs, and low-level device drivers.
    *   Applications have direct access to hardware routines. A bug in an application can overwrite system services, causing a crash.
*   **Modular Structure (e.g., Modern Linux):**
    *   The kernel consists of a small set of core components with clean interfaces. Additional services are compiled as **Loadable Kernel Modules (LKMs)**.
    *   These modules can be loaded and linked dynamically into the kernel space at boot time or during runtime (e.g., loading a USB driver on insertion), keeping the system extensible and secure.
