# Module 2.3: Intelligent Agents

## 1. What is an Agent?
An **Agent** is anything that can be viewed as **perceiving** its **environment** through **sensors** and **acting** upon that environment through **actuators**.

[Click here to see the diagram for Agent Interacting with Environment via Sensors and Actuators](https://www.google.com/search?udm=2&q=Intelligent+Agent+Sensors+Actuators+Environment+diagram+Russell+Norvig)

### Core Terminology of an Agent:
1. **Environment:** The external world or surroundings in which the agent exists and operates.
2. **Sensors:** The input devices/mechanisms through which the agent receives information from the environment.
3. **Percept:** The agent's perceptual inputs at any given instant of time $t$.
4. **Percept Sequence:** The **complete history** of everything the agent has ever perceived up to the current moment.
   * *General Rule:* An agent's choice of action at any given instant can depend on the entire percept sequence observed to date, but not on anything it hasn't perceived.
5. **Actuators (Effectors):** The output mechanisms through which the agent executes actions to change or affect the environment.
6. **Action:** The operation performed by the actuators on the environment.

---

### Examples of Different Types of Agents:

| Type of Agent | Sensors (Inputs) | Actuators (Outputs) | Environment |
| :--- | :--- | :--- | :--- |
| **1. Human Agent** | Eyes, ears, nose, skin, taste buds. | Hands, legs, vocal tract (mouth). | Physical world. |
| **2. Robotic Agent** | Cameras, infrared range finders, LiDAR, bumpers, microphones. | Electric motors, hydraulic arms, wheels, grippers, speakers. | Factory floor, warehouse, roads, Mars surface. |
| **3. Software Agent (Softbot)** | Keystrokes, file contents, network packets, API inputs, database queries. | Displaying text/graphics on screen, writing files, sending network packets. | Operating system, Internet, stock market server. |

## 2. Agent Function vs. Agent Program

Mathematically and computationally, an agent's behavior is described at two levels:

### 1. Agent Function ($f$)
The **Agent Function** is an **abstract mathematical mapping** that maps any given **percept sequence ($P^*$)** to an **action ($A$)**:

$$
f : P^* \rightarrow A
$$

* Theoretically, the agent function can be represented as an (often infinite) lookup table that specifies the exact action to take for every possible percept sequence.

### 2. Agent Program
The **Agent Program** is the **concrete software implementation** of the agent function that runs within the physical system (called the **Agent Architecture**).

| Feature | Agent Function ($f: P^* \rightarrow A$) | Agent Program |
| :--- | :--- | :--- |
| **Nature** | Abstract mathematical description of behavior. | Concrete code/algorithm (Python, C++, neural network) running on hardware. |
| **Size** | Can be conceptually infinite (covers all possible percept histories). | Must be finite and compact to fit inside physical computer memory. |
| **Input** | Takes the **entire percept history** $P^*$ conceptually. | Takes only the **current percept** from sensors at each step (and updates internal memory if needed). |

## 3. Good Behavior: The Concept of Rationality

### What is a Rational Agent (Intelligent Agent)?
A **Rational Agent** is one that **"does the right thing"**—meaning that for each possible percept sequence, a rational agent should select an **action** that is expected to **maximize its performance measure**, given the evidence provided by the percept sequence and whatever built-in knowledge the agent has.

### Performance Measure
* A **Performance Measure** is an objective criterion established by the system designer to evaluate how successful an agent's behavior is in the environment.
* **Design Rule for Performance Measures:** Always design performance measures according to **what one actually wants to be achieved in the environment**, rather than how one thinks the agent should behave.
  * *Example (Vacuum Cleaner):* If we measure performance by *"amount of dirt sucked up"*, a clever agent might endlessly dump dirt on the floor and suck it up again to maximize its score! Instead, a good performance measure rewards **having a clean floor** (e.g., $+1$ point per clean square at each time step, minus energy/noise costs).

---

### The Four Factors That Determine Rationality
What is rational at any given time depends on **four things**:
1. **Performance Measure:** The criterion that defines the degree of success.
2. **Percept Sequence:** Everything the agent has perceived so far.
3. **Prior Knowledge:** What the agent already knows about the environment.
4. **Available Actions:** The actions that the agent can perform via its actuators.

---

### Crucial Distinction: Rationality vs. Omniscience (Perfection)
* **Omniscience:** An omniscient agent knows the **actual outcome** of its actions in advance and can act accordingly. However, **omniscience is impossible in the real world**.
* **Rationality:** Rationality is **NOT** the same as perfection.
  * **Rationality maximizes *expected* performance**, whereas **perfection maximizes *actual* performance**.
  * *Example:* If you look both ways before crossing a street and see no traffic, crossing is **rational**. If a stray meteorite suddenly falls from the sky and hits you while crossing, does that make your decision irrational? **No!** Your action was rational based on your percept sequence.

### Two Extra Requirements for True Rationality:
1. **Information Gathering (Exploration):** Doing actions in order to modify future percepts (e.g., looking both ways before crossing the road, or a robot exploring an unknown room).
2. **Learning & Autonomy:**
   * A rational agent should not only gather information, it should also **learn** as much as possible from what it perceives.
   * **Autonomy:** To the extent that an agent relies on the prior knowledge of its designer rather than on its own percepts and learning, we say that the agent **lacks autonomy**. A rational agent should be **autonomous**—it should learn what it can to compensate for partial or incorrect prior knowledge.

## 4. The PEAS Framework (Specifying the Task Environment)
Before designing an intelligent agent, we must specify its **Task Environment** using the **PEAS** description:
* **P — Performance Measure:** How is the agent's success evaluated?
* **E — Environment:** What are the surroundings/objects the agent interacts with?
* **A — Actuators:** What mechanisms does the agent use to perform actions?
* **S — Sensors:** What inputs does the agent use to perceive the world?

#### **2. Equation of Agent Structure:**

$$
\text{Agent} = \text{Architecture (Hardware: Sensors + Actuators + Processor)} + \text{Agent Program (Software)}
$$

#### **3. Role of Each Component:**
1. **Environment:**
   * The external physical or virtual world in which the agent operates (e.g., roads and traffic for a self-driving car, or a room with dirt for a vacuum robot). It generates states that the agent perceives and gets modified by the agent's actions.
2. **Sensors:**
   * Hardware or software input interfaces (such as cameras, LiDAR, microphones, infrared dirt detectors, or keyboard inputs) that observe the current state of the environment and convert it into **percepts** for the agent program.
3. **Agent Program:**
   * The "brain" or decision-making software of the agent that implements the agent function ($f: P^* \rightarrow A$). It receives the current percept from the sensors, processes it (using condition-action rules, internal world models, goals, or utility functions), and decides the best **action** to execute next.
4. **Actuators:**
   * Physical or software output mechanisms (such as wheels, electric motors, robotic arms, brakes, or display screens) that receive commands from the agent program and physically execute the chosen **actions** upon the environment.
