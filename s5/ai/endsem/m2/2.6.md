# Module 2.6: Case Study – The Vacuum Cleaner Problem

## 1. Introduction to the Vacuum Cleaner World
The **Vacuum Cleaner World** (introduced by Stuart Russell and Peter Norvig) is the classic "toy problem" in Artificial Intelligence used to illustrate how an **Intelligent Agent** perceives its **Environment**, maps **Percepts to Actions** using an **Agent Function/Program**, and gets evaluated by a **Performance Measure**.

In its standard textbook formulation, the world consists of two adjacent rooms/squares—**Location $A$** and **Location $B$**—each of which may or may not contain dirt.

[Click here to see the diagram for Vacuum Cleaner World 2 Rooms A and B and 8 States](https://www.google.com/search?udm=2&q=Vacuum+Cleaner+World+AI+8+states+diagram+Russell+Norvig)

```text
+-----------------------+-----------------------+
|       Room A          |       Room B          |
|    [Vacuum Agent]     |                       |
|     (Dirty/Clean)     |     (Dirty/Clean)     |
+-----------------------+-----------------------+
```

---

## 2. State Space of the Vacuum Cleaner Environment
How many possible world states exist in a Vacuum Cleaner environment with $n$ rooms?
* The vacuum agent can be in any of the **$n$ locations**.
* Each of the $n$ rooms can independently be in one of **$2$ states** (`Clean` or `Dirty`), giving $2^n$ possible dirt configurations.
* **Total Number of Environment States:**
  $$\text{Total States} = n \times 2^n$$
  * **For a 2-Room World ($A$ and $B$, $n = 2$):** $2 \times 2^2 = \mathbf{8\text{ possible states}}$.
  * **For a 5-Room World ($n = 5$):** $5 \times 2^5 = 5 \times 32 = \mathbf{160\text{ possible states}}$.

---

## 3. Percepts and Actions in the Vacuum Cleaner Environment

### A. Percepts (What the Agent Perceives via Sensors)
The vacuum cleaner agent is equipped with two primary sensors:
1. **Location Sensor:** Detects which room/square the agent is currently located in (e.g., `Location = A` or `Location = B`).
2. **Dirt Sensor:** Detects whether the current square is dirty or clean (`Status = Dirty` or `Status = Clean`).

Therefore, at any discrete time step $t$, the agent receives a **2-element percept tuple**:
$$\text{Percept} = [\text{Location}, \text{Status}]$$

In the standard 2-room world ($A$ and $B$), there are **$4$ possible distinct percepts**:
1. $[A, \text{Clean}]$ — The agent is in Room $A$, and Room $A$ is clean.
2. $[A, \text{Dirty}]$ — The agent is in Room $A$, and Room $A$ is dirty.
3. $[B, \text{Clean}]$ — The agent is in Room $B$, and Room $B$ is clean.
4. $[B, \text{Dirty}]$ — The agent is in Room $B$, and Room $B$ is dirty.

---

### B. Actions (What the Agent Can Do via Actuators)
The vacuum agent has motorized wheels (for movement) and a vacuum suction mechanism. In a 1D linear arrangement of rooms, it can execute the following **basic actions**:
1. **`Suck` (or `Clean`):** Activates the suction motor to remove dirt from the current square, changing the current room's status from `Dirty` to `Clean`.
2. **`Right` (or `MoveRight`):** Moves the agent one square to the right (e.g., from Room $A$ to Room $B$). If already at the rightmost boundary wall, the agent remains in the same room.
3. **`Left` (or `MoveLeft`):** Moves the agent one square to the left (e.g., from Room $B$ to Room $A$). If already at the leftmost boundary wall, the agent remains in the same room.
4. **`NoOp` (No Operation / Do Nothing):** *(Optional in some formulations)* The agent stays idle to save battery power when all rooms are known to be clean.

*(Note: In a 2D grid world, the movement actions expand to `Up`, `Down`, `Left`, and `Right`.)*

## 4. PEAS Specification of the Vacuum Cleaner Agent

| Component | Description for Vacuum Cleaner World |
| :--- | :--- |
| **P — Performance Measure** | $+1$ point for each clean square at each time step; $-1$ point penalty for each movement or unit of electricity consumed (encourages fast, energy-efficient cleaning). |
| **E — Environment** | A grid or linear row of rooms ($A, B$ or $R_1 \dots R_n$), floors, dirt/dust patches, walls/obstacles. |
| **A — Actuators** | Motorized wheels (`MoveLeft`, `MoveRight`) and vacuum suction motor (`Suck`). |
| **S — Sensors** | Location sensor (identifies current room) and Dirt sensor (detects `Clean` or `Dirty` status). |

## 5. Agent Function Table & Simple Reflex Agent Program

### A. Percept-Action Rule Table (2-Room World)
For a Simple Reflex Vacuum Agent in a 2-room world ($A, B$), the mapping from the current percept to the action is:

| Current Percept $[\text{Location}, \text{Status}]$ | Condition | Action Chosen |
| :---: | :--- | :---: |
| $[A, \text{Dirty}]$ | Room $A$ is dirty | **`Suck`** |
| $[A, \text{Clean}]$ | Room $A$ is clean $\rightarrow$ check Room $B$ | **`Right`** |
| $[B, \text{Dirty}]$ | Room $B$ is dirty | **`Suck`** |
| $[B, \text{Clean}]$ | Room $B$ is clean $\rightarrow$ check Room $A$ | **`Left`** |

### B. Pseudocode: `REFLEX-VACUUM-AGENT`
```text
function REFLEX-VACUUM-AGENT([location, status]) returns an action
    if status == Dirty then return Suck
    else if location == A then return Right
    else if location == B then return Left
```

## 6. Why the Vacuum Cleaner Problem is an Ideal Example of Agent–Environment Interaction
1. **Clear Separation of Agent and Environment:** It cleanly distinguishes between what is *inside* the agent (sensors, condition-action program, actuators) and what is *outside* in the environment (rooms, dirt, walls).
2. **Closed-Loop Feedback Cycle:** It clearly demonstrates the continuous **Perceive $\rightarrow$ Decide $\rightarrow$ Act $\rightarrow$ State Transition** loop:
   * For example, when the agent perceives $[A, \text{Dirty}]$ and executes `Suck`, its action directly modifies the environment's state so that the next percept becomes $[A, \text{Clean}]$.
3. **Illustrates All Levels of Agent Complexity:**
   * With local sensors and no memory, it demonstrates a **Simple Reflex Agent** (and its limitation of oscillating endlessly between clean rooms).
   * Adding memory of visited clean rooms turns it into a **Model-Based Reflex Agent** (allowing it to stop and execute `NoOp` once both rooms are clean).
   * Adding a path-planner to reach dirty rooms in a house map turns it into a **Goal-Based / Utility-Based Agent**.

## 7. Solved University & Internal Exam Questions

### Question 1 [End Semester Exam - Nov 2025, Part B, Q13 (8 Marks)]
> **a) Describe the percepts and actions in the vacuum cleaner environment. (6 Marks)**  
> **b) Why is this problem considered a good example to illustrate agent-environment interaction? (2 Marks)**

#### **Solution:**

#### **Part (a): Percepts and Actions in the Vacuum Cleaner Environment (6 Marks)**

**1. Overview of the Environment:**
In the standard Vacuum Cleaner World, an intelligent vacuum agent operates in a discrete environment consisting of two (or more) adjacent rooms/squares, typically labeled **Room $A$** and **Room $B$**, each of which may contain dirt (`Dirty`) or be free of dirt (`Clean`).

**2. Percepts (Inputs via Sensors):**
The agent perceives its environment through two sensors: a **Location Sensor** and a **Dirt Sensor**. At each time step, the agent receives a percept pair $[\text{Location}, \text{Status}]$:
* **Location Percept:** Tells the agent which square it currently occupies (e.g., `A` or `B`).
* **Dirt Status Percept:** Tells the agent whether its current square is `Dirty` or `Clean`.
* **Complete Set of Percepts (for 2 rooms $A$ and $B$):**
  1. $[A, \text{Dirty}]$: Agent is in Room $A$, and dirt is detected.
  2. $[A, \text{Clean}]$: Agent is in Room $A$, and the floor is clean.
  3. $[B, \text{Dirty}]$: Agent is in Room $B$, and dirt is detected.
  4. $[B, \text{Clean}]$: Agent is in Room $B$, and the floor is clean.

**3. Actions (Outputs via Actuators):**
Using its wheel motors and suction actuator, the vacuum agent can perform the following actions to change the state of the environment:
* **`Suck` (Clean):** Activates the vacuum mechanism to remove dirt from the current room, changing its state from `Dirty` to `Clean`.
* **`Right` (Move Right):** Moves the agent one square to the right (from Room $A$ to Room $B$).
* **`Left` (Move Left):** Moves the agent one square to the left (from Room $B$ to Room $A$).
* **`NoOp` (Do Nothing):** Keeps the agent stationary (used by model-based agents to conserve energy once all rooms are clean).

**4. Percept-to-Action Mapping Table:**
| Percept $[\text{Location}, \text{Status}]$ | Action Executed | Effect on Environment |
| :---: | :---: | :--- |
| $[A, \text{Dirty}]$ | `Suck` | Room $A$ becomes `Clean`. |
| $[A, \text{Clean}]$ | `Right` | Agent moves from Room $A$ to Room $B$. |
| $[B, \text{Dirty}]$ | `Suck` | Room $B$ becomes `Clean`. |
| $[B, \text{Clean}]$ | `Left` | Agent moves from Room $B$ to Room $A$. |

---

#### **Part (b): Why This Problem is a Good Example to Illustrate Agent–Environment Interaction (2 Marks)**
1. **Demonstrates the Closed-Loop Perception–Action Cycle:** It clearly shows how the environment provides a percept to the agent's sensors ($[A, \text{Dirty}]$), how the agent program selects an action (`Suck`), and how the actuator's action alters the environment state to produce a new percept ($[A, \text{Clean}]$) in the next step.
2. **Highlights Observability, Rationality, and Memory Trade-offs:** Despite having a small, finite state space ($8$ states for $2$ rooms), it effectively demonstrates **partial observability** (the agent cannot see dirt in the other room without moving there) and shows why a memoryless Simple Reflex Agent keeps moving back and forth whereas a Model-Based Agent remembers clean rooms and stops to save energy.

### Question 2 [Series Test-I, Part B, Q9(a) (5 Marks)]
> **Design a Simple Reflex Agent rule table for a vacuum robot operating in five rooms arranged linearly. The robot can perceive only: its current location, and whether the current room is Clean or Dirty. The robot does not remember previously visited rooms. Draw the environment. Provide PEAS, Rule Table & Limitations.**

#### **Solution:**

#### **1. Diagram of the 5-Room Linear Environment:**
Let the five linearly arranged rooms be labeled **Room 1, Room 2, Room 3, Room 4, and Room 5** from left to right:

```text
+------------+------------+------------+------------+------------+
|   Room 1   |   Room 2   |   Room 3   |   Room 4   |   Room 5   |
| (Clean/    | (Clean/    |  [ROBOT]   | (Clean/    | (Clean/    |
|  Dirty)    |  Dirty)    | <-- or --> |  Dirty)    |  Dirty)    |
+------------+------------+------------+------------+------------+
  (Left end)                                          (Right end)
```

---

#### **2. PEAS Description:**
* **P (Performance Measure):** Number of clean rooms per time step ($+$ points for each clean room), minus penalty for each movement step and energy consumed.
* **E (Environment):** Five linearly connected rooms ($R_1, R_2, R_3, R_4, R_5$), floor surfaces, dirt patches, and end walls at $R_1$ and $R_5$.
* **A (Actuators):** Motorized wheels (`MoveRight`, `MoveLeft`) and vacuum suction motor (`Suck`).
* **S (Sensors):** Local Location Sensor ($R_1, R_2, R_3, R_4, R_5$) and local Dirt Sensor (`Clean`, `Dirty`).

---

#### **3. Simple Reflex Agent Condition–Action Rule Table:**
Because the robot **has no memory** of previously visited rooms, its decision can depend *only* on the current percept $[\text{Location}, \text{Status}]$ ($5 \times 2 = 10$ possible percepts).
* **Rule Strategy:** Whenever the current room is `Dirty`, immediately `Suck`. When `Clean`, move systematically (e.g., `MoveRight` from $R_1 \to R_2 \to R_3 \to R_4 \to R_5$, and `MoveLeft` at $R_5$).

| Rule No. | Current Percept $[\text{Location}, \text{Status}]$ | Condition | Action |
| :---: | :---: | :--- | :---: |
| **1** | $[R_1, \text{Dirty}]$ | Room 1 is Dirty | **`Suck`** |
| **2** | $[R_2, \text{Dirty}]$ | Room 2 is Dirty | **`Suck`** |
| **3** | $[R_3, \text{Dirty}]$ | Room 3 is Dirty | **`Suck`** |
| **4** | $[R_4, \text{Dirty}]$ | Room 4 is Dirty | **`Suck`** |
| **5** | $[R_5, \text{Dirty}]$ | Room 5 is Dirty | **`Suck`** |
| **6** | $[R_1, \text{Clean}]$ | Room 1 is Clean | **`MoveRight`** (to $R_2$) |
| **7** | $[R_2, \text{Clean}]$ | Room 2 is Clean | **`MoveRight`** (to $R_3$) |
| **8** | $[R_3, \text{Clean}]$ | Room 3 is Clean | **`MoveRight`** (to $R_4$) |
| **9** | $[R_4, \text{Clean}]$ | Room 4 is Clean | **`MoveRight`** (to $R_5$) |
| **10** | $[R_5, \text{Clean}]$ | Room 5 is Clean | **`MoveLeft`** (to $R_4$) |

---

#### **4. Limitations of This Simple Reflex Agent in a 5-Room Linear World:**
1. **Infinite Oscillation / Looping Trap (Major Limitation):**
   * Because the agent has **no memory** of which direction it came from or which rooms it has already cleaned, any deterministic rule table gets trapped oscillating between two rooms!
   * For example, in the table above: once at $[R_5, \text{Clean}]$, it executes `MoveLeft` to $R_4$. At $[R_4, \text{Clean}]$, Rule 9 tells it to `MoveRight` back to $R_5$! Thus, it gets **stuck bouncing endlessly between $R_4$ and $R_5$** ($R_4 \leftrightarrow R_5$), and if it started in $R_4$, it will **never reach or clean Rooms $R_1, R_2,$ or $R_3$**!
   * *(Even if we randomized `MoveLeft`/`MoveRight` on clean middle rooms to eventually visit all 5 rooms, a randomized simple reflex agent will waste huge time and energy wandering randomly).*
2. **Cannot Terminate (`NoOp`) When All 5 Rooms Are Clean:**
   * Since the environment is **partially observable** (the robot only sees the current room) and the robot has **no internal state/memory**, it can never know that all 5 rooms are clean. It will keep moving forever and drain its battery.
3. **How to Fix It:** Upgrade the agent to a **Model-Based Reflex Agent** that stores its current movement direction (`Heading = Right` or `Left`) and a checklist of cleaned rooms $[R_1 \dots R_5]$ in internal memory.
