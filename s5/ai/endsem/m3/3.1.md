# Module 3.1: Uninformed Search Strategies – Breadth-First Search (BFS) and Depth-First Search (DFS)

## 1. Foundations of Problem-Solving by Search

### A. Formulating a Search Problem (5 Components)
Before applying any search algorithm, a Goal-Based Agent formulates the problem using **five components**:
1. **Initial State ($s_0$):** The state that the agent starts in.
2. **Actions $\text{ACTIONS}(s)$:** The set of legal actions available to the agent in state $s$.
3. **Transition Model $\text{RESULT}(s, a)$:** Returns the state $s'$ that results from doing action $a$ in state $s$. Together, the Initial State, Actions, and Transition Model implicitly define the **State Space** (a directed graph of states and action links).
4. **Goal Test:** Determines whether a given state is a Goal State.
5. **Path Cost $g(n)$:** Assigns a numeric cost to each path, calculated as the sum of individual **step costs** $c(s, a, s')$ along the path from the root to node $n$. An **optimal solution** has the lowest path cost among all solutions.

### B. Search Tree Terminology
* **Root Node:** Corresponds to the Initial State.
* **Expanding a Node:** Applying legal actions to the current state to generate its **child (successor) nodes**.
* **Frontier (OPEN List):** The collection of nodes that have been generated but not yet expanded (stored as a Queue, Stack, or Priority Queue depending on the search strategy).
* **Explored Set (CLOSED List):** In *Graph Search*, a set that remembers every expanded state so the algorithm does not re-expand repeated states or get trapped in cycles.

---

### C. Four Criteria for Evaluating Search Algorithms
Every search algorithm in AI is evaluated using **four criteria**, expressed in terms of three parameters:
* **$b$ (Branching Factor):** Maximum number of successors (children) of any node.
* **$d$ (Depth of Shallowest Goal):** Depth (number of steps from root) of the shallowest goal node.
* **$m$ (Maximum Depth):** Maximum length of any path in the state space (can be $\infty$ if loops exist).

| Evaluation Criterion | Question It Answers |
| :--- | :--- |
| **1. Completeness** | Is the algorithm guaranteed to find a solution whenever at least one solution exists? |
| **2. Optimality** | Does the strategy always find the **optimal solution** (the one with the lowest path cost among all goal states)? |
| **3. Time Complexity** | How long does it take to find a solution (measured by total number of nodes generated/expanded)? |
| **4. Space Complexity** | How much memory is required to perform the search (maximum number of nodes stored in memory at once)? |

---

## 2. What is Uninformed (Blind) Search?
**Uninformed Search Strategies** (also called **Blind Search**) are given **no additional information** about states beyond what is provided in the problem definition itself.
* They can generate successors and distinguish a goal state from a non-goal state, but they have **no heuristic knowledge** of how "close" or "promising" one non-goal state is compared to another.
* All uninformed search algorithms differ only in the **order in which they expand nodes** from the Frontier.

---

## 3. Breadth-First Search (BFS)

### A. Working Principle
**Breadth-First Search (BFS)** is a simple strategy in which the **root node is expanded first**, then all the successors of the root node are expanded next (depth $1$), then their successors (depth $2$), and so on.
* In general, **all nodes are expanded at a given depth $d$ in the search tree before any nodes at the next level $d + 1$ are expanded** (Level-Order Traversal).
* **Data Structure Used:** **FIFO (First-In, First-Out) Queue**. New child nodes are inserted (`ENQUEUE`) at the **back (tail)** of the queue, and the next node to expand (`DEQUEUE`) is always taken from the **front (head)** of the queue.

[Click here to see the diagram for Breadth-First Search (BFS) Level by Level Expansion Tree](https://www.google.com/search?udm=2&q=Breadth+First+Search+BFS+tree+traversal+level+order+diagram)

### B. Example Step-by-Step Trace of BFS
Consider the binary tree below where $A$ is the Start node and $G$ is the Goal node:
```text
          (A)          <-- Depth 0
         /   \
       (B)   (C)       <-- Depth 1
       / \   / \
     (D) (E)(F) (G*)   <-- Depth 2 (Goal G)
```

| Step | Node Expanded | Frontier (FIFO Queue: Front $\rightarrow$ Back) | Explored Set (CLOSED) |
| :---: | :---: | :--- | :--- |
| **Init** | — | `[A]` | `{}` |
| **1** | `A` | `[B, C]` | `{A}` |
| **2** | `B` | `[C, D, E]` | `{A, B}` |
| **3** | `C` | `[D, E, F, G]` | `{A, B, C}` |
| **4** | **`G` (or Goal Test on generation)** | Goal `G` found at Depth $d = 2$! | Path: `A -> C -> G` |

---

### C. Algorithm / Pseudocode for BFS
```text
function BREADTH-FIRST-SEARCH(problem) returns a solution, or failure
    node <- a node with STATE = problem.INITIAL-STATE, PATH-COST = 0
    if problem.GOAL-TEST(node.STATE) then return SOLUTION(node)
    frontier <- a FIFO queue with node as the only element
    explored <- an empty set
    loop do
        if EMPTY?(frontier) then return failure
        node <- POP(frontier) /* chooses the shallowest node in frontier */
        add node.STATE to explored
        for each action in problem.ACTIONS(node.STATE) do
            child <- CHILD-NODE(problem, node, action)
            if child.STATE is not in explored or frontier then
                if problem.GOAL-TEST(child.STATE) then return SOLUTION(child)
                INSERT(child, frontier) /* inserts at back of FIFO queue */
```

---

### D. Evaluation Properties of BFS
1. **Completeness:** **Yes (Complete)**, provided the branching factor $b$ is finite (even if maximum depth $m = \infty$, BFS will eventually reach depth $d$).
2. **Optimality:**
   * **Yes, Optimal ONLY IF all step costs are equal** (e.g., unweighted graph where every edge cost $= 1$, or when path cost is a non-decreasing function of depth $d$). It always finds the **shallowest goal node** (fewest number of edges/hops).
   * **Not Optimal for weighted graphs** with different edge costs (Uniform Cost Search is needed there!).
3. **Time Complexity:**
   At depth $0, 1, 2, \dots, d$, the number of nodes generated is:

$$
1 + b + b^2 + b^3 + \dots + b^d = O(b^d)
$$

   *(Note: If the goal test is applied when a node is popped for expansion rather than when generated, time complexity is $O(b^{d+1})$).*
4. **Space Complexity:** **$O(b^d)$** (or $O(b^{d+1})$).
   * **Major Bottleneck of BFS:** Because every expanded node remains in the `explored` set ($O(b^{d-1})$) and every node at the current level remains in the `frontier` queue ($O(b^d)$), **memory consumption grows exponentially**. In practice, BFS runs out of RAM long before it runs out of time!

## 4. Depth-First Search (DFS)

### A. Working Principle
**Depth-First Search (DFS)** always expands the **deepest node** in the current frontier of the search tree.
* The search proceeds immediately to the deepest level of the search tree, where the nodes have no successors.
* Once those nodes are expanded, they are dropped from the frontier, and the search **"backtracks"** to the next deepest node that still has unexplored successors.
* **Data Structure Used:** **LIFO (Last-In, First-Out) Stack** (or recursive function call stack). New child nodes are pushed (`PUSH`) onto the **top** of the stack, and the next node to expand (`POP`) is also taken from the **top** of the stack.

[Click here to see the diagram for Depth-First Search (DFS) Tree Traversal and Backtracking](https://www.google.com/search?udm=2&q=Depth+First+Search+DFS+tree+traversal+order+diagram)

### B. Example Step-by-Step Trace of DFS
Using the same binary tree where $A$ is Start and $G$ is Goal:
```text
          (A)
         /   \
       (B)   (C)
       / \   / \
     (D) (E)(F) (G*)
```

| Step | Node Expanded | Frontier (LIFO Stack: Top $\rightarrow$ Bottom) | Action / Note |
| :---: | :---: | :--- | :--- |
| **Init** | — | `[A]` | Start at root |
| **1** | `A` | `[B, C]` | Push children of `A` |
| **2** | `B` | `[D, E, C]` | Expand deepest node `B` |
| **3** | `D` | `[E, C]` | `D` is a leaf (dead end) $\rightarrow$ Backtrack |
| **4** | `E` | `[C]` | `E` is a leaf (dead end) $\rightarrow$ Backtrack |
| **5** | `C` | `[F, G]` | Expand `C` |
| **6** | `F` | `[G]` | `F` is a leaf (dead end) $\rightarrow$ Backtrack |
| **7** | **`G`** | `[]` | **Goal `G` found!** Path: `A -> C -> G` |

---

### C. Evaluation Properties of DFS
1. **Completeness:**
   * **Tree-Search DFS:** **No (Incomplete)**—if the state space has infinite paths ($m = \infty$) or cycles/loops, DFS can get trapped going down an infinite branch forever, even if a goal is right next to the root at depth $1$!
   * **Graph-Search DFS:** **Complete in finite state spaces** (since it tracks visited states to avoid cycles), but still incomplete in infinite state spaces.
2. **Optimality:** **No (Not Optimal)**.
   * Suppose a goal $G_1$ exists in the left subtree at depth $d = 100$, and a much closer goal $G_2$ exists in the right subtree at depth $d = 1$. DFS explores the entire left subtree first, finds $G_1$ at depth $100$, and returns that suboptimal path!
3. **Time Complexity:** **$O(b^m)$**, where $m$ is the maximum depth of any node in the state space.
   * Terrible if $m$ is much larger than $d$ ($m \gg d$), though it can be fast if many goals exist deep in the tree.
4. **Space Complexity (The Biggest Advantage of DFS!):** **$O(b \cdot m)$** (Linear Space Complexity!).
   * **Why is DFS so memory-efficient?** A Tree-Search DFS only needs to store a **single path** from the root to a leaf node (of length at most $m$), along with the remaining unexpanded sibling nodes at each step along that path ($b$ siblings per level). Once a subtree is fully explored, it is removed from memory completely!
   * *Example:* If $b = 10$ and $d = m = 12$, BFS needs petabytes of RAM ($10^{12}$ nodes), whereas DFS needs only $10 \times 12 = 120$ nodes (a few kilobytes!).

---

## 5. Comparison Table: BFS vs. DFS

| Feature | Breadth-First Search (BFS) | Depth-First Search (DFS) |
| :--- | :--- | :--- |
| **Traversal Order** | Level-by-level (shallowest nodes first). | Branch-by-branch (deepest nodes first, then backtracks). |
| **Data Structure** | **FIFO Queue** (First-In, First-Out). | **LIFO Stack** (Last-In, First-Out) / Recursion. |
| **Completeness** | **Yes** (if branching factor $b$ is finite). | **No** in infinite trees/cycles (Yes only in finite graph search). |
| **Optimality** | **Yes** (when all step/edge costs are identical). | **No** (can find a deep, expensive goal before a shallow one). |
| **Time Complexity** | $O(b^d)$ — depends on shallowest goal depth $d$. | $O(b^m)$ — depends on maximum tree depth $m$. |
| **Space Complexity** | **$O(b^d)$ (Exponential — very high memory)** | **$O(bm)$ (Linear — extremely memory-efficient)** |
| **Best Used When** | Goal is known to be close to the root ($d$ is small) and shortest-hop path is required. | Memory is severely limited, solutions are deep in the tree, or all paths must be explored. |

## 6. Solved University & Internal Exam Questions

### Question 1 [Series Test-II, Part B, Q8(b) (5 Marks)]
> **State and explain the advantages and disadvantages of DFS and BFS in practical applications.**

#### **Solution:**

#### **1. Breadth-First Search (BFS) in Practical Applications**

* **Advantages of BFS:**
  1. **Guaranteed Completeness:** As long as the branching factor $b$ is finite, BFS is guaranteed to find a solution if one exists without getting trapped in infinite deep paths.
  2. **Guaranteed Shortest Path (in Unweighted Graphs):** When all edge/step costs are equal, BFS always finds the **minimum-hop (optimal) path** because it explores all nodes at distance $d$ before distance $d+1$.
  3. **Ideal for Shallow Goals:** Very fast when the target node is located within a few steps of the starting state.
* **Disadvantages of BFS:**
  1. **Exponential Memory Bottleneck ($O(b^d)$):** BFS must keep every generated node at the current frontier level in memory at once. In large practical state spaces (like robotics or game trees), it quickly exhausts system RAM.
  2. **Ignores Edge Weights:** In weighted road networks or drone routing, BFS returns the path with the fewest edges rather than the minimum total cost.
* **Practical Applications of BFS:**
  * Finding the shortest-hop path in **unweighted networks** (e.g., Peer-to-Peer routing, degrees of separation in Social Networks like LinkedIn/Facebook).
  * **Web Crawlers** (indexing pages within $k$ clicks of a seed URL) and **GPS broadcasting**.

---

#### **2. Depth-First Search (DFS) in Practical Applications**

* **Advantages of DFS:**
  1. **Extremely Low (Linear) Memory Requirement ($O(bm)$):** DFS only stores the current active path from the root to the current node plus unexpanded siblings. This makes it ideal for memory-constrained embedded systems.
  2. **Fast When Solutions Are Deep & Plentiful:** If valid solutions only exist at deep leaf levels (e.g., placing all $N$ queens in the **N-Queens problem** or solving **Sudoku**), DFS dives straight to depth $m$ without wasting time expanding every intermediate level horizontally.
  3. **Natural Fit for Backtracking & Cycle Detection:** Easily implemented via recursion for constraint satisfaction problems.
* **Disadvantages of DFS:**
  1. **Not Optimal:** Returns the first goal it encounters down a deep branch, even if a much shorter solution exists in an adjacent branch.
  2. **Risk of Infinite Loops (Incompleteness):** Without cycle checking or depth limits, DFS can get stuck forever exploring an infinite or cyclic branch.
  3. **High Worst-Case Time ($O(b^m)$):** Wastes huge time if it explores deep dead-end subtrees when the actual goal is very shallow ($m \gg d$).
* **Practical Applications of DFS:**
  * **Backtracking Puzzles & Constraint Satisfaction** (N-Queens, Sudoku, Maze solving).
  * **Topological Sorting**, **Deadlock / Cycle Detection** in operating systems, and **Compiler syntax tree traversal**.

### Question 2 [Series Test-II, Part B, Q7(a)(ii) (Part of 5 Marks)]
> **A delivery drone must fly from $S$ to $G$ over the directed weighted graph given below (edge costs in brackets):**
>
> $$
> S \to A (1), \quad S \to B (4), \quad S \to G (12), \quad A \to B (2), \quad A \to C (5), \quad B \to C (1), \quad B \to G (9), \quad C \to G (3)
> $$
>
> **(i) Apply Uniform Cost Search...** *(Solved in full in Module 3.2)*  
> **(ii) Which path would BFS return? Explain why it differs from (i).**

#### **Solution for Part (ii):**
1. **Path Returned by BFS:**
   * From start node $S$, its immediate neighbors at **Depth $1$ ($1$ hop)** are $A$, $B$, and $G$ (via the direct edge $S \to G$ with cost $12$).
   * Therefore, **BFS returns the direct 1-edge path: $S \to G$**, which has a total path cost of **$12$**.
2. **Why It Differs from Uniform Cost Search (UCS):**
   * **BFS is blind to edge weights (step costs):** It expands nodes strictly in order of **node depth $d$ (number of edges/hops)** from the root. Since $S \to G$ has only $1$ edge ($d = 1$), BFS considers it "closest" and terminates immediately.
   * **UCS expands nodes in order of cumulative path cost $g(n)$:** UCS discovers that the 4-edge path **$S \to A \to B \to C \to G$** has a total cost of $1 + 2 + 1 + 3 = \mathbf{7}$, which is much cheaper than the 1-edge path $S \to G$ (cost $12$). Thus, BFS is **only optimal when all edge costs are equal**, whereas UCS is optimal for any positive edge costs.
