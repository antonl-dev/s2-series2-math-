# Module 3.4: $A^*$ Search Algorithm

## 1. Introduction & Core Principle of $A^*$ Search
The **$A^*$ Search Algorithm** (pronounced *"A-star"*, developed by Peter Hart, Nils Nilsson, and Bertram Raphael in 1968 for the Shakey robot project) is the most widely known form of **Best-First Search** in Artificial Intelligence.

### Why $A^*$ Was Created: Combining UCS and Greedy Best-First Search
* **Uniform Cost Search (UCS)** minimizes $g(n)$ (cost spent so far)—it is **optimal**, but slow and blind because it explores in all directions equally.
* **Greedy Best-First Search** minimizes $h(n)$ (estimated cost remaining to the goal)—it is **fast** and goal-directed, but **not optimal** because it ignores the cost already spent.
* **$A^*$ Search combines both** by evaluating nodes using the sum of $g(n)$ and $h(n)$:

$$f(n) = g(n) + h(n)$$

Where:
* **$g(n)$:** The **actual path cost** from the start node (root) to the current node $n$.
* **$h(n)$:** The **heuristic estimated cost** of the cheapest path from node $n$ to the goal state.
* **$f(n)$:** The **estimated total cost of the cheapest solution path passing through node $n$**.

## 2. Step-by-Step Working Algorithm of $A^*$ Search
$A^*$ maintains two data structures:
1. **`OPEN` List (Frontier):** A **Min-Priority Queue** of generated but unexpanded nodes, ordered by **lowest $f(n) = g(n) + h(n)$**.
2. **`CLOSED` List (Explored Set):** A set of nodes that have already been expanded.

### Algorithm Steps:
1. **Step 1 (Initialization):**
   * Create the start node $S$ with $g(S) = 0$ and $f(S) = 0 + h(S) = h(S)$.
   * Insert $S$ into the `OPEN` list. Initialize `CLOSED` as empty.
2. **Step 2 (Failure Check):**
   * If `OPEN` is empty, terminate and return `Failure` (no path exists).
3. **Step 3 (Select Node with Minimum $f(n)$):**
   * Pop the node $n$ from `OPEN` that has the **smallest $f(n)$ value** and place $n$ into `CLOSED`.
   * *(Tie-breaking rule: If two nodes have the exact same $f(n)$, prefer the Goal node or the node with smaller $h(n)$ / alphabetical order).*
4. **Step 4 (Goal Test Upon Expansion):**
   * If the popped node $n$ is the **Goal State**, terminate and reconstruct the optimal path by following parent pointers back to $S$, returning total cost $g(n) = f(n)$.
5. **Step 5 (Expand Node $n$ & Update Neighbors):**
   * For each successor (neighbor) $m$ of $n$ connected by edge cost $c(n, m)$:
     * Compute tentative path cost: $g_{\text{new}}(m) = g(n) + c(n, m)$
     * Compute evaluation value: $f_{\text{new}}(m) = g_{\text{new}}(m) + h(m)$
     * **Case A ($m$ is not in `OPEN` or `CLOSED`):** Set parent of $m$ to $n$ and insert $m$ into `OPEN` with $f_{\text{new}}(m)$.
     * **Case B ($m$ is already in `OPEN` with higher cost $g_{\text{old}}(m) > g_{\text{new}}(m)$):** Update $m$'s $g$ and $f$ values to $g_{\text{new}}(m)$ and $f_{\text{new}}(m)$, and update its parent pointer to $n$.
     * **Case C ($m$ is in `CLOSED` with $g_{\text{old}}(m) > g_{\text{new}}(m)$):** *(Only possible if heuristic is inconsistent)* Update $m$'s cost and move $m$ back to `OPEN`.
6. **Step 6 (Repeat):** Go back to **Step 2**.

## 3. Conditions for Optimality: Admissibility and Consistency

$A^*$ is guaranteed to be **optimal** (always finding the true minimum-cost path) if the heuristic function $h(n)$ satisfies specific mathematical conditions:

### A. Admissible Heuristic (Required for Tree-Search Optimality)
Let **$h^*(n)$** denote the **true (actual) minimum cost** to reach the goal from node $n$.

A heuristic function $h(n)$ is **Admissible** if it **never overestimates** the true cost to reach the goal from any node $n$:
$$0 \le h(n) \le h^*(n) \quad \text{for all nodes } n$$

* **Intuition:** An admissible heuristic is **optimistic**—it always thinks the cost of solving the problem is less than or equal to what it actually is.
* **Why Admissibility Guarantees Optimality:** Because $h(n) \le h^*(n)$, $f(n) = g(n) + h(n)$ never overestimates the true cost of a path through $n$. Therefore, $A^*$ will **never** expand a suboptimal goal node $G_2$ (where $f(G_2) = g(G_2) > C^*$) as long as there is an unexpanded node $n$ on an optimal path in `OPEN` (whose $f(n) \le C^* < f(G_2)$).
* **Classic Example:** Straight-Line Distance ($h_{\text{SLD}}$) between two cities on a map is always admissible because the shortest distance between two points is a straight line—no road can ever be shorter than a straight line!

---

### B. Consistent (Monotonic) Heuristic (Required for Graph-Search Optimality)
A heuristic $h(n)$ is **Consistent** (or **Monotonic**) if, for every node $n$ and every successor $n'$ of $n$ generated by any action $a$ with step cost $c(n, a, n')$:
$$h(n) \le c(n, a, n') + h(n')$$

* **Intuition:** This is the general **Triangle Inequality**—the estimated cost from $n$ to the goal cannot be greater than the step cost of moving to neighbor $n'$ plus the estimated cost from $n'$ to the goal.
* **Key Consequence:** If $h(n)$ is consistent, then the values of $f(n)$ along any path are **non-decreasing** ($f(n') \ge f(n)$), and whenever $A^*$ pops a node $n$ for expansion, it is guaranteed to have already found the optimal path to $n$.
* **Relationship:** Every consistent heuristic is automatically **admissible**, and almost all natural admissible heuristics (like Straight-Line Distance and Manhattan Distance) are also consistent.

## 4. Properties, Advantages & Disadvantages of $A^*$ Search

### Evaluation Summary:
1. **Completeness:** **Yes (Complete)**, provided the branching factor $b$ is finite and step costs are $\ge \epsilon > 0$.
2. **Optimality:** **Yes (Optimal)**, provided $h(n)$ is admissible (for Tree-Search) / consistent (for Graph-Search).
3. **Optimal Efficiency:** Among all optimal search algorithms that use the same heuristic information $h(n)$, **$A^*$ is optimally efficient**—no other optimal algorithm is guaranteed to expand fewer nodes than $A^*$ (except possibly on tie-breaking where $f(n) = C^*$).
4. **Time Complexity:** Exponential in the worst case ($O(b^d)$), depending on the heuristic error $|h^*(n) - h(n)|$.
5. **Space Complexity (Main Limitation):** **$O(b^d)$** — Because $A^*$ keeps **all generated nodes in memory** (`OPEN` and `CLOSED` lists), it usually runs out of memory before it runs out of time on very large problems (solved by memory-bounded variants like **IDA\***—Iterative Deepening $A^*$).

### Question 1 [End Semester Exam - Nov 2025, Part A, Q5 (2 Marks)]
> **Write any two advantages of $A^*$ search algorithm.**

#### **Solution:**
Any two of the following advantages can be written for full marks:
1. **Complete and Guaranteed Optimal:** Unlike Greedy Best-First Search or DFS, $A^*$ is both **complete** and **guaranteed to find the minimum-cost (optimal) path**, provided the heuristic function $h(n)$ is admissible ($h(n) \le h^*(n)$).
2. **Optimally Efficient:** By combining actual path cost $g(n)$ and heuristic estimate $h(n)$ into $f(n) = g(n) + h(n)$, $A^*$ expands the **minimum number of nodes** needed to guarantee an optimal solution—far fewer nodes than uninformed Uniform Cost Search or BFS.
3. **Versatile Across Weighted Graphs and Grids:** It handles variable edge costs, obstacles, and complex state spaces seamlessly in robotics, GPS routing, and puzzle solving.

#### **Solution:**

#### **1. Working of $A^*$ Search Algorithm (for End Sem Q16(a)):**
* $A^*$ is an informed best-first graph search algorithm that finds the least-cost path from an initial state $S$ to a goal state $G$.
* It evaluates each node $n$ using the evaluation function:
  $$f(n) = g(n) + h(n)$$
  where $g(n)$ is the exact cumulative path cost from the start node $S$ to $n$, and $h(n)$ is an admissible heuristic estimate of the remaining cost from $n$ to $G$ ($0 \le h(n) \le h^*(n)$).
* **Working Steps:**
  1. Place the start node $S$ in a Min-Priority Queue called **`OPEN`** with $g(S)=0$ and $f(S)=h(S)$, and initialize **`CLOSED`** as empty.
  2. In each iteration, pop the node $n$ from `OPEN` that has the **lowest $f(n)$ value** and add it to `CLOSED`.
  3. If $n$ is the Goal node $G$, stop and return the path and cost $g(G)$.
  4. Otherwise, expand $n$ by generating each neighbor $m$. Calculate $g_{\text{new}}(m) = g(n) + c(n, m)$ and $f_{\text{new}}(m) = g_{\text{new}}(m) + h(m)$. Insert $m$ into `OPEN` (or update $m$ in `OPEN` if a cheaper path with lower $g(m)$ is found).
  5. Repeat until $G$ is popped from `OPEN`.

#### **3. Solution to Series Test-II Q8(a)(ii): Compute True Remaining Cost $h^*(n)$ and Verify Admissibility**

Let us compute the **true minimum remaining cost $h^*(n)$** from every node $n$ to the Goal $G$:
* **From $G$:** Already at Goal $\implies \mathbf{h^*(G) = 0}$.
* **From $D$:** Only path is $D \xrightarrow{3} G \implies \mathbf{h^*(D) = 3}$.
* **From $C$:** Only path is $C \xrightarrow{6} G \implies \mathbf{h^*(C) = 6}$.
* **From $B$:** Path is $B \xrightarrow{2} D \xrightarrow{3} G \implies 2 + 3 = \mathbf{h^*(B) = 5}$.
* **From $A$:** Two paths to $G$:
  * Path 1: $A \xrightarrow{4} C \xrightarrow{6} G$ (cost $= 10$)
  * Path 2: $A \xrightarrow{6} D \xrightarrow{3} G$ (cost $= 9$)
  * Minimum true cost $\implies \mathbf{h^*(A) = \min(10, 9) = 9}$.
* **From $S$:** Three paths to $G$:
  * Path 1: $S \xrightarrow{1} A \xrightarrow{4} C \xrightarrow{6} G$ (cost $= 11$)
  * Path 2: $S \xrightarrow{1} A \xrightarrow{6} D \xrightarrow{3} G$ (cost $= 10$)
  * Path 3: $S \xrightarrow{4} B \xrightarrow{2} D \xrightarrow{3} G$ (cost $= 9$)
  * Minimum true cost $\implies \mathbf{h^*(S) = \min(11, 10, 9) = 9}$.

| Node $n$ | Given Heuristic $h(n)$ | True Minimum Remaining Cost $h^*(n)$ | Condition $h(n) \le h^*(n)$ | Status |

#### **4. Solution to End Sem Nov 2025 Q16(b): Two Real-World Examples Where $A^*$ Search is Applied (3 Marks)**

1. **GPS Navigation & Autonomous Vehicle Route Planning (e.g., Google Maps, Waze, Delivery Drones):**
   * **How $A^*$ is used:** Road intersections are modeled as graph nodes and road segments as weighted edges ($g(n)$ = actual driving distance or travel time from the start). The straight-line geographical (Euclidean / Haversine) distance to the destination is used as the admissible heuristic $h(n)$. This allows GPS systems to compute the optimal route across millions of roads in milliseconds without exploring roads heading in the opposite direction.
2. **Video Game Pathfinding & Mobile Robotics (e.g., StarCraft, Age of Empires, Unity/Unreal NavMesh, Warehouse Robots):**
   * **How $A^*$ is used:** In real-time strategy games and autonomous warehouse robots (e.g., Amazon Kiva robots), characters/robots must navigate around walls, dynamic obstacles, and varying terrain costs on a 2D grid or navigation mesh. $A^*$ (using Manhattan or Euclidean distance as $h(n)$) finds the shortest collision-free trajectory to the target location in real time.
