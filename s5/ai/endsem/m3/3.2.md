# Module 3.2: Iterative Deepening DFS (IDDFS) and Uniform Cost Search (UCS)

## Part 1: Iterative Deepening Depth-First Search (IDDFS / IDS)

### 1. From Depth-Limited Search (DLS) to Iterative Deepening (IDDFS)
* **The Problem with Standard DFS:** In trees with infinite branches ($m = \infty$) or cycles, standard DFS gets trapped going down a single deep path forever and is **incomplete** and **non-optimal**.
* **Depth-Limited Search (DLS):** Fixes the infinite-path problem by imposing a predetermined depth limit $\ell$—nodes at depth $\ell$ are treated as if they have no successors. However, if we guess $\ell < d$ (where $d$ is the shallowest goal depth), DLS fails to find the goal!
* **The Solution — Iterative Deepening DFS (IDDFS):**
  **Iterative Deepening Search** solves the problem of picking the right depth limit by gradually increasing the limit: first running Depth-Limited Search with limit $\ell = 0$, then $\ell = 1$, then $\ell = 2$, and so on, until a goal is found at depth $d$!

[Click here to see the diagram for Iterative Deepening Depth First Search Iterations l=0, 1, 2, 3](https://www.google.com/search?udm=2&q=Iterative+Deepening+Depth+First+Search+IDDFS+iterations+diagram+Russell+Norvig)

---

### 2. Why IDDFS is the "Best of Both Worlds" (BFS + DFS)
IDDFS combines the best properties of **Breadth-First Search (BFS)** and **Depth-First Search (DFS)**:
1. **Like BFS:** It explores all nodes at depth $\ell$ before moving to depth $\ell + 1$, so it is **Complete** (when $b$ is finite) and **Optimal** (when all step costs are equal).
2. **Like DFS:** At any given instant, it is simply performing a standard Depth-First Search up to depth $\ell$, so its **Space Complexity is linear: $O(b \cdot d)$** instead of BFS's exponential $O(b^d)$!

---

### 3. Pseudocode for IDDFS
```text
function ITERATIVE-DEEPENING-SEARCH(problem) returns a solution, or failure
    for depth = 0 to infinity do
        result <- DEPTH-LIMITED-SEARCH(problem, depth)
        if result != cutoff then return result
```

---

### 4. Mathematical Analysis of Node Re-generation Overhead in IDDFS
A common question is: *"Doesn't IDDFS waste a lot of time by regenerating upper-level nodes over and over again in each iteration?"*

**Answer: No! The overhead is surprisingly small.**
* **Why?** In a search tree with branching factor $b$, the vast majority of nodes lie at the **bottom-most level $d$**.
* In IDDFS searching up to depth $d$:
  * Nodes at the bottom level (depth $d$) are generated **only once** (in the final iteration $\ell = d$).
  * Nodes at depth $d - 1$ are generated **$2$ times** (in iterations $\ell = d-1$ and $\ell = d$).
  * Nodes at depth $d - 2$ are generated **$3$ times** ...
  * Nodes at depth $1$ are generated **$d$ times**.
  * The root node (depth $0$) is generated **$d + 1$ times** (for $\ell = 0, 1, \dots, d$).

#### **Total Nodes Generated by IDDFS up to Depth $d$:**

$$
N(\text{IDDFS}) = (d + 1)b^0 + d b^1 + (d - 1)b^2 + \dots + 2 b^{d-1} + 1 b^d
$$

#### **Comparison with BFS up to Depth $d$:**

$$
N(\text{BFS}) = b^0 + b^1 + b^2 + \dots + b^{d-1} + b^d = \dfrac{b^{d+1} - 1}{b - 1}
$$

* **Asymptotic Ratio:** For branching factor $b$, the total nodes generated by IDDFS is only about $\displaystyle \frac{b}{b - 1}$ times that of BFS!
  * For $b = 10$ and $d = 5$: $N(\text{BFS}) = 111,111$ and $N(\text{IDDFS}) = 123,456$ (only **$11\%$ extra overhead** in exchange for reducing memory from $100,000$ nodes down to just $50$ nodes!).
* **Rule of Thumb:** **Iterative Deepening is the preferred uninformed search method when the search space is large and the depth of the solution is not known.**

## Part 2: Uniform Cost Search (UCS)

### 1. Working Principle of Uniform Cost Search
When step costs (edge weights) are **not equal**, Breadth-First Search is no longer optimal because it expands the *shallowest* node (fewest edges) rather than the *cheapest* node.

**Uniform Cost Search (UCS)** is a generalization of BFS (and is equivalent to **Dijkstra's Algorithm** for finding the shortest path to a single goal):
* Instead of expanding the shallowest node, **UCS always expands the node $n$ in the frontier with the lowest cumulative path cost $g(n)$ from the start node**.
* **Data Structure Used:** A **Min-Priority Queue** ordered by path cost $g(n)$, where $\displaystyle g(n) = \sum \text{edge costs from Root to } n$.

[Click here to see the diagram for Uniform Cost Search Priority Queue Expansion](https://www.google.com/search?udm=2&q=Uniform+Cost+Search+weighted+graph+example+AI)

---

### 2. Two Crucial Rules in Uniform Cost Search (Exam Must-Know!)
Unlike BFS, UCS has two special operational rules to guarantee optimality:

1. **Goal Test is Applied Upon EXPANSION (When Popped from Frontier), NOT Upon Generation:**
   * When a goal node $G$ is first *generated* and added to the priority queue, it might be via a suboptimal (expensive) direct edge (e.g., $S \to G$ with cost $12$).
   * UCS does **not** stop when $G$ is first generated; it waits until $G$ has the **lowest $g(n)$ at the front of the Priority Queue and is popped for expansion**, guaranteeing that no cheaper path to $G$ can possibly exist!
2. **Updating Frontier When a Cheaper Path is Found (`REPLACE-IF-CHEAPER`):**
   * If a newly generated child state $X$ is **already in the frontier** with a higher path cost $g_{\text{old}}(X) > g_{\text{new}}(X)$, UCS replaces the old frontier node with the new cheaper node $(X : g_{\text{new}})$ and updates its parent pointer.

---

### 3. Pseudocode for Uniform Cost Search
```text
function UNIFORM-COST-SEARCH(problem) returns a solution, or failure
    node <- a node with STATE = problem.INITIAL-STATE, PATH-COST = 0
    frontier <- a priority queue ordered by PATH-COST g(n), with node as the only element
    explored <- an empty set
    loop do
        if EMPTY?(frontier) then return failure
        node <- POP(frontier) /* chooses the lowest-cost node in frontier */
        if problem.GOAL-TEST(node.STATE) then return SOLUTION(node)
        add node.STATE to explored
        for each action in problem.ACTIONS(node.STATE) do
            child <- CHILD-NODE(problem, node, action)
            if child.STATE is not in explored or frontier then
                INSERT(child, frontier)
            else if child.STATE is in frontier with higher PATH-COST then
                replace that frontier node with child
```

### 4. Evaluation Properties of Uniform Cost Search
Let:
* **$C^*$** $=$ Cost of the optimal solution path.
* **$\epsilon$ (epsilon)** $=$ Minimum positive step cost of any action ($c(s, a, s') \ge \epsilon > 0$).

1. **Completeness:** **Yes (Complete)**, provided every step cost is strictly positive ($c(s, a, s') \ge \epsilon > 0$) so the algorithm cannot get stuck in an infinite loop of zero-cost actions.
2. **Optimality:** **Yes (Always Optimal)** for any graph with non-negative (strictly positive $\ge \epsilon$) edge weights, because nodes are expanded in monotonically non-decreasing order of $g(n)$.
3. **Time Complexity:** **$O\left(b^{1 + \lfloor C^*/\epsilon \rfloor}\right)$**
   * Notice that UCS is guided by path cost rather than depth, so its worst-case complexity depends on $\lfloor C^*/\epsilon \rfloor$ (the maximum number of tiny $\epsilon$-cost steps UCS might explore before reaching cost $C^*$). When all step costs are equal ($C^*/\epsilon = d$), this simplifies to $O(b^{d+1})$.
4. **Space Complexity:** **$O\left(b^{1 + \lfloor C^*/\epsilon \rfloor}\right)$** (Exponential, as all generated frontier and explored nodes are kept in memory).

## Part 3: Solved University & Internal Exam Questions

### Question 1 [End Semester Exam - Nov 2025, Part B, Q15 (8 Marks)]
> **(a) Compare Iterative DFS and Uniform Cost Search in terms of completeness, optimality, time, and space. (5 Marks)**  
> **(b) Give one real-world application for Iterative DFS and Uniform Cost Search. (3 Marks)**

#### **Solution:**

#### **Part (a): Comparison of Iterative Deepening DFS (IDDFS) and Uniform Cost Search (UCS) (5 Marks)**

| Criterion | Iterative Deepening DFS (IDDFS) | Uniform Cost Search (UCS) |
| :--- | :--- | :--- |
| **Core Mechanism & Data Structure** | Repeatedly runs Depth-Limited DFS for depth limits $\ell = 0, 1, 2, \dots, d$ using a **LIFO Stack**. | Expands the node $n$ with the lowest cumulative path cost $g(n)$ using a **Min-Priority Queue**. |
| **1. Completeness** | **Complete** (Yes), provided the branching factor $b$ is finite. | **Complete** (Yes), provided $b$ is finite and every step cost is strictly positive ($c(s, a, s') \ge \epsilon > 0$). |
| **2. Optimality** | **Optimal ONLY IF all step costs are equal** (finds the shallowest goal at minimum depth $d$). Not optimal for general weighted graphs. | **Always Optimal** for any positive step costs (guaranteed to find the minimum total cost path $C^*$ even when edge weights vary). |
| **3. Time Complexity** | **$O(b^d)$**, where $b$ is the branching factor and $d$ is the depth of the shallowest goal node. | **$O\left(b^{1 + \lfloor C^*/\epsilon \rfloor}\right)$**, where $C^*$ is the optimal path cost and $\epsilon$ is the minimum step cost (reduces to $O(b^{d+1})$ if all costs are equal). |
| **4. Space Complexity** | **$O(b \cdot d)$ — Linear Space!** Extremely memory-efficient because it only stores the current DFS branch in memory. | **$O\left(b^{1 + \lfloor C^*/\epsilon \rfloor}\right)$ — Exponential Space!** High memory usage because it stores all frontier and explored nodes in memory. |

#### **Part (b): Real-World Applications of IDDFS and UCS (3 Marks)**

1. **Real-World Application of Iterative Deepening DFS (IDDFS):**
   * **Game-Playing AI Engines (e.g., Chess, Checkers, Shogi):**
     * In tournament Chess engines, the game tree is enormous ($b \approx 35$, depth $m \approx 80$) and the AI has a strict time limit per move (e.g., $10$ seconds).
     * IDDFS allows the engine to search completely up to depth $1$, then depth $2$, then depth $3$, etc., while using minimal linear memory $O(bd)$. If the move timer expires mid-search during depth $k$, the AI can immediately play the best move found in the completed depth $k-1$ iteration (**"Anytime Algorithm"** property).
   * *(Alternative Application: Solving large state-space puzzles like the **15-Puzzle** or **Rubik's Cube** (via IDA*) where BFS would crash due to out-of-memory errors).*

2. **Real-World Application of Uniform Cost Search (UCS):**
   * **GPS Road Navigation & Network Packet Routing (OSPF Protocol):**
     * In **Google Maps / Delivery Drone Routing**, road segments have different travel times, distances, or toll costs, and in **Internet Routers (Open Shortest Path First - OSPF)**, communication links have different bandwidths and latencies.
     * Since edge weights are unequal, UCS (Dijkstra's search) is used to find the guaranteed minimum-cost / minimum-latency route from the source to the destination.

### Question 2 [Series Test-II, Part A, Q1 (2 Marks)]
> **Iterative Deepening DFS (IDDFS) is applied to a tree with uniform branching factor $b = 3$. The only goal is the last node generated at depth $3$. Counting the root in every iteration, find the total number of nodes generated by IDDFS (depth limits $0, 1, 2, 3$) and by BFS up to depth $3$. Is the re-generation overhead of IDDFS significant? Justify.**

#### **Solution:**

**Given:** Branching factor $b = 3$, Goal depth $d = 3$ (last node at depth $3$).

#### **1. Number of Nodes Generated by BFS up to Depth $3$:**
At each depth level $k \in \{0, 1, 2, 3\}$, the number of nodes is $b^k = 3^k$:
* Depth $0$ (Root): $3^0 = 1$
* Depth $1$: $3^1 = 3$
* Depth $2$: $3^2 = 9$
* Depth $3$: $3^3 = 27$

$$
N(\text{BFS}) = 1 + 3 + 9 + 27 = \mathbf{40\text{ nodes}}
$$

---

#### **2. Number of Nodes Generated by IDDFS (for Depth Limits $\ell = 0, 1, 2, 3$):**
* **Iteration $\ell = 0$:** Generates $3^0 = \mathbf{1}$ node.
* **Iteration $\ell = 1$:** Generates $3^0 + 3^1 = 1 + 3 = \mathbf{4}$ nodes.
* **Iteration $\ell = 2$:** Generates $3^0 + 3^1 + 3^2 = 1 + 3 + 9 = \mathbf{13}$ nodes.
* **Iteration $\ell = 3$:** Generates $3^0 + 3^1 + 3^2 + 3^3 = 1 + 3 + 9 + 27 = \mathbf{40}$ nodes.

**Total Nodes Generated by IDDFS:**

$$
N(\text{IDDFS}) = 1 + 4 + 13 + 40 = \mathbf{58\text{ nodes}}
$$

*(Or using the direct formula: $(4 \times 1) + (3 \times 3) + (2 \times 9) + (1 \times 27) = 4 + 9 + 18 + 27 = \mathbf{58\text{ nodes}}$).*

---

#### **3. Is the Re-generation Overhead of IDDFS Significant? Justify:**
* **No, the re-generation overhead is NOT asymptotically significant.**
* **Justification:**
  1. In a tree with branching factor $b = 3$, the vast majority of nodes ($27$ out of $40$, i.e., $67.5\%$) lie at the **deepest leaf level ($d = 3$)**, and these bottom-level nodes are generated **only once**!
  2. IDDFS generates $58$ nodes compared to $40$ in BFS—an extra overhead of only $18$ nodes ($\displaystyle \frac{58 - 40}{40} = 45\%$, bounded asymptotically by $\displaystyle \frac{1}{b-1} = \frac{1}{2} = 50\%$). Both have the exact same asymptotic time complexity **$O(b^d)$**, while IDDFS reduces space complexity from exponential $O(b^d)$ to linear $O(bd)$.

### Question 3 [Series Test-II, Part B, Q7(a) (5 Marks)]
> **A delivery drone must fly from $S$ to $G$ over the directed weighted graph given below (edge costs in brackets):**
>
> $$
> S \to A (1), \quad S \to B (4), \quad S \to G (12), \quad A \to B (2), \quad A \to C (5), \quad B \to C (1), \quad B \to G (9), \quad C \to G (3)
> $$
>
> **(i) Apply Uniform Cost Search. Show the frontier as $(\text{node} : g)$ pairs after every expansion, and report the path and cost returned.**  
> **(ii) Which path would BFS return? Explain why it differs from (i).**

#### **Solution:**

#### **1. Graph Visualization & Edge List:**
* From $S$: $S \xrightarrow{1} A$, $\; S \xrightarrow{4} B$, $\; S \xrightarrow{12} G$
* From $A$: $A \xrightarrow{2} B$, $\; A \xrightarrow{5} C$
* From $B$: $B \xrightarrow{1} C$, $\; B \xrightarrow{9} G$
* From $C$: $C \xrightarrow{3} G$

---

#### **Part (i): Step-by-Step Uniform Cost Search (UCS) Execution Trace**

We maintain a **Min-Priority Queue Frontier** ordered by cumulative path cost $g(n)$ (and an `Explored` set):

* **Initial State (Before Expansion):**
  * **Frontier:** `[(S : 0)]`
  * **Explored:** `{}`

* **Expansion 1: Pop `(S : 0)`** (Lowest $g = 0$; not Goal)
  * Generate children of $S$:
    * $A$: $g(A) = 0 + 1 = 1$ *(Path: $S \to A$)*
    * $B$: $g(B) = 0 + 4 = 4$ *(Path: $S \to B$)*
    * $G$: $g(G) = 0 + 12 = 12$ *(Path: $S \to G$)*
  * **Frontier after Expansion 1:** **`[(A : 1), (B : 4), (G : 12)]`**
  * **Explored:** `{S}`

* **Expansion 2: Pop `(A : 1)`** (Lowest $g = 1$; not Goal)
  * Generate children of $A$:
    * $B$: $g(B) = g(A) + c(A, B) = 1 + 2 = \mathbf{3}$ *(Path: $S \to A \to B$)*. Since $(B : 4)$ is already in the frontier with a higher cost ($4 > 3$), **replace $(B : 4)$ with $(B : 3)$**!
    * $C$: $g(C) = g(A) + c(A, C) = 1 + 5 = 6$ *(Path: $S \to A \to C$)*.
  * **Frontier after Expansion 2:** **`[(B : 3), (C : 6), (G : 12)]`**
  * **Explored:** `{S, A}`

* **Expansion 3: Pop `(B : 3)`** (Lowest $g = 3$; not Goal)
  * Generate children of $B$:
    * $C$: $g(C) = g(B) + c(B, C) = 3 + 1 = \mathbf{4}$ *(Path: $S \to A \to B \to C$)*. Since $(C : 6)$ is in the frontier with a higher cost ($6 > 4$), **replace $(C : 6)$ with $(C : 4)$**!
    * $G$: $g(G) = g(B) + c(B, G) = 3 + 9 = 12$ *(Path: $S \to A \to B \to G$)*. Since $(G : 12)$ is already in the frontier with equal cost $12$, it remains $(G : 12)$.
  * **Frontier after Expansion 3:** **`[(C : 4), (G : 12)]`**
  * **Explored:** `{S, A, B}`

* **Expansion 4: Pop `(C : 4)`** (Lowest $g = 4$; not Goal)
  * Generate children of $C$:
    * $G$: $g(G) = g(C) + c(C, G) = 4 + 3 = \mathbf{7}$ *(Path: $S \to A \to B \to C \to G$)*. Since $(G : 12)$ is in the frontier with a higher cost ($12 > 7$), **replace $(G : 12)$ with $(G : 7)$**!
  * **Frontier after Expansion 4:** **`[(G : 7)]`**
  * **Explored:** `{S, A, B, C}`

* **Expansion 5: Pop `(G : 7)`**
  * **$G$ is the Goal State!** Terminate and return solution.

#### **Summary Table of UCS Trace:**

| Step | Node Expanded | Frontier (Sorted by $g$) after Expansion | Path Updates / Remarks |
| :---: | :---: | :--- | :--- |
| **Init** | — | `[(S : 0)]` | Start at $S$ |
| **1** | `(S : 0)` | `[(A : 1), (B : 4), (G : 12)]` | Added neighbors of $S$ |
| **2** | `(A : 1)` | `[(B : 3), (C : 6), (G : 12)]` | Updated $B$ from $4 \to 3$ via $S \to A \to B$ |
| **3** | `(B : 3)` | `[(C : 4), (G : 12)]` | Updated $C$ from $6 \to 4$ via $S \to A \to B \to C$ |
| **4** | `(C : 4)` | `[(G : 7)]` | Updated $G$ from $12 \to 7$ via $S \to A \to B \to C \to G$ |
| **5** | **`(G : 7)`** | `[]` | **Goal $G$ popped! Search terminates.** |

✅ **Result for (i):**
* **Optimal Path Returned by UCS:** **$S \to A \to B \to C \to G$**
* **Total Minimum Cost Returned:** **$7$** (since $1 + 2 + 1 + 3 = 7$).

---

#### **Part (ii): Which Path Would BFS Return & Why It Differs from (i):**
1. **Path Returned by BFS:**
   * **Path:** **$S \to G$** (with total cost $= \mathbf{12}$).
2. **Reason Why BFS Differs from UCS:**
   * **BFS ignores edge weights (step costs)** and expands nodes strictly in increasing order of **depth $d$ (number of edges/hops)**.
   * Since there is a direct $1$-edge connection from $S$ to $G$ ($d = 1$), BFS encounters $G$ at Depth $1$ and immediately returns the $1$-hop path $S \to G$ (cost $12$).
   * In contrast, **UCS expands nodes in order of cumulative path cost $g(n)$** and waits until $G$ is popped from the priority queue, allowing it to find the 4-hop path $S \to A \to B \to C \to G$ which has a much lower total cost of **$7$**.
