# Module 3.3: Informed Search Strategies – Best-First Search Algorithm

## 1. Introduction to Informed (Heuristic) Search
In Module 3.1 and 3.2, we saw that **Uninformed (Blind) Search** strategies (BFS, DFS, IDDFS, UCS) have no knowledge of where the goal is located—they explore the state space blindly until they stumble upon a goal state.

In contrast, an **Informed Search Strategy** (also called **Heuristic Search**) uses **problem-specific domain knowledge** beyond the definition of the problem itself to guide the search toward the goal much more efficiently.

---

### Core Concepts: Evaluation Function $f(n)$ and Heuristic Function $h(n)$

#### 1. Evaluation Function $f(n)$
An informed search algorithm selects which node $n$ in the Frontier (OPEN list) to expand next based on an **Evaluation Function $f(n)$**, which serves as a cost estimate.
* The node with the **lowest evaluation value $f(n)$** is expanded first (using a **Min-Priority Queue**).

#### 2. Heuristic Function $h(n)$
The key component of any informed search evaluation function is a **Heuristic Function**, denoted by **$h(n)$**:

$$
h(n) = \text{Estimated cost of the cheapest path from the state at node } n \text{ to a goal state}
$$

* **Properties of Every Heuristic Function $h(n)$:**
  1. $h(n)$ depends **only** on the state at node $n$ (not on how the agent got there).
  2. $h(n) \ge 0$ for all nodes $n$ (non-negative).
  3. **$h(n) = 0$ if $n$ is a Goal State** (since the estimated remaining distance from the goal to itself is zero!).
* **Examples of Heuristics $h(n)$:**
  * **Route Finding on a Map:** Straight-Line Distance (Euclidean / air distance) from city $n$ to the destination city $G$.
  * **8-Puzzle Problem:** Number of misplaced tiles ($h_1$) or Sum of Manhattan distances ($h_2$).

---

## 2. Best-First Search & Greedy Best-First Search

### A. What is Best-First Search?
**Best-First Search** is an instance of the general `GRAPH-SEARCH` or `TREE-SEARCH` algorithm in which a node is selected for expansion based on an evaluation function $f(n)$.
* When people refer to **"Best-First Search"** as a standalone algorithm (as opposed to $A^*$), they are specifically referring to **Greedy Best-First Search (GBFS)**.

### B. Working Principle of Greedy Best-First Search
**Greedy Best-First Search** tries to expand the node that is judged to be **closest to the goal**, on the grounds that this is likely to lead to a solution quickly.
* Thus, it evaluates nodes **solely by using the heuristic function**:

$$
f(n) = h(n)
$$

* **Why is it called "Greedy"?** Because at each step it greedily picks whichever successor looks closest to the goal right now ($h(n)$), **completely ignoring the path cost $g(n)$ already spent to reach node $n$**!

## 3. Step-by-Step Algorithm of Best-First Search (Using OPEN and CLOSED Lists)

Best-First Search maintains two lists:
1. **`OPEN` List (Frontier):** A **Priority Queue** of nodes that have been generated but not yet expanded, sorted in **ascending order of $h(n)$**.
2. **`CLOSED` List (Explored Set):** A list of nodes that have already been expanded (to prevent infinite loops in graphs).

### Algorithm Steps:
1. **Step 1 (Initialization):** Place the starting node $S$ into the `OPEN` list with its heuristic value $h(S)$. Initialize `CLOSED` as empty.
2. **Step 2 (Failure Check):** If `OPEN` is empty, terminate and return `Failure` (no path exists).
3. **Step 3 (Select Best Node):** Remove the node $n$ from `OPEN` that has the **lowest heuristic value $h(n)$** and place it in `CLOSED`.
4. **Step 4 (Goal Check):** If node $n$ is the **Goal State**, terminate and return the solution path (by tracing parent pointers back to $S$).
5. **Step 5 (Expand Node):** Generate all successors (children) of node $n$. For each child $m$:
   * Evaluate its heuristic value $h(m)$.
   * If $m$ is neither in `OPEN` nor in `CLOSED`, set $n$ as its parent and insert $m$ into `OPEN` (sorted by $h(m)$).
6. **Step 6 (Repeat):** Go back to **Step 2**.

## 4. Illustrative Examples of Best-First Search

### Example 1: Clean Graph Example (Ideal to Draw in Exams!)
Suppose an agent wants to travel from Start node **$S$** to Goal node **$G$** in the graph below. The heuristic values $h(n)$ (estimated distance to $G$) are shown at each node, and actual edge costs are on the links:

```text
                [S] h=10
               /   \
          (2) /     \ (1)
             v       v
       h=8 [A]       [B] h=4
           /         / \
      (2) /     (8) /   \ (10)
         v         v     v
   h=3 [C]       [D]     [G] h=0
         \      (h=6)    ^
      (3) \             /
           +-----------+
```
* **Edges (Actual Cost):** $S \to A (2)$, $S \to B (1)$, $A \to C (2)$, $C \to G (3)$, $B \to D (8)$, $B \to G (10)$.
* **Heuristics $h(n)$:** $h(S)=10, \; h(A)=8, \; h(B)=4, \; h(C)=3, \; h(D)=6, \; h(G)=0$.

#### **Step-by-Step Execution of Greedy Best-First Search ($f(n) = h(n)$):**

| Step | Node Expanded | `OPEN` List (Sorted by $h(n)$) | `CLOSED` List | Explanation |
| :---: | :---: | :--- | :--- | :--- |
| **Init** | — | `[S(10)]` | `[]` | Start with $S$ in `OPEN`. |
| **1** | **`S(10)`** | `[B(4), A(8)]` | `[S]` | Expand $S \rightarrow$ generates $A(8)$ and $B(4)$. Pick $B(4)$ next since $h(B)=4 < h(A)=8$. |
| **2** | **`B(4)`** | `[G(0), D(6), A(8)]` | `[S, B]` | Expand $B \rightarrow$ generates $D(6)$ and $G(0)$. Pick $G(0)$ next since $h(G)=0$ is minimum. |
| **3** | **`G(0)`** | `[D(6), A(8)]` | `[S, B, G]` | **$G$ is the Goal!** Search terminates. |

* **Path Found by Greedy Best-First Search:** **$S \to B \to G$**
* **Actual Cost of This Path:** $1 + 10 = \mathbf{11}$.
* **Notice the Drawback (Non-Optimality):** Because Best-First Search was lured by $B$'s low heuristic ($h(B)=4$), it ignored the much cheaper path **$S \to A \to C \to G$** which has a total actual cost of only $2 + 2 + 3 = \mathbf{7}$!

## 5. Evaluation of Greedy Best-First Search

| Criterion | Evaluation for Greedy Best-First Search ($f(n) = h(n)$) |
| :--- | :--- |
| **1. Completeness** | **No** in Tree-Search (can get stuck in loops, e.g., bouncing back and forth between two nodes). **Yes (Complete)** in Graph-Search (with a `CLOSED` list) on finite state spaces. |
| **2. Optimality** | **No (Not Optimal)** — Because it ignores path cost $g(n)$, it often returns a suboptimal path (as shown in Example 1 and the Romania map). |
| **3. Time Complexity** | **$O(b^m)$** in the worst case (where $m$ is maximum depth). However, a good heuristic can reduce time complexity dramatically toward $O(b \cdot d)$. |
| **4. Space Complexity** | **$O(b^m)$** — Stores all generated nodes in memory (`OPEN` and `CLOSED` lists). |

## 6. Solved University & Internal Exam Questions

### Question 1 [Series Test-II, Part B, Q7(b) (5 Marks)]
> **Explain the working principle of Best First Search with a suitable example and List two advantages and one drawback of Best First Search.**

#### **Solution:**

#### **1. Working Principle of Best-First Search (Greedy Best-First Search):**
* **Best-First Search** is an **informed (heuristic) search strategy** that uses domain-specific knowledge to guide the search toward the goal.
* It uses an **evaluation function $f(n) = h(n)$**, where **$h(n)$ is the heuristic function** that estimates the cost of the cheapest path from current node $n$ to the goal state (with $h(\text{Goal}) = 0$).
* **Core Mechanism:**
  1. It maintains two lists:
     * **`OPEN` List (Min-Priority Queue):** Stores generated but unexpanded nodes, ordered by increasing heuristic value $h(n)$.
     * **`CLOSED` List:** Stores already expanded nodes to avoid revisiting states.
  2. At every step, Best-First Search **greedily pops and expands the node $n$ from `OPEN` that has the lowest heuristic value $h(n)$** (i.e., the node that appears closest to the goal).
  3. Its successors are generated and inserted into `OPEN` according to their $h$ values, and the process repeats until the Goal node ($h(G) = 0$) is selected.

---

#### **2. Suitable Example:**
Consider finding a path from Start node **$S$** to Goal node **$G$** in the following graph, where the heuristic values $h(n)$ are given at each node:
* **Nodes & Heuristics:** $h(S) = 10, \; h(A) = 8, \; h(B) = 4, \; h(C) = 3, \; h(D) = 6, \; h(G) = 0$.
* **Connections:** $S \to \{A, B\}$, $\; A \to \{C\}$, $\; B \to \{D, G\}$, $\; C \to \{G\}$.

```text
          [S] (h=10)
         /   \
(h=8)  [A]   [B] (h=4)
       /     / \
(h=3)[C]   [D] [G*] (h=0)
            ^
          (h=6)
```

* **Step 1:** Initialize `OPEN = [S(10)]`, `CLOSED = []`.
* **Step 2:** Pop `S(10)`, move to `CLOSED = [S]`, and expand its children $A(8)$ and $B(4)$.
  * `OPEN = [B(4), A(8)]` *(sorted by lowest $h$)*.
* **Step 3:** Pop `B(4)` (since $h(B) = 4 < h(A) = 8$), move to `CLOSED = [S, B]`, and expand its children $D(6)$ and $G(0)$.
  * `OPEN = [G(0), D(6), A(8)]`.
* **Step 4:** Pop `G(0)` (lowest $h = 0$). Since **$G$ is the Goal State**, the search terminates and returns the path **$S \to B \to G$** after expanding only $2$ nodes!

---

#### **3. Two Advantages of Best-First Search:**
1. **High Speed & Efficiency Compared to Blind Search:** By using heuristic guidance $h(n)$ to move directly toward the goal, it expands far fewer nodes than uninformed algorithms like BFS or DFS, finding solutions very quickly in practice.
2. **Avoids Exploring Unpromising Branches:** Unlike BFS (which explores all directions equally) or DFS (which dives blindly down one branch), Best-First Search can switch dynamically between branches whenever a current branch starts looking less promising (higher $h(n)$).

---

#### **4. One Major Drawback of Best-First Search:**
1. **Not Optimal (Does Not Guarantee the Shortest/Cheapest Path):** Because Greedy Best-First Search evaluates nodes using only the estimated remaining cost $f(n) = h(n)$ and **completely ignores the actual path cost $g(n)$ already incurred from the start node**, it can be misled by low heuristic values into returning a longer, suboptimal path (or getting misled down deep dead-ends).
