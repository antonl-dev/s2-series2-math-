## PART A: Introduction to Structured Query Language (SQL)

### 1. What is SQL?
* **History:** Originally developed at IBM Research in the 1970s by Donald Chamberlin and Raymond Boyce under the name **SEQUEL** (*Structured English Query Language*), and later standardized by ANSI and ISO as **SQL** (*Structured Query Language*).
* **Declarative (Non-Procedural) Nature:**
  * Unlike Relational Algebra (which is *procedural*—you specify the exact sequence of steps to retrieve data), **SQL is a declarative (non-procedural) language**.
  * In SQL, the user only specifies **WHAT** result is needed, and the DBMS's internal **Query Optimizer** automatically decides **HOW** to fetch that data most efficiently.

### 2. Terminology Mapping: Relational Model vs. SQL
SQL uses everyday table terms instead of formal mathematical relational terms:

| Formal Relational Model Term | SQL Equivalent Term | Example |
| :--- | :--- | :--- |
| **Relation** | **`TABLE`** | `STUDENT` table |
| **Tuple** | **`ROW`** | `(7, 'Adhil', 'EEE')` |
| **Attribute** | **`COLUMN`** | `Roll_No`, `Name`, `Branch` |

> **Crucial Mathematical Difference (Set vs. Multiset/Bag):**
> * A pure mathematical **Relation** is a **Set** of tuples—it **never** contains duplicate rows.
> * An **SQL Table** (and the output of an SQL `SELECT` query) is a **Multiset (or Bag)** of rows—it **CAN contain duplicate rows** unless you define a `PRIMARY KEY` / `UNIQUE` constraint on the table, or explicitly write `SELECT DISTINCT` in your query!

## PART B: SQL Data Types and Domains

Every column in an SQL table must be assigned a specific **Data Type** that defines its **Domain** (what kind of values can be stored in that column).

If an exam question asks *"Explain the various SQL data types with examples"*, group them into these **5 standard categories**:

📸 **[Click here to view SQL Data Types Summary Charts on Google Images](https://www.google.com/search?q=SQL+data+types+in+dbms+chart+diagram&udm=2)**

---

### 1. Numeric Data Types
Used to store whole numbers (integers) and decimal/floating-point numbers.

#### a) Exact Numeric Types (For IDs, Counts, and Money/Salaries)
* **`INT` (or `INTEGER`):** Normal-sized whole integer numbers (typically 4 bytes, range $\approx -2\text{ billion to } +2\text{ billion}$).
  * *Example:* `Roll_No INT`, `Credits INT`
* **`SMALLINT`:** Smaller whole integers (2 bytes, range $-32,768$ to $+32,767$).
  * *Example:* `Semester SMALLINT`
* **`NUMERIC(p, d)` or `DECIMAL(p, d)`:** Fixed-point exact decimal numbers where:
  * **`p` (Precision):** Total number of digits allowed (both before and after the decimal point).
  * **`d` (Scale):** Number of digits to the **right** of the decimal point.
  * *Example:* `Salary DECIMAL(8, 2)` can store values up to `999999.99` (8 total digits, 2 after the decimal point). Always used for money/currency so rounding errors never happen!

#### b) Approximate Numeric Types (Floating-Point)
* **`FLOAT(n)`**, **`REAL`**, and **`DOUBLE PRECISION`**: Used for scientific calculations where values have a huge dynamic range and tiny rounding approximations are acceptable.

---

### 2. Character-String Data Types
Used to store names, codes, addresses, and text.

* **`CHAR(n)` (or `CHARACTER(n)`) – Fixed-Length String:**
  * Stores a fixed-length string of exactly $n$ characters.
  * If you insert a shorter string (e.g., `'EEE'` of length 3 into `CHAR(10)`), SQL **pads the remaining 7 spaces with blank spaces** on the right so it always occupies 10 characters on disk!
  * *Best used for:* Columns whose length never varies, such as `Gender CHAR(1)`, `State_Code CHAR(2)`, `Pin_Code CHAR(6)`.
* **`VARCHAR(n)` (or `CHAR VARYING(n)`) – Variable-Length String:**
  * Stores a variable-length string up to a **maximum** of $n$ characters.
  * If you insert `'Adhil'` (5 characters) into `VARCHAR(50)`, it **only uses 5 characters of storage** (plus 1 byte for length) and does **not** pad with spaces!
  * *Best used for:* Columns whose length varies widely from row to row, such as `Name VARCHAR(50)`, `Email VARCHAR(100)`, `Address VARCHAR(200)`.

#### ⭐ Quick 2-Mark Exam Comparison: `CHAR(n)` vs. `VARCHAR(n)`

| Feature | `CHAR(n)` | `VARCHAR(n)` |
| :--- | :--- | :--- |
| **1. Meaning** | **Fixed-length** character string. | **Variable-length** character string. |
| **2. Storage Used** | Always uses **$n$ bytes/characters**, padding shorter strings with spaces. | Uses **only the actual length** of the string entered (up to max $n$). |
| **3. Memory Efficiency** | Wastes space if string lengths vary. | Saves disk space when strings are shorter than $n$. |
| **4. Example Use Case** | `Gender CHAR(1)`, `Aadhar CHAR(12)` | `Name VARCHAR(50)`, `Address VARCHAR(200)` |

---

### 3. Date and Time Data Types
* **`DATE`:** Stores a calendar date containing Year, Month, and Day in the standard format **`'YYYY-MM-DD'`**.
  * *Example:* `'2026-11-15'`
* **`TIME`:** Stores the time of day in hours, minutes, and seconds in the format **`'HH:MM:SS'`**.
  * *Example:* `'09:30:00'`
* **`TIMESTAMP`:** Stores **both `DATE` and `TIME` together** (down to fractions of a second), useful for logging exact transaction times.
  * *Example:* `'2026-11-15 09:30:00'`

---

### 4. Boolean & Large Object (LOB) Data Types
* **`BOOLEAN`:** Can hold one of three truth values in SQL: **`TRUE`**, **`FALSE`**, or **`UNKNOWN` (`NULL`)**.
* **`BLOB` (Binary Large Object):** Stores large raw binary data like images, PDFs, or audio files.
* **`CLOB` (Character Large Object):** Stores very large blocks of text (like an entire book or article).

---

### 5. User-Defined Domains (`CREATE DOMAIN`)
SQL allows designers to create a custom, reusable domain with its own constraint so you don't have to repeat the data type on every table:
```sql
CREATE DOMAIN Branch_Domain AS CHAR(3)
CHECK (VALUE IN ('EEE', 'CSE', 'ECE', 'ME'));
```

## PART C: Data Definition Language (DDL) Commands in SQL

**DDL (Data Definition Language)** is the subset of SQL used to **define, modify, and remove the database schema** (tables, columns, keys, and integrity constraints). Whenever a DDL command runs, the DBMS updates the **Metadata** in the **System Catalog**.

The **4 core DDL commands** are:
1. **`CREATE`** (Creates a new database, schema, table, view, or index)
2. **`ALTER`** (Modifies the structure of an existing table)
3. **`DROP`** (Completely deletes a table, both its data and its schema)
4. **`TRUNCATE`** (Deletes all rows inside a table while keeping the table schema intact)

---

### 1. The `CREATE TABLE` Command & SQL Constraints

The `CREATE TABLE` command specifies a new relation by giving it a **name**, a list of **attributes (with data types)**, and **integrity constraints**.

#### Syntax of `CREATE TABLE`:
```sql
CREATE TABLE Table_Name (
    Column1  DataType  [Column_Constraints],
    Column2  DataType  [Column_Constraints],
    ...
    [Table_Level_Constraints (e.g., PRIMARY KEY, FOREIGN KEY)]
);
```

#### The 6 Constraints You Can Specify Inside `CREATE TABLE`:

| SQL Constraint | Which Integrity Rule It Enforces | What It Does |
| :--- | :--- | :--- |
| **1. `NOT NULL`** | Domain Constraint | Ensures a column **cannot have a `NULL` value** (mandatory field). |
| **2. `UNIQUE`** | Key / Candidate Key Constraint | Ensures all values in the column are **distinct** (no duplicates). |
| **3. `PRIMARY KEY`** | **Entity Integrity Constraint** | Uniquely identifies each row. Automatically enforces **`UNIQUE` + `NOT NULL`**! |
| **4. `FOREIGN KEY`** | **Referential Integrity Constraint** | Links a column to the `PRIMARY KEY` of a parent table (`REFERENCES Parent(PK)`). |
| **5. `CHECK (...)`** | Domain Constraint | Validates that every value satisfies a boolean condition (e.g., `CHECK (Credits > 0)`). |
| **6. `DEFAULT val`** | Default Value Rule | Assigns a default value automatically if none is given during `INSERT`. |

### 2. Complete Worked DDL Examples (From Your Exam Papers!)

#### Example 1: Writing DDL for Your Oct 2026 Internal Test Q2(b) University Database!
Recall in **Oct 2026 Q2(b)**, we converted the University ER diagram into 3 relational schemas:
1. $\text{STUDENT}(\underline{\text{Student\_ID}}, \text{Name}, \text{Branch})$
2. $\text{COURSE}(\underline{\text{Course\_ID}}, \text{Course\_Name}, \text{Credits})$
3. $\text{REGISTRATION}(\underline{\text{Student\_ID}, \text{Course\_ID}}, \text{Semester}, \text{Grade})$

Here is how you write the complete SQL DDL (`CREATE TABLE`) for those 3 tables:

```sql
-- 1. Create STUDENT Table
CREATE TABLE STUDENT (
    Student_ID  INT          PRIMARY KEY,
    Name        VARCHAR(50)  NOT NULL,
    Branch      VARCHAR(10)  DEFAULT 'EEE'
);

-- 2. Create COURSE Table
CREATE TABLE COURSE (
    Course_ID    CHAR(8)      PRIMARY KEY,
    Course_Name  VARCHAR(60)  NOT NULL UNIQUE,
    Credits      INT          CHECK (Credits BETWEEN 1 AND 5)
);

-- 3. Create REGISTRATION Table (Composite PK + Two Foreign Keys!)
CREATE TABLE REGISTRATION (
    Student_ID  INT,
    Course_ID   CHAR(8),
    Semester    SMALLINT     NOT NULL,
    Grade       CHAR(2),
    PRIMARY KEY (Student_ID, Course_ID),
    FOREIGN KEY (Student_ID) REFERENCES STUDENT(Student_ID)
        ON DELETE CASCADE,
    FOREIGN KEY (Course_ID)  REFERENCES COURSE(Course_ID)
        ON DELETE CASCADE
);
```
> **Exam Tip:** Whenever a table has a **Composite Primary Key** (like `(Student_ID, Course_ID)` above), you **must** write `PRIMARY KEY (Student_ID, Course_ID)` at the bottom of the `CREATE TABLE` statement (as a table-level constraint), NOT next to the individual columns!

---

#### Example 2: Writing DDL for `DEPARTMENT` and `EMPLOYEE` (With Referential Actions)
```sql
CREATE TABLE DEPARTMENT (
    DNO        INT          PRIMARY KEY,
    DNAME      VARCHAR(30)  NOT NULL UNIQUE,
    DLOCATION  VARCHAR(40)
);

CREATE TABLE EMPLOYEE (
    ENO       INT           PRIMARY KEY,
    NAME      VARCHAR(50)   NOT NULL,
    SALARY    DECIMAL(10,2) CHECK (SALARY > 0),
    DNUM      INT,
    SUPERENO  INT,
    FOREIGN KEY (DNUM)     REFERENCES DEPARTMENT(DNO)
        ON DELETE SET NULL
        ON UPDATE CASCADE,
    FOREIGN KEY (SUPERENO) REFERENCES EMPLOYEE(ENO)
        ON DELETE SET NULL
);
```

### 3. The `ALTER TABLE` Command (Modifying an Existing Schema)

Once a table is created, what if requirements change and we need to add a new column, remove an old column, or add a Foreign Key constraint? We use **`ALTER TABLE`**!

#### Common `ALTER TABLE` Operations (Memorize these 4 one-liners!):

```sql
-- 1. Add a new column 'Phone_No' to the STUDENT table:
ALTER TABLE STUDENT ADD Phone_No VARCHAR(15);

-- 2. Drop (remove) an existing column 'Branch' from the STUDENT table:
ALTER TABLE STUDENT DROP COLUMN Branch;

-- 3. Modify the data type / size of an existing column:
ALTER TABLE STUDENT MODIFY Name VARCHAR(100);

-- 4. Add a Foreign Key constraint to an already created table:
ALTER TABLE EMPLOYEE
ADD CONSTRAINT fk_dept FOREIGN KEY (DNUM) REFERENCES DEPARTMENT(DNO);
```

### 4. `DROP TABLE` vs. `TRUNCATE TABLE` (Removing Tables & Data)

#### a) `DROP TABLE` (Deletes Both Data AND Table Structure!)
* **Purpose:** Completely removes a table—including all its rows, its indexes, and its schema definition—from the database catalog. After `DROP TABLE STUDENT;`, the `STUDENT` table no longer exists at all!
* **Syntax:**
  ```sql
  DROP TABLE STUDENT;
  ```
* **`RESTRICT` vs. `CASCADE` Options in `DROP TABLE`:**
  * `DROP TABLE DEPARTMENT RESTRICT;` $\rightarrow$ Drops `DEPARTMENT` **only if** no other table's Foreign Key references it (fails if `EMPLOYEE` still references `DEPARTMENT`).
  * `DROP TABLE DEPARTMENT CASCADE;` $\rightarrow$ Drops `DEPARTMENT` **and automatically drops** any referencing Foreign Key constraints or views that depend on it.

#### b) `TRUNCATE TABLE` (Empties All Rows, Keeps Table Structure!)
* **Purpose:** Quickly deletes **all rows** from a table, resetting it to an empty table, while **keeping the table schema, columns, and constraints intact** so new rows can be inserted later.
* **Syntax:**
  ```sql
  TRUNCATE TABLE STUDENT;
  ```

### ⭐ High-Probability 3-Mark Comparison: `DELETE` vs. `TRUNCATE` vs. `DROP`

📸 **[Click here to view DELETE vs TRUNCATE vs DROP Comparison Diagrams on Google Images](https://www.google.com/search?q=difference+between+delete+truncate+and+drop+in+sql+diagram&udm=2)**

*(Evaluators love asking the difference between `DELETE`, `TRUNCATE`, and `DROP`!)*

| Feature | `DELETE` | `TRUNCATE` | `DROP` |
| :--- | :--- | :--- | :--- |
| **1. SQL Category** | **DML** (Data Manipulation Language) | **DDL** (Data Definition Language) | **DDL** (Data Definition Language) |
| **2. What it Removes** | Removes **specific rows** (using `WHERE`) or all rows one by one. | Removes **ALL rows** at once, but **keeps the table schema/structure**. | Removes **ALL rows AND deletes the entire table schema** from the DB! |
| **3. Does the Table Still Exist After?** | **Yes** (Table structure remains intact). | **Yes** (Empty table structure remains intact). | **No!** (The table is completely gone). |
| **4. Can You Use a `WHERE` Clause?** | **Yes** (`DELETE FROM EMP WHERE ENO = 101;`) | **No** (Cannot filter rows; always empties the whole table). | **No** (Drops the entire table). |
| **5. Speed** | **Slower** (logs each row deletion individually in transaction log). | **Very Fast** (deallocates data pages in bulk). | **Instantaneous**. |
| **6. Syntax** | `DELETE FROM Table WHERE cond;` | `TRUNCATE TABLE Table_Name;` | `DROP TABLE Table_Name;` |

### 🎉 Module 2 Complete! Quick 30-Second Recap of 2.5
* **SQL Sub-languages:**
  * **DDL** = `CREATE`, `ALTER`, `DROP`, `TRUNCATE` *(Schema)*
  * **DML** = `SELECT`, `INSERT`, `UPDATE`, `DELETE` *(Rows)*
  * **DCL** = `GRANT`, `REVOKE` *(Security)*
  * **TCL** = `COMMIT`, `ROLLBACK`, `SAVEPOINT` *(Transactions)*
* **`CHAR(n)` vs `VARCHAR(n)`:** `CHAR(n)` is fixed-length (pads with spaces); `VARCHAR(n)` is variable-length (saves space).
* **SQL Constraints in `CREATE TABLE`:** `PRIMARY KEY`, `FOREIGN KEY ... REFERENCES ...`, `UNIQUE`, `NOT NULL`, `CHECK (...)`, `DEFAULT`.
* **`DROP` vs `TRUNCATE` vs `DELETE`:** `DROP` destroys the table itself; `TRUNCATE` empties all rows but keeps the table skeleton; `DELETE` removes selected rows using `WHERE`.
