## PART A: What is Relational Algebra?

* **Definition:** **Relational Algebra** is a **procedural query language** used to query relational databases. It consists of a set of operations that take **one or two relations (tables) as input** and produce a **new relation (table) as output**.
* **Why is it called "Procedural"?**
  * Unlike SQL (which is *declarative*—you only say *what* result you want), in Relational Algebra you write a step-by-step sequence of operations specifying **how** to obtain the result.
* **Closure Property (Very Important Concept):**
  * Because the input to every Relational Algebra operator is a relation and the **output is also a relation**, the output of one operation can be fed directly as the input to another operation! This allows us to nest operations just like arithmetic expressions: $\pi_{\text{NAME}}(\sigma_{\text{SALARY} > 20000}(\text{EMPLOYEE}))$.

## PART C: Unary Relational Operations ($\sigma$, $\pi$, $\rho$)

### 1. The SELECT Operation ($\sigma$ – Greek letter *Sigma*)
* **Purpose:** Selects a **horizontal subset of rows (tuples)** from a relation that satisfy a given selection condition. *(Think of it as a **Horizontal Filter**—equivalent to the `WHERE` clause in SQL).*
* **Syntax:**
  $$\sigma_{\langle \text{selection condition} \rangle}(R)$$
  * Where $\sigma$ is the SELECT operator, $\langle \text{selection condition} \rangle$ is a boolean expression (using $=, \neq, <, \le, >, \ge$ combined with $\text{AND } (\wedge)$, $\text{OR } (\vee)$, $\text{NOT } (\neg)$), and $R$ is the input relation.

📸 **[Click here to view Select vs Project (Horizontal vs Vertical Partitioning) Diagrams on Google Images](https://www.google.com/search?q=select+and+project+operation+in+relational+algebra+diagram&udm=2)**

#### Properties of SELECT ($\sigma$):
1. **Degree (Number of Columns):** Remains the **exact same** as the input relation $R$ (because $\sigma$ never removes columns, only rows!).
2. **Cardinality (Number of Rows):** Always $\le$ the number of rows in $R$ ($0 \le |\sigma_c(R)| \le |R|$).
3. **Commutative Property:** Selecting in any order gives the exact same result:
   $$\sigma_{c_1}(\sigma_{c_2}(R)) = \sigma_{c_2}(\sigma_{c_1}(R)) = \sigma_{c_1 \text{ AND } c_2}(R)$$

#### Worked Example 1 (Single Condition):
* **Query:** Find all employees in the `'EEE'` department.
* **Expression:**
  $$\sigma_{\text{DEPT} = \text{'EEE'}}(\text{EMPLOYEE})$$
* **Result Table:**
  | ENO | NAME | GENDER | DEPT | SALARY |
  | :--- | :--- | :--- | :--- | :--- |
  | 101 | Adhil | M | EEE | 35000 |
  | 103 | Rahul | M | EEE | 18000 |
  | 104 | Anjali | F | EEE | 25000 |

#### Worked Example 2 (Compound Condition using `AND` / $\wedge$):
* **Query:** Find all female employees whose salary is greater than 20000.
* **Expression:**
  $$\sigma_{\text{GENDER} = \text{'F'} \;\wedge\; \text{SALARY} > 20000}(\text{EMPLOYEE})$$
* **Result Table:**
  | ENO | NAME | GENDER | DEPT | SALARY |
  | :--- | :--- | :--- | :--- | :--- |
  | 102 | Meera | F | CSE | 28000 |
  | 104 | Anjali | F | EEE | 25000 |

---

### 2. The PROJECT Operation ($\pi$ – Greek letter *Pi*)
* **Purpose:** Selects a **vertical subset of columns (attributes)** from a relation and discards all other columns. *(Think of it as a **Vertical Filter**—equivalent to `SELECT DISTINCT col1, col2` in SQL).*
* **Syntax:**
  $$\pi_{\langle \text{attribute list} \rangle}(R)$$

#### Crucial Property of PROJECT ($\pi$): Automatic Duplicate Elimination!
* Because the result of any Relational Algebra operation must be a mathematical relation (a **set** of tuples with no duplicates), **$\pi$ automatically removes duplicate rows** from the output!
* **Commutativity:** Project is **NOT** commutative (you cannot project column $A$ after you already threw column $A$ away!).

#### Worked Example 3 (See Duplicate Elimination in Action!):
* **Query:** List all departments present in the `EMPLOYEE` table.
* **Expression:**
  $$\pi_{\text{DEPT}}(\text{EMPLOYEE})$$
* **Step-by-Step:** Even though `'EEE'` appears 3 times and `'CSE'` appears 2 times in `EMPLOYEE`, $\pi$ eliminates duplicates:
* **Result Table:**
  | DEPT |
  | :--- |
  | EEE |
  | CSE |

---

### 3. Combining SELECT ($\sigma$) and PROJECT ($\pi$) *(Asked in Every Exam!)*

> ⭐ **Direct Exam Question (Oct 2025 Q2b(i) & Nov 2025 Q4a):**
> *"Write a relational algebra expression for: Names of female employees whose salary is more than 20000."*

#### How to Build It Step-by-Step:
1. **Inner Step (Filter the rows using $\sigma$):** Keep only rows where `GENDER = 'F'` AND `SALARY > 20000`:
   $$\sigma_{\text{GENDER} = \text{'F'} \;\wedge\; \text{SALARY} > 20000}(\text{EMPLOYEE})$$
2. **Outer Step (Keep only the `NAME` column using $\pi$):** Wrap $\pi_{\text{NAME}}$ around the inner step:
   $$\pi_{\text{NAME}}\Big(\sigma_{\text{GENDER} = \text{'F'} \;\wedge\; \text{SALARY} > 20000}(\text{EMPLOYEE})\Big)$$

* **Result Table:**
  | NAME |
  | :--- |
  | Meera |
  | Anjali |

> ⚠️ **Common Exam Trap to Avoid:**
> Never apply $\pi_{\text{NAME}}$ *first* and then try to apply $\sigma_{\text{SALARY} > 20000}$ outside! Why? Because once $\pi_{\text{NAME}}$ runs, the `SALARY` and `GENDER` columns are gone! **Always put $\sigma$ on the inside and $\pi$ on the outside.**

---

### 4. The RENAME Operation ($\rho$ – Greek letter *Rho*)
* **Purpose:** Used to give a temporary name to an intermediate relation or to rename its attributes (columns). Very useful when joining a table with itself (self-join) or breaking a long query into readable steps.
* **Syntax:**
  * Rename relation $R$ to $S$: $\rho_{S}(R)$
  * Rename relation $R$ to $S$ and its columns to $(B_1, B_2, \dots, B_n)$: $\rho_{S(B_1, B_2, \dots, B_n)}(R)$
* **Alternative Clean Assignment Notation ($\leftarrow$):**
  In exams, you can also break a complex query into numbered steps using the assignment arrow $\leftarrow$:
  $$\text{HIGH\_PAID\_FEMALES} \leftarrow \sigma_{\text{GENDER} = \text{'F'} \;\wedge\; \text{SALARY} > 20000}(\text{EMPLOYEE})$$
  $$\text{RESULT} \leftarrow \pi_{\text{NAME}}(\text{HIGH\_PAID\_FEMALES})$$
  *(Evaluators love this $\leftarrow$ notation when a query has 3–4 steps because it is neat and easy to grade!)*

## PART D: Set Operations on Relations ($\cup$, $\cap$, $-$)

Since relations are mathematical sets of tuples, we can apply standard set operations: **Union ($\cup$)**, **Intersection ($\cap$)**, and **Set Difference ($-$)**.

### Crucial Rule: Union Compatibility (Type Compatibility)
You **cannot** take the Union, Intersection, or Difference of just any two random tables! Two relations $R(A_1, A_2, \dots, A_n)$ and $S(B_1, B_2, \dots, B_n)$ are **Union-Compatible** if and only if they satisfy **two conditions**:
1. **Same Degree (Same number of columns):** Both $R$ and $S$ must have the exact same number of attributes $n$.
2. **Compatible Domains:** The domain (data type) of each $i$-th attribute of $R$ must be the same as the domain of the $i$-th attribute of $S$: $\text{dom}(A_i) = \text{dom}(B_i)$ for all $1 \le i \le n$.

*(That is why in exams we almost always apply **$\pi$ (Project)** first to extract matching single columns from two tables before applying $\cup$, $\cap$, or $-$!)*

📸 **[Click here to view Union, Intersection, and Set Difference in Relational Algebra on Google Images](https://www.google.com/search?q=union+intersection+set+difference+in+relational+algebra+diagram&udm=2)**

Let's use two small Union-Compatible tables to see all three operations:

**Table $R$ (`SPORTS_CLUB`)**
| Roll_No | Name |
| :--- | :--- |
| 7 | Adhil |
| 8 | Rahul |
| 9 | Meera |

**Table $S$ (`MUSIC_CLUB`)**
| Roll_No | Name |
| :--- | :--- |
| 8 | Rahul |
| 10 | Arjun |

---

### 1. UNION Operation ($R \cup S$)
* **Meaning:** Returns a relation containing all tuples that appear in **$R$, OR in $S$, OR in both $R$ and $S$**. Duplicate tuples are automatically eliminated.
* **Result of $R \cup S$:**
  | Roll_No | Name |
  | :--- | :--- |
  | 7 | Adhil |
  | 8 | Rahul |
  | 9 | Meera |
  | 10 | Arjun |
  *(Notice `(8, 'Rahul')` appears only once!)*

* **Direct Exam Application (Nov 2025 End-Sem Q4c):**
  > *"List all locations that are either department locations or project locations."*
  * First project `DLOCATION` from `DEPARTMENT`: $\pi_{\text{DLOCATION}}(\text{DEPARTMENT})$
  * Second project `PLOCATION` from `PROJECT`: $\pi_{\text{PLOCATION}}(\text{PROJECT})$
  * Take their **Union ($\cup$)**:
    $$\pi_{\text{DLOCATION}}(\text{DEPARTMENT}) \;\cup\; \pi_{\text{PLOCATION}}(\text{PROJECT})$$

---

### 2. INTERSECTION Operation ($R \cap S$)
* **Meaning:** Returns a relation containing only those tuples that appear in **BOTH $R$ AND $S$**.
* **Result of $R \cap S$:**
  | Roll_No | Name |
  | :--- | :--- |
  | 8 | Rahul |

---

### 3. SET DIFFERENCE (or MINUS) Operation ($R - S$)
* **Meaning:** Returns a relation containing all tuples that are present **in $R$, Deal/BUT NOT present in $S$**.
* **Warning:** Set Difference is **NOT commutative** ($R - S \neq S - R$)!
  * **Result of $R - S$ (In Sports Club, NOT in Music Club):**
    | Roll_No | Name |
    | :--- | :--- |
    | 7 | Adhil |
    | 9 | Meera |
  * **Result of $S - R$ (In Music Club, NOT in Sports Club):**
    | Roll_No | Name |
    | :--- | :--- |
    | 10 | Arjun |

* **Direct Exam Application (Nov 2025 End-Sem Q4d):**
  > *"Find the names of employees who are not managers of any department."*
  * Whenever a question says **"who are NOT..."**, think **Set Difference ($-$)** immediately!
  * All Employee IDs: $\pi_{\text{ENO}}(\text{EMPLOYEE})$
  * All Manager Employee IDs: $\pi_{\text{MGRENO}}(\text{DEPARTMENT})$
  * Employee IDs who are **NOT** managers:
    $$\text{NON\_MGR\_IDS} \leftarrow \pi_{\text{ENO}}(\text{EMPLOYEE}) \;-\; \pi_{\text{MGRENO}}(\text{DEPARTMENT})$$

## PART E: The CARTESIAN PRODUCT (Cross Product) Operation ($\times$)

What if we need information from **two different tables** that are **not** union-compatible (for example, Employee `SALARY` is in `EMPLOYEE`, while Department Name `'Accounts'` is in `DEPARTMENT`)?

The fundamental operation for combining two tables horizontally is the **Cartesian Product (or Cross Product)**, denoted by **$\times$**.

📸 **[Click here to view Cartesian Product Operation in Relational Algebra on Google Images](https://www.google.com/search?q=cartesian+product+in+relational+algebra+example+diagram&udm=2)**

### 1. How $R \times S$ Works
* **Definition:** Given relation $R$ (with $n$ columns and $r$ rows) and relation $S$ (with $m$ columns and $s$ rows), the Cartesian Product $R \times S$ pairs **every single row of $R$ with every single row of $S$**!
* **Degree (Number of Columns) of $R \times S$:** $n + m$ (sum of columns).
* **Cardinality (Number of Rows) of $R \times S$:** $r \times s$ (product of rows!).

### 2. Visual Step-by-Step Trace of Cartesian Product ($\times$)

Suppose we have a small `EMP` table (2 rows) and a `DEPT` table (2 rows):

**Table 1: `EMP` (2 rows, 3 cols)**
| ENO | NAME | DNUM (FK) |
| :--- | :--- | :--- |
| 101 | Adhil | 10 |
| 102 | Meera | 20 |

**Table 2: `DEPT` (2 rows, 2 cols)**
| DNO (PK) | DNAME |
| :--- | :--- |
| 10 | EEE |
| 20 | Accounts |

#### Step 1: Take the raw Cartesian Product ($\text{EMP} \times \text{DEPT}$)
Every row of `EMP` gets paired with every row of `DEPT` ($2 \times 2 = 4$ rows, $3 + 2 = 5$ columns):

| ENO | NAME | DNUM | DNO | DNAME | Is this pairing meaningful? |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 101 | Adhil | **10** | **10** | EEE | ✅ **YES!** (`DNUM = DNO = 10`) |
| 101 | Adhil | **10** | **20** | Accounts | ❌ **Garbage row!** (`10 != 20`; Adhil is not in Accounts!) |
| 102 | Meera | **20** | **10** | EEE | ❌ **Garbage row!** (`20 != 10`; Meera is not in EEE!) |
| 102 | Meera | **20** | **20** | Accounts | ✅ **YES!** (`DNUM = DNO = 20`) |

#### Step 2: Filter out the "Garbage Rows" using SELECT ($\sigma_{\text{DNUM} = \text{DNO}}$)!
Notice that on its own, $R \times S$ produces meaningless combinations where an employee from Department 10 is paired with Department 20.
To keep **only the matching rows**, we apply $\sigma_{\text{DNUM} = \text{DNO}}$:

$$\sigma_{\text{DNUM} = \text{DNO}}(\text{EMP} \times \text{DEPT})$$

| ENO | NAME | DNUM | DNO | DNAME |
| :--- | :--- | :--- | :--- | :--- |
| 101 | Adhil | 10 | 10 | EEE |
| 102 | Meera | 20 | 20 | Accounts |

> 💡 **Preview of Module 2.4:** Combining a **Cartesian Product ($\times$)** followed immediately by a **Selection ($\sigma_{\text{FK}=\text{PK}}$)** is so common in databases that it was given its own special shortcut symbol called a **JOIN ($\bowtie$)**!
> $$\sigma_{\text{DNUM} = \text{DNO}}(\text{EMP} \times \text{DEPT}) \;\equiv\; \text{EMP} \bowtie_{\text{DNUM} = \text{DNO}} \text{DEPT}$$

* `PROJECT (PNO, PNAME, PLOCATION, PCOST, CDNO)`
  *(where `DNUM` is FK to `DEPARTMENT(DNO)`, `MGRENO` is FK to `EMPLOYEE(ENO)`, `CDNO` is FK to `DEPARTMENT(DNO)`)*

Here are the exact exam solutions for all the queries that use `2.3` operations:

---

### 1. Oct 2025 Q2(b)(i) & Nov 2025 Q4(a):
> **Query:** *"Names of female employees whose salary is more than 20000."*

#### ✅ Solution:
$$\pi_{\text{NAME}}\Big(\sigma_{\text{GENDER} = \text{'F'} \;\wedge\; \text{SALARY} > 20000}(\text{EMPLOYEE})\Big)$$

* **Explanation:**
  1. $\sigma_{\text{GENDER} = \text{'F'} \;\wedge\; \text{SALARY} > 20000}(\text{EMPLOYEE})$ selects only the rows of female employees earning more than 20,000.
  2. $\pi_{\text{NAME}}(\dots)$ projects only the `NAME` column from those filtered rows.

---

### 2. Oct 2025 Q2(b)(ii) & Nov 2025 Q4(b):
> **Query:** *"Salaries of employee from 'Accounts' department."*

#### ✅ Solution (Using Cartesian Product $\times$, $\sigma$, and $\pi$):
$$\pi_{\text{SALARY}}\Big(\sigma_{\text{DNAME} = \text{'Accounts'} \;\wedge\; \text{DNUM} = \text{DNO}}(\text{EMPLOYEE} \times \text{DEPARTMENT})\Big)$$

*(Or written step-by-step using $\leftarrow$):*
1. $\text{ACCOUNTS\_DEPT} \leftarrow \sigma_{\text{DNAME} = \text{'Accounts'}}(\text{DEPARTMENT})$
2. $\text{ACCOUNTS\_EMP} \leftarrow \sigma_{\text{DNUM} = \text{DNO}}(\text{EMPLOYEE} \times \text{ACCOUNTS\_DEPT})$
3. $\text{RESULT} \leftarrow \pi_{\text{SALARY}}(\text{ACCOUNTS\_EMP})$

---

### 3. Nov 2025 End-Sem Q4(c):
> **Query:** *"List all locations that are either department locations or project locations."*

#### ✅ Solution (Using Project $\pi$ and Union $\cup$):
$$\pi_{\text{DLOCATION}}(\text{DEPARTMENT}) \;\cup\; \pi_{\text{PLOCATION}}(\text{PROJECT})$$

* **Explanation:**
  1. $\pi_{\text{DLOCATION}}(\text{DEPARTMENT})$ extracts the set of all department locations.
  2. $\pi_{\text{PLOCATION}}(\text{PROJECT})$ extracts the set of all project locations.
  3. Since both single-column relations are union-compatible (both are location strings), the **Union ($\cup$)** operator combines them and eliminates duplicate locations.

---

### 4. Nov 2025 End-Sem Q4(d):
> **Query:** *"Find the names of employees who are not managers of any department."*

#### ✅ Solution (Using Set Difference $-$, $\times$, and $\pi$):

**Step 1:** Find the `ENO` of all employees who are **not** managers by subtracting Manager IDs (`MGRENO`) from all Employee IDs (`ENO`):
$$\text{NON\_MGR\_ENO}(\text{ENO}) \leftarrow \pi_{\text{ENO}}(\text{EMPLOYEE}) \;-\; \pi_{\text{MGRENO}}(\text{DEPARTMENT})$$

**Step 2:** Combine with `EMPLOYEE` to get their `NAME`:
$$\text{RESULT} \leftarrow \pi_{\text{NAME}}\Big(\sigma_{\text{EMPLOYEE.ENO} = \text{NON\_MGR\_ENO.ENO}}(\text{EMPLOYEE} \times \text{NON\_MGR\_ENO})\Big)$$
*(Or using Natural Join $\bowtie$: $\pi_{\text{NAME}}(\text{EMPLOYEE} \bowtie \text{NON\_MGR\_ENO})$)*

---

### 5. Oct 2025 Internal Q2(b)(iv):
> **Query:** *"Names of employees working in 'physics' department, not in 'chemistry' department."*

#### ✅ Solution:
*(Note: Since `DNUM` in `EMPLOYEE` is a single value showing each employee works in one department, any employee in the `'physics'` department is automatically not in the `'chemistry'` department. However, to explicitly show the Set Difference ($-$) logic for full marks, write both!)*

**Step 1 (Employees in `'physics'` department):**
$$\text{PHYSICS\_EMP} \leftarrow \pi_{\text{NAME}}\Big(\sigma_{\text{DNAME} = \text{'physics'} \;\wedge\; \text{DNUM} = \text{DNO}}(\text{EMPLOYEE} \times \text{DEPARTMENT})\Big)$$

**Step 2 (Employees in `'chemistry'` department):**
$$\text{CHEM\_EMP} \leftarrow \pi_{\text{NAME}}\Big(\sigma_{\text{DNAME} = \text{'chemistry'} \;\wedge\; \text{DNUM} = \text{DNO}}(\text{EMPLOYEE} \times \text{DEPARTMENT})\Big)$$

**Step 3 (Subtract using Set Difference $-$):**
$$\text{RESULT} \leftarrow \text{PHYSICS\_EMP} \;-\; \text{CHEM\_EMP}$$

### Quick 30-Second Recap of 2.3
* **Select ($\sigma_{\text{condition}}(R)$):** Filters **rows** horizontally.
* **Project ($\pi_{\text{columns}}(R)$):** Filters **columns** vertically and removes duplicate rows.
* **Rule for combining $\sigma$ and $\pi$:** Put $\sigma$ on the **inside** (filter rows first) and $\pi$ on the **outside** (pick columns last).
* **Set Operations ($\cup, \cap, -$):** Require both tables to be **Union-Compatible** (same number of columns + matching data types).
  * *"Either X or Y"* $\rightarrow$ **Union ($\cup$)**
  * *"Both X and Y"* $\rightarrow$ **Intersection ($\cap$)**
  * *"In X, NOT in Y"* $\rightarrow$ **Set Difference ($-$)**
* **Cartesian Product ($R \times S$):** Pairs every row of $R$ with every row of $S$. Must be followed by $\sigma_{\text{FK} = \text{PK}}$ to keep only matching rows!
