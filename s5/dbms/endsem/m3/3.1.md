# Module 3.1: SQL DML – Queries on Single and Multiple Tables

> **Syllabus Coverage:** SQL DML (Data Manipulation Language) – `INSERT`, `UPDATE`, `DELETE`, and `SELECT` Queries on Single and Multiple Tables (`WHERE`, `DISTINCT`, `LIKE`, `BETWEEN`, `IN`, `IS NULL`, `ORDER BY`, Joins, and Table Aliases).

---

## PART A: Modifying Data in SQL (`INSERT`, `UPDATE`, `DELETE`)

Once tables are created using DDL (`CREATE TABLE`), we use **DML (Data Manipulation Language)** to populate, modify, and query the actual rows inside those tables.

Let's use a sample `EMPLOYEE` table:
`EMPLOYEE (EID, EName, Dept, Salary)`

### 1. The `INSERT` Statement (Adding New Rows)
Used to add one or more new tuples (rows) into a relation.

* **Syntax 1 (Inserting values for ALL columns in order):**
  ```sql
  INSERT INTO EMPLOYEE
  VALUES (101, 'Adhil', 'EEE', 45000);
  ```
* **Syntax 2 (Specifying column names explicitly – Safer & Better!):**
  *(Any omitted column that is nullable will automatically receive `NULL` or its `DEFAULT` value)*
  ```sql
  INSERT INTO EMPLOYEE (EID, EName, Salary)
  VALUES (102, 'Rahul', 38000);
  -- Here, 'Dept' is omitted, so it becomes NULL (or DEFAULT)
  ```

---

### 2. The `UPDATE` Statement (Modifying Existing Rows)
Used to change attribute values of one or more existing rows that satisfy a `WHERE` condition.

* **Syntax:**
  ```sql
  UPDATE Table_Name
  SET Column1 = New_Value1, Column2 = New_Value2
  WHERE Condition;
  ```
* **Example 1 (Give a 10% salary hike to all `'EEE'` department employees):**
  ```sql
  UPDATE EMPLOYEE
  SET Salary = Salary * 1.10
  WHERE Dept = 'EEE';
  ```
* ⚠️ **Important Exam Warning:** If you omit the `WHERE` clause (`UPDATE EMPLOYEE SET Salary = 50000;`), **every single row in the entire table** will be updated!

---

### 3. The `DELETE` Statement (Removing Rows)
Used to remove existing rows from a table that satisfy a `WHERE` condition.

* **Syntax:**
  ```sql
  DELETE FROM Table_Name
  WHERE Condition;
  ```
* **Example (Delete the employee with `EID = 102`):**
  ```sql
  DELETE FROM EMPLOYEE
  WHERE EID = 102;
  ```
* *(If you omit the `WHERE` clause—`DELETE FROM EMPLOYEE;`—it deletes all rows in the table, leaving an empty table).*

---

## PART B: Single-Table SQL Queries (`SELECT ... FROM ... WHERE`)

The fundamental block for retrieving information in SQL is the **`SELECT-FROM-WHERE`** statement:

```sql
SELECT   <attribute_list>      -- 3. Which columns to display (like Project π)
FROM     <table_list>          -- 1. Which table(s) to read from (like ×)
WHERE    <condition>           -- 2. Which rows to keep (like Select σ)
ORDER BY <column_name> [ASC|DESC]; -- 4. How to sort the final output
```

> ⚠️ **Don't Confuse SQL `SELECT` with Relational Algebra `SELECT` ($\sigma$)!**
> * In Relational Algebra, **$\sigma$ (Select)** filters *rows*, and **$\pi$ (Project)** picks *columns*.
> * In SQL, the **`SELECT`** keyword actually corresponds to **$\pi$ (Project)** (it picks columns!), while the **`WHERE`** keyword corresponds to **$\sigma$ (Select)** (it filters rows!).

---

### 1. Eliminating Duplicates: `ALL` vs. `DISTINCT`
Unlike Relational Algebra's $\pi$ operator (which automatically removes duplicate rows), **SQL does NOT remove duplicate rows by default** because removing duplicates requires an expensive sorting step.

* **`SELECT Dept FROM EMPLOYEE;`** *(Default = `SELECT ALL`)* $\rightarrow$ Returns `'EEE'`, `'CSE'`, `'EEE'`, `'EEE'` (keeps duplicates!).
* **`SELECT DISTINCT Dept FROM EMPLOYEE;`** $\rightarrow$ Returns `'EEE'`, `'CSE'` (**eliminates duplicates!**).
* **`SELECT * FROM EMPLOYEE;`** $\rightarrow$ The asterisk `*` means **"select all columns"** of the table.

---

### 2. Essential `WHERE` Clause Operators (Exam Toolkit)

When writing SQL queries in exams, you will frequently need these **5 special `WHERE` operators**:

#### a) Comparison & Logical Operators (`AND`, `OR`, `NOT`)
```sql
-- Find female employees in EEE earning more than 20000:
SELECT NAME, SALARY
FROM EMPLOYEE
WHERE GENDER = 'F' AND DNUM = 10 AND SALARY > 20000;
```

#### b) Range Operator: `BETWEEN ... AND ...`
Checks if a value falls within an **inclusive** range (`Salary >= 20000 AND Salary <= 50000`):
```sql
SELECT EName, Salary
FROM EMPLOYEE
WHERE Salary BETWEEN 20000 AND 50000;
```

#### c) Set Membership Operator: `IN (...)` and `NOT IN (...)`
Checks if a value matches **any** value in a given list (cleaner than writing multiple `OR` conditions):
```sql
-- Find employees working in 'EEE', 'CSE', or 'ECE':
SELECT EName, Dept
FROM EMPLOYEE
WHERE Dept IN ('EEE', 'CSE', 'ECE');
```

#### d) Pattern Matching Operator: `LIKE` (With `%` and `_` Wildcards)
Used for searching partial strings/substrings using **two wildcard characters**:
1. **`%` (Percent Sign):** Matches **zero, one, or any number of characters**.
2. **`_` (Underscore):** Matches **exactly ONE single character**.

📸 **[Click here to view SQL LIKE Wildcards (% and _) Examples Charts on Google Images](https://www.google.com/search?q=SQL+LIKE+operator+wildcards+percent+and+underscore+examples+chart&udm=2)**

| Pattern | Exact Meaning | Example Matches |
| :--- | :--- | :--- |
| **`'A%'`** | Starts with `'A'` | `'Adhil'`, `'Anjali'`, `'A'` |
| **`'%n'`** | Ends with `'n'` | `'Kiran'`, `'Arjun'` |
| **`'%ram%'`** | Contains `'ram'` anywhere inside | `'Ramesh'`, `'Vikram'`, `'Subramaniam'` |
| **`'_a%'`** | Second letter is `'a'` | `'Rahul'`, `'Manoj'` |
| **`'____'`** *(4 underscores)* | Exactly 4 characters long | `'Raju'`, `'Meen'` |

```sql
-- Example: Find employees whose name starts with 'A' and has at least 3 characters:
SELECT EName FROM EMPLOYEE WHERE EName LIKE 'A__%';
```

#### e) Checking for `NULL` Values: `IS NULL` and `IS NOT NULL`
* In SQL, you can **NEVER** write `WHERE DNUM = NULL`! Because `NULL` represents an unknown value, comparing anything to `NULL` with `=` evaluates to `UNKNOWN` (and returns 0 rows).
* Always use **`IS NULL`** or **`IS NOT NULL`**:
```sql
-- Find employees who have not been assigned a supervisor yet:
SELECT NAME FROM EMPLOYEE WHERE SUPERENO IS NULL;
```

---

### 3. Sorting Results: The `ORDER BY` Clause
Used at the very end of a query to sort the output rows:
* **`ASC`:** Ascending order ($A \rightarrow Z$, smallest $\rightarrow$ largest). **This is the default** if you don't specify `ASC` or `DESC`.
* **`DESC`:** Descending order ($Z \rightarrow A$, largest $\rightarrow$ smallest).

```sql
-- List employees sorted by highest Salary first; if tied, sort alphabetically by Name:
SELECT EName, Dept, Salary
FROM EMPLOYEE
ORDER BY Salary DESC, EName ASC;
```

---

### 4. Set Operations in SQL (`UNION`, `INTERSECT`, `EXCEPT`)
Just like in Relational Algebra, two union-compatible `SELECT` queries can be combined using:
* **`UNION`**: Combines results of both queries and **eliminates duplicates**. *(Use `UNION ALL` to keep duplicates).*
* **`INTERSECT`**: Keeps rows common to both queries.
* **`EXCEPT` (or `MINUS` in Oracle)**: Keeps rows from the first query that are **not** in the second query.

```sql
-- Nov 2025 Q4(c) in SQL: All locations that are either dept locations or project locations:
SELECT DLOCATION FROM DEPARTMENT
UNION
SELECT PLOCATION FROM PROJECT;
```

## PART C: Multi-Table SQL Queries (Joins & Table Aliases)

When the columns you need live in **two or more different tables**, you must **Join** the tables together using their **Foreign Key = Primary Key** condition.

📸 **[Click here to view SQL Joins Visual Venn Diagram Chart on Google Images](https://www.google.com/search?q=SQL+joins+inner+left+right+full+outer+join+diagram&udm=2)**

### 1. Two Ways to Write an Inner Join in SQL

Suppose we want to find the **`NAME` and `SALARY` of employees working in the `'Accounts'` department** using:
* `EMPLOYEE (ENO, NAME, SALARY, DNUM)`
* `DEPARTMENT (DNO, DNAME)`

#### Method A: Implicit Join (Using comma `,` in `FROM` and join condition in `WHERE`)
```sql
SELECT E.NAME, E.SALARY
FROM EMPLOYEE E, DEPARTMENT D
WHERE E.DNUM = D.DNO
  AND D.DNAME = 'Accounts';
```

#### Method B: Explicit ANSI `JOIN ... ON` Syntax (Modern, Clean & Recommended!)
Separates the **join condition (`ON`)** from the **row filter condition (`WHERE`)**, making multi-table queries much easier to read:
```sql
SELECT E.NAME, E.SALARY
FROM EMPLOYEE E
INNER JOIN DEPARTMENT D ON E.DNUM = D.DNO
WHERE D.DNAME = 'Accounts';
```
*(Both Method A and Method B are 100% valid in exams and get full marks!)*

---

### 2. Joining 3 Tables Together in SQL

Recall **Oct 2025 Internal Q2(b)(iii)**: *"For each employee return name of the employee along with his department name and the names of projects in which he/she works."*
In SQL, we simply chain two `JOIN ... ON` clauses:

```sql
SELECT E.NAME, D.DNAME, P.PNAME
FROM EMPLOYEE E
JOIN DEPARTMENT D ON E.DNUM = D.DNO
JOIN PROJECT P    ON D.DNO  = P.CDNO;
```

---

### 3. Table Aliases (Tuple Variables) & Self-Joins

Notice in the queries above we wrote `FROM EMPLOYEE E, DEPARTMENT D` (or `FROM EMPLOYEE AS E`). Here `E` and `D` are **Table Aliases (Tuple Variables)**.

* **When is a Table Alias Optional?** When joining different tables (`EMPLOYEE` and `DEPARTMENT`), aliases just save typing.
* **When is a Table Alias MANDATORY?** Whenever you need to join a table **with itself (Self-Join)**, or when the **same table plays two different roles** in one query!

#### Classic Self-Join Example (Employee & Supervisor):
> *"For each employee, list the employee's name and their supervisor's name."*

Since both the employee and the supervisor live in the `EMPLOYEE` table, we declare two aliases in `FROM`: **`E` (for the Employee)** and **`S` (for the Supervisor)**:
```sql
SELECT E.NAME AS Employee_Name, S.NAME AS Supervisor_Name
FROM EMPLOYEE E
JOIN EMPLOYEE S ON E.SUPERENO = S.ENO;
```

## PART D: Past Year Question (PYQ) – Multi-Table SQL Join Solved Step-by-Step

### PYQ 1: Oct 2025 Internal Test – Question III(a)(i) [1 Mark]
> **Schema Given in the Question Paper:**
> *"In the following tables foreign keys have the same name as primary keys except `DIRECTED-BY`, which refers to the primary key `ARTIST-ID`. Consider only single director movies."*
> * `MOVIES (MOVIE-ID, MNAME, GENRE, LENGTH, DIRECTED-BY)`
> * `ARTIST (ARTIST-ID, ANAME)`
> * `ACTING (ARTIST-ID, MOVIE-ID)`
>
> **Query i):** *"Write SQL expression for: Name(s) and director name(s) of movie(s) acted by 'Jenny'. (1M)"*

---

#### 🔍 Step-by-Step Visual Breakdown (Why You Need Two Aliases for `ARTIST`!):

Look carefully at what the query asks:
1. We need movies **acted by `'Jenny'`**. Where are actors stored? In `ARTIST` (connected to `MOVIES` through `ACTING`)!
2. We ALSO need the **director's name** (`ANAME`) of those movies. Where are directors stored? **Also in `ARTIST`** (connected to `MOVIES` via `MOVIES.DIRECTED-BY = ARTIST.ARTIST-ID`)!

If you only put `ARTIST` once in the `FROM` clause with `ANAME = 'Jenny'`, you can only get `'Jenny'`'s name, **not** the director's name!
Therefore, we use `ARTIST` **twice** with two aliases:
* **`A1` (or `Actor`):** Represents the actor (`A1.ANAME = 'Jenny'`), linked via `ACTING`.
* **`A2` (or `Director`):** Represents the director (`M.DIRECTED-BY = A2.ARTIST-ID`), whose name `A2.ANAME` we print in `SELECT`!

```text
[ ARTIST as Actor ]                [ ACTING ]                [ MOVIES M ]                [ ARTIST as Director ]
+-----------+---------+     +-----------+----------+     +----------+-------+-----+     +-----------+-------------+
| ARTIST-ID | ANAME   |     | ARTIST-ID | MOVIE-ID |     | MOVIE-ID | MNAME | DIR |     | ARTIST-ID | ANAME       |
+-----------+---------+     +-----------+----------+     +----------+-------+-----+     +-----------+-------------+
|    A10    | 'Jenny' |<--->|    A10    |   M500   |<--->|   M500   | 'Leo' | A99 |<--->|    A99    | 'Lokesh'    |
+-----------+---------+     +-----------+----------+     +----------+-------+-----+     +-----------+-------------+
   (Filter: = 'Jenny')                                    (Print: M.MNAME)               (Print: Director.ANAME)
```

---

#### ✅ Model Exam Answer (Write either version for full marks):

**Method 1 (Using Explicit `JOIN ... ON` – Clearest!):**
```sql
SELECT M.MNAME AS Movie_Name, Director.ANAME AS Director_Name
FROM MOVIES M
JOIN ACTING Act      ON M."MOVIE-ID"    = Act."MOVIE-ID"
JOIN ARTIST Actor    ON Act."ARTIST-ID" = Actor."ARTIST-ID"
JOIN ARTIST Director ON M."DIRECTED-BY" = Director."ARTIST-ID"
WHERE Actor.ANAME = 'Jenny';
```

**Method 2 (Using Implicit Comma Join in `WHERE`):**
```sql
SELECT M.MNAME, Director.ANAME
FROM MOVIES M, ACTING Act, ARTIST Actor, ARTIST Director
WHERE M."MOVIE-ID"    = Act."MOVIE-ID"
  AND Act."ARTIST-ID" = Actor."ARTIST-ID"
  AND M."DIRECTED-BY" = Director."ARTIST-ID"
  AND Actor.ANAME = 'Jenny';
```
