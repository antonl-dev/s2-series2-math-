## PART A: Aggregate Functions in SQL

**Aggregate Functions** take a collection (multiset) of values from a column as input and return a **single summary number** as output.

SQL provides **5 built-in Aggregate Functions**:

📸 **[Click here to view SQL Aggregate Functions Summary Charts on Google Images](https://www.google.com/search?q=SQL+aggregate+functions+COUNT+SUM+AVG+MIN+MAX+chart&udm=2)**

| Function | What It Returns | Example on `EMPLOYEE` Table Above | Output |
| :--- | :--- | :--- | :--- |
| **1. `COUNT(*)`** | Total number of **rows** in the table/group (including `NULL`s). | `SELECT COUNT(*) FROM EMPLOYEE;` | `5` |
| **`COUNT(Col)`** | Number of non-`NULL` values in `Col` *(use `COUNT(DISTINCT Col)` for unique values)*. | `SELECT COUNT(DISTINCT Dept) FROM EMPLOYEE;` | `3` |
| **2. `SUM(Col)`** | Sum of all values in a numeric column. | `SELECT SUM(Salary) FROM EMPLOYEE;` | `200000` |
| **3. `AVG(Col)`** | Arithmetic mean (average) of a numeric column. | `SELECT AVG(Salary) FROM EMPLOYEE;` | `40000` |
| **4. `MAX(Col)`** | Highest (maximum) value in a column. | `SELECT MAX(Salary) FROM EMPLOYEE;` | `60000` |
| **5. `MIN(Col)`** | Lowest (minimum) value in a column. | `SELECT MIN(Salary) FROM EMPLOYEE;` | `30000` |

* **Important Rule on `NULL`s:** Except for `COUNT(*)`, all aggregate functions (`SUM`, `AVG`, `MIN`, `MAX`, `COUNT(Col)`) **automatically ignore `NULL` values**!

### ⚠️ The #1 Beginner Mistake in SQL (Why We Need Subqueries!)
Suppose the exam asks: *"Find the `EID` and `EName` of the employee having the highest salary."*
* ❌ **WRONG SQL (Syntax Error!):**
  ```sql
  -- NEVER WRITE THIS! Aggregate functions are ILLEGAL inside a WHERE clause!
  SELECT EID, EName FROM EMPLOYEE WHERE Salary = MAX(Salary);
  ```
* **Why is this illegal?** Because the `WHERE` clause checks **one row at a time**, whereas `MAX(Salary)` requires scanning the **entire table** first!
* ✅ **CORRECT SQL (Use a Nested Subquery to find `MAX(Salary)` first!):**
  ```sql
  SELECT EID, EName
  FROM EMPLOYEE
  WHERE Salary = (SELECT MAX(Salary) FROM EMPLOYEE);
  ```

## PART B: Grouping (`GROUP BY`) and Filtering Groups (`HAVING`)

What if we don't want the average salary of the *whole company*, but instead want the **average salary of EACH department separately** (or the **count of movies in EACH genre**)?
We use the **`GROUP BY`** clause!

### 1. How `GROUP BY` Works Visually

The `GROUP BY` clause partitions the rows of a table into **non-overlapping groups** where all rows in a group have the **exact same value** for the grouping attribute(s). Then, the aggregate function (`COUNT`, `AVG`, `MAX`, etc.) is calculated **once per group**!

📸 **[Click here to view How SQL GROUP BY Works Visually on Google Images](https://www.google.com/search?q=how+GROUP+BY+works+in+SQL+visual+diagram&udm=2)**

```text
STEP 1: Original EMPLOYEE Table     STEP 2: GROUP BY Dept           STEP 3: Aggregate per Group
+-----+--------+------+--------+    +------+--------+               +------+----------+-------------+
| EID | EName  | Dept | Salary |    | EEE  | 60000  | ------------> | Dept | COUNT(*) | AVG(Salary) |
+-----+--------+------+--------+    | EEE  | 30000  |               +------+----------+-------------+
| 101 | Adhil  | EEE  | 60000  |    +------+--------+               | EEE  |    2     |    45000    |
| 102 | Rahul  | EEE  | 30000  |    | CSE  | 50000  | ------------> | CSE  |    2     |    40000    |
| 103 | Meera  | CSE  | 50000  |    | CSE  | 30000  |               | ECE  |    1     |    30000    |
| 104 | Anjali | CSE  | 30000  |    +------+--------+               +------+----------+-------------+
| 105 | Kiran  | ECE  | 30000  |    | ECE  | 30000  | ------------>
+-----+--------+------+--------+    +------+--------+
```

#### SQL Query for the Diagram Above:
```sql
SELECT Dept, COUNT(*) AS Emp_Count, AVG(Salary) AS Avg_Salary
FROM EMPLOYEE
GROUP BY Dept;
```

> **The Golden Rule of `GROUP BY`:**
> Any column name that appears in the `SELECT` clause **outside** of an aggregate function **MUST also appear in the `GROUP BY` clause**!
> *(For example, you cannot write `SELECT Dept, EName, AVG(Salary) FROM EMPLOYEE GROUP BY Dept;` because each `Dept` has multiple `EName`s!)*

---

### 2. Filtering Groups: The `HAVING` Clause
Just as `WHERE` filters **individual rows**, the **`HAVING`** clause filters **entire groups** created by `GROUP BY`!

* **Example:** *"Find departments that have an average salary greater than 35000 and at least 2 employees."*
```sql
SELECT Dept, COUNT(*) AS Emp_Count, AVG(Salary) AS Avg_Salary
FROM EMPLOYEE
GROUP BY Dept
HAVING AVG(Salary) > 35000 AND COUNT(*) >= 2;
```
*(In our trace above, `'EEE'` [Avg 45000, Count 2] and `'CSE'` [Avg 40000, Count 2] pass the `HAVING` filter, while `'ECE'` [Avg 30000, Count 1] is eliminated!)*

#### ⭐ Quick Comparison Table: `WHERE` vs. `HAVING`

| Feature | `WHERE` Clause | `HAVING` Clause |
| :--- | :--- | :--- |
| **1. What It Filters** | Filters **individual rows (tuples)**. | Filters **summary groups** formed by `GROUP BY`. |
| **2. When It Executes** | Executes **BEFORE** grouping (`GROUP BY`) and aggregation. | Executes **AFTER** grouping (`GROUP BY`) and aggregation. |
| **3. Can It Contain Aggregate Functions (`COUNT`, `AVG`, `MAX`)?** | **NO!** (`WHERE AVG(Salary) > 30000` is a syntax error). | **YES!** (`HAVING AVG(Salary) > 30000` is completely valid). |

#### Complete Order of Clauses in an SQL Query:
```sql
SELECT   Dept, AVG(Salary)      -- 5. Project final columns / aggregates
FROM     EMPLOYEE               -- 1. Pick table
WHERE    Salary > 20000         -- 2. Filter individual rows FIRST
GROUP BY Dept                   -- 3. Form groups from remaining rows
HAVING   COUNT(*) >= 2          -- 4. Filter the formed groups
ORDER BY AVG(Salary) DESC;      -- 6. Sort final output
```

## PART C: Nested Queries (Subqueries) – Non-Correlated vs. Correlated

> ⭐ **DIRECT EXAM QUESTIONS (15 Marks in Oct 2026!):**
> * **Oct 2026 Q3(a) & Q3(b) [7.5 Marks]:** Non-correlated nested queries (`MAX(Salary)` and `> AVG(Salary)`).
> * **Oct 2026 Q5(a) & Q5(b) [7.5 Marks]:** Explain difference between Correlated and Non-Correlated subqueries with examples + Write Correlated subquery for department-wise average salary!

### 1. What is a Nested Query (Subquery)?
* **Definition:** A **Nested Query** (or **Subquery**) is a complete `SELECT-FROM-WHERE` query block that is placed **inside** another SQL query (typically inside the `WHERE`, `HAVING`, or `FROM` clause of the **Outer Query**).
* **Terminology:**
  * **Outer Query (Parent Query):** The main enclosing query.
  * **Inner Query (Subquery / Child Query):** The query enclosed inside parentheses `(...)`.

Based on how the inner query interacts with the outer query, nested queries are classified into **two types**:
1. **Non-Correlated (Independent) Subqueries**
2. **Correlated (Synchronized) Subqueries**

📸 **[Click here to view Correlated vs Non-Correlated Subqueries Execution Diagrams on Google Images](https://www.google.com/search?q=correlated+vs+non+correlated+subquery+in+sql+diagram&udm=2)**

---

### 2. Type 1: Non-Correlated (Independent) Subqueries

* **Definition:** A subquery is **Non-Correlated** when the **Inner Query is completely independent of the Outer Query**. The inner query does **not** reference any table or column from the outer query.
* **How It Executes (Bottom-Up Execution – Runs ONLY ONCE!):**
  1. **Step 1:** The **Inner Query** executes **first** and **only once**.
  2. **Step 2:** The result of the inner query is substituted into the `WHERE` condition of the **Outer Query**.
  3. **Step 3:** The **Outer Query** executes using that fixed value(s).

```text
NON-CORRELATED SUBQUERY EXECUTION (Bottom-Up, Inner Runs 1 Time):

  Outer Query: SELECT EID, EName FROM EMPLOYEE WHERE Salary > ( 40000 );
                                                                  ^
                                                                  | Passes result (40000) once!
  Inner Query: ( SELECT AVG(Salary) FROM EMPLOYEE ) --------------+
               [Executes FIRST & ONLY ONCE on its own!]
```

#### Example A: Single-Row Non-Correlated Subquery (Using `=`, `>`, `<`)
Used when the inner query returns **exactly 1 value** (such as `MAX(...)` or `AVG(...)`):
```sql
-- Find employees whose salary is greater than the overall company average salary:
SELECT EID, EName, Salary
FROM EMPLOYEE
WHERE Salary > (SELECT AVG(Salary) FROM EMPLOYEE);
```
* **Trace on our sample table:**
  1. Inner query `(SELECT AVG(Salary) FROM EMPLOYEE)` runs once and returns **`40000`**.
  2. Outer query becomes `SELECT EID, EName, Salary FROM EMPLOYEE WHERE Salary > 40000;`.
  3. Output: `(101, 'Adhil', 60000)` and `(103, 'Meera', 50000)`.

#### Example B: Multi-Row Non-Correlated Subquery (Using `IN`, `NOT IN`, `ALL`, `ANY`)
Used when the inner query returns a **list of multiple values** (1 column, many rows):
```sql
-- Find names of employees who work in departments located in 'Kollam':
SELECT NAME
FROM EMPLOYEE
WHERE DNUM IN (SELECT DNO FROM DEPARTMENT WHERE DLOCATION = 'Kollam');
```
* **Bonus Operators for Multi-Row Subqueries (`ALL` and `ANY`):**
  * `Salary > ALL (SELECT Salary FROM EMPLOYEE WHERE Dept = 'CSE')` $\rightarrow$ Salary is greater than **every** employee in CSE (i.e., greater than the maximum in CSE).
  * `Salary > ANY (SELECT Salary FROM EMPLOYEE WHERE Dept = 'CSE')` $\rightarrow$ Salary is greater than **at least one** employee in CSE (i.e., greater than the minimum in CSE).

---

### 3. Type 2: Correlated Subqueries *(Explained Step-by-Step!)*

* **Definition:** A **Correlated Subquery** is a nested query in which the **Inner Query references one or more columns from the table in the Outer Query**.
* Because the inner query depends on a value from the current row of the outer query, the inner query **cannot be evaluated independently on its own**!
* **How It Executes (Top-Down / Row-by-Row Nested Loop Execution!):**
  1. **Step 1:** The **Outer Query** picks **one candidate row** (say, row $r_1$) from the outer table.
  2. **Step 2:** It passes the correlated attribute value from row $r_1$ (e.g., `E1.Dept`) into the **Inner Query**.
  3. **Step 3:** The **Inner Query** executes completely for that specific value and returns a result to the Outer Query's `WHERE` condition.
  4. **Step 4:** If the `WHERE` condition is `TRUE`, row $r_1$ is added to the final output.
  5. **Step 5:** **REPEAT Steps 1 to 4 for EVERY SINGLE ROW** in the outer table! *(If the outer table has $N$ rows, the inner query executes **$N$ times**!)*

---

#### 🔍 Step-by-Step Visual Trace of Oct 2026 Q5(b) (The Classic Correlated Subquery!):

> **Problem (Oct 2026 Internal Test Q5b [4.5 Marks]):**
> *"Write a correlated subquery to find employees whose salary is greater than the average salary of their respective department."*

#### Why Can't We Use a Non-Correlated Subquery Here?
Because every employee belongs to a **different department**!
* When checking **Adhil (`Dept = 'EEE'`)**, we must compare his salary against the **average salary of `'EEE'`** (`45000`).
* When checking **Meera (`Dept = 'CSE'`)**, we must compare her salary against the **average salary of `'CSE'`** (`40000`).

#### The Correlated SQL Query:
```sql
SELECT E1.EID, E1.EName, E1.Dept, E1.Salary
FROM EMPLOYEE E1
WHERE E1.Salary > (
    SELECT AVG(E2.Salary)
    FROM EMPLOYEE E2
    WHERE E2.Dept = E1.Dept   -- <-- CORRELATION CONDITION! (References Outer E1.Dept)
);
```

#### Watch How the DBMS Executes This Row-by-Row on Our 5-Row `EMPLOYEE` Table:

```text
+-----+--------+------+--------+
| EID | EName  | Dept | Salary |
+-----+--------+------+--------+
| 101 | Adhil  | EEE  | 60000  |  <-- Row 1: E1.Dept = 'EEE', E1.Salary = 60000
| 102 | Rahul  | EEE  | 30000  |      Inner Query runs for 'EEE': AVG(60000, 30000) = 45000.
| 103 | Meera  | CSE  | 50000  |      Is 60000 > 45000? YES! -> KEEP ADHIL!
| 104 | Anjali | CSE  | 30000  |
| 105 | Kiran  | ECE  | 30000  |  <-- Row 2: E1.Dept = 'EEE', E1.Salary = 30000
+-----+--------+------+--------+      Inner Query runs for 'EEE': AVG = 45000.
                                      Is 30000 > 45000? NO!  -> REJECT RAHUL.

                                  <-- Row 3: E1.Dept = 'CSE', E1.Salary = 50000
                                      Inner Query runs for 'CSE': AVG(50000, 30000) = 40000.
                                      Is 50000 > 40000? YES! -> KEEP MEERA!

                                  <-- Row 4: E1.Dept = 'CSE', E1.Salary = 30000
                                      Inner Query runs for 'CSE': AVG = 40000.
                                      Is 30000 > 40000? NO!  -> REJECT ANJALI.

                                  <-- Row 5: E1.Dept = 'ECE', E1.Salary = 30000
                                      Inner Query runs for 'ECE': AVG(30000) = 30000.
                                      Is 30000 > 30000? NO!  -> REJECT KIRAN.
```

**Final Output Table:**
| EID | EName | Dept | Salary |
| :--- | :--- | :--- | :--- |
| 101 | Adhil | EEE | 60000 |
| 103 | Meera | CSE | 50000 |

### 4. Using `EXISTS` and `NOT EXISTS` in Correlated Subqueries
Correlated subqueries also frequently use the boolean function **`EXISTS (subquery)`**:
* **`EXISTS(Q)`** returns **`TRUE`** if the correlated inner query $Q$ returns **at least one row**, and **`FALSE`** if $Q$ returns zero rows.
* **`NOT EXISTS(Q)`** returns **`TRUE`** if the inner query $Q$ returns **zero rows** (empty set).

```sql
-- Example: Find names of employees who are managers of at least one department:
SELECT E.NAME
FROM EMPLOYEE E
WHERE EXISTS (
    SELECT *
    FROM DEPARTMENT D
    WHERE D.MGRENO = E.ENO   -- Correlated reference to outer E.ENO
);
```

### 5. Side-by-Side Comparison Table: Non-Correlated vs. Correlated Subqueries

> ⭐ **MEMORIZE THIS TABLE:** Directly answers **Oct 2026 Internal Test Q5(a) [3 Marks]**!

| Feature | Non-Correlated Subquery | Correlated Subquery |
| :--- | :--- | :--- |
| **1. Dependency** | The inner query is **completely independent** of the outer query. | The inner query **depends on the outer query** (references outer table columns). |
| **2. Can Inner Query Run Alone?** | **Yes**, the inner query can be copied and executed standalone without errors. | **No**, running the inner query alone gives an error because the outer alias is missing. |
| **3. Execution Order** | **Bottom-Up** (Inner query executes first, then outer query executes). | **Top-Down / Nested Loop** (Outer query fetches a row, then inner query executes for that row). |
| **4. Number of Times Inner Query Executes** | Executes **ONLY ONCE** in total. | Executes **$N$ times** (once for each of the $N$ candidate rows of the outer table). |
| **5. Execution Speed** | **Fast** (since inner query is evaluated only once). | **Slower** (since inner query is re-evaluated repeatedly for every row). |
| **6. Typical Use Case** | Comparing against a global summary (e.g., *salary $>$ overall company average*). | Comparing against a group-specific summary (e.g., *salary $>$ their own department's average*). |

### PYQ 1: Oct 2026 Internal Test – Question III(a) & III(b) [3.5 + 4 = 7.5 Marks]

> **Question III(a) [3.5 Marks]:**
> *"Consider: `EMPLOYEE(EID, EName, Dept, Salary)`*
> *i) Write a nested SQL query to retrieve the employee ID and name of the employee(s) having the highest salary."*
>
> **Question III(b) [4 Marks]:**
> *"Modify the query to find all employees whose salary is greater than the average salary of all employees."*

---

#### ✅ Model Exam Answer for III(a) [3.5 / 3.5 Marks]:

To retrieve the employee(s) having the highest salary, we use a **non-correlated nested SQL query** where the inner subquery computes `MAX(Salary)` from the `EMPLOYEE` table, and the outer query selects all employees whose `Salary` matches that maximum value:

```sql
SELECT EID, EName
FROM EMPLOYEE
WHERE Salary = (
    SELECT MAX(Salary)
    FROM EMPLOYEE
);
```
**How it works:**
1. **Inner Query:** `SELECT MAX(Salary) FROM EMPLOYEE` executes first and returns a single scalar value representing the highest salary in the company.
2. **Outer Query:** Retrieves the `EID` and `EName` of all employees whose `Salary` equals that maximum value (automatically handling ties if multiple employees share the highest salary).

---

#### ✅ Model Exam Answer for III(b) [4 / 4 Marks]:

To find all employees whose salary is greater than the average salary of all employees, we replace `MAX(Salary)` with `AVG(Salary)` in the inner query and change the comparison operator from `=` to **`>`**:

```sql
SELECT EID, EName, Dept, Salary
FROM EMPLOYEE
WHERE Salary > (
    SELECT AVG(Salary)
    FROM EMPLOYEE
);
```
**How it works:**
1. **Inner Query:** `SELECT AVG(Salary) FROM EMPLOYEE` executes once to compute the overall average salary across all employees in the table.
2. **Outer Query:** Compares each employee's `Salary` against that overall average and returns the details of all employees earning strictly more than the company average.

### PYQ 2: Oct 2026 Internal Test – Question V(a) & V(b) [3 + 4.5 = 7.5 Marks]

> **Question V(a) [3 Marks]:**
> *"Explain the difference between correlated and non-correlated subqueries with suitable SQL examples."*
>
> **Question V(b) [4.5 Marks]:**
> *"Write a correlated subquery to find employees whose salary is greater than the average salary of their respective department."*

---

#### ✅ Model Exam Answer for V(a) [3 / 3 Marks]:

| Parameter | Non-Correlated Subquery | Correlated Subquery |
| :--- | :--- | :--- |
| **1. Definition** | The inner subquery is completely independent of the outer query and does not reference any column of the outer table. | The inner subquery depends on the outer query and references one or more columns from the outer query's table. |
| **2. Execution Flow** | **Bottom-Up:** The inner query executes **only once** first, and its result is passed to the outer query. | **Top-Down (Row-by-Row):** The inner query is executed **repeatedly once for every row** processed by the outer query. |
| **3. Standalone Execution** | Can be executed independently on its own. | Cannot be executed alone without the outer query. |

**1. Example of Non-Correlated Subquery:**
*(Finds employees earning more than the overall company average—inner query runs once):*
```sql
SELECT EID, EName
FROM EMPLOYEE
WHERE Salary > (SELECT AVG(Salary) FROM EMPLOYEE);
```

**2. Example of Correlated Subquery:**
*(Finds employees earning more than their own department's average—inner query references `E1.Dept` from outer query):*
```sql
SELECT E1.EID, E1.EName
FROM EMPLOYEE E1
WHERE E1.Salary > (
    SELECT AVG(E2.Salary)
    FROM EMPLOYEE E2
    WHERE E2.Dept = E1.Dept
);
```

---

#### ✅ Model Exam Answer for V(b) [4.5 / 4.5 Marks]:

Assuming the relation schema **`EMPLOYEE(EID, EName, Dept, Salary)`**, the correlated subquery to find employees whose salary is greater than the average salary of their respective department is:

```sql
SELECT E1.EID, E1.EName, E1.Dept, E1.Salary
FROM EMPLOYEE E1
WHERE E1.Salary > (
    SELECT AVG(E2.Salary)
    FROM EMPLOYEE E2
    WHERE E2.Dept = E1.Dept
);
```

**Step-by-Step Explanation of Execution:**
1. **Tuple Variables (Aliases):** We declare `E1` as the alias for the outer `EMPLOYEE` table and `E2` as the alias for the inner `EMPLOYEE` table.
2. **Outer Query Row Selection:** For each tuple `E1` in the outer `EMPLOYEE` table, its department value `E1.Dept` is passed into the inner subquery.
3. **Correlated Evaluation (`WHERE E2.Dept = E1.Dept`):** The inner query computes `AVG(E2.Salary)` considering **only** those employees in `E2` who belong to the same department as the current outer employee (`E1.Dept`).
4. **Comparison:** The outer query checks if `E1.Salary` is strictly greater than that department's average salary. If true, the employee row is returned in the result.

### Quick 30-Second Recap of 3.2
* **5 Aggregate Functions:** `COUNT(*)`, `SUM(Col)`, `AVG(Col)`, `MAX(Col)`, `MIN(Col)`. *(Never put them directly inside a `WHERE` clause!)*
* **`GROUP BY` vs `HAVING`:** `GROUP BY` splits rows into groups; `HAVING` filters those groups using aggregate conditions (whereas `WHERE` filters individual rows before grouping).
* **Non-Correlated Subquery:** Inner query has **no outer reference**, runs **once** (Bottom-Up).
  * *Overall Max Salary:* `WHERE Salary = (SELECT MAX(Salary) FROM EMPLOYEE)`
  * *Above Overall Avg:* `WHERE Salary > (SELECT AVG(Salary) FROM EMPLOYEE)`
* **Correlated Subquery:** Inner query references **outer table alias (`E1.Dept`)**, runs **once per outer row** (Top-Down).
  * *Above Own Dept Avg:* `WHERE E1.Salary > (SELECT AVG(E2.Salary) FROM EMPLOYEE E2 WHERE E2.Dept = E1.Dept)`
