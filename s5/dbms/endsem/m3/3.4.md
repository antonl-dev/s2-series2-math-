## PART A: What is an Index? (And How an Index File is Structured)

### 1. The Textbook Analogy
Imagine a 1,667-page textbook (`Data File`). If you want to find a topic and there is no index, you have to flip through hundreds of pages.
Instead, at the back of the book, there is a small, sorted **Index (`Index File`)** that lists:
$$\langle \text{Keyword}, \;\text{Page Number} \rangle$$
Because each `<Keyword, Page_No>` entry is tiny compared to a full page of text, the entire Index fits in just a few pages! You quickly search the small Index, get the exact Page Number, and jump **straight to that page** in 1 step!

---

### 2. Structure of a Single-Level Ordered Index File on Disk

An **Index File** is a separate, small auxiliary file stored on disk alongside the main **Data File**. Every record inside an Index File is called an **Index Entry** and consists of **only two fields**:

```text
           ONE INDEX ENTRY (Size R_i = V + P bytes)
      +----------------------------+--------------------+
      |   Search Key Value ( V )   | Block Pointer ( P )|
      |   (e.g., ENO = 15 Bytes)   |  (e.g., 5 Bytes)   |
      +----------------------------+--------------------+
```

1. **Indexing Field / Search Key Value ($V$ bytes):** Holds a value of the column on which the index is built (e.g., `employee number` = $15\text{ bytes}$).
2. **Block Pointer ($P$ bytes):** Holds the physical address of the disk block in the Data File that contains that record (e.g., `block pointer` = $5\text{ bytes}$).

####Three Key Formulas for ANY Index File:
1. **Size of One Index Entry ($R_i$):**
   $$R_i = V + P \text{ bytes}$$
2. **Blocking Factor of the Index File ($bfr_i$):** *(How many index entries fit in 1 block of size $B$)*
   $$bfr_i = \left\lfloor \frac{B}{R_i} \right\rfloor \text{ entries per index block}$$
3. **Total Number of Index Blocks ($b_i$):** *(If there are $r_i$ total index entries)*
   $$b_i = \left\lceil \frac{r_i}{bfr_i} \right\rceil \text{ index blocks}$$

## PART B: Dense Indexing vs. Sparse Indexing

> ⭐ **DIRECT EXAM QUESTION:** Asked in **Nov 2025 End-Sem Q5(b) (2 Marks)**: *"Distinguish between sparse indexing and dense indexing."*

How many index entries ($r_i$) do we put inside the Index File? Do we create an index entry for **every single record** in the data file, or only **one entry per disk block**? This gives us **Dense** vs. **Sparse** indexing:

📸 **[Click here to view Dense Index vs Sparse Index Diagrams on Google Images](https://www.google.com/search?q=dense+index+vs+sparse+index+in+dbms+diagram&udm=2)**

```text
1. DENSE INDEX (Has 1 Index Entry for EVERY Record in the Data File!)
   INDEX FILE                           DATA FILE (Block bfr = 3)
   +------+-----+                       +-----------------------+
   |  10  |  *--+---------------------->| ENO = 10  | Adhil     |  Block 1
   |  20  |  *--+---------------------->| ENO = 20  | Rahul     |
   |  30  |  *--+---------------------->| ENO = 30  | Meera     |
   |  40  |  *--+--+                    +-----------------------+
   |  50  |  *--+--+                 +->| ENO = 40  | Anjali    |  Block 2
   |  60  |  *--+--+                 |  | ENO = 50  | Kiran     |
   +------+-----+                    |  | ENO = 60  | Sneha     |
   (Total entries r_i = 6 = r)       |  +-----------------------+


2. SPARSE INDEX (Has ONLY 1 Index Entry per DATA BLOCK -> Points to "Block Anchor"!)
   INDEX FILE                           DATA FILE (MUST be Sorted on ENO!)
   +------+-----+                       +-----------------------+
   |  10  |  *--+---------------------->| ENO = 10  | Adhil     |<- Block Anchor of Block 1
   |  40  |  *--+--+                    | ENO = 20  | Rahul     |
   +------+-----+  |                    | ENO = 30  | Meera     |
   (Total entries  |                    +-----------------------+
    r_i = 2 = b!)  +------------------->| ENO = 40  | Anjali    |<- Block Anchor of Block 2
                                        | ENO = 50  | Kiran     |
                                        | ENO = 60  | Sneha     |
                                        +-----------------------+
```

---

### 1. Dense Index
* **Definition:** A **Dense Index** has **one index entry for EVERY search key value (every record)** in the data file.
* **Number of Index Entries ($r_i$):**
  $$r_i = r \quad (\text{Total number of records in the data file})$$
* **How Search Works:** To find `ENO = 20`, you binary-search the Dense Index for `20` and follow its pointer straight to the block containing `20`. You can even tell if a record exists *just by looking at the index* without reading the data file!
* **Pros & Cons:**
  * **Pro:** Can be built even if the data file is **unsorted (Heap File)**!
  * **Con:** Takes up **much more disk space** (more index blocks $b_i$) because it has an entry for every single record.

---

### 2. Sparse (or Nondense) Index
* **Definition:** A **Sparse Index** has index entries for **only SOME of the search key values**—specifically, it stores **only ONE index entry per Data Block**!
* **What is a "Block Anchor"?**
  * The **first record** inside each disk block of the sorted data file is called the **Block Anchor** (in the diagram above, `ENO = 10` is the Block Anchor of Block 1, and `ENO = 40` is the Block Anchor of Block 2).
  * A Sparse Index stores `<Anchor_Key, Block_Pointer>` for each block.
* **Number of Index Entries ($r_i$):**
  $$r_i = b \quad (\text{Total number of BLOCKS in the data file!})$$
* **How Search Works (e.g., Searching for `ENO = 30` in the Sparse Index above):**
  1. Look in the Sparse Index for the **largest key $\le 30$**.
  2. Since $10 \le 30 < 40$, `ENO = 30` **must** be inside **Block 1**!
  3. Follow the pointer for `10` to load **Block 1** into RAM, and find `ENO = 30` inside Block 1!
* **Crucial Requirement:** A Sparse Index can **ONLY** be used when the data file is physically **sorted (ordered)** on the search key field!

---

### Side-by-Side Comparison Table: Dense Index vs. Sparse Index

*(Memorize this table—it gets you full marks on **Nov 2025 End-Sem Q5b**!)*

| Feature | Dense Index | Sparse (Nondense) Index |
| :--- | :--- | :--- |
| **1. Core Definition** | Contains an index entry for **every single search key value (every record)** in the data file. | Contains index entries for **only some search key values** (one entry per **data block**, called the *Block Anchor*). |
| **2. Number of Index Entries ($r_i$)** | **$r_i = r$** (Equal to the total number of **records** in the file). | **$r_i = b$** (Equal to the total number of **data blocks** in the file). |
| **3. Does Data File Have to be Sorted?** | **No**, can be built on both sorted (ordered) and unsorted (heap) files. | **Yes! Mandatory**—the data file **must** be physically sorted on the search key. |
| **4. Index Size & Space Required** | **Larger** (requires $bfr$ times more index entries and more disk blocks). | **Much Smaller** (compact; often fits entirely in RAM). |
| **5. Index Maintenance on Insert/Delete** | **Higher overhead** (every record insertion/deletion updates the index). | **Lower overhead** (index is updated only when a block splits or its first record changes). |
| **6. Examples** | **Secondary Index** (always Dense). | **Primary Index** (always Sparse). |

## PART C: The 3 Types of Single-Level Ordered Indexes

Depending on **(1) whether the data file is sorted on the indexed column** and **(2) whether that column is a unique Key or a duplicate Non-Key**, there are **three standard types of Single-Level Indexes**:

📸 **[Click here to view Primary vs Clustering vs Secondary Index Diagrams on Google Images](https://www.google.com/search?q=primary+index+clustering+index+secondary+index+in+dbms+diagram&udm=2)**

---

### 1. Primary Index *(Most Common in Exam Numericals!)*
* **Built On:** The **Ordering Key field** of an ordered data file (i.e., the data file is physically **sorted** on its **Primary Key**).
* **Is it Dense or Sparse?** **SPARSE!**
* **Structure:** Has **one index entry per data block** ($r_i = b$). Each entry holds the Primary Key of the first record in that block (**Block Anchor**) and a pointer to that block.
* **Example:** An `EMPLOYEE` file physically sorted on `ENO` (Primary Key), with an index built on `ENO`.

---

### 2. Clustering Index
* **Built On:** The **Ordering Non-Key field** of an ordered data file (i.e., the data file is physically **sorted** on a **non-key column** that has duplicate values!).
* **Why is that column called the "Clustering Field"?** Because all records that share the same value (e.g., all employees in `Dept_No = 10`) are physically clustered together in consecutive disk blocks.
* **Is it Dense or Sparse?** **SPARSE (Nondense)!**
* **Structure:** Has **one index entry for each DISTINCT value** of the clustering field, pointing to the first block that contains records with that value.
* **Note:** A physical data file can be sorted in only **one** order at a time. Therefore, a table can have **at most ONE Primary Index OR ONE Clustering Index** (never both at the same time!).

---

### 3. Secondary Index
* **Built On:** Any **Non-Ordering field** of a file (i.e., the data file is **NOT sorted** on this column!).
  * A Secondary Index can be built on a **Candidate Key** (unique values, like `Aadhar_No` when the file is sorted on `ENO`) or on a **Non-Key** (duplicate values, like `Dept_No` or `Name`).
* **Is it Dense or Sparse?** **ALWAYS DENSE!**
* **Why MUST a Secondary Index be Dense?**
  * Because the data file is **not sorted** on this column! Records with `Aadhar_No = 111`, `112`, `113` are scattered randomly across different disk blocks. A block anchor tells you nothing about the other records in that block, so you **must** store an index entry for **every single record** ($r_i = r$)!
* **Note:** A table can have **many Secondary Indexes**, because they do not require sorting the physical data file.

---

### Master Cheat-Sheet: Primary vs. Clustering vs. Secondary Index

| Index Type | Data File Sorted on This Field? | Is Field Unique (Key)? | Dense or Sparse? | Number of Index Entries ($r_i$) | Max Allowed per Table |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **1. Primary Index** | **YES** (Ordering field) | **YES** (Primary Key) | **Sparse** | **$r_i = b$** *(No. of data blocks)* | At most **1** |
| **2. Clustering Index** | **YES** (Ordering field) | **NO** (Duplicates allowed) | **Sparse** | No. of distinct values | At most **1** |
| **3. Secondary Index** | **NO** (Unordered on this field) | Either Key or Non-Key | **Dense** | **$r_i = r$** *(No. of records)* | **Many** |

## PART D: Universal 5-Step Recipe for Single-Level Index Numericals

Whenever an exam problem gives you a file with **$r$ records**, record size **$R$**, block size **$B$**, key size **$V$**, and block pointer size **$P$**, follow these **exact 5 steps** to get full marks:

### Step 1: Data File Blocking Factor ($bfr$) & Total Data Blocks ($b$)
$$bfr = \left\lfloor \frac{B}{R} \right\rfloor \text{ records/block} \qquad\Longrightarrow\qquad b = \left\lceil \frac{r}{bfr} \right\rceil \text{ data blocks}$$

### Step 2: Index Entry Size ($R_i$) & Index Blocking Factor ($bfr_i$)
$$R_i = V + P \text{ bytes} \qquad\Longrightarrow\qquad bfr_i = \left\lfloor \frac{B}{R_i} \right\rfloor \text{ index entries/block}$$

### Step 3: Number of Index Entries ($r_i$)
* **If Primary Index (Sparse):** $r_i = b$ *(1 entry per data block!)*
* **If Secondary Index (Dense on Key):** $r_i = r$ *(1 entry per record!)*

### Step 4: Total Number of Index Blocks ($b_i$)
$$b_i = \left\lceil \frac{r_i}{bfr_i} \right\rceil \text{ index blocks}$$

### Step 5: Total Block Accesses to Retrieve a Record Using the Single-Level Index!
$$\text{Total Block Accesses} = \underbrace{\left\lceil \log_2(b_i) \right\rceil}_{\substack{\text{Binary search the} \\ \text{Index File blocks}}} + \underbrace{1}_{\substack{\text{Read the target} \\ \text{Data Block!}}}$$

> 💡 **Why do we add $+ 1$ at the end?**
> Because $\left\lceil \log_2(b_i) \right\rceil$ only finds the right block inside the **Index File** (which gives us the block pointer). We still need **$1$ more block access** to go to the **Data File** and fetch the actual employee record!

## PART E: Past Year Questions (PYQs) from Your Papers – Full Answers

### PYQ 1: Oct 2025 Internal Test – Question III(b) [4 Marks]

> **Question III(b) [4 Marks]:**
> *"Consider an EMPLOYEE file with $10000$ records where each record is of size $80\text{ bytes}$. The file is sorted on employee number ($15\text{ bytes}$ long), which is the primary key. Assuming un-spanned organization, block size of $512\text{ bytes}$ and block pointer size of $5\text{ bytes}$ and block anchor size is $6\text{ bytes}$. Compute the number of block accesses needed for retrieving an employee record based on employee number if:*
> *(i) No index is used*
> *(ii) Primary index is used."*

---

#### ✅ Model Exam Answer [4 / 4 Marks]:

**Given Parameters:**
* Number of records in the data file ($r$) = $10,000$
* Record size ($R$) = $80\text{ bytes}$
* Block size ($B$) = $512\text{ bytes}$
* Ordering Primary Key (`employee number`) size ($V$) = $15\text{ bytes}$
* Block pointer size ($P$) = $5\text{ bytes}$ *(and block anchor size given = $6\text{ bytes}$)*
* Organization = **Unspanned**

---

#### Part (i): When NO Index is Used [2 Marks]

1. **Blocking Factor of Data File ($bfr$):**
   $$bfr = \left\lfloor \frac{B}{R} \right\rfloor = \left\lfloor \frac{512}{80} \right\rfloor = \lfloor 6.4 \rfloor = \mathbf{6\text{ records/block}}$$

2. **Total Number of Data Blocks ($b$):**
   $$b = \left\lceil \frac{r}{bfr} \right\rceil = \left\lceil \frac{10000}{6} \right\rceil = \lceil 1666.67 \rceil = \mathbf{1667\text{ blocks}}$$

3. **Block Accesses to Retrieve a Record (No Index):**
   * Since the data file is **sorted** on the search key (`employee number`), we use **Binary Search** on the data blocks:
     $$\text{Block Accesses (Binary Search)} = \left\lceil \log_2(b) \right\rceil = \left\lceil \log_2(1667) \right\rceil = \mathbf{11\text{ block accesses}}$$
   * *(Note: If Linear Search is used instead, average block accesses = $\lceil b/2 \rceil = 834$ blocks, worst case = $1667$ blocks).*

---

#### Part (ii): When a PRIMARY INDEX is Used [2 Marks]

A **Primary Index** is a **sparse index** containing **one index entry per data block** ($r_i = b = 1667\text{ entries}$).

**Case A (Standard Formula: Index Entry = Search Key $V +$ Block Pointer $P$):**
1. **Size of One Index Entry ($R_i$):**
   $$R_i = V + P = 15 + 5 = \mathbf{20\text{ bytes}}$$
2. **Blocking Factor of Index File ($bfr_i$):**
   $$bfr_i = \left\lfloor \frac{B}{R_i} \right\rfloor = \left\lfloor \frac{512}{20} \right\rfloor = \lfloor 25.6 \rfloor = \mathbf{25\text{ entries/block}}$$
3. **Total Number of Index Blocks ($b_i$):**
   $$b_i = \left\lceil \frac{r_i}{bfr_i} \right\rceil = \left\lceil \frac{1667}{25} \right\rceil = \lceil 66.68 \rceil = \mathbf{67\text{ index blocks}}$$
4. **Total Block Accesses Required (Binary Search on Index + 1 Data Block Access):**
   $$\text{Block Accesses} = \left\lceil \log_2(b_i) \right\rceil + 1 = \left\lceil \log_2(67) \right\rceil + 1 = 7 + 1 = \mathbf{8\text{ block accesses}}$$
   *(since $2^6 = 64 < 67 \le 128 = 2^7$, $\lceil \log_2(67) \rceil = 7$).*

*(Note for Alternate Interpretations of the extra "block anchor size = 6 bytes" in the question)*:
* **Case B (If $R_i = V + P + \text{Anchor} = 15 + 5 + 6 = 26\text{ bytes}$):**
  * $bfr_i = \lfloor 512 / 26 \rfloor = 19\text{ entries/block}$
  * $b_i = \lceil 1667 / 19 \rceil = 88\text{ index blocks}$
  * $\text{Block Accesses} = \lceil \log_2(88) \rceil + 1 = 7 + 1 = \mathbf{8\text{ block accesses}}$ *(Exact same answer: 8!)*
* **Case C (If Anchor replaces Key in Index Entry: $R_i = 6 + 5 = 11\text{ bytes}$):**
  * $bfr_i = \lfloor 512 / 11 \rfloor = 46\text{ entries/block}$
  * $b_i = \lceil 1667 / 46 \rceil = 37\text{ index blocks}$
  * $\text{Block Accesses} = \lceil \log_2(37) \rceil + 1 = 6 + 1 = \mathbf{7\text{ block accesses}}$.

### PYQ 2: Nov 2025 End-Sem Exam – Question 5(b) [2 Marks]

> **Question 5(b) [2 Marks]:**
> *"Distinguish between sparse indexing and dense indexing. (2 marks)"*

#### ✅ Model Exam Answer [2 / 2 Marks]:

| Parameter | Dense Indexing | Sparse Indexing |
| :--- | :--- | :--- |
| **1. Definition** | Contains an index entry `<Search_Key, Pointer>` for **every single record** (every search key value) in the data file. | Contains an index entry for **only some records**—specifically **one entry per data block** (pointing to the first record/block anchor of each block). |
| **2. Number of Index Entries** | Equal to the total number of **records ($r$)** in the data file. | Equal to the total number of **data blocks ($b$)** in the data file. |
| **3. Data File Sorting** | Can be built on **both sorted and unsorted** data files. | Can **only** be built if the data file is **physically sorted** on the search key. |
| **4. Storage Space & Example** | Requires **more space** on disk. *Example:* Secondary Index. | Requires **much less space** on disk. *Example:* Primary Index. |

### ⭐ Bonus Practice: What if the Exam Asks for a SECONDARY Index (Dense) on the Same File?
Suppose in Nov 2026 they give the exact same `EMPLOYEE` file ($r = 10000$, $R = 80\text{ B}$, $B = 512\text{ B}$, $V = 15\text{ B}$, $P = 5\text{ B}$) and ask for a **Secondary Index (Dense)** instead of a Primary Index:
* Step 1 & 2 stay identical: $b = 1667$ data blocks, $R_i = 20\text{ B}$, $bfr_i = 25\text{ entries/block}$.
* **Step 3 (Only change!):** Since a Secondary Index is **Dense**, the number of index entries is **$r_i = r = 10,000$** (instead of $1667$)!
* **Step 4:** Index blocks $b_i = \left\lceil \frac{10000}{25} \right\rceil = \mathbf{400\text{ index blocks}}$.
* **Step 5:** Total Block Accesses $= \left\lceil \log_2(400) \right\rceil + 1 = 9 + 1 = \mathbf{10\text{ block accesses}}$!

### Quick 30-Second Recap of 3.4
* **Index Entry Size:** $R_i = V + P$. **Index Blocking Factor:** $bfr_i = \lfloor B / R_i \rfloor$.
* **Dense Index:** 1 entry per **record** ($r_i = r$). Used in **Secondary Index**.
* **Sparse Index:** 1 entry per **data block** ($r_i = b$, points to Block Anchor). Requires sorted data file. Used in **Primary Index**.
* **Single-Level Index Block Accesses:** $\left\lceil \log_2(b_i) \right\rceil + 1$.
